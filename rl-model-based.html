Module 7 · Model-based reinforcement learning

Model-free agents learn only from what they actually experience. A model-based agent also learns how the world works, a table or a network that predicts the next state and reward, and then uses that model to plan: it rehearses decisions in its head before trying them. This module covers Dyna-Q, Monte Carlo tree search, the way model errors compound, and model-predictive control with learned models.

Where this sits in the loop. Model-based methods add a stage to the learning loop: every real transition is stored in a model (the store stage), the model is replayed or searched to produce extra value estimates (the estimate and improve stages), and the policy then acts in the real environment. The price is computation per real step; the gain is fewer real steps.

How the labs work. Every lab is an illustrative simulation on a small problem, not a benchmark. All randomness uses a fixed seed, so a run can be repeated exactly. Numbers in the labs are computed in the browser, and each lab's caption states its simplifications.

7.1

Learned models & Dyna-Q

The questionA robot arm must learn to reach a cup. Each real attempt takes ten seconds and wears the gears a little. A Q-learning agent from Module 4 would need thousands of attempts. Is there a way to get more learning out of each real attempt, by remembering what happened and rehearsing it?

Intuition

Think of a learner who keeps a notebook. Every time something happens, the learner writes down two things: what the value of that action was, and what happened next. The first kind of note is the value estimate you already know from Module 4. The second kind of note is a model: "in this state, when I do this action, I end up in that state and get that reward."

Once the notebook has a model, the learner can plan. Instead of waiting for the world to show the same situation again, the learner opens the model, picks a remembered situation, imagines the outcome and updates its values as if the imagined outcome had really happened. This is a rehearsal. It costs computation, not real attempts. The method that combines real learning with these imagined updates is called Dyna.

Build it up, one piece at a time

Step 1: a model is a lookup table. Take the simplest case, a deterministic world. For each state–action pair (s,a) we store the reward and next state we last saw, written M(s,a) = (r, s'). If the world is deterministic, one observation is enough and the table is exact.

Step 2: a real step does three things. Suppose the agent is in state s, takes action a, and observes reward r and next state s'. It (i) updates its action values with the ordinary Q-learning rule, (ii) writes M(s,a) \leftarrow (r,s'), and (iii) performs n planning updates: pick a pair it has seen before, look up its stored outcome, and apply the same Q-learning rule to that imagined transition.

Step 3: a worked example by hand. Consider a corridor with states 0, 1, 2 and a goal state 3. The actions are L (move left) and R (move right), moves are deterministic and walls stop at state 0. Entering the goal gives reward +1, and every other step gives 0. Use \gamma = 0.9, \alpha = 0.5 and n = 2 planning updates after every real step. In the first episode the agent always moves R. All values start at 0.

Worked example: Dyna-Q on the three-step corridor

The real update for a transition is Q(s,a) \leftarrow Q(s,a) + \alpha\,[\,r + \gamma \max_{a'} Q(s',a') - Q(s,a)\,]. For the planning steps we replay stored pairs in a fixed order, from the pair nearest the goal backwards, cycling through the list.

The reward was seen only once, on the last real step. Without planning (n = 0) the table after the episode would be Q(0,R) = 0, Q(1,R) = 0, Q(2,R) = 0.5, so the start state would know nothing about the goal. With two planning updates per step, the value of the goal has been carried back two states using imagined transitions only. Note that the planning updates at t = 3 used the new value of Q(2,R), which is why the chain of values is built in one pass.

Formal definition

Dyna-Q keeps three things: action values, a model, and a set of pairs seen so far. After each real transition (s,a,r,s') it performs the following.

\begin{aligned} &\text{(direct)}\quad Q(s,a) \leftarrow Q(s,a) + \alpha\big[r + \gamma \max_{a'} Q(s',a') - Q(s,a)\big] \\ &\text{(model)}\quad M(s,a) \leftarrow (r, s') \\ &\text{(planning, repeated } n \text{ times)}\quad (\tilde s,\tilde a) \sim \text{seen pairs},\;(\tilde r,\tilde s') = M(\tilde s,\tilde a),\\ &\qquad Q(\tilde s,\tilde a) \leftarrow Q(\tilde s,\tilde a) + \alpha\big[\tilde r + \gamma \max_{a'} Q(\tilde s',a') - Q(\tilde s,\tilde a)\big] \end{aligned}

Dyna-Q with n = 0 is ordinary Q-learning. Planning changes nothing about what the agent is allowed to do in the world; it only changes how much each real observation is reused.

Pipeline placement. Store stage: the model table (one entry per visited pair, size |S|·|A| in the tabular case). Estimate and improve stages: one real update plus n planning updates per real step, so the cost per real step is 1 + n table updates. The model is updated only in the store stage.
Common traps
  • A planner is only as good as its model. If the model is wrong, planning reinforces the error. The real updates are the only thing that corrects it.
  • The tabular model assumes determinism. If the same pair leads to different outcomes, storing one (r, s') is wrong. The fix is to store averages or estimated distributions, which is the subject of 7.3.
  • Fewer real steps is not zero cost. Dyna trades real experience for computation. On a robot, the planning cost may be cheap; on a large problem it is not.
  • Planning on pairs never visited is impossible. The model only knows pairs the agent has tried, so exploration still matters.
Where it shows up in AI

Dyna (Sutton, 1990) is the origin of this pattern. Its descendants include Model-Based Policy Optimization (Janner et al., 2019), which trains a policy on short rollouts from a learned dynamics model branched off real states, and Dreamer (Hafner et al.), which learns a latent world model and improves its policy by imagining trajectories through it. The same idea of reusing every real transition through a model is what lets these agents work with far fewer environment steps than model-free agents on the same tasks.

Check yourself

1. In the worked example, why does Q(0,R) become nonzero at t = 3 even though state 0 is three moves from the goal?
Because the planning updates at t = 3 propagate the new value Q(2,R) = 0.5 backwards. The update for (1,R) uses the model's next state 2 and gives Q(1,R) = 0.225; the next update for (0,R) uses the new Q(1,·) and gives 0.10125. Each planning update carries value back one state.
2. The world is stochastic: from (s,a) the reward is 0 with probability 0.5 and 1 with probability 0.5. What should the model store instead of a single (r, s')?
An estimate of the distribution, for example the running average reward and the empirical probabilities of each next state. Storing only the last observation makes the model give the same answer every time, so planning would overfit to one outcome.
3. Dyna with n = 20 uses 21 table updates per real step. Under what circumstances is this worth it?
When real steps are expensive or scarce (a robot, a clinical trial) and the table updates are cheap, and when the model is reasonably accurate. If the environment is cheap to simulate, model-free learning with more real steps may be simpler. The answer depends on the relative cost of a real step and a planning update.

Takeaways

  • A model is a stored prediction of (reward, next state) for each state–action pair; a real step updates both values and model.
  • Planning updates replay the model to propagate value backwards with no new real experience.
  • Dyna-Q is Q-learning plus n planning updates; the gain is sample efficiency, the cost is computation, and the risk is model error.
7.2

Monte Carlo tree search

The questionBefore a move, a planner has a model of the game but the full tree of possible futures is far too large to enumerate. In the game of Go the number of legal positions is in the order of 10170. How can a planner choose a good move after looking at only a tiny part of the tree, and how should it decide where to look next?

Intuition

Imagine searching a large building for a lost object. You cannot visit every room, so you go down the corridors that look most promising, but you also try doors you have never opened, because the best room may be behind one of them. Monte Carlo tree search (MCTS) does this for decision trees. It builds a tree of the options it has examined, and each new visit has two aims at once: to look deeper where the results are good (exploit) and to look at branches that have been examined too little to judge (explore).

Each iteration of MCTS has four phases, and the lab shows all four:

  1. Selection. Starting at the root, follow the child with the best score until reaching a node that still has children not yet added to the tree.
  2. Expansion. Add one new child of that node to the tree.
  3. Simulation. From the new node, play random moves to the end of the game and record the final payoff. This is the "Monte Carlo" part.
  4. Backup. Add one visit and the payoff to every node on the path from the root to the new node.

After many iterations the root's children have visit counts and average payoffs. The move to play is the child visited most often, which is more reliable than the one with the highest average when visit counts are small.

Build it up, one piece at a time

Step 1: the test tree. Our decision problem has two decisions. First choose one of three actions A, B, C. Then choose x or y. The leaf payoffs are: A: x = 0.2, y = 0.8; B: x = 0.5, y = 0.4; C: x = 0.9, y = 0.1. The best achievable payoff is 0.9, by playing C then x.

Step 2: the average is not enough. The average payoff of each first action, if the second decision is random, is A: (0.2 + 0.8)/2 = 0.5, B: (0.5 + 0.4)/2 = 0.45, C: (0.9 + 0.1)/2 = 0.5. A planner that uses only averages cannot tell A from C, and C is the one that contains the best answer. Search must keep looking into C.

Step 3: how to choose where to look. The UCT rule (upper confidence bound applied to trees) scores each child by its average payoff plus a bonus that is large when the child has few visits compared with its parent:

Worked example: four iterations, then the UCT choice

Use c = \sqrt{2}. Run the first three iterations. Each expansion adds one first-action node, and the rollout (random second decision) is fixed here so the example is exact: iteration 1 rolls out to y (payoff 0.8), iteration 2 to x (0.5), iteration 3 to y (0.1).

iterationphasenode addedpayoffroot (N, W)A, B, C (N, W)
1expand A, roll outA0.8(1, 0.8)A (1, 0.8)
2expand B, roll outB0.5(2, 1.3)B (1, 0.5)
3expand C, roll outC0.1(3, 1.4)C (1, 0.1)

At iteration 4 all three first actions have been added, so selection applies UCT at the root, with parent visits N = 3. Every child has one visit, so the bonus is the same for all: c\sqrt{\ln 3 / 1} = 1.4142 \times \sqrt{1.0986} = 1.4823. The scores are

\text{UCT}(A) = 0.8 + 1.4823 = 2.2823,\quad \text{UCT}(B) = 0.5 + 1.4823 = 1.9823,\quad \text{UCT}(C) = 0.1 + 1.4823 = 1.5823

So A is selected. Node A has no children yet, so expansion adds A-x, which is terminal with payoff 0.2. The backup gives the root (4, 1.6), A (2, 1.0), A-x (1, 0.2). Notice that C, the branch with the best answer, was visited only once, and that its average 0.1 looks bad after a single unlucky rollout. Further iterations are needed to recover it; this is exactly why the bonus term exists.

Formal definition

For a node v with child u, the UCT score is

\text{UCT}(u) = \frac{W_u}{N_u} + c\sqrt{\frac{\ln N_v}{N_u}}
SymbolMeaning
N_unumber of visits to child u so far
W_usum of payoffs backed up through u; W_u / N_u is its average payoff

The bonus term is large when N_u is small compared with N_v, and it shrinks as the child is visited more. Its growth is logarithmic in the parent's visits, so every branch keeps getting some attention. Under the usual assumption that payoffs lie in [0,1], UCT is the bandit algorithm of Module 1 applied at every node of the tree, which is why the same bounds on regret carry over at each level.

Pipeline placement. Act stage, at decision time: MCTS runs before each move, using the model from the store stage. It stores only the tree for the current decision (one node per expansion), and its cost is iterations × depth model calls per move. The tree is usually discarded after the move, but its statistics can be reused.
Common traps
  • Choosing by average payoff. With few visits the average is noisy. The robust choice is usually the most visited child.
  • Random rollouts are biased. Random play gives a crude estimate of the value of a position. Strong systems replace it with a learned value estimate.
  • The payoffs must be bounded for the constant to mean anything. If payoffs range over [−100, 100], c = √2 explores far too little or too much; rescale the payoffs.
  • Two-player games need a sign flip. The lab is single-agent. In a two-player game, the payoff is negated at alternate levels, so each player's choices are scored from its own point of view.
  • MCTS is anytime, but not free. It can be stopped at any iteration and still return a move, with quality rising with the budget.
Where it shows up in AI

AlphaGo (Silver et al., 2016) used MCTS guided by a policy network that proposed moves and a value network that scored positions instead of random rollouts. AlphaZero (2017) used the same search, with the visit counts of the root children as the training target for the policy network. MuZero (2020) ran MCTS on a learned model without being given the rules of the game, which links this lesson to 7.1 and 7.3.

Check yourself

1. Using the iteration-3 values (root N = 3, A, B, C with N = 1 each and averages 0.8, 0.5, 0.1), which child does UCT select first, and why does the average alone not decide it?
A is selected, with UCT 2.2823 against 1.9823 for B and 1.5823 for C. The average alone would also select A here, but the bonus is what forces the search to keep visiting B and C later as their visit counts stay low.
2. The actions A and C both have an average of 0.5 under random second decisions. Why can an average-only planner not tell which one to choose, and what does MCTS do instead?
Averages hide the spread of the payoffs: A has 0.2 and 0.8, C has 0.9 and 0.1. A search that keeps exploring under-visited children and records the actual values at the leaves will eventually find the 0.9 leaf, while a planner that reads only the mean cannot distinguish the two.
3. Why is the final move chosen by visit count rather than by the highest average?
A child with a high average after only one or two visits may be a lucky rollout. Visit counts concentrate on children the search has repeatedly found to be good, so the most visited child is more robust. The UCT rule already moves visits towards the best children, so visit count and value usually agree after enough iterations.

Takeaways

  • MCTS grows a tree by four repeated phases: selection, expansion, simulation and backup.
  • UCT adds a logarithmic exploration bonus to each child's average, so under-visited branches keep being checked.
  • Choose the move by visit count, and remember that the search is anytime and its quality depends on the budget.
7.3

Model error & compounding rollouts

The questionA learned model predicts the next state with an error of 0.02 at every step. A planner uses the model to imagine ten steps into the future. Is the imagined future about 0.02 wrong, or about 10 × 0.02 = 0.2 wrong, or something else? And if the error grows, is there a safe way to use the model at all?

Intuition

A model that predicts from its own predictions is like a game of telephone. The first person hears the message slightly wrong and passes on a slightly wrong version; each relay adds its own mistake, and the mistakes stack. Whether they stack gently or explosively depends on the dynamics. If small differences shrink each step, the error stays small. If they grow each step, the imagined future drifts far from the real one even when every single prediction looked accurate.

This is why a model can have excellent one-step accuracy and still be useless for long plans. Planning with a model is always an open-loop rollout: the model is fed its own predictions until the planning horizon ends.

Build it up, one piece at a time

Step 1: one step. Let the true system be linear, x_{t+1} = a\,x_t, with a = 1.05 (the state grows by 5% per step). The model is \hat x_{t+1} = a\,\hat x_t + \varepsilon, where the constant \varepsilon = 0.02 is the one-step error. Both start from the same state.

Step 2: two steps. After one step the error is d_1 = \varepsilon. After the second step the model applies the same map to its already-wrong value, so d_2 = a\,d_1 + \varepsilon = a\varepsilon + \varepsilon. The first error has been multiplied by the gain a before being passed on.

Step 3: the general pattern. Repeating the step gives d_h = \varepsilon(1 + a + \dots + a^{h-1}), which is a geometric sum. For a \ne 1 it equals \varepsilon\,(a^h - 1)/(a - 1).

Worked example: one-step error 0.02, gain 1.05

With \varepsilon = 0.02 and a = 1.05, the error after h steps is

d_h = 0.02\,\frac{1.05^h - 1}{0.05}

After ten steps the error is 0.25, more than twelve times the one-step error. Now suppose the planner may only trust the model while the error stays below a tolerance \tau = 0.1. The largest usable horizon is the largest h with d_h \le 0.1. Since d_4 = 0.0862 and d_5 = 0.1105, the answer is h = 4 steps.

Step 4: a stable system. If instead a = 0.95, the sum converges: d_\infty = \varepsilon/(1 - a) = 0.02/0.05 = 0.4. The error saturates instead of growing without bound, but it saturates at twenty times the one-step error. Stability of the dynamics decides how bad compounding is, but even a stable system can accumulate a large error.

Step 5: the short-rollout remedy. Instead of rolling the model out for the full horizon, restart the rollout from a real state every k steps. Each segment then accumulates at most k steps of error. This is the idea behind branched rollouts in MBPO: the policy sees mostly real states, and the model contributes short imagined segments.

Formal definition

Let f be the true one-step map and \hat f the model. Assume that f is L-Lipschitz in the state (nearby states map to nearby next states with a gain of at most L) and that \|\hat f(x,u) - f(x,u)\| \le \varepsilon for all states and actions the rollout visits. Then for an open-loop rollout that starts from the same state, the error satisfies

\|\hat x_h - x_h\| \;\le\; \varepsilon \sum_{j=0}^{h-1} L^{\,j} \;=\; \varepsilon\,\frac{L^h - 1}{L - 1}\quad (L \ne 1)

x_h, \hat x_hthe true and the model's state after h steps, from the same start

The inequality is a worst-case bound. It is exact for the linear example, where the errors add with no cancellation. Its message is the important part: the bound grows like L^h when L > 1 and linearly in h when L = 1. Restarting from real states replaces h with k, so the bound no longer depends on the total horizon.

Pipeline placement. Estimate and improve stages: model rollouts are generated in the learn stage from the model store, with a horizon chosen as a hyperparameter. The cost per model rollout grows linearly with its length. The evaluation stage should measure model error on states the planner actually visits, not only on the training data.
Common traps
  • One-step accuracy is not enough. A model with a small one-step error can still produce useless long rollouts, as the worked example shows.
  • Average error hides compounding. Report error as a function of horizon, not as a single number.
  • Errors are largest where the data are sparse. Imagined states far from the training data are the least reliable, and planning tends to seek exactly those states because they look good under the model.
  • Using a Lipschitz bound you do not have. The bound requires an estimate of L. For a neural network it can be very loose, so treat the formula as a guide to the shape of the error curve, not a guarantee.
Where it shows up in AI

MBPO (Janner et al., 2019) draws short branched rollouts of a learned ensemble model from real states, which keeps the compounding bounded by the rollout length. Dreamer (Hafner et al.) imagines trajectories of about 15 steps in a learned latent space and then learns from them, and it relies on the same trade-off between horizon and model error. Any robot that plans with a learned dynamics model has to make the same choice of horizon.

Check yourself

1. A model has a one-step error of 0.02 and the true gain is a = 1.05. What is the error after 3 steps, and why is it not 0.06?
d_3 = 0.02·(1 + 1.05 + 1.05²) = 0.02 × 3.1525 = 0.06305. It is not exactly 0.06 because each earlier error is multiplied by the gain 1.05 at every later step, so the errors compound slightly.
2. With a = 0.95 and ε = 0.02, does the error keep growing? What is its limit?
No. The error converges to ε/(1 − a) = 0.02/0.05 = 0.4. A stable system bounds the compounding, but the bound can still be twenty times the one-step error.
3. How does restarting a rollout from real states every k steps change the bound, and what does it cost?
The bound depends on the segment length k instead of the full horizon h, so the error no longer keeps growing with the total horizon. The cost is that the model is used for fewer consecutive steps, so fewer imagined transitions are produced per real state, and the policy gets less benefit from planning far ahead.

Takeaways

  • Open-loop model rollouts feed predictions back into the model, so one-step errors compound with a gain that depends on the dynamics.
  • A small one-step error is harmless for short horizons and can be ruinous for long ones; always check error against horizon.
  • Short branched rollouts from real states bound the error without giving up model-based learning entirely.
7.4

Model-predictive control with learned models

The questionA robot's learned model says that pushing with command 1 moves the hand 0.5 units. In reality the hand moves 1 unit. A planner that trusts the model will plan a path that is too slow and then too fast. Can the robot still reach the cup, and what should it do at each moment?

Intuition

Model-predictive control (MPC) is the habit of a driver looking far down the road but steering only for the next few metres. At every moment the controller imagines a sequence of future actions, scores each imagined future with the model, and then carries out only the first action of the best sequence. At the next moment it looks again, now from the state the world actually reached.

Replanning is the safety net. A model error changes the predicted future, but the next replanning starts from the real state, so the error is corrected each step instead of being accumulated over the whole plan. This is the bridge from Module 7 to robot control: the planner of Module 7 is the controller that robotics calls MPC.

Build it up, one piece at a time

Step 1: a one-dimensional reaching task. Let p be the position of the hand, with the cup at p = 0. A command u moves the hand by g\,u, where g is the true gain. The cost of a state is p^2 (distance from the cup, squared) and the cost of a command is a small \lambda u^2 with \lambda = 0.1.

Step 2: plan over a short horizon. With horizon H = 2 and commands in \{-1, 0, +1\}, there are nine action sequences. The planner evaluates each one with the model gain \hat g and picks the cheapest.

Step 3: execute one step and replan. Only the first command is sent to the real hand. The new real position is observed, and the planner starts again from it.

Worked example: model gain 0.5, true gain 1, start at p = 2

The model predicts \hat g = 0.5; the truth is g = 1. Plan with H = 2 and cost \sum_{k=1}^{2} (p_k^2 + 0.1\,u_k^2). The cheapest sequence under the model is (-1,-1). Its predicted positions are p_1 = 2 - 0.5 = 1.5 and p_2 = 1.5 - 0.5 = 1.0, so its cost is

J = (1.5^2 + 0.1) + (1.0^2 + 0.1) = 2.35 + 1.10 = 3.45

For comparison, (-1,0) costs 4.60 and (0,0) costs 8.00. The planner sends u_0 = -1. The real hand moves to p = 2 - 1 \cdot 1 = 1.0, not 1.5 as predicted. Replanning from p = 1.0: the best sequence is again (-1,-1), with cost (0.5^2 + 0.1) + (0^2 + 0.1) = 0.45. The second real move gives p = 0, the cup. The error in the model was half the step, and the closed loop absorbed it in one replanning.

Formal definition

At time t, with the current observed state x_t, the planner solves

\min_{u_t,\dots,u_{t+H-1}}\; \sum_{k=0}^{H-1} c(\hat x_{t+k}, u_{t+k}) \quad\text{subject to}\quad \hat x_{t+k+1} = \hat f(\hat x_{t+k}, u_{t+k}),\; \hat x_t = x_t

It applies u_t^\star, the first action of the best sequence, to the real system, observes x_{t+1}, and repeats. The optimisation over sequences can be done by enumeration (as in the worked example), by random shooting (sample many sequences and keep the best, as in the lab), or by iterative methods such as the cross-entropy method.

  3. Set the horizon to 1, then 8, then 20. A horizon of 1 is greedy; does a longer horizon help when the model is wrong?
  4. Increase the number of sampled sequences. Does a larger sample always give a better first action?
Pipeline placement. Act stage, every control step: the planner runs at the control rate of the robot on top of the model stored after the learn stage. Its compute cost is samples × horizon model calls per step, which sets the maximum control rate. The model should be refit in the learn stage from data gathered by the controller, and its error monitored in the monitor stage.
Common traps
  • A short horizon is greedy. With H = 1 the planner only sees one step, so it may overshoot a target that a longer plan would approach smoothly.
  • A long horizon amplifies model error. The plan's far end is the least reliable part, as 7.3 showed, so the value of a long horizon depends on model quality.
  • Replanning is not free. Each control step costs a full search, so the search budget must fit in the control period.
  • MPC is not the optimal policy. It is a receding-horizon approximation; it is good when the model is reasonable and the cost is well shaped.
  • Random shooting scales badly. In high-dimensional action spaces, sampling uniformly wastes almost every sample; more structured optimisers are used in practice.
Where it shows up in AI

MPC with learned models is used in robot manipulation and locomotion, where the planner re-optimises at the control rate on top of a dynamics model. MuZero (Schrittwieser et al., 2020) combined a learned model with tree search to choose each move, which is the same closed loop of plan, act and replan applied to games. For robot control with classical models, see Robot control and Robot planning.

Check yourself

1. In the worked example, why does the planner choose (−1,−1) and not (−1,0), even though the second action costs something?
Under the model with gain 0.5, the sequence (−1,−1) brings the predicted position to 1.0 after two steps, whereas (−1,0) leaves it at 1.5. The squared-distance cost of 1.0² is much smaller than 1.5², which outweighs the extra command cost of 0.1.
2. After the first real step the hand is at 1.0, but the plan predicted 1.5 at step 1. Why does the controller not simply follow the old plan?
The old plan was built on a model that is wrong. MPC applies only the first action and then plans again from the observed state, so the mismatch is corrected immediately. Following the old plan would reproduce the model's error at every step.
3. Why is a horizon of 1 sometimes a poor choice even when the model is perfect?
A one-step planner minimises the cost of the next state only, so it can make moves that look good now but leave the system far from the target later. A longer horizon accounts for the future cost of each action; with a correct model, it reaches the goal with smoother motion.

Takeaways

  • MPC plans a sequence with the model, applies only the first action, observes the real state and replans.
  • Replanning corrects model error step by step, which is why MPC tolerates imperfect models far better than an open-loop plan.
  • The horizon, the number of samples and the model quality together set the trade-off between accuracy, reaction and compute.
