5.1

From pixels to tokens

The questionA transformer reads a sequence of vectors. A 224×224 colour photo is a grid of 150,528 numbers. If we treat every pixel as a token, attention must compare every pixel with every other: 50,176² ≈ 2.5 billion pairs, per head, per layer. How do we turn an image into a short, sensible sequence without throwing the picture away?

Intuition

Think of a jigsaw puzzle. You do not reason about each grain of colour on a piece; you reason about pieces. A piece is big enough to carry a little meaning (an eye corner, a bit of sky, a stripe of fur) but small enough that you need many of them for a scene. The Vision Transformer does exactly that: cut the image into a grid of square patches, turn each patch into one vector (a token), and line the tokens up as a sequence — a "sentence" whose "words" are pieces of picture.

Words come from a dictionary, but there is no dictionary of patches, so each patch is turned into a vector by a learned linear projection: a single matrix multiplication shared by every patch. That is all "patch embedding" is.

Build it up

Step 1, patchify. Choose a patch side P. An image of height H and width W is cut into H/P rows and W/P columns of patches, so there are N=\frac{HW}{P^2} patches (assume P divides H and W; otherwise crop or pad).

Step 2, flatten. Each patch holds P\times P\times C numbers (C = 3 colour channels). Unroll them into one vector of length P^2C.

Step 3, project. Multiply by a learned matrix E\in\mathbb R^{(P^2C)\times D} and add a bias: the result is a D-dimensional token. D is the model width (768 for ViT-Base).

Worked example: ViT-B/16 on a 224×224 image

P = 16, C = 3, D = 768. Patches per side: 224/16 = 14, so N=14^2=196 tokens. Each patch has 16·16·3 = 768 numbers. The projection matrix is 768×768 = 589,824 weights plus 768 biases = 590,592 parameters. It is applied 196 times: 196·768·768 = 115,605,504 MACs (multiply-accumulates).

Sanity check against a CNN: this is exactly a convolution with a 16×16 kernel, stride 16, 768 output channels (weights 3·16·16·768 = 589,824). The image became 196×768 numbers instead of 150,528: a small reshaping, not a compression: 196·768 = 150,528. The count is identical; the numbers are simply re-arranged and mixed.

Changing the patch size: P = 32 gives (224/32)² = 49 tokens (ViT-B/32); P = 8 gives 28² = 784 tokens (16 times more than P = 32). Halving the patch side quadruples the token count.

Why sequence length is the real cost. Attention compares every token with every token, so its work grows with N². Double the image side and N quadruples, so the attention matrix grows 16×. Patches keep N small enough to be affordable: that is the entire reason ViT cuts the image rather than using pixels.

The formal definition

x_p^{(i)}=\mathrm{vec}\big(\text{patch}_i\big)\in\mathbb R^{P^2C},\qquad z_i=x_p^{(i)}E+b\in\mathbb R^{D},\qquad N=\frac{H}{P}\cdot\frac{W}{P}
H, W, Cimage height, width, channels
Ppatch side in pixels (16 and 14 are common; 32 for fast models)
Nnumber of patches = number of tokens (before adding a class token)
vec(·)unroll a P×P×C block into one vector of length P²C
E, bthe learned projection matrix and bias, shared by all patches
Dembedding width, the size of every token

The output is a matrix Z\in\mathbb R^{N\times D}: one row per patch.

  2. Press sweep. As the image grows the red N² curve overtakes the blue linear one at N = 6D = 4,608 tokens (for D = 768), about 1,088 pixels wide at P = 16.

Common traps
  • Patchify is not pooling. No information is discarded: 16·16·3 = 768 numbers in, 768 numbers per token out (for D = 768). A smaller D would compress.
  • Patches ignore their neighbours. A pure ViT patch embedding never looks across a patch border; pixels on either side of a border only meet later, in attention. (CNN stems do overlap.)
  • Resolution changes the token count. A model trained at 224 with learned position embeddings of length 197 cannot simply be fed 384×384 images; the position table must be interpolated (lesson 5.2).
  • The class token is not a patch. It is added after embedding (next lesson) so the sequence has N+1 tokens.
Where it shows up in AI
  • ViT / DeiT / Swin all begin with a patch embedding (Swin uses 4×4 patches, giving 56×56 = 3,136 tokens).
  • Masked autoencoders mask patches, not pixels, because the patch is the token (lesson 5.6).
  • Video and diffusion transformers cut space-time or latent grids into patches in the same way (Modules 8–9); CLIP's image tower is a ViT.

Check yourself

1. How many tokens does a 384×384 image give with P = 16? With P = 14?
384/16 = 24, so 24² = 576 tokens. 384/14 is not an integer (27.43), so you would crop or pad to 378 (27² = 729 tokens) or 392 (28² = 784).
2. By what factor does the number of attention-matrix entries grow if you double the image side at fixed P?
Tokens grow 4×, the N×N matrix grows 4² = 16×.
3. Parameters of the projection for P = 14, C = 3, D = 1024?
Inputs 14·14·3 = 588. Weights 588·1024 = 602,112, plus 1,024 biases = 603,136.

Takeaways

  • Patchify, flatten, project: one shared linear layer turns each P×P×3 patch into a D-dimensional token.
  • N = (H/P)·(W/P); halving P quadruples N.
  • Attention cost scales with N², which is why tokens are patches and not pixels.
5.2

The Vision Transformer

The questionWe now have 196 tokens, each a 768-vector. What must happen to them so that, at the end, one vector can say "this is a golden retriever"? Tokens must exchange information (which patches belong together?), be transformed individually (what does this combination mean?), know where they came from, and finally be summarised in one place.

Intuition

Picture 196 people in a room, each holding a card describing one patch of a photo. Nobody sees the whole picture. Each round has two stages. In attention every person looks at all the others, decides whom to listen to, and updates their card with a weighted mix of what they heard. In the MLP every person privately thinks about their updated card. After twelve rounds, an extra person, the class token, who has been listening to everyone all along, announces the answer.

Because the people stand in a circle with no seat numbers, the model would not know which patch is top-left. So each card also gets a position embedding: a code for "where I come from".

Build it up

1. Class token. Prepend one extra learned vector x_{cls}\in\mathbb R^{D}. The sequence is now N+1 = 197 tokens. It starts with no image information; through attention it gathers what it needs, and only its final state is sent to the classifier.

2. Position embeddings. Add a learned table E_{pos}\in\mathbb R^{197\times 768} element-wise (151,296 parameters). Without it, attention is blind to order: shuffle the patches and every token's output is unchanged (try the lab below). Learned tables start random and become structured: nearby positions end up with similar codes. Fixed 2-D sinusoidal codes also work. For a new resolution, the 14×14 table is resized by bicubic interpolation.

3. Encoder block (repeated 12 times in ViT-B). With pre-norm layout:

z'_\ell=z_{\ell-1}+\mathrm{MSA}\big(\mathrm{LN}(z_{\ell-1})\big),\qquad z_\ell=z'_\ell+\mathrm{MLP}\big(\mathrm{LN}(z'_\ell)\big)

Multi-head self-attention (MSA) splits the 768 dimensions into 12 heads of 64. Each head has its own queries, keys and values, looks at the tokens in its own way, and the 12 results are concatenated and mixed by an output matrix. The MLP is two linear layers with a GELU between: 768 → 3072 → 768 (a 4× expansion). The residual additions keep the signal flowing through 12 blocks.

4. Head. A final LayerNorm, then the class-token vector (768) goes through a linear layer to the 1000 class scores.

Worked example: attention by hand on three tokens

Use head size d = 2. Suppose after the projections the three tokens have queries = keys Q=K=\begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix} and values V=\begin{bmatrix}1&2\\3&0\\0&4\end{bmatrix}.

Token 1 (query (1,0)): scores q\cdot k_j/\sqrt d with \sqrt2=1.414: (1·1+0·0)/1.414 = 0.707; (1·0+0·1)/1.414 = 0; (1+0)/1.414 = 0.707. Softmax: e^0.707 = 2.028, e^0 = 1, sum = 5.056, so weights = (0.401, 0.198, 0.401). Output = 0.401·(1,2) + 0.198·(3,0) + 0.401·(0,4) = (0.401+0.593, 0.802+1.604) = (0.994, 2.407).

Token 3 (query (1,1)): scores 0.707, 0.707, 1.414. e^ = 2.028, 2.028, 4.113, sum 8.169, weights (0.248, 0.248, 0.503). Output = (0.248+0.745, 0.496+2.014) = (0.993, 2.510). The token that matches itself most strongly (score 1.414) gives itself half the weight.

The formal definition

\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\Big(\frac{QK^{\top}}{\sqrt{d}}\Big)V,\qquad Q=ZW_Q,\;K=ZW_K,\;V=ZW_V
Zthe (N+1)×D token matrix entering the block
W_Q, W_K, W_Vlearned D×D matrices (D×64 per head, 12 heads side by side)
QKᵀ(N+1)×(N+1) table of scores: how strongly token i asks for token j
√dkeeps scores from growing with head size (d = 64 in ViT-B), so softmax does not saturate
softmaxturns each row of scores into weights that are positive and sum to 1

For the full maths of attention, including why the scaling is √d, see the attention-maths lesson; this page is self-contained.

Lab: why position embeddings matter

Try this
  1. Choose none and press Step (or wait): the patches shuffle. The attention output of the selected patch does not change (Δ = 0.000): attention treats tokens as an unordered set.
  2. Switch to 2-D sinusoidal: now the same shuffle changes the output (Δ > 0): the model can tell where each patch sits. Click a patch to see its code's similarity to every other position: a bump centred on it.
  3. Try random (what a learned table looks like before training) and 1-D sinusoidal: patches directly above or below each other are far apart in raster order, which is why 2-D codes are preferred.
Common traps
  • MSA parameter count does not depend on the number of heads (still 4D²): heads split the 768 dimensions, they do not multiply them.
  • Position embeddings are added, not concatenated. The sequence width stays 768.
  • Attention FLOPs are not the whole cost. At 224×224, the MLP and projections cost about 24 times more than the QKᵀ and ·V products (1.39 G vs 0.059 G per block).
  • The class token is optional. Averaging all patch tokens (global average pooling) works as well and many models use it.
Where it shows up in AI
  • Image classification: ViT-B/16 (86.6 M parameters, 17.6 G MACs), ViT-L/16 (304.3 M, 61.6 G), ViT-H/14 (632 M, 167 G). DeiT-S: 22.1 M, 4.6 G; DeiT-Ti: 5.7 M, 1.3 G.
  • Backbones of foundation models: CLIP, DINOv2, SAM's image encoder (Module 7), segmentation and depth models all use ViT blocks.
  • The same block (attention + MLP + residual + norm) is the block of GPT and BERT; only the tokenizer differs.

Check yourself

1. Why are there 197 tokens in ViT-B/16 at 224×224, and what is the shape of the position table?
196 patches + 1 class token = 197. The table is 197×768 = 151,296 parameters.
2. Compute the parameters of one MLP with D = 1024 and hidden size 4096 (ViT-L).
1024·4096·2 = 8,388,608 weights + 4,096 + 1,024 biases = 8,393,728.
3. Why divide scores by √d?
A dot product of two d-dimensional vectors with unit-variance entries has variance d. Dividing by √d restores variance 1, so softmax inputs stay in a range where gradients are not vanishing (a saturated softmax is nearly one-hot).

Takeaways

  • ViT = patch embedding + class token + position embedding + L × (MSA + MLP with residuals) + head.
  • ViT-B/16: 197×768 tokens, 12 blocks, 12 heads × 64, MLP 3072; 86.57 M parameters, 17.56 GMACs.
  • Position embeddings are essential: without them attention is permutation-invariant.
5.3

What attention looks at

The questionA ViT says "dog". Which patches did it use? A CNN can answer with Grad-CAM maps; a transformer carries its own built-in answer, the attention weights. Can we simply plot them, and are they telling the truth?

Intuition

Every token produces one row of attention weights: a distribution over all tokens saying "how much I listened to each". For a chosen patch, colour every patch by that weight and you get a heatmap showing where this patch "looked". Because there are 12 layers × 12 heads = 144 such maps, different heads can specialise: some look at close neighbours (like a small convolution), some look along a row, some look at one salient object wherever the query is.

Build it up

One head, one query. Take query patch i. For each key patch j the score is s_{ij}=q_i\cdot k_j/\sqrt d; the weights are a_{ij}=\mathrm{softmax}_j(s_{ij}). The weights sum to 1 over the 196 (or 197) keys.

Temperature. Dividing scores by a temperature τ before softmax controls sharpness: τ small gives almost one-hot (attend to the best match), τ large gives uniform (average everything). The model's scale 1/√d is a fixed τ; the lab lets you change it to see the effect.

Worked example: temperature

Scores (2, 1, 0). With τ = 1: e² = 7.389, e¹ = 2.718, e⁰ = 1, sum 11.107 → weights (0.665, 0.245, 0.090). With τ = 0.5 the scores become (4, 2, 0): 54.6, 7.389, 1 → sum 62.99 → (0.867, 0.117, 0.016). With τ = 4: scores (0.5, 0.25, 0): 1.649, 1.284, 1 → sum 3.933 → (0.419, 0.326, 0.254), nearly uniform.

Global vs local. Global attention allows every key. Local attention restricts the keys with a mask (set masked scores to −∞ before softmax, which gives weight 0): a window of M×M tokens, or a radius around the query. Local attention is what Swin uses (next lesson) and it is also a useful way to see how masks change who can talk to whom.

Attention rollout. One layer's map shows only one step of mixing. Information passes through residual connections too, so a token at layer 3 contains its own earlier state plus attention-mixed information. Rollout models this: replace each layer's attention A by \hat A=\tfrac12(A+I) (the identity is the residual), and multiply the layers: R=\hat A_L\cdots\hat A_2\hat A_1. Row i of R estimates how much input patch j contributed to token i at the top.

Worked example: rollout on two tokens, two layers

Layer 1: A_1=\begin{bmatrix}0.6&0.4\\0.2&0.8\end{bmatrix}, layer 2: A_2=\begin{bmatrix}0.5&0.5\\0.1&0.9\end{bmatrix}. Add residual and renormalise: \hat A_1=\begin{bmatrix}0.8&0.2\\0.1&0.9\end{bmatrix}, \hat A_2=\begin{bmatrix}0.75&0.25\\0.05&0.95\end{bmatrix}. Then R=\hat A_2\hat A_1: row 1 = 0.75·(0.8, 0.2) + 0.25·(0.1, 0.9) = (0.625, 0.375); row 2 = 0.05·(0.8, 0.2) + 0.95·(0.1, 0.9) = (0.135, 0.865). Token 2 at the top is made mostly (86.5%) of input 2 itself: the residual path keeps tokens close to their origin.

The formal definition

a_{ij}=\frac{\exp(s_{ij}/\tau)\,m_{ij}}{\sum_{k}\exp(s_{ik}/\tau)\,m_{ik}},\qquad \hat A_\ell=\tfrac12(A_\ell+I),\qquad R=\hat A_L\cdots\hat A_1
s_ijscore between query token i and key token j
τtemperature (1 in the plain model, the √d is already inside s)
m_ijmask: 1 if token i may attend to j, else 0 (all ones for global attention)
A_ℓattention matrix of layer ℓ averaged over heads
Rrollout matrix; row i = contribution of each input patch to token i

Lab: click a patch, see where it looks

Try this
  1. Click a patch. Follow the four phases: query, scores, softmax weights, weighted sum (the new colour swatch).
  2. Lower the temperature to 0.3: the map collapses onto one or two patches; raise to 3: it spreads out. Weights always sum to 100%.
  3. Switch to 4 heads side by side: content head (similar colours), local head, row head, saliency head (edges): same query, different behaviour. (These four heads are synthetic stand-ins with hand-set scores, not weights of a trained model.)
  4. Set the mask to window 4×4: patches outside the query's window drop to zero. Then pick rollout and raise the layers.
Common traps
  • Attention is not explanation. A high weight says the value of that token was mixed in strongly, not that it caused the prediction. Rollout and gradient-based methods (Grad-CAM adapted to ViT, attribution) are less misleading but not exact.
  • Raw last-layer attention can look blob-like or focus on background "register" tokens; large ViTs sometimes store global information in a few low-information patches (the motivation of "registers").
  • Averaging heads hides specialisation. Look at heads individually.
  • Class-token attention (row of the CLS token) is the usual saliency map; patch-to-patch maps answer a different question.
Where it shows up in AI
  • DINO: the last-layer class-token attention of a self-supervised ViT segments objects without any labels (lesson 5.6).
  • Interpretability tools: attention rollout, Attention Flow, Transformer-LRP; debugging shortcut learning (e.g. a model attending to a watermark).
  • Efficiency: pruning or merging tokens that receive little attention (token pruning, ToMe).

Check yourself

1. Scores (3, 1, 1): compute the softmax weights.
e³ = 20.086, e = 2.718 twice, sum 25.522: weights (0.787, 0.107, 0.107).
2. Why does a masked score equal −∞ rather than 0?
exp(−∞) = 0, so the key gets weight exactly 0 and the rest renormalise. A score of 0 would still give exp(0) = 1, a large weight.
3. Why add the identity when computing rollout?
Each block outputs z + MSA(z); the identity models the residual path, so a token keeps its own information in addition to what attention mixes in.

Takeaways

  • Each query's attention row is a probability distribution over keys; temperature sets its sharpness.
  • Masks turn global attention into windowed or local attention.
  • Rollout multiplies (A+I)/2 across layers; attention maps are evidence, not proof, of what the model used.
5.4

Hierarchical transformers (Swin)

The questionDetection and segmentation need high-resolution feature maps, and CNN backbones provide a pyramid: 56×56, 28×28, 14×14, 7×7. A plain ViT keeps one fixed 14×14 grid of 196 tokens, and its attention cost explodes at higher resolution (lesson 5.1). Can a transformer give a pyramid and linear cost?

Intuition

Two ideas, both borrowed from how CNNs behave.

Windows. Instead of every token talking to all others, divide the feature map into non-overlapping windows of M×M tokens, and let tokens talk only inside their window. A neighbourhood is usually what matters (like a convolution's receptive field), and cost drops from N² to N·M²: linear in image size.

Shifting. Tokens at the edge of a window never hear from the neighbouring window. So in the next block, shift the window grid by half a window: the old borders are now in the middle, so information crosses them. Alternating regular and shifted windows lets information spread across the whole image after a few blocks.

Merging. To build the pyramid, every few blocks merge each 2×2 group of tokens into one token with twice the channels, exactly like a CNN stage that halves the resolution and doubles the width.

Build it up

Cost of windows. With N tokens of width C and window side M (M² tokens per window):

\Omega(\mathrm{MSA})=4NC^2+2N^2C,\qquad \Omega(\mathrm{W\text{-}MSA})=4NC^2+2M^2NC
Worked example: Swin-T stage 1

The first stage has N = 56·56 = 3,136 tokens, C = 96, M = 7 (M² = 49). The attention products cost 2·N²·C = 2·3,136²·96 = 1,888,223,232 MACs with global attention, but 2·M²·N·C = 2·49·3,136·96 = 29,503,488 with windows: 64× cheaper (the ratio N/M² = 3136/49 = 64, which is also the number of windows).

Reach. After one windowed layer a token has heard from M² tokens. After a shifted layer it has heard from every token in each window that its first neighbours' windows touch, roughly a (1.5M)×(1.5M) area; after several layers the whole map. The lab animates this: click a token and compare the blue (layer 1) and orange (layer 2) regions. Implementation note: the real Swin rolls the feature map cyclically so shifted windows keep equal size, and masks tokens that wrapped around; the lab draws the simpler no-wrap version.

Patch merging. Take every 2×2 group of tokens (4 vectors of size C), concatenate them to one vector of 4C, normalise with LayerNorm, and apply a linear layer 4C → 2C (no bias). Height and width halve, channels double, so the number of numbers halves. From stage 1 to 2: LN(384) = 768 parameters, linear 384·192 = 73,728; total 74,496 parameters; MACs = 28·28·384·192 = 57,802,752.

Common traps
  • Window attention does not make the model local forever. Shifting plus merging (the last stage covers the full 7×7 map) restores global reach.
  • The cyclic shift is a trick, not a copy: it keeps all windows the same size for efficient batching, at the price of masks for wrapped-around tokens.
  • Linear cost holds only for fixed M. If M grew with the image you would be back to global attention.
  • Merging halves resolution but the pyramid is learned: unlike pooling, the 4C → 2C linear layer decides what to keep.
Where it shows up in AI
  • Detection and segmentation backbones: Swin plugs into Mask R-CNN, UPerNet and Mask2Former wherever a ResNet did (Modules 6 and 7).
  • Swin V2, SwinUNETR (medical 3-D), and window-attention in SAM's image encoder (mostly windowed blocks with a few global ones).
  • Hierarchical designs beyond Swin: PVT, MViT (video), Hiera, and ConvNeXt (the CNN that copied the macro design).

Takeaways

  • Window attention makes cost linear in tokens (2M²NC); shifting windows lets information cross borders.
  • Patch merging halves H,W and doubles C, producing a CNN-style feature pyramid.
  • Swin-T: 28.3 M parameters, 4.5 GMACs, stages 56²·96 → 28²·192 → 14²·384 → 7²·768.
5.5

CNNs vs ViTs

The questionYou must choose a backbone for a new product. A ResNet needs less data and runs on a phone. A ViT beats it when pre-trained on enormous data. Why do they behave so differently, and when is each the right tool?

Intuition

A model starts life with assumptions, its inductive bias. A CNN assumes: meaning is local (3×3 neighbourhoods) and the same pattern means the same thing everywhere (weights are shared across positions, so shifting the image shifts the features). These are true for images, so a CNN learns quickly from little data. A ViT assumes almost nothing: every patch may talk to every other, and position is just a learned code. It must discover locality and translation behaviour from data. With little data it overfits or learns slowly; with huge data its flexibility pays off.

An analogy: a CNN is a student given a textbook with the rules of geometry; a ViT is a student given a library and a lot of time.

Build it up

Receptive field. One 3×3 convolution layer sees 3×3; each extra layer adds 2 pixels per side: after L layers the field is (2L+1)×(2L+1). To see a whole 224-image a plain stack needs ~112 layers; pooling and strides shorten that. One self-attention layer sees all tokens at once. The lab below grows each model layer by layer.

Data hunger and DeiT. The original ViT trained on ImageNet-1k alone underperformed comparable ResNets; it surpassed them when pre-trained on ImageNet-21k or JFT-300M (hundreds of millions of images). DeiT showed that the same ViT-B reaches 81.8% top-1 on ImageNet-1k from scratch with a strong training recipe (RandAugment, Mixup, CutMix, random erasing, stochastic depth, long schedule), and about 83.4% with a distillation token trained to imitate a CNN teacher: the teacher passes on locality bias through its labels.

Hybrids. Put a convolutional stem in front of a transformer: the CNN extracts local features at stride 16 (here, a ResNet-50 up to stage 3 gives a 14×14×1024 map), then each position is a token (a 1×1 "patch" projection: 1024 → 768). You get locality early and global reasoning late, with similar token counts. Modern designs go further: ConvNeXt modernises the CNN with transformer recipes (7×7 depthwise kernels, LayerNorm, GELU, inverted bottleneck, patchify stem) and matches Swin.

Worked example: the cost of the hybrid

The visualiser's hybrid (ResNet-50 stages 1–3 + ViT-B encoder) has 95.31 M parameters and 20.88 GMACs at 224×224, with the same 196 tokens as ViT-B/16 (17.56 G): the convolutional stem adds about 3.3 G. Now double the image side for a plain ViT-B/16 at 448×448: N = 784 tokens. Per block 12·784·768² = 5.55 G plus attention 2·784²·768 = 0.94 G gives 6.49 G; times 12 blocks = 77.9 G, plus 0.46 G for the patch embedding: about 78.4 G, 4.5× the 224 cost (four times the tokens, a little extra from the N² term).

Compute scaling. Per-image cost of a CNN is linear in the number of pixels; global-attention ViT is quadratic in tokens, linear only until N ≈ 6D. Memory for attention matrices is N² per head per layer, which is why long-token inputs need windowing, FlashAttention (computes attention in tiles without storing N²), or hierarchical designs. In practice on accelerators, ViTs often achieve higher throughput than CNNs of equal accuracy because they are large dense matrix multiplications.

Common traps
  • "ViT is better" depends on data and recipe. On small datasets (tens of thousands of images) a CNN or a hybrid usually wins unless you start from a pre-trained ViT.
  • MACs are not latency. Memory traffic, kernel launch overhead, resolution and hardware change the ranking; always measure on the target device.
  • Parameters are not compute. ViT-B/32 has about the same parameters as ViT-B/16 (88.2 M vs 86.6 M) but a quarter of the compute (4.4 G vs 17.6 G).
  • Fine-tuning at a higher resolution needs position-embedding interpolation, and token count grows with it.
Where it shows up in AI
  • Choosing backbones: mobile/edge → MobileNet, EfficientNet, small hybrids; accuracy at scale → ViT/Swin/ConvNeXt; dense prediction → hierarchical (Swin, ConvNeXt).
  • Transfer learning: ImageNet-21k or CLIP pre-trained ViTs are the default starting point for fine-tuning.
  • Efficient attention: FlashAttention, windowing and token merging address the N² cost.

Check yourself

1. What are the two inductive biases of a convolution?
Locality (each output depends on a small neighbourhood) and weight sharing / translation equivariance (the same filter is used at every position).
2. Receptive field of 5 stacked 3×3 stride-1 convolutions?
2·5+1 = 11, so 11×11 pixels.
3. Why does DeiT's distillation token help a data-hungry model?
It adds a second training signal: it learns from the soft predictions of a CNN teacher, which carry the CNN's locality bias, so the ViT needs less data to learn it.

Takeaways

  • CNNs build in locality and weight sharing: data-efficient; ViTs learn them: flexible, data-hungry.
  • Training recipe (DeiT) and hybrids close the gap; ConvNeXt shows convolution still competes.
  • Global attention costs N²: windowing, hierarchies and FlashAttention manage it.
5.6

Learning without labels

The questionLabelling images is slow and expensive; the internet has billions of unlabelled ones. Can a network learn useful visual features from the images alone, and what task do we invent so that "solving it" forces the network to understand pictures?

Intuition

Self-supervised learning invents a pretext task whose answer is hidden inside the data. Three families dominate.

  • Contrastive (SimCLR, MoCo): "two different views of the same photo should give similar vectors; views of different photos should not". Like recognising a friend in two different photos.
  • Masked reconstruction (MAE): "hide most of the picture and paint it back". To fill the hole the network must learn what objects and textures are like, as when you complete a jigsaw with 75% of the pieces missing.
  • Self-distillation (DINO): "a student must predict what a slowly-moving copy of itself (the teacher) says about a bigger view of the same image". No negatives needed.

Build it up

Contrastive: SimCLR. Take an image, make two random augmentations (crop, flip, colour jitter, blur), encode both, normalise the vectors u, v to unit length. The InfoNCE (NT-Xent) loss for a batch of N images pulls the matching pair together and pushes the other N−1 away. In the lab below use simclr mode; the full worked loss is computed in lesson 5.7, and the maths is the same. MoCo keeps a queue of past embeddings from a slowly moving (EMA) encoder as extra negatives, so large batches are unnecessary.

Masked autoencoder. Cut the image into patches (14×14 = 196). Mask 75% at random, leaving 49 visible. The encoder (a ViT-B) processes only the 49 visible tokens (no mask tokens inside it). Then a light decoder (8 blocks, width 512) receives the encoded tokens plus a shared learned mask token in every hidden position, with position embeddings so it knows where each goes, and predicts the pixels (normalised per patch) of each masked patch. The loss is mean squared error on masked patches only. After pre-training the decoder is thrown away; the encoder is fine-tuned on the real task.

Worked example: why 75% is a bargain

N = 196 patches, mask 75% → visible Nv = 49. Encoder linear layers scale with tokens: 49/196 = 1/4 of the cost. Attention pair count scales with tokens²: 49² = 2,401 versus 196² = 38,416, i.e. 1/16. So pre-training the encoder is roughly 3–4× faster than running it on all patches, and the task is also harder (a high mask ratio prevents trivial copying from neighbours: images are redundant, text is not, which is why BERT masks only 15%). Each target patch is 16·16·3 = 768 numbers.

Self-distillation: DINO. Two networks with the same architecture: a student (trained by gradient) and a teacher (an exponential moving average of the student, \theta_t\leftarrow m\theta_t+(1-m)\theta_s, m ≈ 0.996–1). The teacher sees two large "global" crops, the student sees all crops (also small "local" ones). The student matches the teacher's output distribution over K pseudo-classes. Collapse (all outputs identical) is avoided by centering the teacher's output (subtract a running mean) and sharpening it (low temperature).

Worked example: the DINO loss on three outputs

Teacher logits after centering (1.0, 0.5, 0.0) with temperature 0.1: scaled (10, 5, 0), softmax = (0.9933, 0.0067, 0.00005). Student logits (0.8, 0.6, 0.1) with temperature 0.1: scaled (8, 6, 1); e^8 = 2981, e^6 = 403.4, e = 2.718, sum 3387 → (0.8801, 0.1191, 0.0008). Cross-entropy H(p_t,p_s)=-\sum_k p_{t,k}\ln p_{s,k} = 0.9933·0.1278 + 0.0067·2.128 + 0.00005·7.13 ≈ 0.141. The sharpened teacher is nearly one-hot, so the student is pushed to put its mass on class 1.

The formal definition

\mathcal L_{\text{InfoNCE}}=-\frac1N\sum_{i=1}^{N}\log\frac{\exp(u_i\!\cdot\!v_i/\tau)}{\sum_{j=1}^{N}\exp(u_i\!\cdot\!v_j/\tau)},\qquad \mathcal L_{\text{MAE}}=\frac1{|\mathcal M|}\sum_{p\in\mathcal M}\|\hat x_p-x_p\|^2
u_i, v_iunit-length embeddings of two views of image i (positive pair)
u_i·v_jcosine similarity of view 1 of image i and view 2 of image j (negatives when j ≠ i)
τtemperature; small τ focuses on the hardest negatives
𝓜the set of masked patches
x̂_p, x_ppredicted and true (normalised) pixels of patch p

Common traps
  • Collapse. Without negatives (DINO, BYOL) or without enough augmentation, the trivial solution (output a constant) gives zero loss. Centering, sharpening, the EMA teacher or negatives prevent it.
  • Augmentations define what is learned. Colour jitter makes features colour-invariant; if colour matters for your task, that is harmful.
  • MAE needs fine-tuning. Its raw features are good for reconstruction; linear-probe accuracy is lower than contrastive methods but fine-tuned accuracy is higher (ViT-L: 85.9%, ViT-H: 86.9% on ImageNet-1k).
  • Batch size matters for SimCLR (thousands) because negatives come from the batch.
Where it shows up in AI
  • Foundation backbones: DINOv2 features are used off-the-shelf for retrieval, segmentation and depth; MAE pre-training for ViT backbones and for video (VideoMAE).
  • Domains with few labels: medical, satellite and industrial imagery use self-supervised pre-training then fine-tune on a few labelled examples.
  • Language–vision: CLIP (next lesson) is contrastive learning between images and text.

Check yourself

1. With mask ratio 90% on 196 patches, how many tokens does the MAE encoder see?
0.1·196 = 19.6, rounded to 20 tokens (176 are masked, the real MAE rounds the count of kept tokens).
2. Why does the MAE decoder receive mask tokens but the encoder does not?
Encoder without mask tokens saves compute (it only runs on visible patches) and avoids a train/test mismatch (at fine-tuning no patch is masked). The decoder needs a slot for each missing patch to predict into.
3. In DINO, what happens to the loss if the teacher outputs a uniform distribution for everything?
The student can match it by also outputting a constant: loss is minimised trivially with no useful features. Sharpening (low temperature) prevents the uniform collapse; centering prevents the one-class collapse.

Takeaways

  • Self-supervision invents a task from the data: contrast views, reconstruct masked patches, or match a teacher.
  • MAE: mask 75%, encode the 25% visible (49 of 196), decode with mask tokens, loss on masked patches only.
  • Preventing collapse (negatives, centering and sharpening, masking) is the central design problem.
5.7

Vision–language models

The questionA classifier trained on 1000 ImageNet classes can never recognise the 1001st. Could a model understand "a photo of a red bicycle leaning on a wall" without ever being trained on a "red bicycle" label? Where would that flexibility come from?

Intuition

The internet is full of images with captions. Suppose one network turns an image into a vector and another turns a sentence into a vector, and we train them so that an image and its own caption land close together and unrelated pairs land far apart. Now the vector space is shared by pictures and words: a new class is just a new sentence. To classify a photo, write a sentence per candidate label ("a photo of a dog", "a photo of a car"), embed them and pick the closest. This is zero-shot classification.

Build it up

CLIP dual encoder. An image encoder (a ViT, for example ViT-B/16, or a ResNet) and a text encoder (a transformer) each produce a vector, projected to a common dimension (512 for ViT-B/16) and normalised to unit length. So all embeddings lie on a sphere, and similarity is the cosine, a dot product in [−1, 1].

Contrastive training. Take a batch of N image–text pairs. Compute the N×N matrix of similarities S_{ij}=u_i\cdot v_j (image i, text j); the correct matches are on the diagonal. Divide by a temperature τ (CLIP learns it; the final value is about 0.01, i.e. logits scaled by 100), apply softmax across each row (which text matches image i?) and across each column (which image matches text j?), and take the cross-entropy against the diagonal.

Worked example: the loss on a 3×3 batch, by hand

Cosine similarities (rows = images 1–3, columns = texts 1–3):

S=\begin{bmatrix}0.9&0.2&0.1\\0.3&0.8&0.2\\0.1&0.4&0.7\end{bmatrix},\quad \tau=0.2\;\Rightarrow\; S/\tau=\begin{bmatrix}4.5&1&0.5\\1.5&4&1\\0.5&2&3.5\end{bmatrix}

Row 1: e^4.5 = 90.02, e^1 = 2.718, e^0.5 = 1.649, sum 94.38. p11 = 90.02/94.38 = 0.9537, loss = −ln 0.9537 = 0.0474.

Row 2: e^1.5 = 4.482, e^4 = 54.60, e^1 = 2.718, sum 61.80. p22 = 0.8835, loss 0.1239. Row 3: e^0.5 = 1.649, e² = 7.389, e^3.5 = 33.12, sum 42.16. p33 = 0.7856, loss 0.2413.

Image→text loss = (0.0474 + 0.1239 + 0.2413)/3 = 0.1375.

Columns (softmax down each column): column 1 (4.5, 1.5, 0.5): 90.02 + 4.482 + 1.649 = 96.15, p11 = 0.9362, loss 0.0659. Column 2 (1, 4, 2): 2.718+54.60+7.389 = 64.71, p22 = 0.8438, loss 0.1698. Column 3 (0.5, 1, 3.5): 1.649+2.718+33.12 = 37.49, p33 = 0.8835, loss 0.1239. Text→image loss = (0.0659+0.1698+0.1239)/3 = 0.1199.

CLIP loss = average of the two = 0.1287. If τ were 1, the logits would be nearly equal and the loss ≈ ln 3 = 1.10: a small temperature is what makes the matrix "peaky".

Zero-shot classification. Embed the image: u. Embed one prompt per class, "a photo of a {class}": v₁…vK. Probabilities = \mathrm{softmax}_k(u\cdot v_k/\tau). No classifier is trained; the prompts are the classifier. Prompt wording matters ("a photo of a …" works better than a bare word), and averaging several templates helps.

Worked example: zero-shot

Image cosines with prompts (cat, dog, car): (0.30, 0.27, 0.10), τ = 0.01 → logits (30, 27, 10). Relative to the first logit the exponentials are (1, e−3 = 0.0498, e−20 ≈ 2·10⁻⁹), sum 1.0498, so the probabilities are (0.953, 0.047, ≈ 0). A 0.03 difference in cosine is a 95% vs 5% decision, because of the 100× scale.

The formal definition

\mathcal L=\tfrac12\Big[\underbrace{-\tfrac1N\sum_i\log\tfrac{e^{S_{ii}/\tau}}{\sum_j e^{S_{ij}/\tau}}}_{\text{image}\to\text{text}}\;\underbrace{-\tfrac1N\sum_j\log\tfrac{e^{S_{jj}/\tau}}{\sum_i e^{S_{ij}/\tau}}}_{\text{text}\to\text{image}}\Big],\quad S_{ij}=\frac{f(x_i)}{\|f(x_i)\|}\cdot\frac{g(t_j)}{\|g(t_j)\|}
f, gimage encoder (ViT) and text encoder (transformer)
x_i, t_jimage i and caption j in the batch
SN×N cosine-similarity matrix; diagonal = true pairs
τlearned temperature (≈ 0.01 at the end of training)
Nbatch size (32,768 in CLIP: ≈ 1 billion entries in S)

Draw it yourself

Image → ViT-B/16 (197×768) → class-token (768) → linear to 512 → L2-normalise → u. Text → tokens (≤ 77) → transformer (12 layers, width 512, 8 heads) → end-token vector → linear to 512 → L2-normalise → v. Then u·vᵀ / τ. Common traps
  • Zero-shot is not magic. It inherits the biases and gaps of web captions; fine-grained and counting tasks are weak; prompt wording changes accuracy by several points.
  • Diagonal ≠ the only truth. Other pairs in a batch may also be valid matches (two cat photos); contrastive loss treats them as negatives.
  • Cosine, not dot product of raw vectors. Embeddings are normalised; otherwise vector length, not direction, would dominate.
  • τ is a learned parameter (log-parametrised and clipped); too low a value early in training gives unstable gradients.
Where it shows up in AI
  • Zero-shot classification and image search: type a sentence, retrieve images (text→image retrieval); reverse image search; dataset filtering (LAION was filtered with CLIP scores).
  • Vision-language models: LLaVA-style models feed a CLIP/SigLIP ViT's tokens into a language model; SigLIP replaces the softmax with a per-pair sigmoid loss.
  • Generative conditioning: Stable Diffusion conditions its U-Net on a CLIP text encoder's tokens; DALL·E 2 generates CLIP image embeddings (Module 8).
  • Open-vocabulary detection and segmentation: OWL-ViT, CLIPSeg, Grounding DINO label arbitrary words.

Check yourself

1. A batch of N = 256 pairs: how many entries are in S, and how many are positives?
256² = 65,536 entries, 256 positives (diagonal), 65,280 negatives.
2. Logits (2, 0, 0) with τ = 1: probability of the first class? With τ = 0.5?
τ = 1: e²/(e²+2) = 7.389/9.389 = 0.787. τ = 0.5: logits (4, 0, 0): 54.6/56.6 = 0.965.
3. Why does CLIP compute the loss in both directions?
Row softmax teaches "which text for this image" (used in zero-shot classification), column softmax teaches "which image for this text" (retrieval). Using both is symmetric and uses each pair in two ways.

Takeaways

  • Two encoders map images and text to one unit-sphere space; a true pair should be near.
  • The loss is cross-entropy on N×N similarities / τ, in both directions; the hand-worked 3×3 example gives 0.1287.
  • Zero-shot: the prompts are the classifier, probabilities = softmax(cosine/τ).
