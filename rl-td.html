Module 4 · Temporal-difference learning

Learn from every step, not only from the end of an episode. A TD method guesses the value of where you are now, checks that guess one step later, and corrects itself. From this one idea come SARSA, Q-learning, Expected SARSA, n-step returns and eligibility traces.

4.1

TD(0) prediction & bootstrapping

The questionA robot walks down a corridor. It gets a reward only when it reaches the charging dock, which may take 200 steps. Monte Carlo methods must wait until the episode ends before they learn anything. Can the robot learn that a corridor cell near the dock is good during the walk, before the reward arrives?

Intuition

Imagine you are estimating how long your commute takes from each junction. Monte Carlo waits until you arrive home, writes down the total time, and then corrects every junction you passed. TD learning does something cleverer: when you reach junction B from junction A, you already have a rough estimate of the time from B. You update your estimate of A using the step you just took plus your current estimate of B. You are using a guess to improve a guess. This is bootstrapping: lifting yourself up by your own boot straps.

The value of a state, V(s), is the expected total discounted reward from s onward under the policy. We never know it exactly, so we keep an estimate V(s) and refine it.

Build it up: the TD error

Suppose the agent is in state S_t, takes an action, receives reward R_{t+1} and lands in S_{t+1}. Two numbers can now be compared. The estimate we had for S_t was V(S_t). A fresh estimate, built from one real step and the current guess for the next state, is R_{t+1}+\gamma V(S_{t+1}). The difference between them is the TD error:

\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)

If \delta_t is positive, the step turned out better than we expected, so we raise V(S_t). If negative, we lower it. The TD(0) update moves the estimate a fraction \alpha of the way toward the target:

V(S_t) \leftarrow V(S_t) + \alpha\,\delta_t
Worked example: a three-state chain

States S_1 \to S_2 \to S_3 \to end. Every move gives reward 0, except the last move from S_3, which gives reward 1. Use \gamma = 0.9, \alpha = 0.5, and start with V = (0,0,0). The true values are V^*(S_3)=1, V^*(S_2)=0.9, V^*(S_1)=0.81.

Episode 1. S_1\to S_2: \delta = 0 + 0.9\cdot0 - 0 = 0. S_2\to S_3: \delta = 0+0.9\cdot 0 - 0 = 0. S_3\to end: \delta = 1 + 0 - 0 = 1, so V(S_3) = 0 + 0.5\cdot 1 = 0.5.

Episode 2. S_1\to S_2: \delta = 0. S_2\to S_3: \delta = 0 + 0.9\cdot 0.5 - 0 = 0.45, so V(S_2)=0.225. S_3\to end: \delta = 1 - 0.5 = 0.5, so V(S_3)=0.75.

Episode 3. S_1\to S_2: \delta = 0 + 0.9\cdot 0.225 - 0 = 0.2025, so V(S_1)=0.10125. S_2\to S_3: \delta = 0.9\cdot 0.75 - 0.225 = 0.45, so V(S_2)=0.45. S_3\to end: \delta = 1-0.75=0.25, so V(S_3)=0.875.

Notice the order of events. The reward 1 was seen in episode 1, but its influence reached S_2 only in episode 2 and S_1 only in episode 3. Credit moves backwards one state per visit. After three episodes the estimates are (0.101, 0.45, 0.875), already closing in on (0.81, 0.9, 1).

The formal definition

V(S_t) \leftarrow V(S_t) + \alpha\big[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\big]
V(s)the current estimate of the value of state s under the policy being evaluated
Rt+1the reward received on the step after time t
γ (gamma)discount factor, 0\le\gamma\le1: rewards later are worth a little less
α (alpha)step size (learning rate), 0<\alpha\le 1: how far one update moves the estimate
δtthe TD error: the surprise between the target and the current estimate
V(St+1) = 0for a terminal state, by convention

Under standard conditions (a fixed policy, every state visited infinitely often, and step sizes that decay in the usual Robbins–Monro way) TD(0) converges to V^\pi. For a constant \alpha it keeps fluctuating around the answer.

Lab

Try this
  1. Press Play and watch one episode. Each step shows its TD error δ; find the step where the walk exits right and check that δ = 1 − V(5) by hand.
  2. Set α to 0.01 and then 0.5. Small α learns smoothly but slowly; large α jumps around. Note the RMS error readout in both cases.
  3. Set γ to 0.5. The true values (dashed green) shrink, because a reward far away is worth little. Compare with γ = 1.
Common traps
  • The TD target is not the truth. R+\gamma V(S') uses an estimate, so TD is biased early on. Monte Carlo targets are unbiased but noisy, because the whole random future is included.
  • Terminal states have value zero. Forgetting this makes the last update use a made-up number.
  • Bootstrapping needs a sensible starting guess. Starting values of zero are common; a very wrong initial table takes longer to correct, and the early estimates can mislead the policy.
Where it shows up in AI
  • Value estimation at scale: the critic of an actor–critic method is trained by TD on a neural network (Module 6).
  • Reward models and evaluators that must give a value to a partial trajectory before it ends.
  • The same TD error, \delta, is the signal in dopamine neurons, a link often drawn in neuroscience texts on learning.

Pipeline view. Stage: estimate. Stores: one table entry V(s) per state. Cost per update: one lookup of V(S′), one multiply-add, constant time and memory per transition.

Check yourself

1. In the chain example, why does V(S₁) stay at 0 in episodes 1 and 2?
Because the two first steps had zero reward and the estimate of the next state was still zero, so every TD error was zero. Credit had not reached S₁ yet; it needs S₂ to have a non-zero value first.
2. Compute δ for a step from s to s′ with r = 0.5, γ = 0.9, V(s) = 1.0 and V(s′) = 2.0.
δ = 0.5 + 0.9·2.0 − 1.0 = 0.5 + 1.8 − 1.0 = 1.3. The step was better than expected, so V(s) rises.
3. Why is TD(0) said to have lower variance than Monte Carlo?
Its target depends on one random reward and one random next state, not on the whole random future of the episode. The price is bias, because V(S′) is only an estimate.

Takeaways

  • TD learning updates after every step, using the TD error δ = R + γV(S′) − V(S).
  • It bootstraps: the target uses the current estimate of the next state.
  • Credit moves backwards one state per visit, so distant rewards take several episodes to reach the start.
4.2

SARSA: on-policy TD control

The questionA robot must cross a warehouse floor from its start to a goal. Along one edge is a drop-off. Each step costs 1; falling costs 100 and sends the robot back to start. The robot still explores at random now and then. Should its learning rule assume that it will always act perfectly from now on, or should it learn the value of the moves it will actually make, mistakes included?

Intuition

Prediction (lesson 4.1) asks: how good is this policy? Control asks: how do I find a better policy? A simple way is to learn action values Q(s,a), the expected return from doing action a in state s, and then act greedily with respect to them. The trouble is that we also need to explore, so the policy we follow is not quite the greedy one.

SARSA (State, Action, Reward, next State, next Action) answers this honestly. It is on-policy: its target uses the next action that the behaviour policy really chose. If exploring means stepping near the cliff and possibly falling, SARSA knows about that risk, because the risk is in its own data. It learns the value of the ε-greedy behaviour, not of a perfect robot.

Build it up: the update rule

A transition now involves five quantities, which is where the name comes from: (S,A,R,S',A'). The agent is in S, takes A, gets R, arrives at S′, and then chooses A′ from S′ with its exploring policy. The update is the TD(0) update applied to Q:

Q(S,A) \leftarrow Q(S,A) + \alpha\big[R + \gamma Q(S',A') - Q(S,A)\big]

An ε-greedy policy takes the greedy action with probability 1-\varepsilon and a uniformly random action with probability \varepsilon. With three actions, the greedy action has probability 1-\varepsilon+\varepsilon/3 and each other action \varepsilon/3.

Worked example: one SARSA update at the cliff

Suppose from the current state the agent took an action that moves it to S′, where the greedy action is safe with Q(S',\text{safe}) = -1 and the cliff move has Q(S',\text{cliff}) = -100. Let Q(S,A)=-5, R=-1, \gamma=1, \alpha=0.5.

If exploration picks the cliff move as A′, the SARSA target is -1 + 1\cdot(-100) = -101, and Q(S,A) \leftarrow -5 + 0.5(-101+5) = -53.

If exploration picks the safe move, the target is -1 + (-1) = -2, and Q(S,A) \leftarrow -5 + 0.5(-2+5) = -3.5.

The same transition gives very different updates, depending on which action was sampled at S′. That is the on-policy character of SARSA: the risky sample is averaged into the estimate in proportion to how often exploration takes it.

The formal definition

Q(S_t,A_t) \leftarrow Q(S_t,A_t)+\alpha\big[R_{t+1}+\gamma Q(S_{t+1},A_{t+1})-Q(S_t,A_t)\big]
Q(s,a)estimated action value: return from taking a in s and then following the policy
At+1the action actually selected in St+1 by the behaviour policy (here ε-greedy)
ε (epsilon)exploration rate, the chance of a random action
α, γstep size and discount, as in 4.1

SARSA converges to the optimal policy among ε-greedy policies under standard conditions (every state–action pair keeps being tried and the step size decays). If ε is kept fixed, the answer is the best policy that still explores at rate ε, which is the safer choice near the cliff.

Lab: the cliff

Try this
  1. Press Play and watch the first few episodes wander. Read the caption: the target uses the action the agent really took next, not the best one.
  2. Let it run for a few hundred episodes and watch the average return. Note the greedy route, the arrows, and how the route changes as the table fills in.
  3. Set ε to 0 and let it run. With no exploration the route may stop changing, but it is not necessarily the best one, because the agent never tries alternatives.
Common traps
  • SARSA is not the value of the best policy. It is the value of the policy you actually follow, including its exploration. Its learned route can be longer than the best route because the best route is risky under exploration.
  • The next action must be chosen before the update. Choosing it after, or taking the max instead, turns SARSA into Q-learning.
  • Terminal transitions have no next action. At the goal the target is just R.
Where it shows up in AI
  • On-policy control in safety-sensitive settings, where the cost of exploration is part of the objective.
  • The conceptual basis of on-policy deep RL, such as SARSA-style critics inside PPO-like methods (Module 6).

Pipeline view. Stages: interact, then estimate and improve (ε-greedy). Stores: a Q-table with one entry per state–action pair. Cost per update: one action sample at S′ and one table entry.

Check yourself

1. Using the worked example, what changes if γ = 0.9 instead of 1?
The SARSA target becomes −1 + 0.9·(−100) = −91 when the cliff move is sampled, so the new Q is −5 + 0.5(−91+5) = −48. The bootstrap is discounted, but the cliff still dominates.
2. Why can SARSA choose a longer, safer path than Q-learning?
Its values include the chance that exploration steps off the edge. A path along the edge is short but has many chances to fall, so its SARSA value is lower, and the greedy route is pushed away from the edge.
3. What is the difference between the behaviour policy and the target policy in SARSA?
In SARSA they are the same ε-greedy policy. That is what on-policy means. Q-learning (next lesson) separates them.

Takeaways

  • SARSA learns Q(S,A) from (S,A,R,S′,A′), using the action actually chosen next.
  • It is on-policy: the learned values include the cost of exploration.
  • With decaying ε and step sizes it converges to the best ε-greedy policy; with fixed ε it prefers safer routes.
4.3

Q-learning: off-policy TD control

The questionA courier learns routes while still trying out side streets to discover shortcuts. Later, the courier wants to know the fastest route from the depot, not the route that a noisy, exploring version of itself happened to take. Can we learn the value of the best behaviour while still behaving imperfectly?

Intuition

SARSA evaluates the moves it makes, exploration included. Q-learning asks a different question at each step: if from the next state I acted as well as possible, what would this be worth? It bootstraps from the best next action, not from the action that was sampled. Because the learning target does not depend on the exploring behaviour, Q-learning is off-policy: the policy it learns about (greedy) differs from the one it follows (ε-greedy).

Build it up: replacing the sample with the max

Take the SARSA update and replace Q(S',A') by the best value available at S′:

Q(S,A) \leftarrow Q(S,A) + \alpha\Big[R + \gamma \max_{a'} Q(S',a') - Q(S,A)\Big]

The max makes the target independent of which action exploration happens to take next. Each update is a little optimistic when exploring has been unlucky, but the table converges to the optimal action values, Q^*, under standard conditions: every state–action pair is visited infinitely often, and the step sizes decay in the usual way.

Worked example: the same transition, max instead of sample

Use the numbers from 4.2: Q(S,A)=-5, R=-1, \gamma=1, \alpha=0.5. At S′ the values are Q(S',\text{safe})=-1 and Q(S',\text{cliff})=-100.

Q-learning uses \max = -1, so the target is -1 + (-1) = -2 and Q(S,A)\leftarrow -5 + 0.5(-2+5) = -3.5.

SARSA, had it sampled the cliff, would have used −101 and written −53. The Q-learning update does not care what exploration did next, which is exactly why it can learn the greedy route.

The price: Q-learning ignores the cost of its own exploration when it updates. Its learned values describe a perfect courier, while its online return is the exploring courier’s. Both facts show up in the lab.

The formal definition

Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\Big[R_{t+1}+\gamma\max_{a}Q(S_{t+1},a)-Q(S_t,A_t)\Big]
maxa Q(s,a)the largest action value at s; the best action according to current estimates
argmaxa Q(s,a)the action achieving that maximum (the greedy choice)
Atthe action actually taken, chosen by an exploring behaviour policy

Q-learning is the tabular ancestor of DQN (Module 5), which replaces the table with a neural network and the max with a network evaluated on sampled batches. Off-policy learning is also what makes replay buffers possible, and it is where the deadly triad (Module 5) comes from.

Lab: the two routes, side by side

  1. Watch both agents from the same empty table with the same seed. Notice that Q-learning's greedy route runs along the row just above the cliff, while SARSA's runs further from it.
  2. Compare the two average returns in the lower plot. Q-learning's learned greedy route is shorter, but its online return is lower, because exploring next to the cliff costs it falls.
  3. Set ε to 0.02 and reset. Less exploration means fewer accidental falls, so compare how the two online returns change. Explain the difference in your own words.
Common traps
  • “Off-policy” does not mean “learns from anything”. It means the target policy (greedy) can differ from the behaviour policy (ε-greedy). Coverage still matters.
  • Comparing online return to the learned route is not like-for-like. The learned greedy route is the policy without exploration; the online return includes exploration.
  • Max-based targets overestimate. Taking a maximum over noisy estimates biases the target upward. This is the reason for Double Q-learning (Module 5).
Where it shows up in AI
  • DQN and its descendants (Atari, Module 5): Q-learning with a neural network, a replay buffer and a target network.
  • Any setting where learning from logged or other-policy data is needed: the max lets the learner use data gathered by a different policy.

Pipeline view. Stages: interact (ε-greedy), store (one transition at a time here, a replay buffer in DQN), estimate (max target), improve (greedy policy). Stores: a Q-table. Cost per update: one max over the actions at S′, four table reads in this problem.

Check yourself

1. Q(S,A) = 0, R = 2, γ = 0.5, Q(S′,·) = (3, 7, −4) for three actions, α = 1. What is the new Q(S,A)?
The max is 7, so the target is 2 + 0.5·7 = 5.5. With α = 1 the new value is 5.5.
2. Why is Q-learning called off-policy?
Its update targets the greedy action value, max Q(S′,·), whereas the agent behaves with an ε-greedy policy. The policy being learned (greedy) differs from the policy generating the data (ε-greedy).
3. In the cliff example, why does Q-learning's online return end up lower even though its greedy route is shorter?
Its updates assume the agent acts greedily from the next state, so it learns that walking along the edge is optimal. But the agent still takes random steps, and occasionally those steps fall off the edge, costing −100 each time.

Takeaways

  • Q-learning replaces the sampled next action with the maximum, learning Q* while exploring.
  • It is off-policy: its target policy is greedy, its behaviour policy is ε-greedy.
  • Learned values and online returns answer different questions; both matter in practice.
4.4

Expected SARSA

The questionSARSA is honest but noisy: its target changes with the single action sampled at the next state. Q-learning is stable but ignores exploration. Is there a middle path that keeps SARSA's honesty about exploration while removing the noise from the sampled action?

Intuition

Instead of sampling the next action and using its value, take the average over all next actions, weighted by how likely the policy is to pick each one. If the policy picks the safe action 80% of the time and the cliff 10% of the time, the expected next value is 80% of the safe value plus 10% of the cliff value plus 10% of the other safe value. The expectation is the quantity that SARSA was trying to sample.

Build it up: averaging the next action

Let \pi(a\mid s) be the probability that the behaviour policy picks action a in state s. The expected action value at S′ is

\mathbb E_\pi[Q(S',A')\mid S'] = \sum_{a}\pi(a\mid S')\,Q(S',a)

Expected SARSA uses this in the target instead of the sampled value:

Q(S,A) \leftarrow Q(S,A) + \alpha\Big[R + \gamma\sum_{a}\pi(a\mid S')Q(S',a) - Q(S,A)\Big]

The target no longer depends on luck at S′. Its expectation is the same as SARSA's, so the two methods have the same target on average, but Expected SARSA has smaller variance.

Worked example: one state, three actions

At S′: Q = (-1,\,-2,\,-10) for actions (safe, edge, cliff). Greedy action: safe. With \varepsilon = 0.3 and three actions, the probabilities are \pi = (1-0.3+0.1,\;0.1,\;0.1) = (0.8,\,0.1,\,0.1).

Expected value: \sum_a \pi(a)Q(a) = 0.8(-1)+0.1(-2)+0.1(-10) = -0.8-0.2-1.0 = -2.0.

Sampled SARSA values: −1 with probability 0.8, −2 with probability 0.1 and −10 with probability 0.1. Its variance is 0.8(1)+0.1(4)+0.1(100)-(-2)^2 = 11.2-4 = 7.2.

Expected SARSA update from Q(S,A)=-5, R=-1, \gamma=1, \alpha=0.5: target -1 + (-2.0) = -3.0, so Q(S,A)\leftarrow -5 + 0.5(-3+5) = -4.0. From the same starting value of −5, this update gives −4.0 every time, whereas the SARSA update from 4.2 gives −3.5 or −53 depending on which action exploration happened to sample.

The formal definition

Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\Big[R_{t+1}+\gamma\sum_{a}\pi(a\mid S_{t+1})\,Q(S_{t+1},a)-Q(S_t,A_t)\Big]
π(a | s)probability that the behaviour (ε-greedy) policy chooses a in s
Σasum over every action available in S′
𝔼π[·]expectation under the policy π

Expected SARSA is on-policy when π is the behaviour policy, and it becomes Q-learning when π is greedy (probability 1 on the max). This makes it a bridge between the two methods, not a third idea.

  2. Raise the cliff value Q(s′, a₃ cliff) to −2. Now the spread shrinks and E moves. Compute E by hand from the bars to check the readout.

Common traps
  • The expectation uses the policy's probabilities, not uniform ones. With a greedy-heavy ε-greedy policy the average is dominated by the greedy action.
  • Lower variance is not free. It needs the probabilities π(a|s′), so the agent must know its own policy exactly, not just sample from it.
  • Expected SARSA is not always better. It is more stable per update but costs a sum over actions per update, which matters when actions are many.
Where it shows up in AI
  • The stable tabular control method of choice in many textbook and applied settings with small discrete actions.
  • The same expectation idea appears in policy-gradient baselines and in soft (entropy-regularised) RL, where the target averages the soft value over the policy.

Pipeline view. Stages: interact, estimate (expectation over actions), improve. Stores: a Q-table plus knowledge of π. Cost per update: one sum over |A| actions at S′ (three terms here).

Check yourself

1. With ε = 0.3 and three actions, what probability does the greedy action get?
1 − ε + ε/|A| = 1 − 0.3 + 0.1 = 0.8.
2. Q(s′,·) = (2, 5) for two actions, ε = 0.2, greedy = action 2. What is the expected value at s′?
Probabilities: action 2 gets 1 − 0.2 + 0.1 = 0.9, action 1 gets 0.1. Expected value = 0.1·2 + 0.9·5 = 0.2 + 4.5 = 4.7.
3. Why does Expected SARSA have lower variance than SARSA?
Its target averages over all next actions with their probabilities instead of using one sampled action, so the randomness of the single draw is removed. The remaining randomness comes only from S′ and R.

Takeaways

  • Expected SARSA replaces the sampled Q(S′,A′) with its expectation under the policy.
  • Same expected target as SARSA, lower variance; it reduces to Q-learning under a greedy policy.
  • It needs the next-state probabilities, and it costs a sum over actions per update.
4.5

n-step returns

The questionOne-step TD learns fast but leans on a possibly wrong estimate of the next state. Monte Carlo waits for the whole episode, so its target is unbiased but noisy and slow to arrive. Can we choose how far to look ahead before we trust the estimate?

Intuition

Think of predicting your monthly spending. You can extrapolate from this week alone (one step: quick but guessy), or you can wait for the full month and add everything up (Monte Carlo: accurate but late). Or you can add the first n weeks of real spending and then assume the rest will look like your usual average. More real data means less dependence on the guess, but more waiting and more variance from the random future.

Build it up: the n-step return

Write the return from time t as a sum of real rewards, with discount \gamma. A one-step return uses one reward and bootstraps; an n-step return uses n rewards and bootstraps from the state reached after them:

G^{(n)}_t = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1}R_{t+n} + \gamma^{n}V(S_{t+n})

With n=1 this is the TD(0) target from 4.1. If the episode ends before step n, the missing terms are zero, which makes G^{(n)}_t equal to the full Monte Carlo return. The update is V(S_t)\leftarrow V(S_t)+\alpha\big[G^{(n)}_t - V(S_t)\big].

Worked example: the three-step chain

Use the chain from 4.1 with rewards R_1=0, R_2=0, R_3=1, \gamma=0.9, and the estimates after two episodes: V(S_2)=0.225, V(S_3)=0.75. We compute the targets for S_1, whose true value is 0.81.

n=1:\quad G^{(1)} = 0 + 0.9\cdot0.225 = 0.2025

n=2:\quad G^{(2)} = 0 + 0.9\cdot0 + 0.81\cdot0.75 = 0.6075

n=3:\quad G^{(3)} = 0 + 0 + 0.81\cdot1 + 0.729\cdot V(\text{end}) = 0.81

The errors against the true 0.81 are −0.6075, −0.2025 and 0. Longer windows use more real reward and less of the guessed V(S_2) or V(S_3). Here n = 3 reaches the Monte Carlo return, because the episode ends first.

The formal definition

G^{(n)}_t=\sum_{k=0}^{n-1}\gamma^{k}R_{t+k+1}+\gamma^{n}V(S_{t+n}),\qquad V(S_{t+n})=0 \text{ if } S_{t+n}\text{ is terminal}
G(n)tthe n-step return, the target for the state visited at time t
nthe number of real rewards used before bootstrapping
Rt+k+1the reward k+1 steps after time t
γkthe discount applied to that reward

Error reduction. The expected n-step target is closer to the truth than the current estimates: \max_s|\mathbb E[G^{(n)}_t\mid S_t=s]-V^\pi(s)|\le\gamma^{n}\max_s|V(s)-V^\pi(s)|. Each extra step shrinks the worst-case error by a factor \gamma^n. Under the usual conditions, n-step TD converges as TD(0) does.

Lab: building a target term by term

Try this
  1. Set n = 1. Watch the orange reward term and the blue bootstrap term; the target is 0.2025 and misses the truth by −0.6075.
  2. Set n = 2 and press Play. The second reward term is zero, and the bootstrap from S₃ is 0.81 × 0.75 = 0.6075.
  3. Set n = 3. The bootstrap disappears (the episode has ended), and the target is exactly the Monte Carlo return 0.81.
Common traps
  • Off-by-one indices. G^{(n)}_t uses rewards up to R_{t+n}, and bootstraps from S_{t+n}. Mixing these up is the most common bug.
  • Larger n is not always better. The error shrinks in expectation, but the variance of a longer window grows with the number of random rewards it includes.
  • n-step methods need a delay. The update for time t can only be applied after time t+n has been observed.
Where it shows up in AI
  • A standard way to trade bias against variance in value learning; A2C and PPO use n-step advantage estimates (Module 6).
  • Multi-step targets for Q-learning in Rainbow-style agents, where a fixed n is one of the tuned hyperparameters.

Pipeline view. Stages: interact (a window of n transitions), store (a short buffer of the last n rewards), estimate (n-step target), improve. Stores: V or Q plus an n-step buffer. Cost per update: n reward terms and one bootstrap.

Check yourself

1. From the first state, rewards are 1, 0, 2 and then the episode ends. γ = 0.5. What are G⁽²⁾ and G⁽³⁾? (Assume the estimate of the state reached after two steps is V = 4.)
G⁽²⁾ = 1 + 0.5·0 + 0.25·V(S₂ after two steps) = 1 + 0 + 0.25·4 = 2. G⁽³⁾ = 1 + 0 + 0.25·2 = 1.5, with no bootstrap, because the episode ends at step 3.
2. Using the worked example, what is the target G⁽¹⁾ if V(S₂) were 0.9 instead of 0.225?
G⁽¹⁾ = 0 + 0.9·0.9 = 0.81, which is exactly the true value. The one-step target is only as good as V(S₂).
3. Why does G⁽ⁿ⁾ with n equal to the episode length equal the Monte Carlo return?
Every reward is included, and the bootstrap term is multiplied by the value of the terminal state, which is zero. Nothing is estimated, only the realised rewards are used.

Takeaways

  • G⁽ⁿ⁾ uses n real rewards and bootstraps from V(St+n).
  • n = 1 is TD(0); n = episode length is Monte Carlo.
  • Longer windows reduce bias and increase variance; this trade-off is what TD(λ) blends.
4.6

TD(λ) & eligibility traces

The questionChoosing n in lesson 4.5 means committing to one window length. Could we average over all of them at once, giving short windows more weight and long ones less, and could we compute that average without storing the whole episode?

Intuition

Give every window a weight that decays geometrically with its length. The one-step target gets the largest share, the two-step target a smaller one, and so on. The decay rate is \lambda\in[0,1]. With \lambda=0 all weight goes to one step (pure TD(0)); with \lambda=1 all weight goes to the full return (Monte Carlo). Everything in between is a blend.

The surprise is that this blend can be run online. Each state keeps an eligibility trace: a number that says how much credit it is still owed for recent TD errors. A state visited recently is "eligible", and its trace decays by \gamma\lambda each step.

Build it up: the λ-return

The λ-return averages the n-step returns with geometric weights (1-\lambda)\lambda^{n-1}. For an episode that ends after T steps:

G^{\lambda}_t=(1-\lambda)\sum_{n=1}^{T-t-1}\lambda^{n-1}G^{(n)}_t+\lambda^{T-t-1}G_t

The weights sum to 1: (1-\lambda)\sum_{n\ge1}\lambda^{n-1}=1, with the final full return Gt taking the remaining \lambda^{T-t-1}.

Worked example: the λ-return on the chain

Same chain, \gamma=0.9, \lambda=0.5, V=(0,0.225,0.75). The episode has T=3 steps, so the windows are n=1,2 plus the full return.

From 4.5: G^{(1)}=0.2025, G^{(2)}=0.6075, and G=0.81. Weights: (1-\lambda)=0.5, (1-\lambda)\lambda=0.25, \lambda^{2}=0.25; they sum to 1.

G^{\lambda}_0 = 0.5(0.2025)+0.25(0.6075)+0.25(0.81) = 0.45563, to five decimals 0.455625.

Backward view, same answer. Start with e=0. Use \gamma\lambda = 0.45. TD errors with these fixed values: \delta_0 = 0.2025, \delta_1 = 0.45, \delta_2 = 0.25. The trace for S₁ is 1,\ 0.45,\ 0.2025 at the three steps. Summing \delta_t e_t(S_1): 0.2025 + 0.2025 + 0.050625 = 0.455625, which matches the forward λ-return.

With step size \alpha=0.5, both views give \Delta V(S_1)=0.2278.

The formal definition

e_t(s) = \gamma\lambda\,e_{t-1}(s)+\mathbf 1[S_t=s],\qquad V(s)\leftarrow V(s)+\alpha\,\delta_t\,e_t(s)\ \ \forall s
λ (lambda)trace decay, 0\le\lambda\le1; λ = 0 gives TD(0), λ = 1 gives Monte Carlo (for episodic tasks)
et(s)the eligibility of state s at time t: how much recent TD errors should update it
𝟙[St=s]1 if the agent is in s at time t, else 0
δtthe TD error from 4.1, applied to every state in proportion to its trace

The forward view (the λ-return) and the backward view (traces) give identical total updates for offline updates; the backward view is the one that runs online. With λ = 0, e_t(s)=\mathbf 1[S_t=s] and the rule is TD(0). With λ = 1 and γ = 1 for episodic tasks, the total update over an episode equals the Monte Carlo update.

Common traps
  • The equivalence is offline. The forward and backward totals match when V is held fixed during the episode. Online TD(λ) with changing V only approximates the λ-return.
  • Accumulating versus replacing traces. Accumulating traces add 1 on each visit; replacing traces reset to 1. They differ when a state is revisited within an episode, and the lab uses accumulating traces.
  • λ is not a learning rate. It sets how far credit spreads back; α sets how big each update is.
Where it shows up in AI
  • Fast credit assignment in tabular and linear RL, where a single reward should reach many earlier states quickly.
  • GAE (generalised advantage estimation) in PPO and other policy-gradient methods (Module 6) uses the same λ-weighted blend of multi-step advantages, with λ typically around 0.95.

Pipeline view. Stages: interact, store (a trace per state, or per parameter in neural nets), estimate (TD error times trace), improve. Stores: one trace per state (or per weight). Cost per update: a decay and an add for every state, which is cheap for tables and costly for large networks.

Check yourself

1. What is the λ-return weight on the one-step target when λ = 0.8?
(1 − λ) = 0.2. The weights on n = 1, 2, 3, … are 0.2, 0.16, 0.128, …, which add up to 1 in the limit.
2. With λ = 0.5, γ = 0.9, the trace of a state visited two steps ago is 0.45² times its trace from then. What is the trace factor after two steps?
The trace decays by γλ = 0.45 each step. Two steps give 0.45² = 0.2025, which is the factor used for S₁ in the worked example at step 2.
3. Why is TD(λ) useful on problems with long delays between action and reward?
A single reward updates every recently visited state through its trace, so credit reaches back many states in one update rather than one state per episode, as in TD(0).

Takeaways

  • The λ-return blends all n-step returns with geometric weights; λ = 0 is TD(0), λ = 1 is Monte Carlo.
  • Eligibility traces compute the same blend online, decaying by γλ each step.
  • Forward and backward views agree for offline updates; traces are what make the method practical.
