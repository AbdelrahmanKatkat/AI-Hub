Level 1

What is ML & the pipeline

Traditional software: rules + data → answers. Machine learning flips it: data + answers → rules. We pick a family of functions and let an algorithm find the parameters that fit our examples.

\hat y = f(x;\,\theta) \qquad \theta^\star = \arg\min_\theta \; \frac1N \sum_{i=1}^{N} \ell\big(f(x_i;\theta),\,y_i\big)

Supervisedinputs x and labels ypredict price, class, risk
Unsupervisedonly xcluster, compress, find structure
Reinforcementrewards from interactionchoose actions (own topic later)

Key takeaways

  • ML = choose a model family, define a loss, optimise parameters.
  • Training and inference are different workloads with different compute and storage needs.
  • The loop never ends: monitoring feeds new data back in.
Level 2

Data & preprocessing

Models do arithmetic, so features must be numeric and comparably scaled. Income in dollars (tens of thousands) beside age in years (tens) lets income dominate distances and make gradient descent zig-zag. Preprocessing fixes this.

x' = \frac{x-\mu}{\sigma} \qquad\qquad x' = \frac{x-x_{\min}}{x_{\max}-x_{\min}}

Try the lab: pick the skewed income feature, then switch between Standardize, Log and Clip. Notice that standardizing changes scale but not shape, while log changes the shape. You can also type your own formula.

Avoid data leakageSplit into train/test first, compute mean and std on the training split only, then apply those same numbers to validation, test and production data.

Key takeaways

  • Scale for optimisation, transform for shape, clip for outliers.
  • Fit preprocessing on training data only, and store the fitted parameters with the model.
Level 3

Models & training

Training measures how wrong the model is (the loss), then nudges every parameter in the direction that reduces it. For regression the standard loss is mean squared error:

L(\theta)=\frac1N\sum_i\big(f(x_i;\theta)-y_i\big)^2 \qquad \theta \leftarrow \theta-\eta\,\nabla_\theta L

The learning rate \eta is the step size. Too small and training crawls; too large and it overshoots and diverges. Edit the model equation — the lab differentiates it numerically and fits whatever you write, so you can see underfitting (a line on a sine wave) and good fits (a sine on a sine wave).

Key takeaways

  • The model family sets what can be learned; optimisation decides what is learned.
  • Watch the loss curve: flat = stuck or converged, rising = learning rate too high.
  • The calculus behind the gradient is on the Mathematics page.
Level 4

Neural networks

A neural network stacks layers: each one multiplies by a weight matrix, adds a bias, and applies a nonlinearity. Without the nonlinearity, many layers collapse into one linear map and could never separate a circle from its centre.

a^{(l)}=\phi\!\big(W^{(l)}a^{(l-1)}+b^{(l)}\big) \qquad \hat y=\sigma\!\big(W^{(L)}a^{(L-1)}+b^{(L)}\big)

Experiment: on circle or spiral, a network using only x and y needs hidden units; adding features like x² and y² can solve circle with almost none — that is feature engineering. Click the map to trace one point through the network.

Key takeaways

  • Depth and width add flexibility; good features reduce how much flexibility you need.
  • Activation choice changes training speed and the shape of the decision boundary.
  • Weights are the model's stored knowledge: line colour = sign, thickness = size.
Level 5

Evaluation, inference & post-processing

At inference the model outputs a score. Post-processing turns it into a decision, usually with a threshold. Moving the threshold trades false positives against false negatives; the right point depends on what each mistake costs.

\text{precision}=\frac{TP}{TP+FP}\quad \text{recall}=\frac{TP}{TP+FN}\quad F_1=\frac{2\,P\,R}{P+R}

Drag the threshold and watch the dot slide along the ROC curve. Increase d′ (a better model) and the whole curve bows toward the top-left corner.

Key takeaways

  • A good score is not a good decision until the threshold is chosen for the real costs.
  • Accuracy hides problems when classes are imbalanced; check precision and recall.

Computation & storage

In production, the questions change from "is it accurate?" to "is it fast, cheap, reproducible and safe over time?"

StageComputationStorageTypical trade-off
PreprocessingCPU, vectorised or distributedParquet, feature storeSame code for training and serving, or you get train/serve skew
TrainingGPU/TPU, large batches, mixed precisionCheckpoints, experiment tracker, dataset versionsBigger batch = faster, but needs tuned learning rate
InferenceBatching, quantization, distillation, edge devicesModel registry, warm cacheLatency vs throughput vs accuracy
Post-processingCPU, trivialVersioned rules and thresholdsChange thresholds without retraining
MonitoringStream or batch jobsPrediction logs, drift metricsLogging volume vs privacy
DriftWhen live data stops resembling training data (new devices, seasons, behaviours), accuracy decays silently. Compare input distributions against training statistics — the same mean and std you saved during preprocessing.
