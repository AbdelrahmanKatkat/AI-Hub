7.1

The neuron & universal approximation

The questionA straight line y=ax+b cannot draw a wave, a bump, or even the simple rule "output 1 when exactly one of two switches is on". Yet a neural network can approximate almost any shape. What is the single small building block, and why does stacking many copies of it give such enormous power?

Intuition

Think of a neuron as a tiny voter. It receives several pieces of evidence (the inputs x_1,x_2,\dots). It does not weigh them equally: each piece of evidence has its own importance (a weight, possibly negative for "evidence against"). It adds up the weighted evidence, adds a personal bias — how easily it gets excited — and then decides how loudly to shout, using a fixed shaping rule called the activation function.

That is the whole story: weighted vote → shaping rule. A neuron has two stages, and it is worth keeping them apart in your mind:

  1. The affine stage (linear + shift): z=w_1x_1+w_2x_2+\dots+w_nx_n+b. You met this as the dot product plus a constant in Modules 1–2.
  2. The nonlinear stage: a=\varphi(z), where \varphi ("phi") is the activation function, applied to the single number z.

Geometrically (try the first lab below) the affine stage draws a straight line in input space — the set of points where z=0. Weights \mathbf w set the tilt of that line (the vector \mathbf w is perpendicular to it and points toward larger z); the bias slides it toward or away from the origin. The activation then says what happens on each side: with a hard step the neuron says "1 on this side, 0 on the other". With a smooth sigmoid, "confidently 1 far on this side, unsure near the line".

Build it up

Why must there be a nonlinear stage? Suppose we skip it and stack two layers of purely affine neurons. Layer one computes \mathbf h=W_1\mathbf x+\mathbf b_1, layer two computes \mathbf y=W_2\mathbf h+\mathbf b_2. Substitute:

\mathbf y=W_2(W_1\mathbf x+\mathbf b_1)+\mathbf b_2=\underbrace{(W_2W_1)}_{W'}\mathbf x+\underbrace{(W_2\mathbf b_1+\mathbf b_2)}_{\mathbf b'}

It is one affine map again. A hundred linear layers are exactly as powerful as one. The nonlinearity is what stops the layers from collapsing into one; it is the only reason depth helps.

The common activation functions. The following four appear everywhere; their derivatives matter because backpropagation (lesson 7.4) multiplies by them.

step\varphi(z)=\mathbb 1[z>0]. The original perceptron. Derivative is 0 everywhere (and undefined at 0), so gradient descent cannot train it — we replace it with smooth cousins.
sigmoid\sigma(z)=\dfrac{1}{1+e^{-z}}\in(0,1), with \sigma'(z)=\sigma(z)(1-\sigma(z))\le\tfrac14. A smooth step. Good for probabilities; saturates (flat) for large |z|.
tanh\tanh z=\dfrac{e^z-e^{-z}}{e^z+e^{-z}}\in(-1,1), \tanh'(z)=1-\tanh^2 z\le1. A zero-centred sigmoid (\tanh z=2\sigma(2z)-1).
ReLU\max(0,z), derivative 1 for z>0, 0 for z<0. Cheap, does not saturate on the positive side; the default in deep nets.

The XOR puzzle. A single neuron's decision region is a half-plane, so it can only separate two groups with a straight line. XOR (output 1 when exactly one of x_1,x_2\in\{0,1\} is 1) places (0,1),(1,0) on one side and (0,0),(1,1) on the other — no line does that. Two layers can, because the hidden layer re-describes the points in a new space where a line suffices:

Worked example — XOR with two ReLU neurons and one output

Hidden layer: h_1=\mathrm{ReLU}(x_1+x_2), h_2=\mathrm{ReLU}(x_1+x_2-1). Output: y=h_1-2h_2.

(x₁,x₂)z₁ = x₁+x₂ → h₁ ; z₂ = x₁+x₂−1 → h₂ ; y = h₁ − 2h₂
(0,0)0 → 0 ; −1 → 0 ; y = 0 − 0 = 0
(1,0)1 → 1 ; 0 → 0 ; y = 1 − 0 = 1
(0,1)1 → 1 ; 0 → 0 ; y = 1
(1,1)2 → 2 ; 1 → 1 ; y = 2 − 2 = 0

XOR solved. The second neuron "kicks in" only when both inputs are on and cancels the first.

Universal approximation — the idea. Take the sigmoid \sigma(k(x-t)). For a large steepness k it is almost a step: 0 before t, 1 after. Multiply by a height c and you get a "jump of height c at position t". Add many of these jumps and you get a staircase. Choose the jump positions and heights so the staircase follows a target curve f: place knots p_0<p_1<\dots<p_N, and give the neuron sitting between p_{i-1} and p_i the height f(p_i)-f(p_{i-1}). More neurons = finer stairs = smaller error. With ReLU ramps instead of steps you get a piecewise-linear curve that bends once per neuron. The universal approximation theorem (Cybenko 1989, Hornik 1991) turns this picture into a theorem: a network with one hidden layer and enough neurons can approximate any continuous function on a bounded region as closely as you like.

Read the theorem carefully. It says an approximator exists. It does not say how many neurons are needed (possibly astronomically many), that gradient descent will find the weights, or that the network will generalise beyond the training data. Depth is what makes the representation efficient: deep networks can express some functions with exponentially fewer neurons than a shallow one.

The formal definition

a=\varphi(z),\qquad z=\mathbf w^\top\mathbf x+b=\sum_{j=1}^{n}w_jx_j+b

A whole layer of m neurons shares the input and stacks its weight vectors as the rows of a matrix:

\mathbf a=\varphi(W\mathbf x+\mathbf b),\qquad W\in\mathbb R^{m\times n},\ \mathbf b\in\mathbb R^{m},\ \varphi\text{ applied entry by entry}

A multi-layer perceptron (MLP) with one hidden layer of width N computes f(\mathbf x)=\sum_{i=1}^{N}c_i\,\varphi(\mathbf w_i^\top\mathbf x+b_i)+c_0.

x ∈ ℝⁿthe input vector (features, pixels, an embedding …)
w, bweight vector (importance of each input) and bias (a shift of the boundary)
zpre-activation: the raw weighted vote, any real number
φactivation function; the nonlinearity
aactivation: the neuron's output
W (m×n)row i holds the weights of neuron i; there are mn+m parameters per layer
cᵢoutput weights of the hidden units (the "heights" of the steps/ramps)
Worked example — one neuron by hand

Weights \mathbf w=(2,-1), bias b=0.5, input \mathbf x=(1,3).

z=2\cdot1+(-1)\cdot3+0.5=-0.5. Then: step → 0; ReLU → 0; sigmoid → 1/(1+e^{0.5})=0.3775; tanh → -0.4621.

Parameter count for an MLP 784→128→10: (784\cdot128+128)+(128\cdot10+10)=100\,480+1\,290=101\,770.

Common traps
  • "More layers of linear neurons are more powerful." No: without a nonlinearity they collapse to one affine map (shown above).
  • Confusing z and a. z is before the activation, a after. Backpropagation uses both (\varphi' is evaluated at z).
  • Reading the universal approximation theorem as a recipe. It guarantees existence, not learnability or efficiency or generalisation.
  • The bias is not an input weight in disguise to be dropped: without it every boundary must pass through the origin.
Where it shows up in AI
  • The MLP / feed-forward block inside every transformer: W_2\,\mathrm{GELU}(W_1\mathbf x+\mathbf b_1)+\mathbf b_2 with the hidden width 4× the model width — most of a language model's parameters live here.
  • Activation choices: ReLU for CNNs and ResNets, GELU/SwiGLU for modern LLMs, sigmoid for gates (LSTM) and binary outputs, tanh in recurrent cells.
  • Logistic regression is a single sigmoid neuron trained on cross-entropy (lesson 7.3). A deep network is millions of them composed.

Takeaways

  • A neuron = affine map z=\mathbf w\cdot\mathbf x+b followed by a nonlinearity φ; weights tilt, bias shifts the boundary z=0.
  • Without a nonlinearity, depth collapses into a single linear map.
  • Many neurons add steps or ramps and can approximate any continuous function (universal approximation) — but existence is not learnability.
7.2

Softmax, log-sum-exp & numerical stability

The questionA classifier ends with three raw scores — say 2.0, 1.0, 0.1 — which can be any real numbers, positive or negative. We need three probabilities: all positive, adding to 1, and larger scores must get larger probabilities. What is the natural transformation? And why does a computer, handed scores like 1000, 1001, 1002, produce NaN if we implement it naively?

Intuition

The raw scores are called logits. To turn scores into probabilities we need two things: make everything positive and normalise to sum 1. Normalising is easy: divide each positive number by the total. Making things positive while keeping the order and treating differences sensibly is the interesting part.

The exponential e^{z} is the natural choice. It is always positive, it is increasing (higher score → higher probability), and — the key property — it turns differences into ratios: e^{z_i}/e^{z_j}=e^{z_i-z_j}. If class 1 has a score 2 higher than class 2 it becomes e^2\approx7.4 times more likely, no matter what the absolute scores are. This is exactly the statement "the logits are log-odds", and physicists know the same formula as the Boltzmann distribution p\propto e^{-E/T}, with scores as negative energies.

Consequence: adding the same constant c to every logit changes nothing, since e^{z_i+c}/\sum_je^{z_j+c}=e^{z_i}/\sum_je^{z_j}. Softmax only cares about differences between logits. This one observation is also the cure for overflow.

Build it up

Worked example — by hand

Logits \mathbf z=(2,\,1,\,0.1). Exponentiate: e^{2}=7.389,\ e^{1}=2.718,\ e^{0.1}=1.105. Sum = 11.212. Divide: (0.659, 0.242, 0.099) — they add to 1.

Cross-entropy loss if the true class is class 1: -\ln0.659=0.417; if the true class were class 3: -\ln0.0986=2.317. A confident wrong answer costs far more.

Temperature. Divide the logits by a number T first: p_i\propto e^{z_i/T}. For T<1 the gaps between logits are amplified and the distribution sharpens towards a one-hot vector (as T\to0 it becomes argmax); for T>1 gaps shrink and it flattens toward uniform (as T\to\infty). For our logits: T=0.5\Rightarrow(0.864,0.117,0.019), T=1\Rightarrow(0.659,0.242,0.099), T=2\Rightarrow(0.502,0.304,0.194). This is exactly the "temperature" knob when sampling words from a language model.

The Jacobian of softmax. Backpropagation needs \partial p_i/\partial z_j. Write p_i=e^{z_i}/S with S=\sum_ke^{z_k}, so \partial S/\partial z_j=e^{z_j}. Use the quotient rule.

Case i = j: \dfrac{\partial p_i}{\partial z_i}=\dfrac{e^{z_i}S-e^{z_i}e^{z_i}}{S^2}=p_i-p_i^2=p_i(1-p_i).

Case i ≠ j: \dfrac{\partial p_i}{\partial z_j}=\dfrac{0\cdot S-e^{z_i}e^{z_j}}{S^2}=-p_ip_j.

Both cases in one line, with the Kronecker delta \delta_{ij} (1 if i=j else 0):

\frac{\partial p_i}{\partial z_j}=p_i(\delta_{ij}-p_j)\qquad\Longleftrightarrow\qquad J=\mathrm{diag}(\mathbf p)-\mathbf p\mathbf p^\top

Sanity checks: each row of J sums to 0 (the probabilities always add to 1, so raising one must lower the others); and J\mathbf 1=0 reflects the shift invariance above.

Softmax + cross-entropy = a beautifully simple gradient. For a one-hot label \mathbf y (1 at the true class c), the cross-entropy loss is L=-\sum_ky_k\ln p_k=-\ln p_c. Differentiate with respect to the logit z_j using the chain rule through every p_k:

\frac{\partial L}{\partial z_j}=-\sum_k\frac{y_k}{p_k}\frac{\partial p_k}{\partial z_j}=-\sum_k\frac{y_k}{p_k}\,p_k(\delta_{kj}-p_j)=-\sum_ky_k(\delta_{kj}-p_j)=-y_j+p_j\underbrace{\sum_ky_k}_{=1}=p_j-y_j

So \nabla_{\mathbf z}L=\mathbf p-\mathbf y: the gradient is "predicted probabilities minus the truth". The ugly division by p_k cancelled the ugly p_k in the Jacobian. For the example above (true class 1): \mathbf p-\mathbf y=(0.659-1,\,0.242,\,0.099)=(-0.341,\,0.242,\,0.099) — push the true logit up, the others down, in proportion to how wrong each is.

Numerical stability. Computers store numbers with finite range. In float32 the largest value is about 3.4\times10^{38}, so e^{z} overflows to inf when z\gtrsim88.7; in float64 at about 709. And e^{-104} underflows to 0 in float32. Then the naive recipe computes inf/inf = NaN, or log(0) = −inf. Logits of 100 are not exotic — they appear in the middle of real models.

The cure is the shift invariance: subtract the maximum m=\max_kz_k first. Then the largest exponent is e^0=1 (no overflow), at least one term equals 1 (no total underflow to 0 in the denominator).

Worked example — logits (1000, 1001, 1002)

Naive: e^{1000}=\infty even in float64 → NaN. Stable: m=1002, shifted logits (-2,-1,0), exponentials (0.1353,\,0.3679,\,1), sum 1.5032, probabilities (0.0900, 0.2447, 0.6652) — the same as softmax of (−2,−1,0).

Log-sum-exp. Losses need \ln p_i, i.e. \ln\sum_je^{z_j}. Same trick, applied to the log of the sum:

\mathrm{LSE}(\mathbf z)=\ln\sum_je^{z_j}=m+\ln\sum_je^{z_j-m},\qquad m=\max_jz_j

and then \ln p_i=z_i-\mathrm{LSE}(\mathbf z) ("log-softmax"), which never forms the dangerous quantities. For (1000,1001,1002): \mathrm{LSE}=1002+\ln1.5032=1002.4076. Never compute log(softmax(z)) in two separate steps; use the fused log_softmax or the fused cross-entropy-from-logits function that every framework provides.

The formal definition

\mathrm{softmax}(\mathbf z)_i=\frac{e^{z_i/T}}{\sum_{k=1}^{K}e^{z_k/T}},\qquad \mathrm{LSE}(\mathbf z)=\ln\sum_{k=1}^Ke^{z_k},\qquad \ln\mathrm{softmax}(\mathbf z)_i=z_i-\mathrm{LSE}(\mathbf z)
z ∈ ℝᴷlogits: unnormalised scores for the K classes
T > 0temperature: <1 sharpens, >1 flattens (default 1)
pᵢprobability of class i: positive, sums to 1
m = max zₖthe shift that makes the computation safe
δᵢⱼKronecker delta, 1 if i=j else 0
LSElog-sum-exp: a smooth version of max, satisfying \max_kz_k\le\mathrm{LSE}(\mathbf z)\le\max_kz_k+\ln K

  2. Lower temperature T to 0.1: one bar takes everything (argmax). Raise it to 5: the bars become almost equal.

Common traps
  • Applying softmax twice. Most frameworks' cross-entropy loss expects logits and applies log-softmax itself. Feeding it probabilities gives a wrong (and flatter) loss with no error message.
  • Computing log(softmax(z)) in two steps instead of log_softmax: when a probability underflows to 0, the log is −∞.
  • Softmax is not scale invariant: only shifting logits is harmless; multiplying them by a number changes the distribution (that is what temperature does).
  • "Softmax outputs are confident, so the model is right." A poorly-calibrated model can output 0.99 and be wrong; probabilities from softmax are not automatically calibrated.
Where it shows up in AI
  • Every classification head and the next-token distribution of a language model (a softmax over a vocabulary of 30 000–200 000 tokens). Sampling temperature and top-p act on exactly this distribution.
  • Attention weights (lesson 7.7) are softmax over scores; frameworks use the max-subtraction in fused kernels (FlashAttention keeps a running max and running sum — an online log-sum-exp).
  • Mixed precision (float16/bfloat16) training makes overflow far more likely (float16 overflows near e^{11}), so stability tricks are mandatory, not optional.
  • Reinforcement learning: policy networks output softmax action probabilities; knowledge distillation matches softened (high-T) teacher distributions.

Takeaways

  • Softmax = exponentiate then normalise; logits are log-odds; only differences between logits matter.
  • Temperature rescales logits: low T → sharp, high T → flat.
  • Softmax + cross-entropy gives the clean gradient \mathbf p-\mathbf y.
  • Always subtract the max; compute log-softmax via z_i-\mathrm{LSE}(\mathbf z), never log of softmax.
7.3

Loss functions from first principles

The questionTo train a network we must turn "how wrong is this prediction?" into a single number. But there are dozens of formulas — squared error, absolute error, cross-entropy, hinge. They are not arbitrary menu choices. Is there a principle that tells us which one to use, and what each one secretly assumes about the world?

Intuition

A loss is a penalty schedule: it says how angry we are for each possible size of mistake. Two design questions decide everything:

  • How does the penalty grow with the size of the mistake? If it grows like the square, one big mistake dominates the total; if it grows linearly, a big mistake counts only in proportion.
  • What push does the model feel? The gradient of the loss is the force that moves the weights. A loss whose gradient vanishes when the model is confidently wrong is a bad teacher.

Here is the principle that ties the menu together. A model does not predict a number — it predicts a distribution: "given x, the label y is probably around f(x), give or take noise". The best parameters are those that make the observed labels most probable (maximum likelihood, Module 4). Maximising a product of probabilities is the same as minimising the sum of their negative logs, so:

\text{loss}(\theta)=-\ln p(y_i\mid x_i;\theta)\quad(\text{per example}),\qquad \text{total}=\frac1N\sum_i-\ln p(y_i\mid x_i;\theta)

Every classic loss is just this formula for a particular assumed noise distribution. Choosing a loss is choosing a noise model.

Build it up: five derivations

1. Gaussian noise gives squared error (MSE). Suppose y=f(x)+\varepsilon with \varepsilon\sim\mathcal N(0,\sigma^2). The density is p(y\mid x)=\frac{1}{\sqrt{2\pi}\sigma}\exp\!\big(-\frac{(y-f(x))^2}{2\sigma^2}\big). Take -\ln:

-\ln p(y\mid x)=\frac{(y-f(x))^2}{2\sigma^2}+\ln(\sqrt{2\pi}\sigma)

The second term does not involve the parameters, so minimising the negative log-likelihood is minimising \tfrac12(f(x)-y)^2 up to a constant. MSE ⇔ "errors are Gaussian". The gradient with respect to the prediction is \hat y-y — proportional to the error, so far-away points pull hardest.

2. Laplace noise gives absolute error (MAE). If the noise has the heavier-tailed Laplace density \frac{1}{2b}e^{-|\varepsilon|/b}, then -\ln p=|y-f(x)|/b+\text{const}. MAE ⇔ "errors are Laplace". Gradient is \mathrm{sign}(\hat y-y): constant size, so outliers cannot shout. The best constant under MSE is the mean; under MAE it is the median (see the lab).

3. Huber: both worlds. Quadratic near zero (smooth, precise), linear beyond a threshold \delta (robust):

\ell_\delta(e)=\begin{cases}\tfrac12e^2&|e|\le\delta\\[2pt]\delta\big(|e|-\tfrac12\delta\big)&|e|>\delta\end{cases}\qquad e=\hat y-y

Its gradient is the error clipped to [-\delta,\delta]. It corresponds to Gaussian noise in the middle with Laplace-like tails.

4. Bernoulli labels give binary cross-entropy (BCE). For a yes/no label y\in\{0,1\} let the model output p=\sigma(s) = probability of "yes". Then P(y)=p^{y}(1-p)^{1-y} (the Bernoulli distribution: it equals p if y=1 and 1−p if y=0). Take -\ln:

\mathrm{BCE}(y,p)=-\big[y\ln p+(1-y)\ln(1-p)\big]

Gradient with respect to the logit s (use \sigma'=\sigma(1-\sigma)): for y=1, L=-\ln\sigma(s) and \frac{dL}{ds}=-\frac{\sigma(1-\sigma)}{\sigma}=-(1-p)=p-1; for y=0 symmetrically p. In both cases \frac{dL}{ds}=p-y — the same clean "prediction minus truth" as softmax (lesson 7.2).

5. Categorical labels give cross-entropy (CE). With K classes and a one-hot label, the model's softmax probabilities define P(y=c)=p_c, so L=-\ln p_c=-\sum_ky_k\ln p_k, and the gradient with respect to logits is \mathbf p-\mathbf y (derived in 7.2). Notice also: cross-entropy H(\mathbf y,\mathbf p)=H(\mathbf y)+D_{\mathrm{KL}}(\mathbf y\|\mathbf p) (Module 5), so minimising it pulls the model's distribution toward the label distribution.

Hinge loss comes from geometry rather than probability. With labels y=\pm1 and score s, define the margin m=ys (positive when correct). The hinge loss \max(0,1-m) penalises only examples that are wrong or not yet confidently right, and is exactly zero once m\ge1 — those points stop influencing the model. This is the support-vector-machine loss.

Worked example — one outlier, three losses

Errors on four predictions: e=(0.5,\,-1,\,0.2,\,8); the last is an outlier.

MSE (average of e^2): (0.25+1+0.04+64)/4=16.3225 — the single outlier contributes 64 of 65.29, i.e. 98% of the total.

MAE: (0.5+1+0.2+8)/4=2.425 — outlier share 8/9.7 = 82%.

Common traps
  • MSE for classification. With L=\tfrac12(\sigma(s)-y)^2 the gradient is (\sigma(s)-y)\sigma(s)(1-\sigma(s)); when the model is confidently wrong, \sigma(1-\sigma)\to0 and learning stalls. BCE's gradient p-y stays large exactly when it should.
  • BCE with exactly 0 or 1. \ln0=-\infty. Use the fused "with logits" version, which stays finite (lesson 7.2).
  • "Lower loss = better metric." The loss is a training surrogate; accuracy, F1 or BLEU may not move together with it.
  • Reduction mismatch: mean versus sum over the batch changes the effective learning rate by a factor of the batch size.
Where it shows up in AI
  • Language models minimise categorical cross-entropy over the next token; perplexity is e^{\mathrm{CE}}.
  • Regression nets and value functions (RL) use MSE or Huber — DQN's "Huber loss" is the robust choice for noisy bootstrapped targets.
  • Object detection uses smooth-L1 (Huber) for box coordinates and BCE/focal loss for objectness; SVMs use hinge; GAN/diffusion/VAE losses are likelihood or divergence objectives derived the same way.

7.4

Backpropagation

The questionA network may have a billion weights. Training needs the derivative of the loss with respect to every one of them. Nudging each weight and re-running the network a billion times is impossible. How can all billion derivatives be obtained for roughly the price of running the network just a couple of times?

Intuition

Imagine an assembly line: raw material enters, passes through stations one after another, and a finished product is inspected at the end. The inspector finds a defect and wants to know which station is to blame, and by how much. She cannot afford to re-run the line for every station. Instead she walks backwards along the line carrying one piece of information: "how much does the final defect change if the output of the station right behind me changes?" At each station she multiplies by that station's local sensitivity and passes the result further back. Each station's share of the blame falls out as she goes.

That is backpropagation: the chain rule (Module 2) organised so that the shared factors are computed once and reused. It has two phases:

  1. Forward pass — compute and store every intermediate value, from the input to the loss.
  2. Backward pass — start from \partial L/\partial L=1 and walk back through the graph, computing \partial L/\partial(\cdot) for each quantity from the ones already computed.

Build it up

Step 1: the computational graph. Break the computation into elementary operations (add, multiply, sigmoid …); each becomes a node, each value flowing between them an edge. Take f=(x+y)\,z. Introduce the intermediate q=x+y, so f=qz.

Worked example — a tiny graph

Let x=-2,\ y=5,\ z=-4. Forward: q=x+y=3, f=qz=-12.

Backward, starting with \partial f/\partial f=1. At the multiply node: \partial f/\partial q=z=-4 and \partial f/\partial z=q=3 (the "swap" rule: the gradient to one factor is the upstream gradient times the other factor). At the add node, the gradient is passed unchanged to both inputs: \partial f/\partial x=\partial f/\partial q\cdot1=-4, \partial f/\partial y=-4.

Check: increase x by 0.001 → q = 3.001, f = −12.004: change −0.004 = −4 × 0.001 ✓.

The local rules to remember: add distributes the gradient to both inputs; multiply swaps; a unary function v=g(u) multiplies the upstream gradient by g'(u).

Step 2: fan-out means sum. If a value is used in several places, the gradients arriving from each use add. For f=x\cdot x at x=3 the multiply node sends gradient x=3 down each of its two input edges (both into x); total 3+3=6=2x ✓. This is the multivariable chain rule, and in a network it is why a hidden unit that feeds several next-layer neurons collects the sum of their complaints.

  2. Try x*x: the same leaf receives two contributions that add.

Step 3: backprop for an MLP, layer by layer. Notation: layer \ell receives \mathbf h^{(\ell-1)} and computes

\mathbf z^{(\ell)}=W^{(\ell)}\mathbf h^{(\ell-1)}+\mathbf b^{(\ell)},\qquad\mathbf h^{(\ell)}=\varphi\big(\mathbf z^{(\ell)}\big),\qquad\mathbf h^{(0)}=\mathbf x,\quad L=\mathcal L(\mathbf h^{(\mathrm{out})},\mathbf y)

Define the error signal \boldsymbol\delta^{(\ell)}=\partial L/\partial\mathbf z^{(\ell)} — the blame at the pre-activation of layer ℓ. Everything follows from three steps:

  1. Output layer. Start from the loss: \boldsymbol\delta^{(\mathrm{out})}=\partial L/\partial\mathbf h^{(\mathrm{out})}\odot\varphi'(\mathbf z^{(\mathrm{out})}). For softmax+cross-entropy this simplifies to \mathbf p-\mathbf y (lesson 7.2); for a linear output with ½(ŷ−y)² it is \hat y-y.
  2. Parameter gradients from δ. Because z_i=\sum_jW_{ij}h_j+b_i, we have \partial z_i/\partial W_{ij}=h_j and \partial z_i/\partial b_i=1, so
    \frac{\partial L}{\partial W^{(\ell)}_{ij}}=\delta^{(\ell)}_i\,h^{(\ell-1)}_j\ \Longleftrightarrow\ \frac{\partial L}{\partial W^{(\ell)}}=\boldsymbol\delta^{(\ell)}\big(\mathbf h^{(\ell-1)}\big)^{\!\top},\qquad\frac{\partial L}{\partial\mathbf b^{(\ell)}}=\boldsymbol\delta^{(\ell)}
  3. Pass the blame back one layer. The activation h_j^{(\ell-1)} feeds all neurons i of layer ℓ (fan-out → sum): \partial L/\partial h_j=\sum_i\delta_iW_{ij}. Then pass through the earlier activation function:
    \frac{\partial L}{\partial\mathbf h^{(\ell-1)}}=\big(W^{(\ell)}\big)^{\!\top}\boldsymbol\delta^{(\ell)},\qquad\boldsymbol\delta^{(\ell-1)}=\Big(\big(W^{(\ell)}\big)^{\!\top}\boldsymbol\delta^{(\ell)}\Big)\odot\varphi'\big(\mathbf z^{(\ell-1)}\big)

Repeat step 2 and 3 down to the first layer. The forward pass multiplies by W; the backward pass multiplies by W^\top, and wherever the forward pass applied \varphi the backward pass multiplies elementwise (⊙) by \varphi' evaluated at the stored forward value — which is why the forward values must be kept in memory.

Why this is cheap. One forward pass costs about one multiplication per weight; the backward pass costs about two per weight (one for the gradient, one for W^\top\boldsymbol\delta). So all gradients cost ≈ 3× a forward pass, regardless of the number of parameters. Perturbing each weight separately (finite differences) would cost one forward pass per weight. This "reverse mode" of automatic differentiation is efficient precisely because the loss is a single number with many inputs (the parameters). The price is memory: activations must be stored (and that is what gradient checkpointing trades against recomputation).

The formal definition

\boldsymbol\delta^{(\ell)}=\frac{\partial L}{\partial\mathbf z^{(\ell)}},\quad\boldsymbol\delta^{(\ell-1)}=\big(W^{(\ell)\top}\boldsymbol\delta^{(\ell)}\big)\odot\varphi'(\mathbf z^{(\ell-1)}),\quad\frac{\partial L}{\partial W^{(\ell)}}=\boldsymbol\delta^{(\ell)}\mathbf h^{(\ell-1)\top},\quad\frac{\partial L}{\partial\mathbf b^{(\ell)}}=\boldsymbol\delta^{(\ell)}
z⁽ˡ⁾pre-activation of layer ℓ (stored during the forward pass)
h⁽ˡ⁾activation (output) of layer ℓ, with h⁽⁰⁾ = x
δ⁽ˡ⁾error signal ∂L/∂z⁽ˡ⁾: how sensitive the loss is to each pre-activation
Wᵀtranspose: the backward pass travels each weight in the opposite direction
⊙elementwise (Hadamard) product
φ′derivative of the activation, evaluated at the stored z
δ hᵀouter product: column vector times row vector gives a matrix with the shape of W

Frameworks (PyTorch, JAX, TensorFlow) implement exactly this generically: each operation knows its own "local backward rule", and the engine walks the graph in reverse topological order — automatic differentiation. You never write the backward pass by hand, but you must understand it to debug exploding gradients, custom layers and memory use.

Common traps
  • Forgetting to sum at fan-out. A value used twice receives two gradient contributions that add; overwriting instead of accumulating is the classic hand-written-backward bug (and why frameworks += into .grad and need zero_grad()).
  • Using the wrong z for φ′. The derivative is evaluated at the forward pre-activation of that same layer, not at the neighbour's.
  • Confusing "backprop" with "gradient descent". Backprop computes the gradient; gradient descent (Module 6) uses it to update.
  • Believing backprop is an approximation. It is the exact chain rule; only the numerical precision is finite. Test any implementation with finite differences, as the lab does.
Where it shows up in AI
  • All deep learning training (loss.backward() in PyTorch). The same algorithm trains CNNs, transformers, diffusion models and recommendation nets.
  • Backprop through time for RNNs unrolls the recurrence into a deep graph; backprop through attention is lesson 7.7; gradient checkpointing and activation recomputation exist because storing activations is the main memory cost of training.
  • Differentiable programming: any code built from differentiable operations (physics simulators, rendering, optimisers themselves) can be trained by the same machinery.

The backward rules need them: φ′ needs z or h; ∂L/∂W = δhᵀ needs the previous activation h. Storing every layer's activations costs memory proportional to depth × batch size × width — usually the dominant memory use in training.

Takeaways

  • Backprop = chain rule on a computational graph: forward stores values, backward multiplies local derivatives from the loss to every parameter.
  • MLP rules: \partial L/\partial W=\delta h^\top, \delta^{(\ell-1)}=(W^\top\delta)\odot\varphi'; fan-out sums, add distributes, multiply swaps.
  • All gradients cost about 3× one forward pass; the price is storing activations.
  • Always validate with finite differences.
7.5

Matrix calculus for layers

The questionA real layer is not one neuron but a whole matrix multiplication, applied to a whole batch of examples at once. When you read dW = dY.T @ X in someone's code, or need to write a custom backward pass, how do you know the correct matrix, in the correct order, with the correct transposes — without expanding everything into thousands of scalar sums?

Intuition

Backprop for one neuron is easy because everything is a scalar. Matrix calculus is not a new kind of calculus; it is the same chain rule with bookkeeping. The bookkeeping rule that rescues you every time is:

The shape rule. The gradient of a scalar loss with respect to any tensor has exactly the same shape as that tensor. If W is 5×3, then \partial L/\partial W is 5×3. Always.

That is a very strong constraint: among the ways of multiplying the available matrices, usually exactly one produces the right shape — so the formula is often forced. The second idea is "sum over what was shared". A weight that was used for every example in a batch collects the gradient from every example (fan-out → sum, from lesson 7.4); a bias that was added to every row collects the sum of all the rows' gradients.

Build it up

One example first. A layer takes \mathbf x\in\mathbb R^{n} and produces \mathbf y=W\mathbf x+\mathbf b\in\mathbb R^{m}, with W\in\mathbb R^{m\times n}. Write it out entry by entry:

y_i=\sum_{j=1}^{n}W_{ij}x_j+b_i

Let the upstream gradient be \delta_i=\partial L/\partial y_i (a vector of length m, the same shape as y). We want three things. Use the chain rule: \frac{\partial L}{\partial\theta}=\sum_i\delta_i\frac{\partial y_i}{\partial\theta}.

  • With respect to the bias. \partial y_i/\partial b_k=\delta_{ik} (1 if i=k else 0), so \partial L/\partial b_k=\delta_k. \Rightarrow\ \partial L/\partial\mathbf b=\boldsymbol\delta.
  • With respect to the weights. \partial y_i/\partial W_{kl}=\delta_{ik}x_l: only row k of W touches output k, and it multiplies x_l. So \partial L/\partial W_{kl}=\delta_kx_l, i.e. the outer product \partial L/\partial W=\boldsymbol\delta\,\mathbf x^{\top} (an m×1 column times a 1×n row gives m×n ✓).
  • With respect to the input. \partial y_i/\partial x_j=W_{ij}, so \partial L/\partial x_j=\sum_i\delta_iW_{ij}=(W^\top\boldsymbol\delta)_j. \Rightarrow\ \partial L/\partial\mathbf x=W^\top\boldsymbol\delta (n×m times m-vector gives an n-vector ✓).

In Jacobian language: the Jacobian of y with respect to x is W itself (m×n). The backward pass multiplies the upstream gradient by the transpose of the Jacobian — a "vector–Jacobian product" — which is the whole content of reverse-mode autodiff. For an elementwise activation \mathbf h=\varphi(\mathbf z) the Jacobian is diagonal, so the product collapses into \boldsymbol\delta_z=\boldsymbol\delta_h\odot\varphi'(\mathbf z).

Worked example — one example, 2×3 layer

W=\begin{pmatrix}1&2&0\\0&-1&3\end{pmatrix}, \mathbf x=(1,2,3), \mathbf b=(0.5,-0.5). Forward: \mathbf y=(1+4+0+0.5,\ 0-2+9-0.5)=(5.5,\ 6.5). Suppose the upstream gradient is \boldsymbol\delta=(1,-2).

\partial L/\partial W=\boldsymbol\delta\mathbf x^\top=\begin{pmatrix}1\cdot1&1\cdot2&1\cdot3\\-2\cdot1&-2\cdot2&-2\cdot3\end{pmatrix}=\begin{pmatrix}1&2&3\\-2&-4&-6\end{pmatrix} (2×3 ✓ same shape as W).

\partial L/\partial\mathbf x=W^\top\boldsymbol\delta=(1\cdot1+0\cdot(-2),\ 2\cdot1+(-1)(-2),\ 0\cdot1+3\cdot(-2))=(1,\,4,\,-6) (3 numbers ✓). \partial L/\partial\mathbf b=(1,-2).

Now a batch. Real training processes B examples at once. Stack them as the rows of X\in\mathbb R^{B\times n}. The layer becomes (this is exactly PyTorch's nn.Linear, with W stored as m×n):

Y=XW^\top+\mathbf 1\mathbf b^\top,\qquad X\in\mathbb R^{B\times n},\ W\in\mathbb R^{m\times n},\ Y\in\mathbb R^{B\times m}

where \mathbf 1 is a column of B ones: the bias row is copied ("broadcast") onto every example. The upstream gradient is a matrix \Delta=\partial L/\partial Y\in\mathbb R^{B\times m}. Use the shape rule and the single-example result (the total gradient is the sum over examples of the single-example gradients \boldsymbol\delta_b\mathbf x_b^\top):

\frac{\partial L}{\partial W}=\Delta^\top X\ \ (m\times n),\qquad\frac{\partial L}{\partial X}=\Delta\,W\ \ (B\times n),\qquad\frac{\partial L}{\partial\mathbf b}=\Delta^\top\mathbf 1=\textstyle\sum_{b}\Delta_{b,:}\ \ (m)

Check that these are forced by shapes: for \partial L/\partial W (m×n) the only product of \Delta (B×m), X (B×n) (with transposes allowed) that fits is \Delta^\top X=(m\times B)(B\times n). The inner B is summed — the gradients of all examples are accumulated in the matrix product itself.

Worked example — batch of B = 2

Same W, X=\begin{pmatrix}1&2&3\\0&1&-1\end{pmatrix}, \Delta=\begin{pmatrix}1&-2\\0.5&1\end{pmatrix} (first row = the example above).

\partial L/\partial W=\Delta^\top X=\begin{pmatrix}1&0.5\\-2&1\end{pmatrix}\begin{pmatrix}1&2&3\\0&1&-1\end{pmatrix}=\begin{pmatrix}1&2.5&2.5\\-2&-3&-7\end{pmatrix}. The first row of the product contributions: example 1 gave (1,2,3), example 2 gives 0.5·(0,1,−1)=(0,0.5,−0.5); sum (1,2.5,2.5) ✓.

\partial L/\partial X=\Delta W=\begin{pmatrix}1&4&-6\\0.5&0&3\end{pmatrix}: row 1 equals the single-example W^\top\boldsymbol\delta above ✓. \partial L/\partial\mathbf b=(1+0.5,\,-2+1)=(1.5,\,-1).

Putting a whole MLP together. With H_\ell=\varphi(Z_\ell), Z_\ell=H_{\ell-1}W_\ell^\top+\mathbf 1\mathbf b_\ell^\top, the backward pass of lesson 7.4 in batch form reads: \Delta_{\ell-1}=(\Delta_\ell W_\ell)\odot\varphi'(Z_{\ell-1}), \partial L/\partial W_\ell=\Delta_\ell^\top H_{\ell-1}. Two matrix multiplications per layer going backwards — the same cost as the forward multiply, twice. (Mean loss over the batch adds a factor 1/B to Δ at the very start.)

Two more rules worth knowing. For L=\tfrac12\|A\mathbf x-\mathbf y\|^2 (least squares), \nabla_{\mathbf x}L=A^\top(A\mathbf x-\mathbf y) — the normal-equations gradient from Module 1 — which is the layer rule with \boldsymbol\delta=A\mathbf x-\mathbf y. And for L=\mathbf a^\top\mathbf x, \nabla_{\mathbf x}L=\mathbf a; for L=\mathbf x^\top A\mathbf x, \nabla_{\mathbf x}L=(A+A^\top)\mathbf x.

The formal definition

Y=XW^\top+\mathbf 1\mathbf b^\top\quad\Longrightarrow\quad\frac{\partial L}{\partial W}=\Delta^\top X,\ \ \frac{\partial L}{\partial X}=\Delta W,\ \ \frac{\partial L}{\partial\mathbf b}=\Delta^\top\mathbf 1,\qquad\Delta=\frac{\partial L}{\partial Y}
X (B×n)batch of inputs, one example per row
W (m×n)weights; row i = neuron i (PyTorch convention weight.shape == (out, in))
b (m)bias, broadcast over the batch
Y (B×m)layer output
Δ (B×m)upstream gradient ∂L/∂Y, same shape as Y
1vector of ones; \Delta^\top\mathbf 1 sums the rows of Δ
⊙elementwise product (used for activation derivatives)

(If your convention stores examples as columns — textbook style Y=WX+\mathbf b\mathbf 1^\top — the same rules appear transposed: \partial L/\partial W=\Delta X^\top, \partial L/\partial X=W^\top\Delta. The shape rule resolves any confusion.)

Common traps
  • Transpose confusion between conventions. Row-major batches (XW^\top) and column-major (WX) give transposed formulas. Pick one and check shapes before every matmul.
  • Forgetting to sum the bias gradient over the batch. \partial L/\partial\mathbf b must have m entries, not B×m.
  • Mean versus sum. If L is the batch mean, Δ carries a factor 1/B; if you accidentally use a sum, gradients are B times too large.
  • Treating ∂L/∂x as ∂L/∂W. The input gradient W^\top\delta is needed to continue backprop; the weight gradient \delta\mathbf x^\top is needed to update. A first layer does not need ∂L/∂X unless the input is trained.
Where it shows up in AI
  • Every dense layer in every framework: dX = dY @ W, dW = dY.T @ X, db = dY.sum(0) is literally the backward of torch.nn.Linear; transformer attention and MLP blocks are chains of such matmuls.
  • Reading papers and code: custom CUDA/Triton kernels (FlashAttention, fused layers) implement these formulas by hand; LoRA adds a low-rank W+BA whose gradients follow the same rules.
  • Cost accounting: a layer's forward costs 2Bnm FLOPs and its backward 4Bnm (two matmuls), the origin of the "training ≈ 3× inference" rule of thumb.

7.6

Vanishing/exploding gradients & initialisation

The questionBefore 2010 it was nearly impossible to train networks deeper than a handful of layers; nothing in the loss or the data was wrong — yet early layers simply stopped learning, or training blew up to NaN within a few steps. What goes wrong when you multiply a signal through many layers, and how do we choose the starting weights so that signals and gradients keep a healthy size?

Intuition

Photocopy a photocopy of a photocopy. If each copy is slightly lighter, after 30 copies you see nothing (vanishing). If each copy is slightly darker (higher contrast), after 30 copies it is a black blob (exploding). A deep network repeats one operation — "multiply by a matrix, squash" — dozens of times, and the signal passing forward and the gradient passing back are both subject to this repeated gain. A gain of 0.9 per layer over 100 layers gives 0.9^{100}=2.7\times10^{-5}; a gain of 1.1 gives 1.1^{100}=13\,781. A tiny deviation from 1 becomes catastrophic with depth. The art is to engineer a gain of exactly about 1 per layer.

Build it up

Step 1: why the gradient is a product. By the backprop rule of 7.4, the error signal travels backwards by \boldsymbol\delta^{(\ell-1)}=D_{\ell-1}W_\ell^\top\boldsymbol\delta^{(\ell)}, where D=\mathrm{diag}(\varphi'(\mathbf z)). Unrolling it over L layers:

\boldsymbol\delta^{(1)}=\big(D_1W_2^\top\big)\big(D_2W_3^\top\big)\cdots\big(D_{L-1}W_L^\top\big)\,\boldsymbol\delta^{(L)}

It is a product of L Jacobians (the Chain-Rule/Jacobian lesson of Module 2). Size of a product ≈ (typical size of one factor)L: exponential in depth. Two ingredients control a factor: the weight matrix and the activation slope.

The activation slope. \sigma'(z)\le\tfrac14, so even if every weight matrix preserved lengths, the gradient through L sigmoid layers shrinks at least like 0.25^{L}: for L=10, 9.5\times10^{-7}; for L=20, 9\times10^{-13}. This is the original vanishing-gradient problem and a main reason ReLU (slope exactly 1 for z>0) replaced sigmoid in deep nets. tanh has slope up to 1 but only near zero.

Step 2: the weight matrices — a variance analysis. Take one layer without bias, z_i=\sum_{j=1}^{n_{\rm in}}w_{ij}x_j, with weights drawn independently with mean 0 and variance \sigma_w^2, inputs x_j independent of the weights with mean 0. For independent terms variances add (Module 3), and \mathrm{Var}(w_{ij}x_j)=\mathbb E[w^2]\mathbb E[x^2]=\sigma_w^2\,\mathbb E[x_j^2]. So

\mathrm{Var}(z)=n_{\rm in}\,\sigma_w^2\,\mathbb E[x^2]

For a linear or tanh-near-zero activation, \mathbb E[x^2]=\mathrm{Var}(x)=\mathrm{Var}(z_{\rm prev}), so each layer multiplies the variance of the signal by n_{\rm in}\sigma_w^2. To keep it at 1 choose \sigma_w^2=1/n_{\rm in} (LeCun initialisation). Now run the same argument backwards: the gradient on the inputs is \sum_iw_{ij}\delta_i, a sum of n_{\rm out} terms, so \mathrm{Var}(\partial L/\partial x)=n_{\rm out}\sigma_w^2\mathrm{Var}(\delta), which prefers \sigma_w^2=1/n_{\rm out}. We cannot satisfy both unless n_{\rm in}=n_{\rm out}; Xavier/Glorot initialisation compromises:

\mathrm{Var}(w)=\frac{2}{n_{\rm in}+n_{\rm out}}\quad(\text{Xavier, for tanh/linear}),\qquad\mathrm{Var}(w)=\frac{2}{n_{\rm in}}\quad(\text{He, for ReLU})

Why He has an extra 2. ReLU zeroes every negative pre-activation. If z is symmetric around 0, exactly half the units output 0 and the rest keep their value, so \mathbb E[x^2]=\mathbb E[\mathrm{ReLU}(z)^2]=\tfrac12\mathrm{Var}(z). Then \mathrm{Var}(z_\ell)=n_{\rm in}\sigma_w^2\cdot\tfrac12\mathrm{Var}(z_{\ell-1}), which equals the previous variance when \sigma_w^2=2/n_{\rm in}. The 2 compensates for the half of the signal ReLU throws away. Xavier's "2" in the numerator arises from averaging 1/n_{\rm in} and 1/n_{\rm out} harmonically: \tfrac{2}{n_{\rm in}+n_{\rm out}}.

Worked example — what happens to a ReLU net of width 100

Per-layer variance factor =\tfrac12n\sigma_w^2 with n = 100.

σ_w = 1 ("just use N(0,1)"): factor 50. After 10 layers, variance × 50^{10}\approx9.8\times10^{16} (standard deviation × 3×10⁸): exploding.

σ_w = 0.02: factor 0.02; after 10 layers × 10^{-17}: vanishing; the output is the same for every input and gradients are zero.

He: σ_w² = 2/100 = 0.02, σ_w = 0.1414: factor \tfrac12\cdot100\cdot0.02=1 exactly, at every depth. For a layer of 512 inputs, He gives \sigma_w=\sqrt{2/512}=0.0625.

Step 3: architecture fixes. Initialisation fixes the gain at the start. Architecture keeps it healthy throughout:

  • Residual (skip) connections. Instead of \mathbf h_{\ell+1}=F(\mathbf h_\ell), compute \mathbf h_{\ell+1}=\mathbf h_\ell+F(\mathbf h_\ell). The Jacobian is I+\partial F/\partial\mathbf h, and the backward product becomes \prod_\ell(I+J_\ell). Expanding it, one term is just the identity: the gradient has a direct highway from the loss to every layer that cannot vanish, whatever J_\ell does. This is why ResNets train hundreds of layers. (The activations, however, add up across blocks, so deep residual nets rely on normalisation and on scaling down or zero-initialising the last layer of each block.)
  • Normalisation (BatchNorm, LayerNorm, RMSNorm) re-centres and re-scales activations to roughly unit scale at every layer, resetting the gain regardless of the weights; it also makes the loss less sensitive to the weight scale.
  • Gradient clipping caps the global gradient norm, a pragmatic cure for rare explosions (essential in RNN and LLM training). Gated cells (LSTM/GRU) and careful learning-rate warm-up (Module 6) serve the same purpose.

Common traps
  • Initialising everything to the same constant (e.g. 0). Then all neurons in a layer compute the same function and get the same gradient forever; symmetry is never broken. Randomness is required (biases may be 0).
  • Using Xavier with ReLU (or He with tanh): the gain per layer is then off by √2, which compounds: (1/2)^{L} in variance. See "ReLU + Xavier" in the lab.
  • Believing ReLU cannot vanish. A neuron whose z is always negative has gradient exactly 0 ("dead ReLU"); a large learning rate or a bad bias can kill many units.
  • Blaming the optimiser. Adam rescales per-parameter step sizes but cannot rescue a layer whose gradient is exactly zero, or invent information that was never propagated.
Where it shows up in AI
  • Framework defaults: torch.nn.init.kaiming_normal_ (He) for ReLU layers, xavier_uniform_ (Glorot) as the classical default; transformers use small-std normal initialisation (≈0.02) with the output projections scaled by 1/√(2·layers).
  • ResNet (2015) made 152-layer vision models trainable; transformers wrap every attention and MLP sub-layer in a residual connection plus LayerNorm.
  • LSTM/GRU gates and gradient clipping exist because backprop through time is a product of the same Jacobian hundreds of times.
  • The mixed-precision loss-scaling trick multiplies the loss so that tiny gradients do not underflow in float16.

Check yourself

1. What is the He-initialisation standard deviation for a ReLU layer with 512 inputs? And Xavier for a layer with 300 inputs and 100 outputs?
He: √(2/512) = 0.0625. Xavier: Var = 2/(300+100) = 0.005, so std = √0.005 ≈ 0.0707.
2. Even with perfectly norm-preserving weight matrices, what is the largest possible gradient factor through 20 sigmoid layers?
σ′ ≤ 1/4 at every layer, so the factor is at most 0.25²⁰ ≈ 9×10⁻¹³: effectively zero.
3. In a residual block h' = h + F(h), why can the gradient not vanish just because ∂F/∂h is tiny?
∂h'/∂h = I + ∂F/∂h ≈ I when ∂F/∂h is small, so the upstream gradient passes through almost unchanged. The identity term provides a direct path from the loss to every layer.

Takeaways

  • Backprop gradients are products of Jacobians, so their size is exponential in depth: aim for a per-layer gain ≈ 1.
  • Variance analysis gives Xavier (2/(n_{\rm in}+n_{\rm out})) for tanh and He (2/n_{\rm in}) for ReLU.
  • Sigmoid's slope ≤ 1/4 is a built-in vanishing factor; ReLU, residual connections and normalisation are the standard cures.
7.7

Attention & transformers

The questionIn "The trophy did not fit in the suitcase because it was too big", what does "it" refer to? To resolve it, the word "it" must look at other words and borrow information from the right ones, with the choice depending on the content of the sentence — not on a fixed position. How do we build a differentiable operation that lets every position of a sequence fetch information from every other position, weighted by relevance?

Intuition

Think of a soft dictionary lookup. In an ordinary Python dictionary you present a query, it compares the query with the stored keys, finds the exactly matching key, and returns the associated value. Attention is the same, with three upgrades: queries and keys are vectors; the match is not yes/no but a similarity score (a dot product, Module 1: large when two vectors point the same way); and instead of returning one value we return a weighted average of all values, with weights obtained by passing the scores through a softmax (lesson 7.2) so they are positive and add to 1. The output for a token is a blend of the values of the tokens it finds relevant.

Every token plays three roles, produced from its embedding \mathbf x_i by three learned matrices: a query \mathbf q_i=W_Q\mathbf x_i ("what am I looking for?"), a key \mathbf k_i=W_K\mathbf x_i ("what do I advertise?"), and a value \mathbf v_i=W_V\mathbf x_i ("what do I hand over if selected?"). Separating key from value lets a token be found by one property but deliver another.

Build it up

Step 1: scores. For n tokens stack the queries, keys and values as rows of Q,K\in\mathbb R^{n\times d_k} and V\in\mathbb R^{n\times d_v}. All pairwise dot products come from one matrix product: S=QK^\top\in\mathbb R^{n\times n} with S_{ij}=\mathbf q_i\cdot\mathbf k_j — "how much does token i want token j".

Step 2: scale and normalise. A=\mathrm{softmax}(S/\sqrt{d_k}), applied to each row, so each row of A is a probability distribution over the tokens being attended to.

Step 3: blend. O=AV: row i of the output is \mathbf o_i=\sum_jA_{ij}\mathbf v_j. Put together:

\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}}\Big)V
Worked example — three tokens, d_k = 2

Q=K=\begin{pmatrix}1&0\\0&1\\1&1\end{pmatrix}, V=\begin{pmatrix}1&0\\0&2\\3&1\end{pmatrix}.

Scores QK^\top=\begin{pmatrix}1&0&1\\0&1&1\\1&1&2\end{pmatrix}; divide by \sqrt2=1.4142: first row (0.7071, 0, 0.7071).

Softmax of row 1: e^{0.7071}=2.0281,\ e^0=1,\ 2.0281, sum 5.0562 → (0.4011, 0.1978, 0.4011). Token 1 attends equally to itself and token 3 (their keys have the same dot product with q₁), and less to token 2 (orthogonal).

Output 1 = 0.4011·(1,0) + 0.1978·(0,2) + 0.4011·(3,1) = (0.4011+1.2033, 0.3956+0.4011) = (1.6044, 0.7967).

Row 3: scores (0.7071, 0.7071, 1.4142) → weights (0.2483, 0.2483, 0.5035) → output (1.759, 1.000): it attends most to itself, whose key matches best.

Without the scaling, row 1 would be softmax(1,0,1) = (0.4223, 0.1554, 0.4223): slightly sharper. In two dimensions that is harmless; in 64 dimensions it is not (next).

Why divide by √d_k?

Suppose the entries of a query q and a key k are independent with mean 0 and variance 1 (roughly what good initialisation and normalisation give). Then each product q_ik_i has mean 0 and variance \mathbb E[q_i^2]\mathbb E[k_i^2]=1, and the dot product is a sum of d_k independent such terms:

\mathrm{Var}(\mathbf q\cdot\mathbf k)=\sum_{i=1}^{d_k}\mathrm{Var}(q_ik_i)=d_k\qquad\Longrightarrow\qquad\mathrm{std}(\mathbf q\cdot\mathbf k)=\sqrt{d_k}

So for d_k=64 the raw scores typically differ by ±8 or more. Softmax of numbers that spread apart is nearly one-hot: e^{8}\approx3000. A one-hot softmax output is saturated: its Jacobian \mathrm{diag}(\mathbf p)-\mathbf p\mathbf p^\top (lesson 7.2) is ≈ 0, so almost no gradient flows back to the queries and keys and learning stalls. Dividing by \sqrt{d_k} restores unit variance: \mathrm{Var}(\mathbf q\cdot\mathbf k/\sqrt{d_k})=d_k/d_k=1, regardless of dimension, keeping softmax in its soft, trainable region. (It is the same variance-preserving idea as He initialisation in 7.6.)

Masking, multi-head, positions

Causal masking. A language model predicts the next word, so token i must not see tokens j>i. Add -\infty to those scores before the softmax: e^{-\infty}=0, so those weights are exactly 0 and each row still sums to 1. (Check the "causal mask" box in the lab below: the upper triangle of the weight matrix vanishes.)

Multi-head attention. One attention pattern is limiting (one token may need to attend to a subject and to a nearby punctuation mark). So we run h attention operations in parallel, each in its own lower-dimensional subspace (d_k=d_{\rm model}/h) with its own matrices, then concatenate and mix with an output matrix:

\mathrm{head}_a=\mathrm{Attention}(XW_Q^{a},XW_K^{a},XW_V^{a}),\qquad\mathrm{MHA}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,W_O

For d_{\rm model}=512, h=8: d_k=64, and the four projection matrices W_Q,W_K,W_V,W_O (each 512×512 when all heads are packed together) hold 4\times512^2=1\,048\,576 parameters (no biases). The cost of the score matrix is O(n^2d_k) per head: quadratic in sequence length, which is the central scaling problem of long-context models.

Backward pass (a nice use of 7.5). With O=AV: \partial L/\partial A=(\partial L/\partial O)V^\top and \partial L/\partial V=A^\top(\partial L/\partial O) (the linear-layer rules). Through each row's softmax: dS_i=A_i\odot\big(dA_i-(dA_i\cdot A_i)\mathbf 1\big) (the softmax Jacobian applied to a vector), and finally \partial L/\partial Q=dS\,K/\sqrt{d_k}, \partial L/\partial K=dS^\top Q/\sqrt{d_k}.

Positional encoding. Notice something: if you shuffle the tokens, Q, K, V are shuffled the same way, and the output is the same shuffled — attention is permutation-equivariant and has no idea of word order! Order must be injected. The original transformer adds a position-dependent vector to each embedding:

\mathrm{PE}(p,2i)=\sin\!\Big(\frac{p}{10000^{2i/d}}\Big),\qquad\mathrm{PE}(p,2i+1)=\cos\!\Big(\frac{p}{10000^{2i/d}}\Big)

Each pair (2i, 2i+1) is a point on a circle rotating at its own frequency \omega_i=10000^{-2i/d}: fast rotation (wavelength 2π ≈ 6 positions) in the first dimensions, very slow in the last (wavelength up to ≈ 62 800). Like the hands of a clock (seconds, minutes, hours) the combination identifies the position uniquely. Two properties make it useful. First, \mathrm{PE}(p+k) is a linear function of \mathrm{PE}(p) — each pair gets rotated by angle \omega_ik, by the angle-addition formulas \sin(a+b)=\sin a\cos b+\cos a\sin b — so a layer can learn "attend k positions back". Second, the dot product depends only on the distance:

\mathrm{PE}(p)\cdot\mathrm{PE}(p+k)=\sum_{i=0}^{d/2-1}\big[\sin(\omega_ip)\sin(\omega_i(p+k))+\cos(\omega_ip)\cos(\omega_i(p+k))\big]=\sum_i\cos(\omega_ik)

(using \cos(a-b)=\cos a\cos b+\sin a\sin b). It equals d/2 at k=0 (dividing by d/2 gives 1) and falls off with |k|. Modern LLMs often use rotary embeddings (RoPE), which rotate queries and keys by position-dependent angles so that \mathbf q\cdot\mathbf k depends only on relative distance — the same idea built directly into the score.

Common traps
  • Softmax over the wrong axis. Normalise over the keys (each row of S) — every query gets a distribution over tokens; a column-wise softmax is a classic bug.
  • "Attention weights explain the model." They show where information is read from in one layer and one head; they are not a faithful explanation of the final decision.
  • Masking by multiplying with 0 after softmax breaks normalisation; add −∞ before the softmax (or a large negative number such as −10⁹ in low precision).
  • Forgetting positions. Without positional information the model is a bag-of-tokens model.
  • d_k versus d_model. The scaling factor uses the per-head dimension, not the full model width.
Where it shows up in AI
  • Transformers / LLMs (GPT, Claude, Llama, BERT): every layer is multi-head attention followed by a feed-forward MLP (lesson 7.1), each wrapped with residual + normalisation (7.6). Decoder-only LLMs use the causal mask; encoder models (BERT) do not.
  • Vision transformers split an image into patches and attend among them; diffusion models use cross-attention between image features and text-prompt embeddings (queries from the image, keys/values from the text).
  • Efficiency: the n^2 score matrix motivates FlashAttention (tiling plus online log-sum-exp from 7.2), multi-query/grouped-query attention (sharing K,V across heads), sparse and linear attention, and the KV cache that stores keys/values of past tokens at inference.
  • Rotary (RoPE), ALiBi and learned positional embeddings are the modern descendants of the sinusoidal scheme above.

Takeaways

  • Attention is a soft dictionary: scores QK^\top → softmax weights → weighted average of values.
  • Dividing by \sqrt{d_k} keeps score variance at 1 so softmax does not saturate and gradients survive.
  • Masks add −∞ before softmax; multi-head runs several attention patterns in parallel; positional encodings supply the order that attention itself lacks.
  • Every piece — dot products, softmax, matrix gradients, residuals, initialisation — is something you now know from first principles.
