8.1

Autoencoders

The questionA 32×32 colour image is 3,072 numbers, yet the set of sensible images is a tiny sliver of all 3,072-number lists (random numbers look like static, not like anything). Could a network find a short description, perhaps 512 numbers or even 2, from which the picture can be rebuilt, and what would those few numbers mean?

Intuition

Imagine describing a face to a friend over the phone so they can draw it. You do not read out every pixel; you say "round, glasses, smiling, dark hair". A short list of properties is a code. An autoencoder learns both halves of this game at once: an encoder that turns an image into a short code, and a decoder that turns the code back into an image. It is trained by one simple rule: the output should look like the input.

The trick is the bottleneck, the narrow middle. If the code were as big as the image, the network could just copy it and learn nothing. Because the code is small, the network must discover what matters: shapes, positions, textures. The code space is called the latent space ("latent" = hidden), and nearby codes decode to similar images, so you can walk through it and watch one picture morph into another.

Build it up

Blueprint. The encoder is an ordinary CNN that halves the resolution and increases channels (you met this pattern in Module 3). The decoder mirrors it with transposed convolutions that double the resolution. Below is a small convolutional autoencoder for 32×32 RGB images; the bottleneck is a 8×8×8 tensor.

stagelayeroutput shapeweights + biases
inputimage3×32×32 = 3,0720
encoder 1conv 3×3 /2, 3→3232×16×163·9·32 + 32 = 896
encoder 2conv 3×3 /2, 32→6464×8×832·9·64 + 64 = 18,496
bottleneckconv 1×1, 64→88×8×8 = 51264·8 + 8 = 520
decoder 1up-conv 2×2 ×2, 8→6464×16×168·4·64 + 64 = 2,112
decoder 2up-conv 2×2 ×2, 64→3232×32×3264·4·32 + 32 = 8,224
outputconv 1×1, 32→33×32×3232·3 + 3 = 99

Total: 896 + 18,496 + 520 + 2,112 + 8,224 + 99 = 30,347 parameters. Compression ratio = input numbers ÷ code numbers = 3,072 ÷ 512 = 6 : 1.

Worked example · a fully connected autoencoder for 28×28 digits

784 → 128 → 32 → 128 → 784. Weights plus biases per layer: 784·128+128 = 100,480; 128·32+32 = 4,128; 32·128+128 = 4,224; 128·784+784 = 101,136. Total 209,968. The bottleneck stores 32 numbers for 784 pixels: ratio 784/32 = 24.5 : 1. Reconstruction loss for one image is the mean squared error over its pixels: if a pixel is 0.80 and the output is 0.65, that pixel contributes (0.15)² = 0.0225; the loss is the average over all 784.

Three flavours

  • Plain autoencoder: minimise reconstruction error. Good for compression and features, but its latent space has holes: a random code often decodes to garbage.
  • Denoising autoencoder: feed a corrupted image (noise, masked patches), ask for the clean original. The network can no longer copy; it must learn what clean images look like. This idea is the seed of diffusion (lesson 8.3) and of masked autoencoders (Module 5).
  • Variational autoencoder (VAE): the encoder outputs a mean \mu and spread \sigma, the code is sampled as z=\mu+\sigma\epsilon with \epsilon\sim\mathcal N(0,1), and a penalty keeps these distributions close to \mathcal N(0,1). The latent space then has no holes, so sampling z\sim\mathcal N(0,1) and decoding gives a new image. Derivation: the ELBO lesson.
Worked example · the VAE penalty for one latent number

The encoder says \mu=1,\ \sigma=0.5. The KL penalty against \mathcal N(0,1) is \tfrac12(\mu^2+\sigma^2-\ln\sigma^2-1)=\tfrac12(1+0.25+1.386-1)=0.818. If the encoder instead said \mu=0,\sigma=1 the penalty is 0, but the code would carry no information about the image. The two terms (reconstruction vs KL) pull in opposite directions, and training finds the compromise. Reparameterisation: with \epsilon=0.8, z=1+0.5\cdot0.8=1.4; randomness sits in \epsilon, so gradients flow through \mu,\sigma.

The formal definition

z=f_\phi(x),\quad \hat x=g_\theta(z),\quad \mathcal L_{AE}=\frac1{HWC}\lVert x-\hat x\rVert_2^2,\quad \mathcal L_{VAE}=\lVert x-\hat x\rVert^2+\beta\,D_{KL}\big(\mathcal N(\mu,\sigma^2)\,\Vert\,\mathcal N(0,I)\big)
x, x̂input image and its reconstruction
fφencoder network with weights φ
gθdecoder network with weights θ
zlatent code (the bottleneck tensor, flattened)
μ, σthe encoder's predicted mean and standard deviation for each latent number (VAE)
βweight of the KL term; larger β gives a smoother latent space but blurrier images

Draw it yourself

Block diagram: image → [conv /2] → [conv /2] → [1×1 conv] → code → [up ×2] → [up ×2] → [1×1 conv] → image. Shapes 3×32×32 → 32×16×16 → 64×8×8 → 8×8×8 → 64×16×16 → 32×32×32 → 3×32×32. A transposed 2×2 convolution with stride 2 has C_{in}\cdot4\cdot C_{out} weights, for example 64·4·32 = 8,192, plus 32 biases.

Common traps
  • A big bottleneck makes a perfect copier that has learned nothing useful. The narrowness is the point.
  • Low reconstruction error does not mean a good generator: sampling a random code from a plain autoencoder usually gives junk.
  • MSE averages over plausible answers, so reconstructions look blurry. That blur is not a bug but the mean of the possibilities, and it motivates GANs and diffusion.
Where it shows up in AI
  • Stable Diffusion's VAE compresses 512×512×3 images to 64×64×4 latents so the diffusion model can work 48× cheaper (lesson 8.3).
  • Anomaly detection in factories: train on good parts only; a defect reconstructs badly, so the error map highlights it.
  • Learned image compression and denoising; masked autoencoders (MAE) pretrain ViTs by reconstructing hidden patches.

Check yourself

1. Why must the bottleneck be smaller than the input?
Otherwise the network can learn the identity mapping and never has to find structure. A narrow code forces it to keep only what is needed to rebuild the image.
2. For the 3×32×32 autoencoder above, what is the compression ratio and how many weights does the 2×2 up-conv 8→64 have?
3,072/512 = 6:1. Weights 8·4·64 = 2,048, plus 64 biases = 2,112.
3. Why does a VAE sample z=\mu+\sigma\epsilon rather than sampling z directly?
Sampling directly is not differentiable. Moving the randomness into ε makes z a smooth function of μ and σ, so backpropagation can train the encoder.

Takeaways

  • Encoder squeezes, decoder expands; the bottleneck forces useful features.
  • Compression ratio = input values ÷ code values (6:1 and 24.5:1 above).
  • Denoising and variational versions turn it into the seed of modern generators.
8.2

GANs

The questionWe want a network that produces new realistic images, but nobody can write down a formula for "realistic". Averaging errors gives blur (lesson 8.1). How can we train a generator when the only judge of quality is another network?

Intuition

A forger and a detective. The generator G turns random noise into fake paintings. The discriminator D looks at a painting and says "real" or "fake". The detective improves by catching forgeries; the forger improves by studying what gave the fake away. Neither is told what a good painting looks like; the realism emerges from their competition. If the forger gets so good that the detective can only guess (50 / 50), the game has reached its equilibrium.

Build it up: the blueprints

The DCGAN (2015) made this work for images with a simple recipe: no pooling, batch norm, ReLU in G, LeakyReLU in D. The generator takes a 100-number noise vector, projects it with one fully connected layer to 4×4×512 (that is 8,192 numbers), then repeatedly doubles the resolution while halving the channels: 4×4×512 → 8×8×256 → 16×16×128 → 32×32×64 → 64×64×3.

The projection from noise is a dense layer: 100·8,192 + 8,192 = 827,392 parameters. The explorer uses compact 2×2 up-convolutions (e.g. 512·4·256+256 = 524,544, plus 512 for batch norm = 525,056). The original DCGAN uses 4×4 kernels, so each up-conv has four times as many weights (512·16·256 = 2,097,152).

The discriminator is a mirror image: a strided CNN that shrinks the picture and ends in one number, the probability of "real".

layeroutputparams
conv 4×4 /2, 3→6464×32×323·16·64+64 = 3,136
conv 4×4 /2, 64→128 + BN128×16×1664·16·128+256 = 131,328
conv 4×4 /2, 128→256 + BN256×8×8524,800

The game and its loss

D wants D(x)\to1 on real images and D(G(z))\to0 on fakes. G wants the opposite for its fakes. One equation expresses both:

\min_G\max_D\;V(D,G)=\mathbb E_{x\sim p_{data}}[\log D(x)]+\mathbb E_{z\sim p_z}[\log(1-D(G(z)))]
x ~ pdataa real training image
z ~ pzrandom noise (for example 100 numbers, each from a normal distribution)
D(·)discriminator output, a probability between 0 and 1
G(z)the generator's fake image
minG maxDD tries to make V large, G tries to make it small
Worked example · numbers for the loss

Suppose D gives 0.9 on a real image and 0.1 on a fake. D's objective: ln 0.9 + ln(1−0.1) = −0.105 − 0.105 = −0.211 (best possible is 0). At the perfect-forger equilibrium, D = 0.5 everywhere and V = 2·ln 0.5 = −1.386.

Why the original G loss fails early. Early on, fakes are obvious: D(G(z)) = 0.01. Write D = σ(a) with logit a. The minimax generator loss is log(1−D); its gradient wrt the logit is −σ(a) = −0.01, tiny, so G barely learns exactly when it is worst (saturation). The non-saturating loss -\log D(G(z)) has value 4.605 and gradient wrt the logit −(1−σ(a)) = −0.99, 99 times larger. At D = 0.5 both gradients have size 0.5. Same goal, same fixed point, healthy learning signal.

The ideal detective. With p_{data}(x)=0.6 and p_g(x)=0.2 at some x, the best D is D^*(x)=\dfrac{p_{data}}{p_{data}+p_g}=\dfrac{0.6}{0.8}=0.75. Plugging D* back in shows G is minimising the Jensen-Shannon divergence between the real and fake distributions.

Training dynamics and mode collapse

Training alternates: a few D steps (tilt the decision boundary), one G step (move fakes up the slope of D). It is a moving target: each side's best move changes as the other improves, so curves oscillate and the loss value does not tell you image quality. The classic failure is mode collapse: G finds one output (or a few) that fools the current D, and produces only that. D then learns to reject that mode, G hops to another, and the game chases itself without ever covering all the real modes. Remedies: Wasserstein loss with gradient penalty, spectral normalisation, minibatch statistics, and careful learning rates.

Common traps
  • The loss is not a quality score. Both losses can look flat while images improve, or look fine while G has collapsed. Look at samples.
  • If D wins too completely, G's gradient vanishes; if G wins, D stops giving information. Balance matters.
  • GANs only judge realism of samples; they give no density, so you cannot easily say "how likely is this image".
Where it shows up in AI
  • StyleGAN: photorealistic faces; its generator uses a style code at every resolution. BigGAN: class-conditional ImageNet.
  • The discriminator idea lives on inside pix2pix, CycleGAN, super-resolution (lesson 8.4) and as an adversarial loss in the Stable Diffusion VAE.
  • Deepfakes, data augmentation, face editing, texture synthesis.

Check yourself

1. A real image gets D = 0.8 and a fake gets D = 0.3. What is D's objective ln D(x) + ln(1−D(G(z)))?
ln 0.8 + ln 0.7 = −0.223 − 0.357 = −0.580.
2. If D(G(z)) = 0.02, compare the logit gradients of the saturating and non-saturating G losses.
Saturating: magnitude σ(a) = 0.02. Non-saturating: 1 − σ(a) = 0.98, which is 49 times larger.
3. What does mode collapse look like in the generated samples?
Little diversity: many different noise vectors give almost the same image (or a handful of them), even though the real data has many varieties.

Takeaways

  • G maps noise to images (100 → 4×4×512 → … → 64×64×3), D maps images to one probability.
  • Minimax loss; the non-saturating trick gives G a strong gradient early.
  • Training is a moving target; mode collapse is the characteristic failure.
8.3

Diffusion for images

The questionGANs are hard to train and can collapse. Destroying an image is easy: keep adding noise and it becomes static. Could we train a network to undo one small step of destruction, and then generate by starting from pure static and undoing step after step?

Intuition

Think of a sculptor with a block of marble who does not know the statue in advance but, at every moment, can tell which flecks of stone are "not part of the statue". Chip away a little and repeat. A diffusion model starts from noise and, in about 20 to 50 steps, repeatedly asks: "what part of this picture is noise?" and removes a bit of it. Early steps decide the big layout (a dark blob here, a bright blob there); late steps add fine detail.

Training is surprisingly simple. Take a real image, add a random amount of noise, and ask the network to predict the noise that was added. That is a plain regression problem with a clear target, with none of the game of lesson 8.2.

Build it up

Forward process (no learning). With a schedule of numbers \bar\alpha_t falling from nearly 1 to nearly 0, mix the image with noise:

x_t=\sqrt{\bar\alpha_t}\,x_0+\sqrt{1-\bar\alpha_t}\,\epsilon,\qquad \epsilon\sim\mathcal N(0,I)
Worked example · one pixel

At step t, \bar\alpha_t=0.64, so \sqrt{\bar\alpha_t}=0.8 and \sqrt{1-\bar\alpha_t}=0.6. A pixel with x_0=1.0 gets noise \epsilon=0.5: x_t=0.8\cdot1.0+0.6\cdot0.5=1.1. The network sees 1.1 and must output the noise, 0.5. If it does, we recover the clean pixel: \hat x_0=(x_t-\sqrt{1-\bar\alpha_t}\,\hat\epsilon)/\sqrt{\bar\alpha_t}=(1.1-0.3)/0.8=1.0. The weights 0.8 and 0.6 satisfy 0.8²+0.6² = 1, so the signal-plus-noise keeps a steady overall scale.

Reverse process (the learned part). A network \epsilon_\theta(x_t,t) predicts the noise. Training loss: \mathbb E\,\lVert\epsilon-\epsilon_\theta(x_t,t)\rVert^2. Sampling (DDIM style, deterministic): estimate the clean image, then re-noise it to the previous, slightly cleaner level:

\hat x_0=\frac{x_t-\sqrt{1-\bar\alpha_t}\,\hat\epsilon}{\sqrt{\bar\alpha_t}},\qquad x_{t-1}=\sqrt{\bar\alpha_{t-1}}\,\hat x_0+\sqrt{1-\bar\alpha_{t-1}}\,\hat\epsilon

Derivations and why predicting noise is the same as following the gradient of the log-density: the diffusion maths lesson.

The denoiser blueprint: a U-Net

The noise predictor must output an image-shaped tensor from an image-shaped input, with fine detail preserved, so it is a U-Net: an encoder that halves resolution while raising channels, a bottleneck, a decoder that doubles resolution, and skip connections that concatenate encoder features into the decoder. Here is a small one working on a 64×64×4 latent:

This toy has 1,679,108 parameters and 1.29 GMACs. Notice the concat blocks: after up 128 (128 channels) concatenating @e2 (128 channels) gives 256, and the next 3×3 conv, 256→128, has 256·9·128+128 = 295,040 weights. Two additions turn it into the real thing:

  • Time embedding. The network must know how noisy the input is. The step t becomes a vector (sinusoidal features then a small MLP) that is injected into every residual block, usually as a per-channel scale and shift.
  • Cross-attention to text. A text encoder (CLIP in Stable Diffusion v1) turns the prompt into 77 tokens × 768 numbers. In attention layers the image positions are the queries and the text tokens are the keys and values, so each location can ask "which words matter for me".

Latent diffusion (Stable Diffusion)

Denoising 512×512×3 directly is expensive (786,432 values, and attention over 262,144 positions). Latent diffusion first compresses with a pretrained VAE (lesson 8.1) and diffuses in the small space:

stageshaperole
text prompt → CLIP text encoder77×768conditioning tokens (≈123 M parameters)
VAE encoder (training only)512×512×3 → 64×64×48× smaller each side: 786,432 → 16,384 values, 48× fewer
start sampling: pure noise64×64×4xT
U-Net denoiser ×(20–50 steps)64×64×4 → 64×64×4time embedding + cross-attention to text (≈860 M parameters)
VAE decoder64×64×4 → 512×512×3latent to pixels (≈84 M for the whole VAE)

Attention in the U-Net at 64×64 has 4,096 positions, so a score matrix of 4,096² ≈ 16.8 M entries, instead of 262,144² ≈ 6.9·10¹⁰ in pixel space.

Classifier-free guidance

We want the image to obey the prompt. During training the prompt is dropped (replaced by an empty prompt) about 10 % of the time, so one network learns both an unconditional noise prediction \epsilon_u and a conditional one \epsilon_c. At sampling time we run both and extrapolate away from the unconditional one, in the direction the prompt adds:

\hat\epsilon=\epsilon_u+w\,(\epsilon_c-\epsilon_u)
εunoise prediction without the prompt
εcnoise prediction with the prompt
wguidance scale; w = 0 ignores the prompt, w = 1 is plain conditional, 5 to 8 is typical
Worked example · by hand

For one pixel \epsilon_u=0.20 and \epsilon_c=0.50. The prompt's push is 0.50 − 0.20 = 0.30. With w=7.5: \hat\epsilon=0.20+7.5\cdot0.30=2.45. With w = 1 you get 0.50; with w = 0 you get 0.20. Using \bar\alpha=0.64,\ x_t=1.1 from before, \hat x_0=(1.1-0.6\cdot2.45)/0.8=-0.4625: strong guidance pushes the image prediction far from what plain conditioning would say ((1.1-0.3)/0.8=1.0). That is why high guidance gives vivid, prompt-obeying but less diverse, over-saturated images. The cost: two network evaluations per step.

Common traps
  • The network predicts noise (or equivalently the clean image or a velocity), not the image directly in one shot; one-shot prediction would be a blurry average.
  • High guidance is not "better": it reduces diversity and can burn colours.
  • Latent diffusion's "512×512" quality is capped by the VAE: tiny text and fine faces can be lost in the 64×64×4 code.
Where it shows up in AI
  • Stable Diffusion, DALL·E 2/3, Imagen, Midjourney: text to image. Inpainting and ControlNet: the same U-Net with extra conditions.
  • Faster samplers (DDIM, DPM-solver) and distillation reduce 50 steps to 1–4. Video generators run the same idea over time (lesson 8.6).
  • Diffusion transformers (DiT) replace the U-Net by a transformer on latent patches (Module 5 ideas).

Takeaways

  • Forward noising is a fixed formula; the network learns to predict the noise.
  • The denoiser is a U-Net with a time embedding and cross-attention to text; latent diffusion runs it on a 64×64×4 code between a VAE encoder and decoder.
  • Guidance ε = εu + w(εc − εu) trades diversity for prompt obedience.
8.4

Image-to-image & super-resolution

The questionYou have a blurry 64×64 photo, or a sketch, or a summer scene that should be winter. The output is itself an image, tied pixel by pixel to the input. Which networks and losses do this, and why does the "most accurate" answer often look worse than a sharper one?

Intuition

Image-to-image translation means learning a mapping from one picture type to another: edges → photo, day → night, segmentation map → street scene, noisy → clean. The network sees the input in full, so the structure comes from the input; the network only has to invent appearance.

Super-resolution (SR) is the special case "small → big". Making a 4× larger image from 1 pixel per 16 means inventing 15 of every 16 pixels. Many sharp images shrink to the same blurry one, so the task is ambiguous: a model trained to minimise average error returns the average of all plausible sharp images, which is blurry. Sharp results need a loss that rewards realism, not only closeness.

Build it up

pix2pix (paired data). A U-Net generator (skips carry the input's edges straight to the output) plus a PatchGAN discriminator that classifies each 70×70 patch of the pair (input, output) as real or fake. The loss combines adversarial and pixel terms:

\mathcal L=\mathcal L_{cGAN}(G,D)+\lambda\,\mathbb E\,\lVert y-G(x)\rVert_1,\qquad\lambda=100

The L1 term keeps the output close to the target (structure, colours), the GAN term supplies sharp texture.

CycleGAN (unpaired data). There are no matched pairs of horse and zebra photos. Train two generators, G:X\to Y and F:Y\to X, with a discriminator for each domain, and add a cycle-consistency loss: translating there and back must return the start, \lVert F(G(x))-x\rVert_1. Without it G could output any plausible zebra that ignores the horse.

SR networks. SRCNN (2014) was three convolutions: 9×9, 64 filters; 1×1, 32; 5×5, 1, working on a bicubic-upsampled image. Weights: 9·9·1·64 = 5,184; 1·1·64·32 = 2,048; 5·5·32·1 = 800; total 8,032 (8,129 with biases). Later nets (EDSR, ESRGAN) work at low resolution and upscale at the end with sub-pixel convolution (pixel shuffle): a conv outputs C\,r^2 channels and these are rearranged into an r times bigger image. For 4× colour SR the last conv outputs 3·16 = 48 channels at H×W which become 3 channels at 4H×4W.

Worked example · PSNR and what it misses

Peak signal-to-noise ratio for 8-bit images: \text{PSNR}=10\log_{10}(255^2/\text{MSE}). With MSE = 100: 10·log₁₀(650.25) = 28.13 dB. Halving the MSE adds only 3 dB. A blurry average and a sharp-but-slightly-shifted result can have the same PSNR, but people prefer the sharp one.

Perceptual loss. Instead of comparing pixels, compare features of a pretrained network (for example VGG at some layer): \lVert\phi(y)-\phi(\hat y)\rVert^2. Two images with the same edges and textures give similar features even if pixels differ slightly. SR GANs use perceptual + adversarial + small pixel loss.

The formal definition

\mathcal L_{SR}=\lambda_{pix}\lVert y-\hat y\rVert_1+\lambda_{perc}\lVert\phi(y)-\phi(\hat y)\rVert_2^2+\lambda_{adv}\,(-\log D(\hat y))
y, ŷtrue high-resolution image and the network's output
φfrozen feature extractor, for example some layers of VGG-19
Ddiscriminator that judges realism of ŷ
λpix, λperc, λadvweights of the three terms

Common traps
  • Higher PSNR is not "looks better". Models optimised for PSNR look soft; GAN-based models look sharp but may invent details (a wrong letter, a different face). Never use SR output as evidence.
  • Training on bicubic-downsampled pairs and testing on real blurry photos fails: the degradation differs. Real-ESRGAN synthesises complex degradations for this reason.
  • Cycle consistency does not guarantee a meaningful translation, only a reversible one.
Where it shows up in AI
  • Phone cameras (night mode, zoom), medical and satellite enhancement, old-film restoration, video upscaling (DLSS-style game upscalers).
  • pix2pix and its descendants: sketch-to-photo, map-to-aerial, colourisation. ControlNet gives diffusion models the same input-conditioned control.
  • Diffusion SR (for example SR3) now often replaces GAN SR.

Check yourself

1. Why does an L2/L1-only SR network produce blurry output?
Many different sharp images downscale to the same input. The error-minimising answer is the average of those possibilities, which has no sharp edges.
2. How many output channels must the last conv have for 3× colour super-resolution with pixel shuffle?
3·3² = 27.
3. MSE = 25 on 8-bit images: PSNR?
10·log₁₀(65025/25) = 10·log₁₀(2601) = 34.15 dB.

Takeaways

  • pix2pix = U-Net + PatchGAN + λ·L1; CycleGAN adds cycle consistency for unpaired data.
  • SR: SRCNN (8,032 weights) to sub-pixel convolution networks to GAN and diffusion SR.
  • Perceptual and adversarial losses give sharpness that pixel losses cannot.
8.5

3-D from images

The questionYou walk around a statue taking 50 photos. Can a program build a 3-D model so that it renders the statue correctly from a viewpoint you never photographed, including shiny highlights that move as you move?

Intuition

A Neural Radiance Field (NeRF) stores the scene as a function, not a mesh: give it any 3-D point and a viewing direction, and it answers "how dense is the matter here, and what colour does it emit toward that direction?" To make a photo, shoot a ray through each pixel, ask the function at points along the ray, and blend the answers like looking through layers of fog and coloured glass: nearby opaque stuff hides what is behind it.

Build it up: volume rendering on four samples

Pick N points along the ray, spaced δ apart. At sample i the network gives a density \sigma_i\ge0 and colour c_i.

  • Opacity of the segment: \alpha_i=1-e^{-\sigma_i\delta} (how much light this slab blocks).
  • Transmittance: T_i=\prod_{j (how much light survives to reach sample i).
  • Weight: w_i=T_i\alpha_i; pixel colour C=\sum_i w_ic_i (plus T_{N+1} times the background colour).

Blueprint of the NeRF network. A plain MLP (no convolutions!). Positions go through positional encoding (sin and cos at 10 frequencies per coordinate, so 3·2·10 + 3 = 63 inputs; directions use 4 frequencies, 27 inputs) because MLPs on raw coordinates produce blurry results. Eight layers of 256 units (a skip re-injects the 63 input numbers at layer 5) output density σ and a 256-feature vector; the feature plus the encoded direction goes through one 128-unit layer to RGB. Weights: 63·256+256 = 16,384; three 256→256 layers 3·65,792 = 197,376; layer 5 (319→256) 81,920; three more 197,376; density head 257; feature layer 65,792; view layer (283→128) 36,352; RGB head 387. Total ≈ 595,844 parameters, small compared to a ResNet-50, but one image needs 640,000 rays × (64+128 samples) ≈ 123 million network evaluations at 800×800. Training: render the pixel, compare with the photo's pixel (MSE), backpropagate through the sum above into the MLP; the camera poses come from structure-from-motion (Module 2).

The cost of NeRF motivated 3-D Gaussian splatting: represent the scene as millions of explicit 3-D Gaussian blobs, each with position (3), scale (3), rotation quaternion (4), opacity (1) and colour as spherical harmonics (48): 59 numbers each. Rendering projects ("splats") the blobs onto the image and alpha-blends them front to back, which is the same transmittance sum but without a network call per sample, so it runs in real time (100+ frames per second) and trains in minutes.

Common traps
  • NeRF needs known camera poses; garbage poses give blurry scenes. It is per-scene: each scene trains its own network (minutes to hours).
  • Too few samples along a ray cause thin objects to flicker or vanish; NeRF uses a coarse pass to choose where to place fine samples.
  • It reconstructs only what the photos saw; unseen regions are hallucinated by smoothness, not knowledge.
Where it shows up in AI
  • 3-D capture for VR/AR, film and real estate; Google Maps immersive views; digital twins; robot mapping.
  • Faster variants (Instant-NGP hash grids, Gaussian splatting); text-to-3-D (DreamFusion) uses a diffusion model to supervise a NeRF.

Check yourself

T₂ = 0.5, T₃ = 0.5·0.5 = 0.25; w₂ = T₂α₂ = 0.25.
3. Why positional encoding?
An MLP is biased towards smooth functions of its input; sines and cosines of many frequencies let it represent sharp detail.

Takeaways

  • C = Σ Ti αi ci with Ti = Π(1−αj): occlusion falls out of the formula.
  • NeRF is a ≈0.6 M-parameter MLP queried on ~10⁸ points per image.
  • Gaussian splatting keeps the same blend but with explicit blobs, for real-time speed.
8.6

Video models

The questionOne frame of a person with a raised arm could be waving, stretching or hailing a taxi. What tells them apart is how the pixels change over time. How do we give a network the time axis without making it a thousand times more expensive?

Intuition

A video is a stack of images: a tensor of shape T × H × W × 3. A 2-D kernel slides over height and width. A 3-D kernel also slides over time: a 3×3×3 cube looks at a 3×3 patch in three consecutive frames, so it can respond to change, such as an edge moving right. Alternatives avoid the cost of the cube: compute motion explicitly (optical flow) and feed it to a second network, or let a transformer's attention connect patches across frames.

Build it up

Clips and frame sampling. You cannot feed a whole movie. Sample a clip: for example 32 frames spaced 2 apart from a 30 fps video covers 64 frames ≈ 2.1 s. At test time average predictions over several clips. Sparse sampling (a few frames spread over the video) captures the whole action cheaply.

3-D convolutions (C3D, I3D). A 3-D conv with kernel k_t\times k\times k has C_{in}\,k_t\,k^2\,C_{out} weights.

Worked example · cost of the time axis

2-D conv 3×3, 64→64: 64·9·64 = 36,864 weights. The 3-D version 3×3×3: 64·27·64 = 110,592, three times as many, and it is applied at every position of every frame as well. I3D "inflates" an ImageNet 2-D kernel by repeating it along time and dividing by 3, so pretrained knowledge is reused.

Two-stream (Simonyan & Zisserman): one CNN on a single RGB frame (appearance) and one on a stack of 10 optical-flow fields (2 channels each, so 20 input channels; motion). The first layer of a ResNet-style 7×7 conv with 64 filters has 3·49·64 = 9,408 weights on RGB but 20·49·64 = 62,720 on the flow stack. Predictions are fused at the end.

Video transformers. Cut a clip of 8 frames at 224×224 into 16×16 patches: 14×14 = 196 tokens per frame, 8·196 = 1,568 tokens. Joint space-time attention compares every token with every other: 1,568² = 2,458,624 pairs per head. TimeSformer's divided attention does spatial attention within each frame (8·196² = 307,328 pairs) and temporal attention across the 8 frames at each location (196·8² = 12,544 pairs): 319,872, about 7.7 times fewer. ViViT's "tubelet" embedding cuts 2×16×16 blocks, so 16 frames also give 8·196 = 1,568 tokens.

SlowFast uses two pathways on the same clip: a slow one (few frames, many channels, appearance) and a fast one (many frames, few channels, motion), joined by lateral connections.

Optical flow is a motion vector for each pixel between two frames. The classic estimate, block matching, searches a small neighbourhood for the shift that best aligns a patch: the lab shows it.

Common traps
  • Video datasets are scene-biased: a model may recognise "swimming" from the blue water, not the motion. Test with frames shuffled; a model that does not care about order is not using time.
  • Memory scales with frames: batch size shrinks drastically, so clip length and resolution are always a trade-off.
  • Frame sampling that misses the key moment (a short event) gives wrong labels.
Where it shows up in AI
  • Action recognition on Kinetics (SlowFast, TimeSformer, VideoMAE), sports analytics, sign language, gesture control, surveillance triage.
  • Video generation (Sora-like models) use spacetime patches, the same tokens as above, with diffusion (lesson 8.3).

Check yourself

3. Why does divided attention save compute?
It replaces one (T·N)² comparison by T·N² (space) plus N·T² (time), which is far smaller when T and N are large.

Takeaways

  • 3-D kernels add a time axis at kt times the weights; two-stream adds explicit motion; transformers tokenise space-time.
  • Token count and attention pairs decide the cost; divided attention cuts it about 8 times here.
8.7

Tracking

The questionA detector says "car at (310, 120)" in frame 7 and "car at (322, 118)" and "car at (88, 200)" in frame 8. Which detection is the same car as before? What if the detector misses the car for one frame, or jitters by a few pixels, or two cars cross?

Intuition

Tracking-by-detection splits the problem in two. A detector finds objects in every frame independently (Module 6). A tracker links detections over time and gives each object a persistent ID. Linking uses two ideas: predict where each known object should be now (a motion model), then associate the predictions to the new detections by overlap. A Kalman filter provides the prediction and also keeps a calibrated sense of its own uncertainty.

Build it up: the Kalman filter in one dimension

State = (position p, velocity v). Each frame we predict with constant velocity, which grows our doubt, then update with a noisy measurement, which shrinks it. The balance is set by the Kalman gain K: trust the measurement if the prediction is uncertain, trust the prediction if the measurement is noisy.

\text{predict: }\ x^-=Fx,\ P^-=FPF^\top+Q\qquad\text{update: }\ K=P^-H^\top(HP^-H^\top+R)^{-1},\ x=x^-+K(z-Hx^-),\ P=(I-KH)P^-
x = (p, v)state estimate: position and velocity
Fmotion model; for dt = 1: p ← p + v, v ← v
Pcovariance: how unsure we are (diagonal = variances, off-diagonal = position and velocity uncertainty move together)
Qprocess noise: the world is not exactly constant velocity
H = [1 0]we measure only position
Rmeasurement noise variance
zthe measurement (a detection)
KKalman gain: how much of the surprise z − Hx⁻ to believe
Worked example · one cycle

Previous estimate: p = 10, v = 2, P = diag(1, 1). Q = diag(0.1, 0.1), R = 1, dt = 1.

Predict. p⁻ = 10 + 2 = 12, v⁻ = 2. FPF^\top=\begin{pmatrix}2&1\\1&1\end{pmatrix} (position variance 1 + velocity variance 1), so P^-=\begin{pmatrix}2.1&1\\1&1.1\end{pmatrix}: uncertain position grew from 1 to 2.1.

Update. Detection z = 13.5. Surprise y = 13.5 − 12 = 1.5. S = 2.1 + 1 = 3.1. Gain K = (2.1/3.1, 1/3.1) = (0.677, 0.323). p = 12 + 0.677·1.5 = 13.016; v = 2 + 0.323·1.5 = 2.484 (the filter learned the object is a bit faster, from position evidence alone). New variances: P₁₁ = (1−0.677)·2.1 = 0.677, P₁₂ = 0.323, P₂₂ = 1.1 − 0.323·1 = 0.777. The position doubt shrank from 2.1 to 0.68, which is less than both the prediction (2.1) and the measurement (1.0).

Data association. Boxes of predicted tracks vs boxes of detections. Overlap measure IoU = area of intersection ÷ area of union. For A = [0,0,10,10] and B = [5,0,15,10]: intersection 5·10 = 50, union 100+100−50 = 150, IoU = 0.333. Cost = 1 − IoU. We need the one-to-one assignment with smallest total cost, solved by the Hungarian algorithm.

Worked example · why not greedy

IoU matrix, tracks T1, T2 against detections D1, D2: T1: (0.6, 0.3); T2: (0.5, 0.1). Greedy takes the biggest first: T1-D1 (0.6), then T2 is left with D2 (0.1): total 0.7. The Hungarian optimum is T1-D2 + T2-D1 = 0.3 + 0.5 = 0.8. Greedy gave T2 a nearly non-overlapping box, a likely ID swap. Pairs below an IoU threshold (SORT: 0.3) are rejected: the detection starts a new track and the track is marked missed.

SORT (2016) = Kalman filter on box state (centre, area, aspect ratio and their velocities) + IoU + Hungarian, running at hundreds of frames per second; tracks are born tentative, confirmed after a few hits, and deleted after some missed frames. DeepSORT adds an appearance embedding (a 128-number re-identification vector from a small CNN) and uses cosine distance and a Mahalanobis gate (a 95 % chi-squared gate of 9.49 for 4 degrees of freedom), so identities survive occlusions. ByteTrack also uses low-confidence detections for a second matching round.

Common traps
  • Constant-velocity prediction fails for sudden turns; a high Q fixes this at the cost of noisier tracks.
  • A camera moving fast breaks IoU association; compensate camera motion first.
  • IDs, not boxes, are the product: report ID switches and fragmentation (MOTA, IDF1, HOTA), not only detection accuracy.
Where it shows up in AI
  • Traffic counting, sports analytics (player and ball tracking), retail footfall, drones, self-driving perception (a tracker feeds prediction and planning).
  • Modern research: transformer trackers (MOTR, TrackFormer) learn association end to end, but SORT-style baselines remain in most production systems.

Check yourself

1. Boxes [0,0,4,4] and [2,2,6,6]: IoU?
Intersection 2·2 = 4; union 16+16−4 = 28; IoU = 1/7 = 0.143.
2. If measurement noise R becomes huge, what happens to K and to the estimate?
K → 0: the filter nearly ignores detections and follows its own prediction.
3. Why does the Kalman estimate of position variance after the update fall below both P⁻ and R?
Two independent pieces of evidence combine; their combined information is the sum, so uncertainty drops (in 1-D: 1/(1/2.1+1/1) = 0.68).

Takeaways

  • Predict (uncertainty grows), then update (uncertainty shrinks); K balances prediction and measurement.
  • IoU cost plus Hungarian gives the optimal one-to-one matching; greedy can be worse.
  • SORT is the lightweight baseline; DeepSORT adds appearance to survive occlusion.
