4.1

How to read an architecture

The questionA paper says "ResNet-50: 25.6 M parameters, 4.1 GFLOPs". Your phone has 4 GB of memory and a few watts of power. Can it run the model? Which of the two numbers decides memory, which decides speed, and which part of the network do they come from? Before comparing architectures we need a way to read one.

Intuition

Think of a network as a factory assembly line for a photograph. The raw photo arrives at the door (the input). A stem does the first rough work: it shrinks the photo and creates a first set of simple features. Then comes a sequence of stages. Inside one stage the picture keeps the same size, and the same block design is repeated several times, each repetition refining the features. Between stages the picture is shrunk (usually halved in height and width) while the number of channels is increased (usually doubled): the factory trades where things are for what they are. A head at the end collapses the last feature maps into class scores.

Every architecture paper is therefore a variation on four decisions: (1) what is the block, (2) how many blocks per stage (depth), (3) how many channels per stage (width), (4) how large is the input (resolution). Learn to read these and you can read any paper.

Build it up: the three accounts

For every layer we keep three accounts. Take a convolution with input C_{in}\times H\times W, kernel k\times k, C_{out} filters, stride s and padding p.

1 · Shape. The output has C_{out} channels and spatial size \lfloor (H+2p-k)/s\rfloor+1. Shape bookkeeping tells you which layers can be connected and how big every tensor is.

2 · Parameters (what you must store). Each filter has C_{in}k^2 weights, and there are C_{out} filters, so C_{in}k^2C_{out} weights (plus C_{out} biases, or 2C_{out} if a batch-norm follows, because BN has a scale and a shift per channel). Notice that the image size H,W is absent: the same filter is reused at every position. That reuse is the whole point of a convolution.

3 · MACs (what you must compute). One multiply-accumulate is a\leftarrow a+w\cdot x. Every output position needs C_{in}k^2 of them per filter, so the layer costs C_{in}k^2C_{out}\cdot H_{out}W_{out} MACs. Papers often say "FLOPs" but mean MACs; a true floating-point operation count is twice as large (one multiply plus one add). Here we always say MACs.

Two more quantities complete the picture. Activation memory: the output tensors must be kept for backpropagation, C_{out}H_{out}W_{out} numbers per layer — this is what limits your batch size when training. Receptive field (RF): the patch of input pixels that can influence one output value. It grows by (k-1)\cdot j per layer, where the jump j is the product of all strides so far.

Worked example — one VGG layer, four accounts

The second convolution of VGG-16 takes a 64\times224\times224 tensor and applies 64 filters of 3×3 (padding 1, stride 1).

  • Shape: \lfloor(224+2-3)/1\rfloor+1=224 → output 64\times224\times224.
  • Weights: 64\cdot 9\cdot 64=36{,}864; plus 64 biases = 36,928 parameters.
  • MACs: 36{,}864\times224\times224=1{,}849{,}688{,}064\approx1.85 G. This one layer alone costs about as much as the whole of ResNet-18 (1.81 G).
  • Activations: 64\cdot224\cdot224=3{,}211{,}264 numbers, i.e. 12.8 MB in float32 — for one image.
  • Receptive field: it is the second 3×3 conv, so RF = 1 + 2 + 2 = 5.

Notice the asymmetry: 36.9 K parameters but 1.85 G MACs. Early layers are compute-heavy and parameter-light; late layers (small maps, many channels) are the opposite; fully connected layers are parameter-heavy and compute-light. Reading an architecture means knowing where each account is spent.

Common traps
  • FLOPs vs MACs. "4.1 GFLOPs" in many papers means 4.1 G MACs. A real FLOP count is 2×. Always check which one is meant before comparing.
  • Parameters ≠ speed. MobileNets have few parameters and few MACs, but real latency also depends on memory traffic and hardware support; depthwise layers move a lot of data per MAC.
  • Counting memory. Parameters decide the file size (×4 bytes in float32); activations decide training memory and, with the weights, inference memory.
  • Forgetting BN's 2C parameters, or the bias that disappears when BN follows a conv.
Where it shows up in AI
  • Every model card and paper table lists params and MACs; you will use this arithmetic to decide whether a backbone fits an edge device or a GPU budget.
  • Detection and segmentation models (Modules 6–7) reuse these backbones and use the stage outputs (strides 4, 8, 16, 32) as a feature pyramid, so the stage structure you learn here is the vocabulary of everything later.

Takeaways

  • Stem → stages of repeated blocks → head; depth, width, resolution are the dials.
  • Params = C_{in}k^2C_{out}/g; MACs = params × output pixels; RF grows by (k-1)j.
  • Early layers: compute-heavy. Late layers and FC heads: parameter-heavy.
4.2

LeNet → AlexNet → VGG

The questionIn 1998 a 61 K-parameter network read handwritten digits for banks. In 2012 a 61 M-parameter network won ImageNet by a landslide. In 2014 a network used only 3×3 kernels and 138 M parameters. What changed each time, and why does a stack of small kernels beat a single big one?

Intuition

LeNet-5 (1998) already had the whole recipe: convolution to find local patterns, pooling to shrink the image, then a small fully connected classifier. Its limits were data and hardware: there was no large labelled set and no GPU. AlexNet (2012) was LeNet scaled up when ImageNet (1.2 M images) and GPUs arrived, plus three tricks that made scale trainable: ReLU instead of tanh (no saturating gradient, much faster training), dropout in the big FC layers (they hold 96 % of the parameters and overfit), and data augmentation. It cut top-5 error from 26.2 % to 15.3 %. VGG (2014) asked: instead of mixing 11×11, 5×5, 3×3 kernels with ad-hoc choices, what if we use one simple rule — 3×3 convs only, double the channels each time the map is halved — and just go deeper?

Why is 3×3 enough? Two stacked 3×3 convs see a 5×5 patch; three see 7×7 — the same receptive field as a single 7×7 — but with fewer parameters (3\cdot3^2C^2=27C^2 instead of 49C^2) and three non-linearities instead of one, so the stack can represent more complex functions.

Build it up: shape tables

The problem each design had. LeNet: too small for natural images. AlexNet: irregular, hand-tuned kernel sizes (11×11 stride 4 loses detail) and a monstrous FC head. VGG: simple and accurate, but enormous (138 M parameters, 15.5 G MACs): about 90 % of its parameters sit in the first FC layer.

Worked example — VGG keeps compute balanced

The last conv of each VGG stage (64→64 at 224, 128→128 at 112, 256→256 at 56, 512→512 at 28) costs exactly 1.85 G MACs each. The designer's rule "÷2 size, ×2 channels" keeps work per stage almost constant, while parameters grow 4× per stage. Only the last stage (14×14) is cheaper, at 0.46 G.

Common traps
  • "Bigger kernels see more": stacking small kernels gives the same receptive field more cheaply.
  • Believing depth is free: VGG-16 needs 15.5 G MACs per image, ≈ 3.8× ResNet-50, for lower accuracy.

Where it shows up in AI
  • VGG-16 features are still used as a perceptual loss (style transfer, super-resolution, GAN training): distances between VGG feature maps match human similarity better than pixel distances.
  • AlexNet's ReLU + dropout + data augmentation + GPU training became the default recipe; LeNet's conv–pool–FC pattern is the skeleton of every small classifier (digits, MNIST-style tasks, microcontrollers).

4.3

Inception & multi-branch blocks

The questionA cat may fill the whole frame or be a tiny patch in a corner. Which kernel size should a layer use: 1×1, 3×3, 5×5? VGG's answer was "always 3×3". Could a layer simply use all of them in parallel and let training pick — and could it do so without exploding the cost?

Intuition

Imagine a team of four specialists examining the same photograph: one looks at single pixels' colour mixtures (1×1), one at small details (3×3), one at larger shapes (5×5) and one at the strongest local response (max-pool). Each writes a report with its own number of feature maps; the reports are stacked side by side (concatenated along channels) so the next layer reads all of them. This is the Inception module of GoogLeNet (2014).

The naive version has a problem. A 5×5 conv on 192 channels producing 32 maps costs 192\cdot25\cdot32=153{,}600 weights, and the pooling branch passes all 192 channels on, so the output grows wider and wider. The fix is the 1×1 bottleneck ("network-in-network"): before an expensive 3×3 or 5×5 conv, a cheap 1×1 conv reduces the channels (192→16); after pooling, a 1×1 conv projects the channels down. A 1×1 conv mixes channels at each pixel and costs only C_{in}C_{out}.

Build it up: the block, the numbers

The problem the previous design had: VGG/AlexNet commit to one scale per layer and spend most parameters in FC layers; making them wider quadratically increases cost. The idea: multi-scale branches + 1×1 reductions + global average pooling instead of big FC layers. Result: 22 layers deep, 7.0 M parameters (8.7× fewer than AlexNet), 1.58 G MACs, top-5 error 6.7 % (ILSVRC-2014 winner).

Worked example — inception 3a (input 192×28×28)

Branches (output channels): 1×1 → 64; 1×1 reduce → 96 then 3×3 → 128; 1×1 reduce → 16 then 5×5 → 32; max-pool 3×3 then 1×1 → 32. Concatenated: 64+128+32+32=256 channels, still 28×28.

  • 1×1 branch: 192\cdot64=12{,}288
  • 3×3 branch: 192\cdot96+96\cdot9\cdot128=18{,}432+110{,}592=129{,}024
  • 5×5 branch: 192\cdot16+16\cdot25\cdot32=3{,}072+12{,}800=15{,}872 (versus 153,600 without the reduction: 9.7× less)
  • pool-proj branch: 192\cdot32=6{,}144
  • weights total 163,328 + 368 biases = 163,696 parameters; MACs = 163,328 × 784 ≈ 128.0 M.

The naive module (no reductions, pool passes 192 channels through) has 387,296 parameters, 303.5 M MACs and 416 output channels: 2.4× the cost and a wider output that snowballs through later modules.

Why it works

(1) Multi-scale: the four branches have receptive fields of 1, 3, 5 and 3 pixels at the same depth, so a single layer can respond to different object sizes. (2) Dimension reduction: a 1×1 conv is a learned low-rank projection of channels; squeezing 192→16 before a 5×5 loses little because feature maps are highly redundant. (3) Global average pooling replaced VGG's 100 M-parameter FC layer: the whole classifier is 1024×1000 ≈ 1.0 M. (4) Auxiliary classifiers on middle modules injected gradient into early layers (a precursor of ResNet's shortcut idea). Later Inception-v2/v3 factorised further: a 5×5 becomes two 3×3 (25C^2\to18C^2), an n\times n becomes 1\times n followed by n\times1 (7×7: 49→14), and added batch-norm.

The formal definition

y=\big[\,f_{1\times1}(x)\;\Vert\;f_{3\times3}(r_3(x))\;\Vert\;f_{5\times5}(r_5(x))\;\Vert\;f_{1\times1}(\text{pool}(x))\,\big],\qquad C_{out}=\sum_b C_b
‖concatenation along the channel axis (spatial sizes must match, hence "same" padding in every branch)

4.4

ResNet & residual connections

The questionIf a 20-layer network works, a 56-layer network should work at least as well: just let the extra 36 layers copy their input. Yet in 2015 He et al. measured the opposite — the deeper plain network had higher training error than the shallow one. It was not overfitting. What was going wrong, and what one-line change fixed it?

Intuition

Asking a stack of non-linear layers to copy its input is surprisingly hard: it needs the weights to land on an exact identity map. Optimisers fail to find it, and the deeper stack ends up worse than the shallow one — this is the degradation problem (a training-optimisation failure, distinct from vanishing gradients, which batch-norm largely fixed).

The residual idea: stop asking the layers to produce the whole output. Let them produce only the correction. The block outputs x+F(x): the input travels along a skip connection untouched, and the layers learn the residual F(x). "Do nothing" is now the easy default (F=0, just shrink the weights), and each block has only to learn a small adjustment. Think of editing a draft instead of rewriting it from scratch.

Build it up: the block, the gradient, the shapes

Problem: accuracy gets worse beyond ~20 plain layers. Idea: y=F(x)+x. Blocks:

  • Basic block (ResNet-18/34): two 3×3 convs (BN after each, ReLU between) + identity skip. When the stage downsamples or the channel count changes, the skip uses a 1×1 conv (stride 2) so that the shapes match before the addition.
  • Bottleneck block (ResNet-50/101/152): 1×1 reduce → 3×3 → 1×1 expand, skip around all three. The 3×3 runs on a quarter of the channels.
Worked example — basic block, 64 channels at 56×56

Two 3×3 convs: 64\cdot9\cdot64=36{,}864 weights each → 73,728; two BN layers: 2·128 = 256; total 73,984 parameters. MACs: 73{,}728\cdot3136=231{,}211{,}008. The identity skip costs nothing. A downsampling block (64→128, stride 2) adds a 1×1 projection of 64\cdot128+256=8{,}448 parameters: its total is 230,144.

Worked example — why a bottleneck?

At 256 channels, two 3×3 convs would need 2\cdot256\cdot9\cdot256=1{,}179{,}648 weights. The bottleneck (256→64→64→256) needs 16{,}384+36{,}864+16{,}384=69{,}632 (+768 BN) = 70,400 parameters and 218.4 M MACs at 56×56: 17× fewer parameters, so ResNet-50 can be deeper (50 layers) than ResNet-34 at similar cost (4.1 G vs 3.7 G MACs).

Why it works: the gradient highway

Write a stack of residual blocks as x_{l+1}=x_l+F_l(x_l). Unrolling from block l to the end L:

x_L=x_l+\sum_{i=l}^{L-1}F_i(x_i)\quad\Longrightarrow\quad \frac{\partial\mathcal L}{\partial x_l}=\frac{\partial\mathcal L}{\partial x_L}\left(1+\frac{\partial}{\partial x_l}\sum_{i=l}^{L-1}F_i(x_i)\right)

For a single block this is the chain rule applied to y=F(x)+x: \partial\mathcal L/\partial x=\partial\mathcal L/\partial y\cdot(1+\partial F/\partial x). The "1" is the key. In a plain network the gradient is a product of per-layer Jacobians, so a typical factor below 1 shrinks it exponentially with depth. With the skip, the gradient always contains the direct term \partial\mathcal L/\partial x_L: whatever happens inside the branches, the loss signal reaches every block unchanged. Also in the forward direction, the features of any earlier block are available to every later block by simple addition.

Worked example — the numbers

Suppose every layer scales the gradient by 0.8. After 20 plain layers: 0.8^{20}=0.0115 — the first layer receives 1 % of the signal; after 50 layers: 1.4\times10^{-5}. In a residual network each block's factor is 1+F' with F' small at the start (e.g. 0.05 — branches are often initialised near zero), so 20 blocks give 1.05^{20}=2.65: the signal neither vanishes nor needs luck. (A residual branch can of course learn F'=-0.2 and reproduce the plain factor 0.8 — but it is no longer forced to.)

Pre-activation ResNet (v2). The original block applies ReLU after the addition, which sits on the skip path. The follow-up puts BN → ReLU → conv inside the branch, so the skip path is a pure identity from the first block to the last; this trained 1001-layer networks. Projection vs identity: only use a 1×1 projection when shapes change.

4.5

DenseNet & feature reuse

The questionResNet adds the input to the output. Adding mixes two feature sets into one — information from earlier layers can no longer be told apart. What if, instead, each layer received everything computed before it, intact? And would that waste or save parameters?

Intuition

Picture a group project with a shared whiteboard. In a ResNet, each member overwrites the board with a revised version of what was there. In a DenseNet nobody erases anything: each member reads the entire board, writes a small new note (only k new feature maps — the growth rate), and pins it to the board. The board (collective knowledge) grows by k channels per layer. Because earlier features stay available, later layers do not have to re-learn them: that is feature reuse, and it lets each layer be very thin (k = 32 versus 64–512 channels in a ResNet).

Build it up

Problem: in ResNet, identical features are re-computed in many layers and the sum x+F(x) blurs which layer contributed what. Idea: concatenation. In a dense block of L layers, layer \ell receives [x_0,x_1,\dots,x_{\ell-1}]:

x_\ell=H_\ell\big([x_0,x_1,\dots,x_{\ell-1}]\big),\qquad C_\ell^{in}=C_0+k(\ell-1),\qquad \#\text{connections}=\frac{L(L+1)}{2}
H_\ellBN-ReLU-1×1 conv (4k channels) → BN-ReLU-3×3 conv (k channels): a "bottleneck" layer (DenseNet-B)
[ · ]concatenation along channels
kgrowth rate: new channels per layer (32 in DenseNet-121)
C_0channels entering the block
Worked example — the first dense block of DenseNet-121 (64 channels at 56×56, L = 6, k = 32)

Layer 1 sees 64 channels: BN (128 params) + 1×1: 64\cdot128=8{,}192 + BN (256) + 3×3: 128\cdot9\cdot32=36{,}864 = 45,440 parameters and outputs 32 channels. Layer 2 sees 96 channels, layer 6 sees 224. After six layers the block outputs 64+6\cdot32=256 channels. Block total: 335,552 parameters, 1.04 G MACs. The 3×3 conv costs the same in every layer (36,864 weights); only the 1×1 grows with the input width.

Transition layers between blocks stop the channel count from growing forever: BN → 1×1 conv that halves the channels (compression θ = 0.5) → 2×2 average pool. Channels through DenseNet-121: 64 → 256 → 128 → 512 → 256 → 1024 → 512 → 1024 (after blocks of 6, 12, 24, 16 layers; 1 + 2·58 + 3 + 1 = 121 layers).

Why it works — and what it costs

  • Parameter efficiency: DenseNet-121 has 7.98 M parameters and top-1 ≈ 74.4 % — fewer parameters than ResNet-18 (11.7 M, 69.8 %), though 2.83 G MACs.
  • Short paths: the loss gradient reaches every layer directly (like ResNet's highway), and every layer gets "deep supervision".
  • Reuse vs refine: addition (ResNet) re-uses features by refining them; concatenation (DenseNet) keeps them separate and explores new ones. Dual Path Networks combine both: part of the channels are summed (residual path, reuse) and part concatenated (dense path, exploration).
  • The cost: concatenated tensors must be stored and copied, so training memory is high (naïve implementations materialise every concatenation); and the cost of a layer grows with the accumulated width. This is why DenseNets are loved in medical imaging (small data, few parameters) but rarely used as fast production backbones.

4.6

Efficient convolutions

The questionA 3×3 conv with 256 input and 256 output channels has 590,000 parameters and a phone must run dozens of them every frame at 30 fps. Is there a way to get nearly the same representational power for ~9× less compute? What are we really paying for in a convolution?

Intuition

An ordinary convolution does two jobs at once: it looks at a spatial neighbourhood (3×3) and it mixes all input channels. Doing both jointly is the expensive part: every filter has k^2C_{in} weights. Separate the jobs. First, a depthwise convolution: one 3×3 filter per channel, no mixing — pure spatial filtering. Then a pointwise 1×1 convolution: no spatial look, but it mixes channels. Like a kitchen where one cook chops (spatial) and another seasons (channel), instead of every cook doing both.

Build it up: derive the saving

Input C_{in}\times H\times W, output C_{out}\times H\times W (stride 1).

\text{standard: } k^2C_{in}C_{out}HW\qquad\text{depthwise: }k^2C_{in}HW\qquad\text{pointwise: }C_{in}C_{out}HW
\frac{\text{depthwise}+\text{pointwise}}{\text{standard}}=\frac{k^2C_{in}+C_{in}C_{out}}{k^2C_{in}C_{out}}=\frac{1}{C_{out}}+\frac{1}{k^2}

For k=3 and large C_{out} the ratio approaches 1/9: about 8–9× cheaper. The product k^2\cdot C_{out} became a sum.

Worked example — 128 → 128 channels at 56×56

Standard 3×3: 128\cdot9\cdot128=147{,}456 weights, 147{,}456\cdot3136=462.4 M MACs. Separable: depthwise 128\cdot9=1{,}152 + pointwise 128\cdot128=16{,}384 = 17,536 weights, 55.0 M MACs. Ratio 17{,}536/147{,}456=0.1189=1/128+1/9: 8.4× cheaper.

Grouped convolution is the continuum between the two extremes: split channels into g groups, each group convolves only its own channels: cost k^2C_{in}C_{out}/g. g=1 is a standard conv; g=C_{in} is depthwise. ResNeXt uses g=32 in the 3×3 of a bottleneck: with 128 mid channels the 3×3 has 4,608 weights instead of 147,456, so the block (70,144 weights) matches a ResNet bottleneck's cost but is much wider.

The blueprints

MobileNet-v1 (2017): stack of depthwise-separable blocks (dw 3×3 + BN + ReLU, pw 1×1 + BN + ReLU). 4.23 M parameters, 0.569 G MACs, 70.6 % top-1 — 27× fewer MACs than VGG-16 (15.47 G) at similar accuracy. 95 % of its MACs and 75 % of its parameters are in the 1×1 convs; the FC layer holds most of the rest. Width multiplier α (thin channels everywhere) scales cost by α², resolution multiplier ρ scales it by ρ².

The problem with v1: no residuals, and ReLU applied to very narrow tensors destroys information. MobileNet-v2 (2018): the inverted residual with linear bottleneck. A classical residual block is wide → narrow → wide (bottleneck). v2 inverts it: the block's ends are narrow (24 channels) and its middle is wide (×6 = 144): expand with a 1×1, filter with a cheap depthwise 3×3 on the wide tensor, project back with a 1×1 that has no ReLU. The skip connects the narrow ends (cheap to store).

Worked example — inverted residual, 24 → 24 channels, t = 6, at 56×56

Expand: 24\cdot144=3{,}456 (+288 BN). Depthwise: 144\cdot9=1{,}296 (+288). Project: 144\cdot24=3{,}456 (+48). Total 8,832 parameters, 25.7 M MACs; the skip adds nothing. A ResNet basic block with 24 channels would be 10,368 weights but with no wide intermediate space.

Why "linear"? The interesting content of a feature map lies on a low-dimensional manifold. ReLU zeroes every negative coordinate. If the tensor is wide (144 dims) the data still survives — enough coordinates stay positive to reconstruct it. In a narrow tensor (24 dims, or 2 in the lab below) ReLU folds the manifold onto itself and information is lost for good. Hence: apply the non-linearity only in the wide middle; make the narrow projection linear.

Squeeze-and-Excitation (2017) adds channel attention: global-average-pool each channel to a single number (squeeze), pass the C-vector through a small MLP C\to C/r\to C with sigmoid (excitation), and multiply the feature map by these gates (scale). For C=256,\ r=16: 256\cdot16+16+16\cdot256+256=8{,}464 parameters, only 8,192 MACs — negligible compute. Adding SE to every block of ResNet-50 costs +2.53 M parameters (≈ 28.1 M total) for a gain of roughly 1–1.5 points top-1. EfficientNet and MobileNet-v3 use it.

ShuffleNet (2018) pushes further: the 1×1 convs now hold the cost, so make them grouped. Grouped 1×1 convs never mix channels across groups, so a channel shuffle (a free reordering) interleaves the groups before the next grouped conv. With C = 240, g = 3, bottleneck width 60: 4,800 + 540 + 4,800 = 10,140 weights.

4.7

Scaling networks

The questionYou have a good small network and 10× more compute. Do you make it deeper, wider, or feed it larger images? Practitioners used to pick one and tune by hand — ResNet-18 → 200 (depth), WideResNet (width), 480-pixel inputs (resolution). Is there a principled recipe that gives a whole family of models, from a phone-sized B0 to a server-sized B7?

Intuition

Think of a photograph you want to examine. Resolution is how much detail you can see; depth is how many reasoning steps you take to connect details into objects; width is how many different things you look for at each step. Making only one of them large hits diminishing returns: with very high resolution but few layers the network cannot "think" about all the detail (its receptive field is too small); with very many layers but low resolution there is no detail left to think about; with huge width and tiny depth you look for many simple things but never combine them. The three have to grow together, in balance.

Build it up: the cost law and the recipe

What each dial costs. Doubling the depth doubles the number of layers: ×2 params, ×2 MACs. Doubling the width doubles both C_{in} and C_{out} of every conv: ×4. Doubling the resolution makes every feature map 4× larger: ×4 MACs (parameters unchanged). So, with multipliers d,w,r:

\text{params}\propto d\,w^2,\qquad \text{MACs}\propto d\,w^2\,r^2

Compound scaling (EfficientNet, 2019): use one coefficient \phi to scale all three with fixed bases found by a small grid search at \phi=1:

d=\alpha^{\phi},\quad w=\beta^{\phi},\quad r=\gamma^{\phi},\qquad \text{s.t. }\ \alpha\cdot\beta^2\cdot\gamma^2\approx2,\ \ \alpha,\beta,\gamma\ge1
\phiuser-chosen compute knob: each +1 roughly doubles the MACs
\alpha,\beta,\gammafixed constants for depth, width, resolution; found once for the baseline (EfficientNet-B0: α = 1.2, β = 1.1, γ = 1.15)
\alpha\beta^2\gamma^2\approx2since MACs ∝ d·w²·r², the total cost is (\alpha\beta^2\gamma^2)^\phi\approx2^\phi
Worked example — φ = 3

Check the constraint: 1.2\cdot1.1^2\cdot1.15^2=1.2\cdot1.21\cdot1.3225=1.920 ≈ 2. For φ = 3: depth ×1.2^3=1.728, width ×1.1^3=1.331, resolution ×1.15^3=1.521 → 224·1.521 ≈ 341 px. MACs × 1.728\cdot1.331^2\cdot1.521^2=7.08 (= 1.920³) → 0.39 G · 7.08 ≈ 2.8 G; parameters × 1.728\cdot1.331^2=3.06 → 5.29 M · 3.06 ≈ 16 M. The published B3 (12 M params, 1.8 G MACs, 300 px) lies in this neighbourhood; the published family used hand-picked coefficients near the same law.

The baseline matters. B0 itself was found by neural architecture search (NAS): a controller proposes architectures from a search space (kernel sizes, expansion ratios, SE or not, layers per stage), each is trained briefly, and the controller is rewarded for accuracy and penalised for cost (MnasNet's reward is \text{ACC}\cdot(\text{LAT}/T)^{w} with w\approx-0.07). The result is a MobileNet-v2-like network of MBConv blocks (inverted residuals) with SE and some 5×5 depthwise kernels: 5.29 M params, 0.386 G MACs, 77.1 % top-1. RegNet (2020) takes the opposite view — instead of searching single networks, search the design space: it finds that good networks have stage widths following a quantised linear rule (u_j=w_0+w_a\,j), similar depth ≈ 20 blocks, and that blocks should be simple (bottleneck ratio 1). Both ideas answer "how do I choose widths and depths" systematically.

Why it works. A larger input needs a larger receptive field (more depth) and more channels to capture finer patterns; balancing keeps all three limited by the same compute. Scaling a single dimension saturates quickly: the EfficientNet paper reports that ResNet-1000 is barely better than ResNet-101, and wider/higher-resolution variants saturate at about 80 % top-1 — whereas the compound-scaled B7 reaches 84.3 %.

4.8

Modernising the ConvNet

The questionIn 2020–2021 Vision Transformers overtook ResNets on ImageNet. Is it the attention mechanism — or the training recipe and a pile of design details that came with it? Liu et al. (2022) asked: if we take a plain ResNet-50 and change it one step at a time toward a transformer's design choices, keeping convolutions, how far do we get?

Intuition

It is like tuning an old car with a modern engineer's checklist: new tyres, better fuel, a lighter frame — each change is small, but together they make it competitive with the new model. Each step of the roadmap has a reason borrowed from transformers (a layer-by-layer ratio, a big patchify stem, a larger spatial window, an inverted MLP, LayerNorm and GELU) — and each can be implemented with convolutions.

Build it up: the roadmap

Step 0 — the recipe. Retraining ResNet-50 with a modern recipe (AdamW, long schedule, strong augmentation, label smoothing, stochastic depth) lifts it from 76.1 % to 78.8 % with no architecture change. Part of the "transformer advantage" was the recipe. Then (accuracy as reported by the authors):

Compare ResNet-50's first bottleneck (stage 1, 256 channels): 70,400 parameters. The ConvNeXt block uses more parameters per block but spends 94 % of its MACs in the two 1×1 layers — the same structure as an MLP block.

Why it works

The ConvNeXt block is a transformer block with attention replaced by a depthwise conv: token mixing (spatial) first, then a channel MLP (inverted bottleneck), both wrapped in LayerNorm and a residual. A depthwise 7×7 is a fixed-window, weight-shared, local version of self-attention. It keeps the convolution's inductive biases (translation equivariance, locality), so it needs less data than a ViT and is simpler to run at high resolution — important for detection and segmentation.

4.9

Capstone: design under a budget

The questionA product manager says: "Our app must classify photos on a mid-range phone: under 4 million parameters and 0.35 billion MACs per image." Another: "The microcontroller in our camera has 256 K weights of flash." Which blocks from Module 4 do you choose, how wide, how deep — and how do you check your design before training anything?

Intuition

Architecture design is budget accounting. You have three currencies: parameters (flash/RAM for weights), MACs (latency and energy) and activation memory (peak RAM). Every block you learned is a different exchange rate between them and representational power:

  • Standard conv: expensive, powerful (the baseline: VGG).
  • Bottleneck / 1×1 reduction: 8–17× cheaper than a full 3×3 at the same width (Inception, ResNet-50).
  • Depthwise-separable / inverted residual: ≈ 8–9× cheaper (MobileNets).
  • Global average pooling instead of flatten + FC: removes tens of millions of parameters (AlexNet: 58.6 M in FC).
  • Earlier or stronger downsampling: ÷4 MACs per halving of resolution.
  • Width and depth: params ∝ d·w², MACs ∝ d·w²·r² (Lesson 4.7).

Build it up: a design procedure

1. Fix the input resolution (it multiplies MACs by r²). 2. Choose a stem that downsamples fast (stride 2, then pool or stride 2). 3. Choose a block by budget: ResNet blocks for servers, inverted residuals / dw-sep for phones and microcontrollers. 4. Set channel widths per stage (double when halving). 5. End with gap + fc (never flatten of a big map). 6. Compute params and MACs; find the biggest spender and fix it first. 7. Check the receptive field: the last layer should see most of the image (RF ≥ ~75 % of the input here).

Worked example — meeting the phone budget

Start from ResNet-18 (11.69 M, 1.81 G MACs): fails both. The biggest spenders are the last stage (4.7 M + 3.7 M params) and the early layers (compute). Replace the whole body by MobileNet-v2's inverted residuals: 3.505 M parameters, 0.301 G MACs, RF 491 — meets ≤ 4 M and ≤ 0.35 G (note the 1.28 M-parameter classifier alone is 36 % of the whole model!). For the 160-pixel camera task (≤ 2 M, ≤ 0.15 G) MobileNet-v2 gives 3.5 M / 0.154 G — over budget; halving the channels of a MobileNet-v1 body gives 1.33 M / 0.077 G. For the 96-pixel microcontroller task (≤ 0.25 M, ≤ 0.03 G): a nine-block dw-sep network ending at 128 channels has 0.188 M parameters and 0.004 G MACs — the 128 K FC layer is now the largest single cost.

Each solution is a point on an accuracy–cost trade-off; the comparison lab below shows the published points. Your goal in the lab is feasibility first, then efficiency: meet the budget, then see how far below it you can go.

Common traps
  • Optimising the wrong number. Parameters, MACs and latency are different; a model with fewer MACs can be slower on your hardware (memory-bound depthwise layers). Measure on the device when it matters.
  • Ignoring the classifier. With 1000 classes, fc 1000 from 1280 channels is 1.28 M parameters — more than half of a small budget.
  • Budget met ≠ accurate. This lab checks cost and structure only; a feasible design still has to be trained and validated.
  • Resolution is a multiplier on everything: dropping input size is the cheapest MAC saver but loses small objects.
Where it shows up in AI
  • Model selection in production: choose a backbone family and size (MobileNet / EfficientNet / ResNet / ConvNeXt) by params, MACs and measured latency on the target chip.
  • Hardware-aware NAS (MnasNet, FBNet, Once-for-All) automates exactly the loop you did by hand: propose → count cost → keep if within budget → measure accuracy.

3. A design meets the budget but accuracy is poor. What do you try, in order?
Spend remaining budget where it helps most: increase resolution or width slightly (compound), use stronger blocks (SE, inverted residual instead of plain), train with a better recipe; confirm with measured latency.

Takeaways

  • Design = budget accounting over params, MACs, activations.
  • Find the biggest spender first; typical fixes: dw-sep/invres blocks, gap instead of FC, earlier downsampling, narrower widths.
  • Cost checks are necessary, not sufficient: train and measure.
