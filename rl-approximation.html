Module 5 · Function approximation & deep Q-learning

Tables work for a corridor of 5 cells. They fail for a game screen with millions of pixel patterns, or a robot joint angle that is continuous. This module replaces the table with a function that generalises from one state to its neighbours, and then shows the three problems that appear the moment you do: the deadly triad that can make learning diverge, the correlated data that experience replay and target networks were invented to tame, and the upward bias of a maximum that Double DQN corrects.

Where this sits in the loop. Every lesson here changes the estimate stage of the learning loop: the value function is no longer a table, but a parametric model whose weights are updated from experience. The store stage changes too, from a table to a weight vector, a network and, in DQN, a replay buffer.

5.1

Linear function approximation

The questionA delivery robot's position is a continuous number between 0 and 10 metres, and the value of each position must be learned from experience. A table needs one entry per position, so it cannot cover every position, and it learns nothing about a position it has never visited. Can one small set of numbers describe the value of every position, so that visiting one place also teaches us about nearby places?

Intuition

Imagine fitting a straight line through a scatter of points. The line has two numbers, a slope and an intercept, but it gives an answer for every x, including x values you never measured. The line generalises. A table is the opposite: it stores one answer per x and is silent everywhere else.

The value function can be treated the same way. Choose a fixed feature vector \mathbf x(s) that describes state s with a few numbers, and make the value a weighted sum of those features. Learning then means adjusting the weights, so that one experience moves the values of many states at once.

Build it up

Step 1: a state becomes a feature vector. Describe a position s by two numbers: a constant 1 and the position itself. Then \mathbf x(s) = (1, s).

Step 2: the value is a weighted sum. With weights \mathbf w = (w_0, w_1), define \hat v(s,\mathbf w)=\mathbf w^{\top}\mathbf x(s)=w_0+w_1 s. The hat means "estimate": \hat v is what we have learned, and v^\pi is the true value.

Step 3: the TD update, with the gradient of a linear model. Recall the TD error from Module 4: \delta = R + \gamma\hat v(S',\mathbf w) - \hat v(S,\mathbf w). For a linear model the gradient of \hat v(S,\mathbf w) with respect to \mathbf w is just the feature vector \mathbf x(S). The update is therefore

\mathbf w \leftarrow \mathbf w + \alpha\,\delta\,\mathbf x(S)

This is called a semi-gradient update. It is a gradient step on the squared error to the target, but the target R+\gamma\hat v(S') is treated as a fixed number, even though it depends on \mathbf w. The target is bootstrapped, and we do not differentiate through it. That shortcut is what makes it "semi".

Worked example: two TD updates on a three-state walk

States A and B have features \mathbf x(A)=(1,1) and \mathbf x(B)=(1,2). The terminal state has value 0. Take \gamma=0.9, \alpha=0.1, and start with \mathbf w=(0,0).

Episode 1, step B → end, reward 1. \hat v(B)=0, so \delta = 1 + 0 - 0 = 1. The update gives \mathbf w = (0,0) + 0.1(1)(1,2) = (0.1,\ 0.2). Now \hat v(B) = 0.1 + 0.4 = 0.5. One experience has moved the value of B, and also the values of every state that shares its features.

Episode 2, step A → B, reward 0. \hat v(A) = 0.1 + 0.2 = 0.3 and the target is 0 + 0.9 \times 0.5 = 0.45. So \delta = 0.45 - 0.30 = 0.15, and \mathbf w = (0.1,0.2) + 0.1(0.15)(1,1) = (0.115,\ 0.215).

Check: \hat v(A) = 0.330 and \hat v(B)=0.545. A had no reward of its own, but its value rose because it leads to B. That is bootstrapping, and the feature sharing is what spreads the change.

The formal definition

\hat v(s,\mathbf w)=\mathbf w^{\top}\mathbf x(s)=\sum_{i=1}^{d} w_i\,x_i(s)
\mathbf w \leftarrow \mathbf w+\alpha\big[R_{t+1}+\gamma\,\hat v(S_{t+1},\mathbf w)-\hat v(S_t,\mathbf w)\big]\,\mathbf x(S_t)

On-policy linear TD(0) with a suitable step size converges to a unique fixed point, under the conditions in Tsitsiklis and Van Roy (1997). That fixed point is generally not the value function that minimises the error; it is the solution of a projected Bellman equation. Read convergence claims with that condition attached.

s, S_ta state, and the state at time t
\mathbf x(s)feature vector of state s, fixed in advance (the design choice)
\mathbf wweight vector learned from experience; dimension d = number of features
\hat v(s,\mathbf w)estimated value of state s under weights w
\deltaTD error: bootstrapped target minus current estimate
\alphastep size (learning rate)
\gammadiscount factor (here 1 in the lab: episodic and undiscounted)

  2. Switch to "constant". One weight cannot tell the states apart, so every bar takes the same height. Notice that the RMSE stops improving at a non-zero value.
  3. Switch to "pairs". Each pair of states shares one value, so the bars form a staircase that misses the slope.
  4. Switch to "tabular". One weight per state reaches the true values exactly. Compare how many weights each choice uses with the error it leaves.
Common traps
  • The feature vector limits what can be learned. No step size fixes a feature set that cannot represent the true values. Check the representation before tuning α.
  • Semi-gradient is not the gradient of anything in general. The update does not descend the gradient of the squared Bellman error, so the usual gradient-descent guarantees do not carry over automatically.
  • The bias term is a feature too. Forgetting the constant 1 in the feature vector silently forces the line through the origin.
Where it shows up in AI
  • Early reinforcement learning on large control problems used linear value functions over hand-chosen features, for example for pole-balancing and tile-coded robot control.
  • Every deep value network is a nonlinear generalisation of this model: the last layer is often linear in learned features, and the TD update still uses the same semi-gradient form.
  • Linear value models remain a useful baseline when a deep model is hard to debug.
Pipeline placement. Estimate stage: the TD update runs once per transition, costing one feature evaluation and one vector update, so O(d) work per step. Stores: a weight vector of length d and the feature function. Evaluate by the RMSE on a set of states with known or well-estimated values.

Check yourself

1. In the worked example, the first update gave w = (0.1, 0.2). What is v̂ at state B after that, and what would it be with α = 0.2 instead?
v̂(B) = 0.1 + 2(0.2) = 0.5 with α = 0.1. With α = 0.2 the update is w = (0.2, 0.4), so v̂(B) = 0.2 + 0.8 = 1.0. The TD error was 1, so the estimate moves exactly to the target when α = 1 and overshoots for larger α.
2. Why is the update called "semi"-gradient?
Because the target R + γv̂(S′,w) also depends on w, but the update treats it as a constant. A full gradient would differentiate through the target too, which the TD method does not do.
3. A linear model with features (1, s) cannot represent a curved value function exactly. Does better tuning of α fix this?
No. The limit is in the feature set, not the step size. A smaller α averages out noise but still converges to the best line-like fit. A richer feature set is needed, which is the subject of the next lesson.

Takeaways

  • A linear value function is a weighted sum of features, and one experience moves the values of every state that shares features.
  • The semi-gradient TD update is the TD error times the feature vector.
  • The feature design caps what can be learned; the step size cannot remove that cap.
5.2

Feature construction and tile coding

The questionA line cannot bend, and a single polynomial behaves badly at the edges of its data. How do we build features that can represent a curved value function, while still changing the value of nearby states together and not the value of distant ones?

Intuition

Coarse coding is the idea that a state is described by which broad regions it lies in. Think of a map of a country drawn with many overlapping circles. A city inside three circles is described by "in circle 2, in circle 5, in circle 9". Nearby cities share most circles, so their descriptions overlap, and a learned value for one city moves its neighbours too. Its resolution comes from the overlaps, not from the size of any single circle.

Tile coding makes this concrete. Lay several grids of square tiles over the state space, each one shifted by a fraction of a tile width. Each grid is a tiling. A state activates exactly one tile in each tiling. The feature vector is then a binary vector with one 1 per tiling. Few features are on at once, so each update is cheap, and the many offsets give a fine resolution that a single grid could not.

Build it up

Step 1: one tiling, one feature per tile. Divide [0,1) into tiles of width 0.5. A state s activates the tile whose interval contains it. The value is the weight of that tile. This is a staircase, and it is just a table with coarser cells.

Step 2: add a second tiling, shifted. Shift the grid by 0.25. Now each state has two active tiles, one from each grid, and the value is the sum of their two weights. The staircases do not line up, so the sum is no longer a staircase with a single step size.

Worked example: two tilings at s = 0.3

Tiling 0 has offset 0 and tiles of width 0.5, so the tile index is \lfloor (0.3+0)/0.5\rfloor = \lfloor 0.6\rfloor = 0, the interval [0, 0.5). Tiling 1 has offset 0.25, so the index is \lfloor (0.3+0.25)/0.5\rfloor = \lfloor 1.1\rfloor = 1, the interval [0.25, 0.75). Let the weights be tiling 0: (0.2, 0.5, −0.1) and tiling 1: (0.0, 0.4, 0.3).

The active weights are 0.2 (tiling 0, tile 0) and 0.4 (tiling 1, tile 1), so \hat v(0.3) = 0.6. Now let the target be 1.0 and the step size α = 0.2, shared across the two tilings. The TD error is \delta = 1.0 - 0.6 = 0.4, and each active weight moves by \tfrac{\alpha}{2}\delta = 0.04. The new value is \hat v(0.3) = 0.6 + 2(0.04) = 0.68 = 0.6 + \alpha\delta.

Step 3: radial basis features. A different family uses smooth bumps instead of tiles: \phi_c(s)=\exp\!\big(-(s-c)^2/(2\sigma^2)\big) around centres c. For centres 0, 0.5 and 1 and width σ = 0.25, a state s = 0.3 gives the feature vector (0.487,\ 0.726,\ 0.020). The bumps overlap and vary smoothly, so the approximation is smooth, but each update touches every feature a little.

The formal definition

\hat v(s,\mathbf w)=\sum_{j=1}^{m} w_{j,\,k_j(s)},\qquad k_j(s)=\Big\lfloor \frac{s+o_j}{\,1/n\,}\Big\rfloor,\qquad o_j=\frac{j}{m}\cdot\frac{1}{n}

Here there are m tilings, each with tiles of width 1/n, and the tiling j is shifted by its offset o_j. The update is the semi-gradient rule from lesson 5.1, with the active tile of each tiling as the feature. Dividing the step by m keeps the total change per update equal to α.

mnumber of tilings; each state activates m features
nnumber of tiles per tiling along the state range (width 1/n)
o_joffset of tiling j, a fraction j/m of a tile width
k_j(s)index of the tile that state s activates in tiling j
\phi_c(s)radial basis feature: a Gaussian bump centred at c with width σ

  2. Set m = 6 and n = 4. The sum of six shifted staircases is much smoother. Watch the highlighted tiles: one per tiling at the probe.

Common traps
  • Tile resolution and generalisation trade off. Large tiles generalise widely but cannot represent detail; small tiles represent detail but learn slowly and generalise little.
  • The number of features grows fast. With m tilings of n + 1 tiles each in one dimension, you have m(n+1) weights. In many dimensions the count explodes, which is why tile coding is used in low dimensions.
  • Offsets must be spread out. Tilings with the same offset are copies of one grid and add no resolution.
Where it shows up in AI
  • Tile coding was the standard feature method in classic control benchmarks such as mountain car and robot arm control, from the 1990s onward.
  • Radial basis networks are the same idea with learned centres and widths.
  • Deep networks replace hand-designed features with learned ones, but the representational question remains the same: which features make the value simple to represent?
Pipeline placement. Estimate stage: each sample activates m tiles and updates m weights. Stores: the weight table of size m(n+1) per dimension, which is the design budget. Evaluate by the error on a grid of states, as the lab does.

Check yourself

1. In the worked example, what is v̂(0.3) if the tiling-1 weight for tile 1 is 0.4 but the tiling-0 weight for tile 0 is changed to 0.5?
The active weights are now 0.5 and 0.4, so v̂(0.3) = 0.9.
2. Why does a second tiling shifted by a quarter of a tile help more than a second tiling with the same grid?
A copy of the same grid activates the same tile and adds no new boundaries. A shifted grid puts its boundaries in different places, so the sum of the two can change direction at more points and represent finer detail.
3. Why does each tiling use a weight of α/m rather than α?
Each state activates m tiles, so without the division the total change in v̂ would be mα·δ. Dividing by m makes the total change per update equal to α·δ, so the step size keeps its meaning when m changes.

Takeaways

  • Coarse coding and tile coding describe a state by the regions it lies in; overlaps give the generalisation.
  • Several shifted tilings add resolution with few active features per state.
  • Feature design sets both what can be represented and how fast learning is.
5.3

The deadly triad

The questionEach ingredient in this module is sensible on its own: a linear model, bootstrapped targets, and learning from a state distribution that differs from the one the target policy would produce. Put the three together and the values can grow without bound. Which combination is dangerous, and why?

Intuition

Sutton and Barto call the combination the deadly triad. Its three parts are: function approximation, where one parameter changes the values of many states; bootstrapping, where the target is built from the learner's own estimate; and off-policy learning, where the data come from a distribution that differs from the one the target policy would produce.

The danger is a feedback loop. Raising the value of one state through shared weights also raises the target for the states that lead to it. If those states are updated more heavily than the rest, the errors can feed back and grow, and nothing in the update pulls them back. Tabular learning cannot do this, because each state has its own entry and an update to one entry cannot change another.

Build it up

Step 1: a two-state system. Let state s1 lead to s2 and s2 lead to itself, with reward 0 everywhere. The true value is 0 in both states. A shared feature gives \phi(s_1)=1,\ \phi(s_2)=2, so the value estimate is \hat v(s_1)=w and \hat v(s_2)=2w. The target for s1 is therefore \gamma\cdot 2w, and the estimate for s1 is w.

Step 2: the expected update. Assume the learner updates state s1 with weight d(s1) and s2 with weight d(s2) = 1 − d(s1), with importance weights 1. The expected semi-gradient update is

w \leftarrow w + \alpha\Big[d_1(2\gamma-1)\cdot 1 + d_2(4\gamma-4)\Big]w

The term (2\gamma-1) comes from state s1: its target is 2\gamma w and its estimate is w, multiplied by its feature 1. The term (4\gamma-4) comes from state s2, whose target is 2\gamma w and estimate 2w, multiplied by its feature 2.

Worked example: γ = 0.9, α = 0.5, d(s1) = 0.5

The bracket is 0.5(0.8) + 0.5(-0.4) = 0.2, so each iteration multiplies w by 1 + 0.5(0.2) = 1.1. Starting from w = 1, the values are 1, 1.100, 1.210, 1.331, 1.464, and so on. The weight grows by 10% per iteration, which is divergence, even though the true value is 0 and the reward is 0 throughout.

Now the same system with a separate weight per state (tabular, θ₁ and θ₂, starting from (1, 2)). The update is θ₁ ← θ₁ + α·d₁(γθ₂ − θ₁) and θ₂ ← θ₂ + α·d₂(γθ₂ − θ₂). After one iteration θ = (1.2, 1.95), and θ shrinks towards 0 from then on. Tabular learning is stable here, and the only difference is the shared weight.

Step 3: where the threshold is. Setting the bracket to zero gives d_1(2\gamma-1)+(1-d_1)(4\gamma-4)=0, so the shared weight grows when d(s_1) > (4-4\gamma)/(3-2\gamma). For γ = 0.9 the threshold is 1/3. With the same α, the state distribution alone decides whether this toy diverges.

The formal definition

\text{expected update:}\quad \mathbf w \leftarrow \mathbf w+\alpha\sum_s d(s)\,\rho(s)\big[R+\gamma\,\hat v(s',\mathbf w)-\hat v(s,\mathbf w)\big]\mathbf x(s)

The sum runs over states weighted by the distribution d the updates are drawn from. The importance weight \rho(s)=\pi(a\mid s)/b(a\mid s) corrects for an off-policy mismatch when ρ is used; it equals 1 in this toy. The lab uses the expected form to show the dynamics cleanly. Sampled updates can behave differently for the same parameters.

d(s)the distribution of states the updates are drawn from
\rho(s)importance weight correcting from the behaviour to the target policy (1 in the toy)
\gamma, \alphadiscount and step size, as before
\phi(s)feature of state s: here φ(s₁)=1 and φ(s₂)=2

  2. Set d(s1) to 0. Only state s2 is updated. The shared weight now shrinks, because the bracket is 4γ − 4 < 0.

Common traps
  • Divergence is not noise. The weight grows steadily and predictably. A stable average with a noisy estimate is a different problem.
  • The triad is sufficient for trouble, not a guarantee. Many function-approximation systems with all three ingredients train successfully. The triad says where divergence can happen, not where it must.
  • Removing one ingredient is a standard remedy. Monte Carlo targets remove bootstrapping, tabular features remove approximation, and on-policy data remove the mismatch. Each has a cost in variance or sample efficiency.
Where it shows up in AI
  • Baird's counterexample (Baird, 1995) is a classic seven-state system where linear off-policy TD diverges. Its tiny size is the reason it is used to explain the phenomenon.
  • Deep Q-learning uses all three ingredients, which is why it needs replay buffers, target networks and careful step sizes.
  • Offline reinforcement learning from fixed datasets (Module 8) is hard for the same reason: the data are off-policy and the model is bootstrapped.
Pipeline placement. Estimate stage: the divergence arises in the update rule, so it is checked during training, through the values and the TD error, not at deployment. Stores: the weights and the training distribution. Monitor the magnitude of the weights and of the TD error as a basic health check.

Check yourself

1. Using the worked example, what growth factor does the shared weight have when d(s1) = 0.2 and γ = 0.9, α = 0.5?
Bracket = 0.2(0.8) + 0.8(−0.4) = 0.16 − 0.32 = −0.16. Factor = 1 + 0.5(−0.16) = 0.92. The weight shrinks.
2. Why does the tabular version of the same two-state system not diverge?
Each state has its own weight. The update of θ₁ changes only θ₁ and the update of θ₂ changes only θ₂, through the d-weighted terms. The shared feature is what lets an update to one state change the value of the other.
3. At γ = 0.9, which state distribution lies exactly at the threshold, and what does that tell you about the stability of the shared weight?
d(s1) = 1/3, since (4 − 3.6)/(3 − 1.8) = 0.4/1.2 = 1/3. At this distribution the bracket is zero and the shared weight is neither growing nor shrinking to first order. It shows that stability depends on the distribution, not only on the step size.

Takeaways

  • Function approximation, bootstrapping and off-policy data together can make a semi-gradient method diverge.
  • In the two-state toy, divergence depends on the state distribution and on γ, not just on α.
  • Tabular learning is stable here; the shared feature is the source of the problem.
5.4

Experience replay

The questionAn agent learns from each step as it happens. Consecutive steps are strongly correlated: the next state is almost the same as the last one, and the same action is often repeated. A gradient update built only from the latest step pulls the weights towards whatever just happened. How can we learn from a stream of correlated experience without forgetting what came before?

Intuition

A student who revises only the last page of a textbook will remember that page and forget the rest. A student who keeps all their notes and revises a random selection each day covers the whole course. Experience replay is the second student. The agent stores each transition (s, a, r, s') in a buffer, and each learning step draws a random mini-batch from that buffer rather than using only the latest transition.

Two things improve. The data become closer to independent and identically distributed, which the gradient-based learners in this module assume. And each transition can be reused many times, so experience is used more efficiently. The cost is memory, and the reused data are slightly older than the current policy, which is one more reason the off-policy caveats of lesson 5.3 matter.

Build it up

Step 1: a buffer of transitions. Store every transition. When the buffer reaches its capacity N, the oldest transition is overwritten. This is a first-in, first-out buffer.

Step 2: sample a mini-batch. At each learning step, draw B transitions uniformly at random from the buffer and apply the update to each one. The batch is random, so neighbouring steps in time rarely end up in the same batch.

Worked example: a buffer of capacity 4

Transitions t1, t2, …, t6 arrive in order. The buffer has four slots, and transition tk goes into slot (k − 1) mod 4. After t1–t4, the slots hold t1, t2, t3, t4. Transition t5 overwrites slot 0 and t6 overwrites slot 1, so the buffer holds [t_5, t_6, t_3, t_4].

Measure the age of each stored transition as the number of steps since it was created: t6 has age 0, t5 has age 1, t4 has age 2 and t3 has age 3. The ages in slot order are (1, 0, 3, 2), with mean 1.5. A uniform draw of two transitions from this buffer might return t3 and t5, which are two steps apart in time, instead of the two newest transitions t5 and t6, which are consecutive.

The formal definition

\mathcal D_t = \{(s_k,a_k,r_{k+1},s_{k+1})\}_{k=t-N+1}^{t},\qquad \mathcal B \sim \operatorname{Uniform}(\mathcal D_t)\ \text{with}\ |\mathcal B| = B

The learning step then averages the per-transition loss over the batch \mathcal B, using a target that is computed for each sample. The buffer and the sampling rule are the entire mechanism.

\mathcal D_tthe buffer at time t: the N most recent transitions
Nbuffer capacity; older transitions are overwritten
\mathcal Bmini-batch sampled uniformly from the buffer
Bbatch size: the number of transitions per learning step

  2. Switch to "uniform replay" with capacity 40 and batch 4. The histogram spreads across the buffer, and the mean age settles near the value printed in the readout.
  3. Increase the capacity to 200. Samples come from a longer history, so the mean age grows, while the data stay representative of the walk.
  4. Reduce the capacity to 5. The buffer forgets quickly, and the samples become almost as recent as with no replay.
Common traps
  • Replay assumes that old transitions are still informative. If the environment or the policy changed a lot, old transitions describe a world that no longer exists. A small buffer is the usual remedy.
  • Uniform sampling is not prioritised sampling. Some transitions teach more than others. Prioritised replay samples them more often, but it biases the update, and corrections are needed.
  • Batch size and buffer size are both hyperparameters. A large buffer with a tiny batch can still learn slowly, because each update uses few samples.
Where it shows up in AI
  • Experience replay was introduced in Lin's work on reinforcement learning for robots (1992) and became central to the deep Q-network of Mnih and colleagues (2015), which used a buffer of about one million transitions.
  • Off-policy actor–critic methods such as SAC and TD3 keep a replay buffer for the same reason.
  • Language-model fine-tuning on logged generations uses a similar idea: the training batch is drawn from stored data, not from the latest sample only.
Pipeline placement. Store stage: the buffer holds N transitions, each a tuple of state, action, reward and next state. Interact stage: transitions are written at every step. Estimate stage: each learning step reads B samples. Cost: O(B) per update plus the memory of the buffer.

Check yourself

1. Using the worked example, what are the ages in the buffer after t7 arrives?
t7 overwrites slot 2, which held t3, so the buffer is [t5, t6, t7, t4]. Ages: t5 = 2, t6 = 1, t7 = 0, t4 = 3, giving the slot-order ages (2, 1, 0, 3).
2. Why does replay not make the sampled transitions fully independent?
The transitions are drawn from one trajectory, so they share history, and an old transition was generated by an older policy. Replay reduces the correlation between consecutive updates, but it does not make the data i.i.d.
3. A batch of size 1 with no replay learns from the last transition only. What is the mean age of its samples?
Zero: the batch is the newest transition, so its age is 0 at every step.

Takeaways

  • Replay stores transitions and learns from random mini-batches, which breaks the correlation between consecutive updates.
  • The buffer capacity sets how old the data may be; the batch size sets how much each update uses.
  • Replay makes off-policy learning possible in deep Q-learning, and it inherits the off-policy caveats.
5.5

Target networks and DQN

The questionIn Q-learning the target r+\gamma\max_{a'}Q(s',a') is computed with the same network we are training. Every update therefore moves the target, and the regression is chasing its own tail. With a deep network the effect is strong enough to make learning unstable. How can we make the regression target stay still long enough to learn?

Intuition

Think of a student trying to hit a target that moves every time they throw. The shot is always aimed at the target's current position, so the student never settles. The fix is to freeze the target for a while: the student throws many times at one fixed position, then the target is moved once and the process repeats.

A target network is a second copy of the Q-network, with parameters \theta^-. The targets are computed with \theta^-, and the training network with parameters \theta is updated towards them. Every K updates, the frozen copy is replaced by the current parameters. Between replacements the regression problem is fixed.

Build it up

Step 1: the DQN target. For a transition (s,a,r,s'), the target is y = r + \gamma\max_{a'}Q(s',a';\theta^-). The max is taken over the actions of the frozen network.

Step 2: the loss. The loss is the squared difference between the online prediction and the target: L(\theta)=\tfrac12\big(Q(s,a;\theta)-y\big)^2. Only the online network is differentiated; the target is treated as a constant, as in the semi-gradient update.

Worked example: one DQN update

Take r = 1, \gamma = 0.9, and frozen next-state values Q^-(s',\cdot) = (2.0,\ 3.5,\ 1.2). The max is 3.5, so y = 1 + 0.9 \times 3.5 = 4.15. The online network predicts Q(s,a)=3.0, so the TD error is y - Q = 1.15, and the loss is \tfrac12(1.15)^2 = 0.661.

A gradient step with learning rate α = 0.1 on the output moves the prediction by \alpha(y-Q)=0.1 \times 1.15 = 0.115, so the new prediction is 3.115. The target stayed at 4.15 for this step and for every step until the next copy.

Step 3: the training loop. Each learning step samples a batch from the replay buffer (lesson 5.4), computes the targets with the frozen network, takes a gradient step on the online network, and every K steps copies the online parameters to the frozen network. An exploration rule such as ε-greedy chooses the actions that fill the buffer.

Atari-style inputs. The 2015 DQN paper used the screen of an Atari game, converted to 84 × 84 greyscale, with the last four frames stacked so the network can see motion. A convolutional network maps this stack to one Q value per action. In that work the frozen copy was replaced only about every ten thousand parameter updates, which is what keeps the targets still.

The formal definition

\theta, \theta^-online parameters (trained) and frozen target parameters (copied every K updates)

  2. Set K = 10. The orange frozen copy now rises in steps, and the blue weight moves towards it, then the copy jumps. Read the readout at update 10 and 20.

Common traps
  • A target network is not a guarantee. It makes the regression target stable for a while. It does not remove the divergence risk of the deadly triad.
  • Syncing too rarely slows learning. The frozen target can be far from the current estimate, and the update then uses stale information.
  • Forgetting the max is over the frozen network. Using the online network for the max reintroduces the moving target that the copy was meant to remove.
Where it shows up in AI
  • Deep Q-networks (Mnih and colleagues, 2015) used a replay buffer and a target network to learn Atari games from pixels, with one agent and fixed hyperparameters across games.
  • Most deep off-policy methods, including DDPG, TD3 and SAC, use slowly moving target networks, implemented as a Polyak average rather than a hard copy.
  • The same freezing idea underlies fitted value iteration in offline and batch settings.
Pipeline placement. Estimate stage: the target network is evaluated once per sample, and the copy is performed every K updates. Stores: two copies of the network weights, so memory doubles for the value model. Cost per update: one forward pass through the target and one through the online network per sample, plus the backward pass on the online network.

Check yourself

1. In the worked example, what would the TD error be if the online prediction were 4.0 instead of 3.0?
y − Q = 4.15 − 4.0 = 0.15.
2. Why is the max in the target taken over the frozen network and not the online network?
The frozen network is the target, so it should not move during the period between copies. Using the online network for the max would make the target depend on the parameters being trained, the moving-target problem the copy is meant to solve.
3. In the scalar lab with K = 1, why does the trace move smoothly, while with K = 10 it moves in steps?
With K = 1 the frozen copy equals the weight after the previous update, so the target changes at every step. With K = 10 the target is constant for ten updates, so the weight moves towards one fixed number, and only then does the target change.

Takeaways

  • DQN regresses Q towards a target computed with a frozen copy of the network.
  • The sync period K trades stability of the target against lag.
  • A target network stabilises the regression; it does not guarantee convergence.
5.6

Overestimation and Double DQN

The questionSuppose every action in a state is equally good, with true value 1.0. Our estimates are noisy, so one action looks better than the others by chance. If the target always takes the largest estimate, does the learned value drift upwards, and how can we stop it?

Intuition

Imagine three friends each guessing the weight of the same parcel, with honest but noisy guesses. If you ask each guess and then report the highest, you are reporting the most optimistic error, not the average. The maximum of noisy numbers is biased upwards, even when every number is unbiased. Q-learning's target \max_{a'}Q(s',a') is exactly such a maximum, taken over noisy estimates, so it systematically overestimates.

The fix separates the two jobs the max does. One network selects the action with the largest value, and a different network evaluates that action. If the selection error and the evaluation error are independent, the optimistic bias of picking the largest value is not copied into the value you read.

Build it up

Step 1: the max is biased. For K actions with independent standard normal noise and true values 0, the expected maximum is E[\max] = 0.564 for K = 2, 0.846 for K = 3 and 1.029 for K = 4. The bias grows with the number of actions and with the noise.

Step 2: the DQN target uses one noisy table for both jobs. The DQN target y=r+\gamma\max_{a'}Q(s',a';\theta^-) selects and evaluates with the same frozen network, so the selection bias is carried into the target.

Step 3: Double DQN separates them. Select with the online network, evaluate with the frozen one: y=r+\gamma\,Q(s',\arg\max_{a'}Q(s',a';\theta);\,\theta^-).

Worked example: three actions, true value 1.0

Let r=0 and \gamma=0.9, so the true target is 0.9 \times 1.0 = 0.90. Online values in s′: (1.3,\ 0.8,\ 1.1). Frozen target values: (1.1,\ 1.4,\ 0.7).

DQN: the max of the frozen values is 1.4 (action 2), so y = 0.9 \times 1.4 = 1.26. That is 0.36 above the truth, and the frozen network's noise is being taken at its largest.

Double DQN: the online network selects the largest value, action 1 (1.3). The frozen network evaluates action 1 at 1.1, so y = 0.9 \times 1.1 = 0.99, which is 0.09 above the truth. The selection error no longer picks the target value.

The formal definition

\text{DQN:}\ \ y=r+\gamma\max_{a'}Q(s',a';\theta^-)\qquad\text{Double DQN:}\ \ y=r+\gamma\,Q\big(s',\arg\max_{a'}Q(s',a';\theta);\,\theta^-\big)

The two estimators differ only in which network chooses the action. Double Q-learning (van Hasselt, 2010) applies the same split to two tabular tables; Double DQN (van Hasselt, Guez and Silver, 2016) uses the online and target networks that DQN already has, so it costs almost nothing extra.

\arg\max_{a'}the action with the largest value in the online network: the selection step
Q(\cdot;\theta^-)the frozen network, used only to read the value of the selected action: the evaluation step
\gammadiscount factor (0.9 in the worked example)
rimmediate reward (0 in the example)

Common traps
  • Double DQN does not remove all bias. It removes the selection bias when the two networks have independent errors. It can still underestimate in some cases.
  • Overestimation is not always harmful. A large overestimate can drive exploration, but it can also let a bad action look good for a long time. Measure the true return, not the estimate alone.
  • The online and target networks must differ. If they are identical, as with a target network that has just been copied, the two estimators coincide and the correction is lost.
Where it shows up in AI
  • Double DQN is a standard component of value-based agents, and it is one of the six extensions combined in the Rainbow agent (Hessel and colleagues, 2018).
  • The same overestimation appears in actor–critic methods, where TD3 uses two critics and takes the minimum, a related idea.
  • Max over noisy scores is everywhere in AI, from beam search to hyperparameter selection, and the same selection bias needs checking there.
Pipeline placement. Estimate stage: the target uses two forward passes through the same networks that DQN already needs, so the cost per update is almost unchanged. Stores: the online and frozen networks, as before. Evaluate by the true return of the greedy policy, not only by the estimated values.

Check yourself

1. In the worked example, what is the DQN target if the frozen values were (1.1, 1.0, 0.7) instead?
The max is 1.1, so y = 0.9 × 1.1 = 0.99. It equals the Double DQN value in the example, because the largest frozen value now happens to be the action the online network selects.
2. Why does the double estimator average to zero in the lab when the true values are equal?
The action is selected with one independent set of noisy estimates and its value is read from another. The selected action's frozen-network value has expectation equal to its true value, which is 0 for every action.
3. With K actions and σ = 1, the expected DQN-style bias is about 0.846 at K = 3. What is it at K = 4, and why does it grow with K?
About 1.029. The maximum of more independent noisy values is more likely to be an unusually large one, so its expectation grows with the number of values.

Takeaways

  • A maximum over noisy estimates is biased upwards, and the bias grows with the number of actions and the noise.
  • Double DQN selects the action with the online network and evaluates it with the frozen network.
  • The correction costs almost nothing extra and removes most of the selection bias.
