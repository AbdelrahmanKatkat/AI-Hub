Numbers, sets & ℝⁿ

The questionA house has 3 bedrooms, 120 m² of floor area, is 8 years old and sits 2 km from the city centre. A computer can only work with numbers. How do we hand it this house so that it can estimate a price — and what does it even mean to say two houses are "similar"?

Intuition

Numbers are tools, and different jobs need different tools.

  • Counting things (3 bedrooms): the natural numbers \mathbb N=\{0,1,2,3,\dots\}.
  • Gaining and losing (a bank balance of −40, a temperature of −5 °C): the integers \mathbb Z=\{\dots,-2,-1,0,1,2,\dots\}.
  • Sharing (half a pizza, ¾ of a tank): the rational numbers \mathbb Q — anything you can write as a fraction p/q.
  • Measuring (120.5 m², 1.7320508… km): the real numbers \mathbb R — every point on an unbroken number line, including numbers like \sqrt2 and \pi that no fraction can capture.

Each set contains the one before it: every natural number is an integer, every integer is a fraction (5=5/1), every fraction is real. Almost everything in AI lives in \mathbb R.

A set is simply a bag of distinct things where we only care what is in it, not the order. We write it with braces: \{2,4,6\}. The symbol \in reads "is an element of": 4\in\{2,4,6\} is true, 5\in\{2,4,6\} is false. If every element of A is also in B we write A\subset B ("A is a subset of B"). Sets of real numbers between two ends are intervals: [0,1] includes both ends, (0,1) excludes them, and [0,\infty) means "zero and everything above".

Build it up: from one number to many

One measurement is one real number. But a house has several measurements, and their order matters (bedrooms first, age third — swapping them changes the meaning). An ordered list of numbers is a tuple. Our house becomes:

\text{house}=(3,\;120,\;8,\;2)

A list of 2 numbers is a point on a flat map (x across, y up). A list of 3 numbers is a point in space. A list of 4 numbers is a point in a space we cannot draw — but everything we know about points (distance, direction, "between", "close to") still works. We call the space of all lists of n real numbers \mathbb R^n.

Worked example

House A = (3, 120, 8, 2), house B = (3, 118, 9, 2.5). Both live in \mathbb R^4. They are close in this space because every coordinate is nearly the same. House C = (6, 300, 1, 15) is far from both. "Similar houses" has become "nearby points" — a statement a computer can test with arithmetic. (We make "nearby" precise in lesson 0.7.)

The formal definition

\mathbb R^n=\{(x_1,x_2,\dots,x_n)\;:\;x_i\in\mathbb R\text{ for every }i=1,\dots,n\}
ℝⁿthe set of all ordered lists of n real numbers
(x₁, …, xₙ)one such list; the small number below is a position (an index), so x_2 means "the second entry"
:reads "such that"
∈"is an element of"

A whole dataset with N examples is then a collection of N such points — which we will arrange as a table (a matrix) in Module 1.

Lab

Try this
  1. Move only the first slider: your point travels along a line (ℝ¹).
  2. Move the second as well: the point moves around a plane (ℝ²).
  3. Move all three: the same three numbers describe a colour. A single pixel of a photo is a point in ℝ³.
Common traps
  • Computers do not store all of ℝ. They store finite approximations (floating-point). In most languages 0.1 + 0.2 gives 0.30000000000000004. Usually harmless, but it is why we later care about numerical stability.
  • Categories are not numbers. Encoding colour as red=1, green=2, blue=3 tells the model that blue is "three times red" and that green sits "between" them. Categories need special encodings (one-hot vectors).
Where it shows up in AI
  • A tabular row, like our house, is a point in \mathbb R^n; the features are its coordinates.
  • A 28×28 greyscale image is a point in \mathbb R^{784}; a 224×224 colour image lives in \mathbb R^{150528}.
  • A word becomes an integer token id in \mathbb N, then an embedding — a point in \mathbb R^{d} with d typically 768 to 12288.
  • A model's parameters are also just a (very long) list of reals: a point in \mathbb R^{P}. Training moves that point around.

Check yourself

1. Is −3 a natural number? An integer? A real number?
Not a natural number (those start at 0), but it is an integer and a real number.
2. A weather report uses (temperature, humidity, wind speed, pressure). Which ℝⁿ does a report live in, and what does the order of the list mean?
ℝ⁴. The order is a fixed convention: slot 1 always means temperature, slot 2 humidity, and so on. Swapping entries would describe a different weather.
3. Why is "colour = 1, 2, 3" a bad encoding for red, green and blue as three categories?
The numbers imply an order and distances (blue is 3× red, green lies between them) that do not exist in the data. One-hot vectors (1,0,0), (0,1,0), (0,0,1) are equally far apart and avoid this.

Takeaways

  • ℕ ⊂ ℤ ⊂ ℚ ⊂ ℝ; AI works almost entirely in ℝ.
  • An ordered list of n reals is a point in ℝⁿ — data, images, embeddings and parameters are all points.
  • "Similar" will become "close", which is something we can compute.

Functions

The questionWe want a rule that takes a house's size and returns a predicted price. What exactly is a "rule" in mathematics, how do we combine several rules, and how do we say "a rule with adjustable knobs"?

Intuition

A function is a machine with one slot for input and one for output. Drop in a number, a number comes out. The single most important property: the same input always gives the same output. A vending machine is a function (press B4, always the same snack); a dice roll is not.

We name the machine f, the input x, and write f(x) for "what comes out when x goes in". The set of allowed inputs is the domain; the set of outputs that actually occur is the range. For f(x)=\sqrt x, the domain is [0,\infty) because we cannot take the square root of a negative number (yet).

A graph is a picture of the machine's behaviour: for every input x on the horizontal axis we plot a dot at height f(x). Watch the machine below, then see how its graph is built.

Try this
  1. Let it run with 2*x+1. Check one pair by hand: input 3 → 2·3+1 = 7.
  2. Change the rule to x^2. Feed −2 and then 2. Different inputs, same output — allowed! A function may send many inputs to one output; what it may not do is send one input to two outputs.
  3. Try 1/x and feed 0. The machine jams: 0 is not in its domain.

Build it up

Composition — chaining machines. Put the output of one machine into the input of another. If g acts first and f second, we write (f\circ g)(x)=f(g(x)), read "f after g". Order matters, and the notation reads from the inside out.

Worked example

Let f(x)=3x-2 and g(x)=x^2.

f(g(2)): first g(2)=4, then f(4)=3\cdot4-2=10.

g(f(2)): first f(2)=4, then g(4)=16.

10 ≠ 16: composition is not commutative.

Inverse — the undo machine. If f turns 2 into 7, the inverse f^{-1} turns 7 back into 2. To find it, write y=f(x) and solve for x. For f(x)=3x-2: y=3x-2\Rightarrow x=\frac{y+2}{3}, so f^{-1}(y)=\frac{y+2}{3}. An inverse exists only when different inputs always give different outputs (so x^2 has no inverse on all of ℝ: both −2 and 2 map to 4, so we could not know which to return).

Variables versus parameters. Consider f(x)=ax+b. We think of x as the input that changes from example to example, while a and b are knobs that fix which line we have. To emphasise this we write f(x;a,b) or f(x;\theta) with \theta=(a,b): the semicolon separates the input from the parameters. Machine learning is the art of turning the knobs \theta until the machine fits the data.

The formal definition

f:A\to B,\qquad x\mapsto f(x)\qquad\text{such that each }x\in A\text{ has exactly one }f(x)\in B
f : A → B"f is a function from the set A (domain) to the set B (where outputs live)"
x ↦ f(x)"x is sent to f(x)" — the rule itself
f ∘ gcomposition, "f after g"
f⁻¹inverse function (not 1/f)

Lab: knobs, and chaining machines

Try this
  1. In the first plot, drag a and b. You are not changing the formula, only the knobs — yet you sweep through every possible line. A family of functions is a model.
  2. In the second plot, the green curve is g(f(x)). Move the sliders and compare it with the orange g alone: composition bends and moves the shape.
Common traps
  • f(x) is not "f times x". It means "apply f to x".
  • f^{-1}(x) is the inverse function, not 1/f(x).
  • f(a+b) is generally not f(a)+f(b) — only special "linear" functions behave that way (Module 1).
Where it shows up in AI
  • A model is a function \hat y=f(x;\theta): input features in, prediction out, parameters as knobs.
  • A deep network is a composition f=f_L\circ\dots\circ f_2\circ f_1 — each layer is one machine feeding the next. Understanding composition is understanding depth.
  • A perspective flip. The loss L(\theta) is a function whose input is the parameters and whose output is "how wrong the model is". Training = finding the input of L that gives the smallest output.

Check yourself

1. If f(x)=x+1 and g(x)=2x, compute f(g(3)) and g(f(3)).
g(3)=6, f(6)=7. f(3)=4, g(4)=8. So 7 and 8.
2. Find the inverse of f(x)=5x−10.
y=5x−10 ⇒ x=(y+10)/5, so f⁻¹(y)=(y+10)/5 = y/5+2.
3. Why is "pick a random number" not a function?
A function must give the same output every time for the same input. A random pick can give different outputs for the same input (nothing).

Takeaways

  • A function maps each input to exactly one output; its graph shows all pairs.
  • Composition chains functions; order matters. Deep nets are long compositions.
  • f(x; θ) separates the data x from the knobs θ — learning adjusts θ.

Algebra & equations

The questionA taxi charges $3 to start and $2 per kilometre. You have $17. How far can you travel? More generally: given a rule and a result, how do we work backwards to find the missing input?

Intuition

An equation is a balanced scale. The left pan and the right pan hold the same weight. You may do anything you like — add 5, double, halve — as long as you do the same thing to both pans; the scale stays balanced. Solving an equation means using this rule to peel away everything around the unknown until it stands alone.

Worked example — the taxi

Cost = 3 + 2x where x is kilometres. We want cost = 17: 3+2x=17.

Subtract 3 from both sides: 2x=14. Divide both sides by 2: x=7.

Check: 3 + 2·7 = 17 ✓. Always substitute back — it catches mistakes.

Rearranging formulas is the same skill with letters. From y=ax+b, "solve for x": subtract b, divide by a: x=\frac{y-b}{a} (valid when a\ne0). This is exactly the inverse function from lesson 0.2.

Build it up

Inequalities work the same way with one dangerous exception: multiplying or dividing by a negative number flips the sign. From -2x>6 divide by −2 to get x<-3. (Sanity check: x = −4 gives −2·(−4) = 8 > 6 ✓.)

Quadratics. Equations with an x^2 term, ax^2+bx+c=0, can have 0, 1 or 2 solutions — where the U-shaped curve crosses the horizontal axis. The formula:

x=\frac{-b\pm\sqrt{b^2-4ac}}{2a}

The number under the root, \Delta=b^2-4ac (the discriminant), predicts the count: positive → two crossings, zero → touches once, negative → none (no real solution). The lowest (or highest) point of the parabola, its vertex, sits at x=-\frac{b}{2a}. Remember this — it is the first time we meet minimising a function, which is what training does.

Worked example

x^2-5x+6=0: a=1, b=−5, c=6. Δ = 25 − 24 = 1. So x=\frac{5\pm1}{2} → x = 3 or x = 2. Check x=2: 4 − 10 + 6 = 0 ✓.

Systems of equations ask for values that satisfy several equations at once. Two lines in the plane usually cross at exactly one point. Solve x+y=5,\; x-y=1: add the equations → 2x=6, so x = 3; then y = 2. Geometrically: the point where two lines meet.

Lab

Try this
  1. Linear: the blue line is ax+b, the orange line is a flat target c. The white dot is the solution of ax+b=c. Change c and watch it slide.
  2. Quadratic: change the knobs until the parabola just touches the axis (one solution), then lift it so it misses (none). That is the discriminant in action.
  3. System: make the two lines parallel (same slope). The solution vanishes — the system has no solution.
Common traps
  • Never divide by something that could be zero. x(x-2)=x divided by x loses the solution x=0.
  • Squaring both sides can create false solutions: x=-3 becomes x^2=9, which also accepts +3. Always check.
  • \sqrt{x^2}=|x|, not x.
  • (a+b)^2\ne a^2+b^2; the correct expansion is a^2+2ab+b^2.
Where it shows up in AI
  • Closed-form fitting. Fit a line y=ax+b through two data points: that is a 2×2 system, solved exactly as above. With more points we use linear algebra (Module 1) — the same idea at scale.
  • The first optimisation. A quadratic loss such as L(w)=(w-3)^2+1 is smallest at its vertex w = 3. Gradient descent finds this vertex step by step when no neat formula exists.
  • Rearranging is how every paper derives a loss, an update rule, a normalisation. It is the daily bread of ML maths.

Check yourself

1. Solve 5x − 7 = 18.
5x = 25, so x = 5.
2. How many real solutions does x² + 2x + 5 = 0 have?
Δ = 4 − 20 = −16 < 0 → none. The parabola never reaches the axis.
3. Solve −3x ≤ 12.
Divide by −3 and flip the sign: x ≥ −4.

Takeaways

  • Do the same to both sides; check by substituting back.
  • Negative multiplication flips inequalities.
  • Quadratics: the discriminant counts the roots; the vertex at −b/2a is the minimum (for a>0).
  • Solving equations is "running a function backwards".

Σ and Π notation

The questionA model makes five predictions and is off by 2, −1, 0, 3 and −2. How do we write "the average squared error" without writing five terms — and without writing a thousand terms when there are a thousand predictions?

Intuition

The capital Greek letter Σ (sigma) means "add up"; capital Π (pi) means "multiply together". They are the mathematician's for-loop. Under the symbol you say where the counter i starts, on top where it stops, and to the right what to compute at each step.

# Σ_{i=1}^{n} i²              # Π_{i=1}^{n} i
total = 0                       product = 1
for i in range(1, n + 1):       for i in range(1, n + 1):
    total += i ** 2                 product *= i

Build it up

\sum_{i=1}^{4} i^2 \;=\; 1^2+2^2+3^2+4^2 \;=\; 1+4+9+16 \;=\; 30
Σ"sum of"
i = 1 (below)the counter i starts at 1
4 (above)and stops after 4
i²the body: what to compute and add at each step

Rules that save effort.

  • Constants pull out: \sum_i c\,x_i=c\sum_i x_i.
  • Sums split: \sum_i (x_i+y_i)=\sum_i x_i+\sum_i y_i.
  • Adding the constant 1 n times gives n: \sum_{i=1}^n 1=n.
  • Gauss's trick: \sum_{i=1}^n i=\frac{n(n+1)}{2} (pair 1 with n, 2 with n−1, … each pair sums to n+1 and there are n/2 pairs).

The average (mean) of n numbers is the most common sum in ML:

\bar x=\frac1n\sum_{i=1}^{n}x_i\qquad\qquad \text{MSE}=\frac1n\sum_{i=1}^{n}(\hat y_i-y_i)^2
Worked example — the question we started with

Errors: 2, −1, 0, 3, −2. Squares: 4, 1, 0, 9, 4. Sum = 18. Divide by n = 5: MSE = 3.6.

Why square? So positive and negative errors don't cancel (their plain sum is 2 − 1 + 0 + 3 − 2 = 2, which would wrongly suggest a small error) and so large mistakes count extra.

Products. \prod_{i=1}^{n} i=n! (factorial): 5!=1\cdot2\cdot3\cdot4\cdot5=120. Products appear whenever independent events combine: the chance that five independent coin flips are all heads is \prod_{i=1}^5\tfrac12=\tfrac1{32}. That is the shape of a likelihood: the probability of all the data is the product of the probabilities of each example.

Lab

Try this
  1. Press ▶ Replay with i^2 and n = 4. Watch the orange total climb to 30.
  2. Switch the term to i and set n = 10: the total is 55 = 10·11/2 (Gauss).
  3. Switch to Π with term i: you are computing the factorial and the product explodes quickly — note how fast.
  4. Try the term 1/2 with Π: halving repeatedly shrinks the product towards 0.
Common traps
  • Σ ranges include both ends. \sum_{i=1}^{4} has 4 terms; \sum_{i=0}^{4} has 5. Off-by-one errors are the classic bug.
  • \sum x_i^2\ne\left(\sum x_i\right)^2. Square-then-add and add-then-square differ.
  • The counter i is a dummy: \sum_i x_i and \sum_j x_j are identical.
Where it shows up in AI
  • Losses are averages over the dataset: L=\frac1N\sum_i\ell(\hat y_i,y_i).
  • A neuron computes a weighted sum z=\sum_{j}w_jx_j+b — the dot product in Module 1.
  • Likelihood is a product \prod_i p(y_i\mid x_i). Taking logs (lesson 0.5) turns it into a sum \sum_i\log p(y_i\mid x_i), which is why log-likelihood is so convenient.
  • Softmax divides by a sum over all classes: \sum_k e^{z_k}.

Check yourself

1. Write out and evaluate Σ_{i=1}^{3} (2i+1).
(2·1+1)+(2·2+1)+(2·3+1) = 3+5+7 = 15.
2. What does Π_{i=1}^{4} 2 equal?
2·2·2·2 = 16 (it is 2⁴).
3. Compute the MSE for predictions (3, 5) and targets (2, 8).
Errors 1 and −3; squares 1 and 9; mean = 10/2 = 5.

Takeaways

  • Σ is a loop that adds, Π is a loop that multiplies; the bounds are inclusive.
  • Mean and MSE are sums divided by n.
  • Independent probabilities multiply (Π), and logs will turn that into a sum (Σ).

Exponents & logarithms

The questionA model assigns probability 0.01 to each of 200 independent examples. The probability of all of them is 0.01²⁰⁰ = 10⁻⁴⁰⁰ — a number so small a computer rounds it to zero. Is there a way to handle such numbers without losing them?

Intuition

Exponents are repeated multiplication: 2^5=2\cdot2\cdot2\cdot2\cdot2=32. Addition grows steadily (+2, +2, +2…); exponentiation grows by multiplying (×2, ×2, ×2…), which explodes — a sheet of paper folded 42 times would reach the Moon.

The rules all follow from "count the multiplications":

a^m\cdot a^n=a^{m+n}\qquad (a^m)^n=a^{mn}\qquad a^0=1\qquad a^{-n}=\frac1{a^n}\qquad a^{1/2}=\sqrt a

(Why a^0=1? Because a^3/a^3=a^{3-3}=a^0 and anything divided by itself is 1.)

A logarithm asks the reverse question: "what exponent do I need?" Since 2^3=8, we say \log_2 8=3. In general \log_a y=x\iff a^x=y. The log of a number counts "how many multiplications by a it took to get here" — so it turns huge ranges into small ones (that's why earthquake and sound scales use it).

Build it up

The special number e. Suppose you earn 100 % interest per year. Paid once you get ×2. Paid in two halves (50 % twice): 1.5² = 2.25. Monthly: (1+1/12)¹² ≈ 2.613. Continuously, you approach e=\lim_{n\to\infty}(1+\tfrac1n)^n\approx2.71828. This is the natural rate of continuous growth, and e^x has the beautiful property that its slope equals its height — the reason it dominates calculus and probability. The logarithm base e is the natural log, written \ln (and in ML code, log almost always means ln).

The most important property of logs:

\log(ab)=\log a+\log b\qquad\log\frac ab=\log a-\log b\qquad \log(a^k)=k\log a

Logarithms turn multiplication into addition. This is what rescues our 200 tiny probabilities: instead of multiplying 0.01 two hundred times (underflow), add \ln0.01\approx-4.605 two hundred times to get ≈ −921, a perfectly ordinary number.

Worked example

\log_{10}(1000\cdot100)=\log_{10}(100000)=5 and \log_{10}1000+\log_{10}100=3+2=5 ✓.

Change of base: \log_2 10=\frac{\ln10}{\ln2}\approx\frac{2.3026}{0.6931}\approx3.32 — about 3.3 doublings to reach 10.

Finally the sigmoid, a curve you'll meet constantly: \sigma(x)=\dfrac1{1+e^{-x}}. It squashes any real number into (0,1), which is how a model turns a raw score into a probability. Large positive x → e^{-x}\to0 → σ → 1. Large negative x → σ → 0.

Lab

Try this
  1. In the first plot, the blue curve aˣ and orange log_a(x) are mirror images across the dashed line y = x: each undoes the other. Change a and confirm the mirror holds.
  2. In the log-rule panel, pick any p and q: the first two rows always match the third.
  3. In the underflow panel, push n up. The raw product hits 0 near n ≈ 155 while the log-sum remains sensible.
  4. In the sigmoid plot, increase k: the S-curve steepens into a switch.
Common traps
  • \log(a+b)\ne\log a+\log b. Logs convert products to sums, not sums to anything simple.
  • The log of zero or a negative number is undefined (for real numbers). In code, log(0) is −∞: always clip probabilities away from 0.
  • \ln (base e), \log_{10} and \log_2 differ by constant factors only; ML papers mean ln unless they say bits.
Where it shows up in AI
  • Log-likelihood: maximise \sum_i\log p(y_i\mid x_i) instead of the product — stable and easier to differentiate.
  • Cross-entropy loss is just a negative log-probability, -\log p_{\text{correct}}.
  • Sigmoid and softmax are built from e^x; they convert scores into probabilities.
  • Perplexity of a language model is e^{\text{loss}}.
  • Learning-rate schedules and many hyper-parameters are searched on a log scale (1e-5, 1e-4, 1e-3…).

Check yourself

1. Evaluate log₂ 32 and 5⁻².
2⁵ = 32 so log₂ 32 = 5. 5⁻² = 1/25 = 0.04.
2. Simplify ln(e³ · e⁵).
e³·e⁵ = e⁸, so ln = 8 (or 3 + 5 using the log rule).
3. Why is it better to add log-probabilities than to multiply probabilities?
Products of many numbers below 1 underflow to 0 in floating point; sums of their logs stay in a normal range. Sums are also easier to differentiate.

Takeaways

  • Exponents multiply repeatedly; logs ask "which exponent?" and undo them.
  • log(ab) = log a + log b — the property that makes ML numerically workable.
  • e is the natural growth base; σ and softmax are built from eˣ.

Angles, sine & cosine

The questionHow do we describe a turning wheel, a pure musical note, or "rotate this image by 30°" with numbers — and why do transformers feed sines and cosines into language models?

Intuition

Imagine a wheel of radius 1 with a lamp on its rim, spinning steadily. Shine the lamp sideways onto a wall: the shadow slides up and down — smoothly, slowing at the top, fastest through the middle. That up-down shadow is sine. The shadow on the floor, sliding left-right, is cosine. Same wheel, two views; cosine is just sine shifted by a quarter turn.

To measure "how far round the wheel" we use radians: the angle equals the length of arc travelled on the unit circle. A full lap has circumference 2π, so a full turn is 2π radians; half a turn is π; a quarter turn is π/2. Degrees are the same idea with 360 instead of 2π (so \pi\text{ rad}=180^\circ). Radians are preferred in maths because formulas such as "the slope of sine is cosine" are only that simple in radians.

Build it up

Definition: the point on the unit circle at angle θ (measured anticlockwise from the positive x-axis) has coordinates (\cos\theta,\ \sin\theta). Because that point lies on a circle of radius 1, Pythagoras gives \cos^2\theta+\sin^2\theta=1. Use the lab to see it all at once.

Try this
  1. Press Spin and watch the dot's horizontal shadow (orange) and vertical shadow (green) trace the two waves on the right.
  2. Stop at θ = π/2 (1.57): cosine is 0, sine is 1. Stop at π (3.14): cosine −1, sine 0.
  3. Check that cos² + sin² stays at exactly 1 everywhere.
Worked examples

\theta=\pi/6 (30°): \sin=\tfrac12,\ \cos=\tfrac{\sqrt3}2\approx0.866. Check: 0.25 + 0.75 = 1 ✓.

\theta=\pi/4 (45°): sin = cos = \tfrac{\sqrt2}2\approx0.707.

Right triangles. With hypotenuse h, side opposite the angle o and adjacent side a: \sin\theta=o/h,\ \cos\theta=a/h,\ \tan\theta=o/a.

Waves. Real signals have different heights, speeds and starting points. The general sine wave is

y(t)=A\sin(2\pi f\,t+\varphi)
Aamplitude — the height of the peaks
ffrequency — complete cycles per unit of t (so the period is 1/f)
φphase — a horizontal shift, where in the cycle you start
Try this
  1. Raise f: more waves squeezed into the window — a higher pitch.
  2. Raise A: louder, same pitch.
  3. Move φ: the pattern slides sideways without changing shape.

Rotation preview. Rotating a point (x,y) by angle θ about the origin gives (x\cos\theta-y\sin\theta,\ x\sin\theta+y\cos\theta). Rotation never changes a point's distance from the origin — a fact we will see as a matrix in Module 1.

Common traps
  • Calculators and code libraries differ: sin in Python/NumPy expects radians. Passing 30 means 30 radians, not 30°.
  • \sin^2\theta means (\sin\theta)^2, not sin of θ².
  • Sine and cosine only repeat every 2π — so they cannot tell θ from θ + 2π.
Where it shows up in AI
  • Transformer positional encodings use \sin(pos/10000^{2k/d}) and cosine at many frequencies so each position gets a unique, smoothly varying fingerprint; rotary embeddings (RoPE) rotate query/key vectors by position-dependent angles.
  • Fourier analysis — any signal is a sum of sine waves — underlies audio models, spectrograms and many image filters.
  • Cyclic features (hour of day, day of year) should be fed as (\sin\tfrac{2\pi h}{24},\cos\tfrac{2\pi h}{24}); otherwise hour 23 looks "far" from hour 0.
  • Data augmentation rotates images by random angles.

Check yourself

π/2 rad. sin = 1, cos = 0.
2. A wave is y = 3 sin(2π·2·t). What are its amplitude, frequency and period?
Amplitude 3, frequency 2 cycles per unit, period 1/2.
3. Why feed (sin, cos) of the hour instead of the hour itself?
The raw number makes 23 and 0 look far apart although they are adjacent on the clock. (sin, cos) places times on a circle so neighbours stay close.

Takeaways

  • (cos θ, sin θ) is the point on the unit circle; cos² + sin² = 1.
  • Radians measure arc length; 2π is a full turn.
  • A sin(2πft+φ): amplitude, frequency, phase.
  • Rotation preserves lengths.

Coordinates & geometry

The questionTwo houses are points in ℝ⁴. How far apart are they? And if we draw a "line" through that space to separate cheap houses from expensive ones, how does a computer decide which side a new house falls on?

Intuition

Coordinates are addresses. On a map, two numbers pinpoint a place; the distance between two places is the straight-line "as the crow flies" length. Pythagoras gives it: walk dx east and dy north, the shortcut is \sqrt{dx^2+dy^2}.

The wonderful fact is that this recipe never changes with dimension. For points with n coordinates, square every coordinate difference, add them up, take the root.

d(\mathbf a,\mathbf b)=\sqrt{\sum_{i=1}^{n}(a_i-b_i)^2}
Worked example

Houses A=(3, 120, 8, 2) and B=(3, 118, 9, 2.5): differences (0, 2, −1, −0.5); squares (0, 4, 1, 0.25); sum 5.25; distance √5.25 ≈ 2.29. Note the size difference (2 m²) contributes most — features with large numbers dominate distance, which is why we scale features before using distances.

Try this
  1. Drag the blue and orange tips. The red segment is the distance; the readout shows it computed from coordinates.
  2. Put both tips at the same height: the distance becomes just the horizontal gap.

Build it up: lines, planes and hyperplanes

A line in the plane is y=mx+b. A more useful form for ML writes it as w_1x_1+w_2x_2+b=0. Define the score s(\mathbf x)=w_1x_1+w_2x_2+b. Points on the line have score 0; points on one side have positive score, on the other side negative. The vector \mathbf w=(w_1,w_2) points perpendicular to the line toward the positive side, and the distance from a point to the line is |s(\mathbf x)|/\lVert\mathbf w\rVert.

In 3-D the same equation describes a flat plane. In ℝⁿ it describes an (n−1)-dimensional flat sheet called a hyperplane: it splits the whole space into two halves. Classifying a point = checking the sign of one score.

Try this
  1. Change w₁, w₂ and b and watch the boundary rotate and shift; the purple arrow (w) always points to the blue side.
  2. Click different places: the sign of the score flips exactly when you cross the line.
  3. Set b = 0: the line passes through the origin. Changing b slides the line without turning it.

Circles and spheres. All points at distance r from a centre (a,b): (x-a)^2+(y-b)^2=r^2. The same idea in ℝⁿ gives a hypersphere — the set of points at equal distance from a centre, i.e. "all points equally similar to a prototype".

High dimensions are strange

Our intuition was trained in 2-D and 3-D, and it misleads us at 100 or 1000 dimensions. One famous effect: with many dimensions, random points become almost equally far from each other, so "nearest" loses meaning. See it for yourself.

Try this
  1. Start at d = 2: distances spread wide. Slide d up to several hundred: the histogram collapses onto 1.
  2. Watch "farthest ÷ nearest" shrink toward 1 — the curse of dimensionality.
Common traps
  • Unscaled features let one big-number coordinate dominate every distance.
  • Straight-line (Euclidean) distance is only one choice; Module 1 introduces others (L1, cosine).
  • Pictures lie in high dimensions: your 3-D intuition about volume, corners and neighbours does not transfer.
Where it shows up in AI
  • k-nearest neighbours predicts by distance to stored examples.
  • Linear classifiers, logistic regression and SVMs are hyperplanes \mathbf w\cdot\mathbf x+b=0; a single neuron is exactly this score.
  • Embeddings are placed so that similar items are near each other; retrieval and recommendation are "find the closest points".
  • The curse of dimensionality motivates dimension reduction and good features.

Check yourself

1. Distance between (1, 2) and (4, 6)?
√(3² + 4²) = 5.
2. For w=(2, −1), b=3, which side is the point (1, 1) on?
Score = 2·1 − 1·1 + 3 = 4 > 0, the positive side.
3. Why does scaling features matter for distance-based methods?
Differences in a feature with large numbers (e.g. area in m²) swamp differences in small-valued features (e.g. bedrooms), so the distance mostly measures the big feature.

Takeaways

  • Distance = √(sum of squared coordinate differences), in any dimension.
  • w·x + b = 0 is a line / plane / hyperplane; its sign classifies points.
  • High dimensions break low-dimensional intuition: distances concentrate.

Reading mathematical notation

The questionYou open a machine-learning paper and see \theta^\star=\arg\min_\theta\frac1N\sum_{i=1}^N\ell\big(f(\mathbf x_i;\theta),y_i\big)+\lambda\lVert\theta\rVert_2^2. How do you read that without panic?

Intuition

Mathematical notation is shorthand — dense, but every symbol has a plain-English reading. Nothing in a formula is magic; it is a sentence. Authors also follow strong conventions, so once you know them, you can guess a symbol's job before reading its definition.

A three-step reading procedure. (1) Find the shapes: which symbols are scalars, vectors, matrices? (2) Read inside-out, left to right, saying each symbol in words. (3) Translate to code — if you can write the loop, you understand the formula.

Try this

Click each piece of the formula below. The explanation appears underneath, and the code at the bottom is the very same computation.

Now the formula from the start of the lesson

\theta^\star=\arg\min_\theta\ \frac1N\sum_i\ell(f(\mathbf x_i;\theta),y_i)+\lambda\lVert\theta\rVert_2^2

"The best parameters θ-star are the θ that make the following smallest: the average over all examples of the loss ℓ between the model's prediction and the true label, plus λ times the squared length of θ." The last term penalises large parameters (regularisation, Module 4 and 6). The whole thing is one training objective.

Common traps
  • The same letter means different things in different papers. Always find the definition (often a "Notation" paragraph).
  • x^2 (square) versus x^{(2)} (second example) versus x_2 (second feature) are three different things.
  • Bold may be dropped in handwritten or lazy typesetting; use shapes to infer.
Where it shows up in AI
  • Every paper, textbook and framework docs page. Fluency here turns "I can use the library" into "I can understand why it works and modify it".
  • Code ↔ maths translation is the daily skill: np.dot(w, x) + b ↔ \mathbf w\cdot\mathbf x+b; np.argmax(p) ↔ \arg\max_k p_k.

Check yourself

1. Say in words: ŷ = f(x; θ).
"y-hat, the prediction, equals the model f applied to the input x with parameters θ."
2. What is the difference between min and argmin?
min g(θ) is the smallest value of g; argmin g(θ) is the input θ where that smallest value occurs.
3. Translate into code: (1/n) Σ_{i=1}^{n} x_i².
np.mean(x ** 2) or sum(v*v for v in x) / n.

Takeaways

  • Bold = vector/matrix, subscript = entry, hat = estimate, star = optimum.
  • Read formulas as sentences, inside-out; translate to code to confirm understanding.
  • Always check each paper's own notation.
