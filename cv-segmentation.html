7.1

Semantic segmentation & FCN

The questionA self-driving car needs to know, for every pixel of the camera image, whether it is road, pavement, car, pedestrian or sky. A VGG-16 classifier ends in fully connected layers that squash the whole image into 1000 numbers and throw the "where" away. How do we turn a classifier into something that answers per pixel — and how do we even score such an answer?

Intuition

Semantic segmentation means giving every pixel a class label. Imagine colouring a photo with a set of crayons, one crayon per class: all road pixels grey, all sky pixels blue. It does not separate two different cars (that is lesson 7.5) — both are simply "car".

Two ideas make it possible. First, a convolutional layer already works at every position, so it can keep the "where". Second, the only layers that destroy position are the fully connected ones — and a fully connected layer is just a convolution in disguise. If the last feature map is 512×7×7, a layer 512\cdot7\cdot7\to4096 is exactly a convolution with 4096 filters of size 7×7. Re-read it as a convolution and it can slide over a larger image, producing a grid of class scores instead of one vector. A network with no fully connected layers is a fully convolutional network (FCN).

Build it up: the FCN recipe

  1. Take a classification backbone (VGG-16). Keep the convolutional part: 224×224 → 5 poolings → 512×7×7.
  2. Replace fc6 by a 7×7 convolution with 4096 filters, fc7 by a 1×1 convolution with 4096 filters, and the classifier by a 1×1 convolution with K filters (K = number of classes, say 21 for PASCAL VOC).
  3. The result is a score map of size K×7×7: each cell scores a 32×32 patch of the input. It is coarse (stride 32).
  4. Upsample the score map back to 224×224 (lesson 7.2), then take the arg-max over classes per pixel.
  5. Coarse-to-fine: FCN-16s adds a 1×1 score map from pool4 (14×14) to the 2× upsampled score, FCN-8s adds pool3 (28×28) as well. Early layers know where, late layers know what; adding them gives both.
Worked example — shapes and parameters

Input 3×224×224. Pools give 112, 56, 28, 14, 7 pixels per side. VGG-16 convolutions: 14,714,688 parameters (computed from the model). Then:

fc6 as conv 7×7: 512\cdot7\cdot7\cdot4096=102{,}760{,}448 weights (+4096 biases). fc7 as conv 1×1: 4096\cdot4096=16{,}777{,}216. Score layer: 4096\cdot21=86{,}016 (+21).

Total ≈ 134.4 M parameters, 21×7×7 scores. Note that 76% of the weights sit in fc6 alone — the part we converted. Upsampling the 7×7 map by 32 gives 21×224×224. The blueprint below chains five ×2 up-convolutions as a stand-in for FCN's single 32× upsampling layer.

Scoring a segmentation

Training loss: a cross-entropy per pixel, averaged: if the network gives probability p_{i,c} to class c at pixel i and the truth is class y_i,

\mathcal L_{CE}=-\frac1{HW}\sum_{i=1}^{HW}\log p_{i,y_i}

Worked: three pixels whose true class received probabilities 0.7, 0.2 and 0.9 cost -\ln0.7=0.357, -\ln0.2=1.609, -\ln0.9=0.105; the mean is 0.690. The badly classified pixel dominates.

Evaluation metrics count, per class, true positives TP (predicted and true), false positives FP (predicted only), false negatives FN (true only):

\mathrm{IoU}_c=\frac{TP}{TP+FP+FN},\qquad \mathrm{Dice}_c=\frac{2TP}{2TP+FP+FN},\qquad \mathrm{mIoU}=\frac1K\sum_c\mathrm{IoU}_c
TP, FP, FNpixel counts for one class, summed over the image (or dataset)
IoUintersection over union = overlap area ÷ combined area; 1 = perfect, 0 = disjoint
Dice2·overlap ÷ (size of prediction + size of truth); relates to IoU by \mathrm{Dice}=2\mathrm{IoU}/(1+\mathrm{IoU})
mIoUmean of the per-class IoUs — the standard benchmark number
p_{i,c}, y_ipredicted probability of class c at pixel i; true class at pixel i
Worked example — IoU, Dice, mIoU

Prediction covers 6 pixels, truth covers 6, and 4 are shared: TP = 4, FP = 2, FN = 2. IoU = 4/8 = 0.5. Dice = 8/12 = 0.667 (check: 2·0.5/1.5 = 0.667). If the background class has IoU 0.8, then mIoU = (0.5+0.8)/2 = 0.65.

Soft Dice for probabilities p = (0.9, 0.8, 0.2, 0.1) against truth y = (1, 1, 0, 0): overlap \sum p\,y=1.7, \sum p=2.0, \sum y=2, so Dice = 3.4/4 = 0.85 and the Dice loss is 0.15. It is differentiable, and it does not drown when the object is tiny.

Common traps
  • Pixel accuracy lies when classes are imbalanced: calling everything background scores 97% on a 3%-object image.
  • FCN output is stride-32 coarse; without the skip fusion (16s/8s) boundaries are blobby.
  • Averaging IoU over images is not the same as computing IoU over the whole dataset; benchmarks use dataset-wide TP/FP/FN per class.
Where it shows up in AI
  • Scene parsing / driving: Cityscapes, ADE20K labels for road, lane, building; FCN-style heads still sit on top of ResNet and ViT backbones.
  • Every dense task (segmentation, depth, optical flow) reuses "backbone + 1×1 conv head + upsampling".
  • Medical and satellite imaging: Dice loss is the default for small structures.

Check yourself

1. A 512×7×7 map feeds fc6 with 4096 outputs. What convolution is this, and how many weights?
A 7×7 convolution with 512 input channels and 4096 filters: 512·49·4096 = 102,760,448 weights.
2. TP = 30, FP = 10, FN = 20 for one class. IoU and Dice?
IoU = 30/60 = 0.5; Dice = 60/(60+10+20) = 0.667.
3. Why does FCN-8s beat FCN-32s at boundaries?
pool3 and pool4 feature maps have strides 8 and 16, so they keep finer location information; adding their scores to the coarse deep scores gives sharper edges.

Takeaways

  • Segmentation = classification at every pixel; fully connected layers become convolutions.
  • The deep map is coarse (stride 32); upsampling and skip fusion restore resolution.
  • Train with per-pixel cross-entropy (± Dice); report mIoU, not pixel accuracy.
7.2

Upsampling

The questionPooling and strided convolutions throw away resolution. A decoder has to produce a 128×128 mask from a 16×16 feature map. What operation grows a map — without inventing grid-shaped ugly patterns?

Intuition

Growing an image is guessing the pixels in between. There are two families. Fixed interpolation guesses with a rule: nearest copies the closest pixel (blocky), bilinear blends the four closest pixels by distance (smooth). It has no parameters, so you follow it with an ordinary convolution that learns what to do with the smooth result. Learned upsampling — the transposed convolution — lets the network learn the kernel that fills in the gaps.

Picture a transposed convolution as stamping: every input pixel is a rubber stamp, whose ink amount is the pixel value and whose shape is the kernel. You stamp each input pixel onto a larger sheet, moving S cells (the stride) between stamps, and ink adds up where stamps overlap. It is the ordinary convolution run backwards (hence also called a "deconvolution", although it does not invert it).

Build it up

Worked example — 1-D transposed convolution

Input [1,2,3], kernel [1,1,1], stride 2. Stamp 1 at positions 0–2, stamp 2 at 2–4, stamp 3 at 4–6:

positions 0..6 → [1, 1, 3, 2, 5, 3, 3]. Output length = (3−1)·2 + 3 = 7.

Now feed all ones: output [1, 1, 2, 1, 2, 1, 1]. A constant image becomes striped: cells 2 and 4 receive two stamps, the others one. In 2-D this is the checkerboard artefact. The cause: the kernel size 3 is not divisible by the stride 2, so overlap is uneven. With kernel 4 and stride 2, interior counts are all 2 (1,1,2,2,2,2,1,1) — even.

The output size comes from reversing the convolution formula O_{conv}=\lfloor (I+2P-K)/S\rfloor+1:

O=(I-1)\,S-2P+K\;(+\text{output padding})
I, Oinput and output side length
Kkernel size
Sstride: distance between consecutive stamps
Ppadding: this many border cells are cropped from the output

Common choices: K=2, S=2, P=0 doubles the size with no overlap (U-Net's up-convolution: O=2I). K=4, S=2, P=1 also doubles ((I-1)2-2+4=2I) with even overlap (pose estimation, GANs).

Pixel shuffle (sub-pixel convolution) avoids overlap entirely: a convolution produces C\,r^2 channels at low resolution and the tensor (Cr^2,H,W) is rearranged into (C,rH,rW): channel (a,b) becomes the sub-position (a,b) of every r×r output block. No multiplication, every output cell written exactly once, so no checkerboard. It is the workhorse of super-resolution (lesson 8.4).

The recommended recipe (Odena et al.): resize with nearest or bilinear, then a 3×3 convolution. Bilinear worked: input 2×2 = [[0,10],[20,30]], upsample ×2; output cell (1,1) sits at input coordinate (0.25,0.25), so it blends 9/16·0 + 3/16·10 + 3/16·20 + 1/16·30 = 7.5.

Lab: four ways to grow a map

Try this
  1. Choose "transposed convolution", kernel 3, stride 2, and the preset "all ones". Press play, then tick "colour output by overlap count": stripes of ×1 and ×2 are the checkerboard.
  2. Switch kernel to 4 (stride 2): the interior is uniformly ×2 and the stripes vanish. Switch the stride to 1: smooth overlap.
  3. Edit kernel weights (e.g. the centre to 4, others to 0) — the output becomes a scaled copy with gaps: what the net must learn to avoid.
  4. Pixel shuffle: edit the four channel weights; every output cell is written once.
Common traps
  • "Deconvolution" does not undo a convolution; it only restores the shape, not the values.
  • K=3, S=2 is the classic checkerboard configuration. Prefer K=4 or K=2 with S=2, or resize + conv.
  • Parameters: a transposed conv has K·K·C_in·C_out weights — for 1024→512 with K=2 that is 2,097,152, more than many whole layers.
Where it shows up in AI
  • U-Net and DeepLab decoders (2×2 up-conv, bilinear + conv), GAN generators (DCGAN transposed convolutions), super-resolution (ESPCN pixel shuffle), diffusion U-Nets (nearest ×2 + conv), pose heads (three 4×4 deconvs).

Draw it yourself

Block: C×H×W → [up-conv 2×2, stride 2] → C/2×2H×2W; concat with encoder map; conv 3×3 twice. Worked count: up-conv 256→128, K=2: 256\cdot4\cdot128+128=131{,}200 parameters (matches the 131,200 in the U-Net blueprint of lesson 7.3).

Check yourself

1. I = 16, K = 4, S = 2, P = 1. Output size?
(16−1)·2 − 2 + 4 = 32.
2. Why does K=3, S=2 cause checkerboards but K=4, S=2 not?
With K=3 stamps overlap on every second cell only (counts 1,2,1,2…); K=4 gives uniform overlap of 2 in the interior because K is divisible by S.
3. A pixel shuffle with r = 2 turns a 64×32×32 tensor into what shape?
16×64×64 (channels divide by r² = 4, sides multiply by 2).

Takeaways

  • Nearest/bilinear are fixed; transposed conv and pixel shuffle are learned.
  • O=(I-1)S-2P+K; K divisible by S avoids checkerboards.
  • Resize-then-conv is the safest default.
7.3

U-Net

The questionThe deep layers know what is in the image but not exactly where; the early layers know the exact edges but not what they belong to. A biomedical lab has only 30 annotated microscope images. How do we combine both kinds of knowledge and still train from so little data?

Intuition

Think of an architect sketching a building (the contracting encoder: the more she zooms out the more she understands the whole). Then she must draw the detailed plans (the expanding decoder). She would be foolish to draw the plans only from memory of the coarse sketch — she keeps the original photos on the desk. The skip connections are those photos: at every scale, the decoder receives a copy of the encoder's feature map of the same size, concatenated channel-wise to its own upsampled map. The network is shaped like a "U": down one side, up the other, with horizontal bridges.

Build it up

  1. Encoder: repeat [two 3×3 convs + ReLU → 2×2 max-pool]. Each step halves the resolution and doubles the channels (64 → 128 → 256 → 512 → 1024 in the original).
  2. Bottleneck: the smallest map; the largest receptive field.
  3. Decoder: repeat [2×2 up-convolution (halves channels, doubles size) → concatenate the encoder map → two 3×3 convs].
  4. Head: 1×1 conv to K class channels; per-pixel softmax.

Why concatenation rather than addition? Concatenation keeps both sources separate and lets the next convolution decide how to mix them; the doubling of channels at the merge (e.g. 256 + 256 = 512) is visible in the shape table. Why does it work with little data? The loss is per-pixel (a 512×512 image gives 262,144 training signals), the architecture is a strong locality prior, and the original paper added heavy elastic-deformation augmentation and a weighted loss that forces the network to separate touching cells.

Common traps
  • Input sizes must be divisible by 2^(levels) or the decoder maps will not match the skips (the original needed special tile sizes).
  • Concatenate before the convolution, not after; the 3×3 conv that follows is where the mixing happens.
  • Parameter count is not compute: the 1024-channel level holds most weights, but the full-resolution level holds most MACs.
Where it shows up in AI
  • Medical imaging (nnU-Net, tumour and organ masks), satellite building/crop maps, Stable Diffusion's noise predictor (a U-Net with attention), image-to-image translation (pix2pix), matting and inpainting.

Draw it yourself

Check yourself

1. In the original U-Net, why is the skip cropped?
Unpadded convs shrink each map, so the encoder map (e.g. 64×64) is larger than the upsampled decoder map (56×56). It is centre-cropped to match.
2. Which skip would you remove first to save memory and lose the least accuracy?
Skips cost activation memory proportional to resolution, so the finest one is the most expensive — but it also carries the most boundary detail. In practice you keep it; if forced, cut the coarsest skip (its information is already in the decoder).
3. After concatenating 128 decoder channels with 128 skip channels, what is the next 3×3 conv's weight count if it outputs 128 channels?
256·9·128 = 294,912 weights.

Takeaways

  • U-Net = encoder + decoder + same-scale skips by concatenation.
  • Original ≈ 31.03 M parameters, 572×572 → 388×388; the 128×128 preset has 6.92 M.
  • Skips return the fine detail; cutting them blurs boundaries.
7.4

Dilated convolutions & context

The questionTo label a pixel as "road" or "sidewalk" the network needs to see far beyond that pixel. Pooling enlarges the field of view but costs resolution; the decoder then has to rebuild it. Can we enlarge the receptive field without shrinking the map and without adding parameters?

Intuition

A normal 3×3 kernel reads nine neighbouring pixels. A dilated (atrous, "with holes") kernel keeps the same nine weights but spreads the taps apart: with rate r the taps are r pixels apart. It is like reading a page through a grid with holes: the same nine numbers cover a bigger area. The map size does not change, and the parameter count does not change.

Build it up

A 3×3 kernel with rate r behaves like a kernel of effective size k_{\mathrm{eff}}=k+(k-1)(r-1): rates 1, 2, 4, 8 give 3, 5, 9, 17. Stacking layers adds the effective widths: the receptive field after layers with rates r_1..r_L (3×3 each) is

\mathrm{RF}=1+2\sum_{l=1}^{L}r_l
RFside of the input square that influences one output pixel
r_ldilation rate of layer l; 1 = ordinary convolution
2each 3×3 layer reaches r pixels left and r right of the centre
Worked example

Four layers, rate 1 each: RF = 1 + 2·4 = 9. Rates 1, 2, 4, 8: RF = 1 + 2·15 = 31. Growing layer by layer: 3, 7, 15, 31 — it doubles each time (exponential), while the parameter count stays 4·9·C² and the resolution is unchanged. Rates 2, 2, 2 leave holes: only every second pixel of the 13×13 field is reached by some path (a gridding artefact). Fix: mix rates (1, 2, 5) so the taps cover the field.

ASPP and DeepLab

Objects have many sizes; one rate sees only one scale. Atrous spatial pyramid pooling (ASPP) looks at the same feature map with several rates in parallel and concatenates the answers. DeepLabv3's ASPP (output stride 16) has five branches over the 2048-channel backbone output: a 1×1 conv, three 3×3 convs with rates 6, 12, 18, and an image-level pooling branch (global average → 1×1 conv → broadcast), each producing 256 channels. They are concatenated (5·256 = 1280) and projected by a 1×1 conv to 256.

ASPP parameter count

1×1 branch: 2048·256 = 524,288. Each 3×3 branch: 2048·9·256 = 4,718,592; three of them 14,155,776. Pooling branch: 524,288. Projection: 1280·256 = 327,680. Total 15,532,032 weights (≈ 15.5 M, before batch-norm). Rates do not change this number — only where the taps look.

Context vs resolution. A classification ResNet reduces the map by 32. DeepLab removes the last strides (output stride 8 or 16) and replaces them by dilation 2 and 4 in later stages: the field of view is preserved while the map stays 4× (or 2×) larger. The cost: later stages operate on bigger maps, so compute rises. DeepLabv3+ adds a light decoder that merges a low-level (stride-4) feature map — the same idea as the U-Net skip.

Common traps
  • Using the same rate in every layer causes gridding. Vary the rates, ideally without a common factor.
  • A huge rate on a small map: the taps fall into the padding and the kernel degenerates to a 1×1 (why ASPP adds the image-pooling branch).
  • Dilation keeps parameters but not FLOPs: more pixels are processed at high resolution.
Where it shows up in AI
  • DeepLab v1–v3+ (semantic segmentation), WaveNet (1-D dilated convs for audio with rates 1…512), dilated temporal convolutions (TCN) for sequences, context modules in dense prediction.

Draw it yourself

Check yourself

1 + 2·(1+3+9) = 27.

Takeaways

  • Dilation spreads the taps: bigger context, same parameters, same resolution.
  • RF = 1 + 2Σr; rates 1,2,4,8 give 31.
  • ASPP samples several scales in parallel; vary rates to avoid gridding.
7.5

Instance & panoptic segmentation

The questionTwo cars are parked side by side. Semantic segmentation paints both pixels "car" — it cannot say how many cars there are, or where one ends and the next begins. How do we separate individual objects, and how do we also label the "stuff" such as road and sky that has no countable instances?

Intuition

Things are countable objects (car, person); stuff is amorphous regions (road, sky, grass). Semantic segmentation labels both but cannot count things. Instance segmentation finds each thing and gives it its own mask. Panoptic segmentation unifies them: every pixel gets a class, and thing pixels also get an instance id.

Mask R-CNN does instance segmentation in two stages: detect first, then segment inside each box. It extends Faster R-CNN with a third branch next to the box classifier and the box regressor: a small fully convolutional mask head that predicts a binary mask for the region.

Build it up: the mask head

  1. A region proposal (a box) is resampled by RoIAlign to a fixed 256×14×14 feature patch (bilinear sampling without rounding, so mask pixels stay aligned to the image).
  2. Four 3×3 convolutions, 256 channels each (keeping 14×14).
  3. One 2×2 transposed convolution, stride 2, 256 channels: 14×14 → 28×28.
  4. A 1×1 convolution to K channels: one 28×28 mask per class (K = 80 for COCO), with a per-pixel sigmoid. Only the mask of the predicted class is used and trained, so classes do not compete.
  5. The 28×28 mask is resized into the box in the image.
Worked example — mask head count

3×3, 256→256: 256\cdot9\cdot256+256=590{,}080; four of them 2,360,320. Up-conv 2×2: 256\cdot4\cdot256+256=262{,}400. Class layer 1×1: 256\cdot80+80=20{,}560. Total = 2,643,280 parameters (the blueprint computes the same). Each 28×28 mask has 784 pixels; a 280×280 car in the image gets its mask upsampled 10×, which is why Mask R-CNN edges look smooth but slightly rounded.

Panoptic quality. For each class, ground-truth segments and predicted segments are matched when their IoU exceeds 0.5 (this makes the match unique). Matched pairs are true positives; unmatched predictions are false positives; unmatched truth are false negatives:

\mathrm{PQ}=\underbrace{\frac{\sum_{(p,g)\in TP}\mathrm{IoU}(p,g)}{|TP|}}_{\mathrm{SQ}}\times\underbrace{\frac{|TP|}{|TP|+\tfrac12|FP|+\tfrac12|FN|}}_{\mathrm{RQ}}
SQsegmentation quality: how well matched segments overlap
RQrecognition quality: an F1-style term for finding the right segments
TP/FP/FNmatched pairs / unmatched predictions / unmatched truths (counted per class)
Worked example

TP = 3 with IoUs 0.9, 0.8, 0.7 (sum 2.4); FP = 1; FN = 2. SQ = 2.4/3 = 0.800. RQ = 3/(3+0.5+1) = 0.667. PQ = 0.8·0.667 = 0.533 (= 2.4/4.5).

7.6

Promptable segmentation (SAM)

The questionEvery segmentation model so far has a fixed list of classes. What if you could simply point at anything — a window, a shadow, a screw — and get its mask, even for objects the model was never labelled on? And what should the model do when "a click on the window" could mean the window, the wall or the whole house?

Intuition

The Segment Anything Model (SAM) splits the job in two. A very heavy image encoder turns the picture into an embedding once (seconds). Then a tiny mask decoder turns that embedding plus a prompt into masks in milliseconds. You can therefore click around interactively while the heavy part is cached — like indexing a book once and then searching it instantly.

Build it up: the three parts

  • Image encoder: a ViT (the ViT-H version has 32 layers, 16 heads, width 1280), pre-trained with masked autoencoding. Input 1024×1024, patches 16×16, so 64×64 = 4096 tokens; most blocks use windowed (14×14) attention and four use global attention. A small neck gives a 256×64×64 embedding. ViT-H ≈ 632 M parameters (ViT-L 308 M, ViT-B 91 M).
  • Prompt encoder: points and box corners become positional encodings of (x, y) plus a learned embedding saying "foreground", "background" or "top-left/bottom-right corner". Text uses CLIP; a mask prompt is encoded by a few convolutions.
  • Mask decoder: two "two-way" transformer blocks (≈ 4 M parameters): prompt tokens attend to the image embedding, and the image embedding attends back to the tokens. Then the embedding is upsampled 4× to a 256×256 mask and a dot product with the output tokens gives mask logits, plus a predicted IoU score for each mask.

Ambiguity. A single point is ambiguous (window? wall? house?). A model forced to give one answer averages the possibilities into a bad mask. SAM instead outputs three masks (whole, part, sub-part) for one prompt, each with a predicted IoU; training uses only the best of the three in the loss (minimum over masks), so the heads specialise. With more prompts (a second point, a box) the ambiguity vanishes and a single mask is usually enough.

Worked example — token and parameter budget

1024/16 = 64, so 64² = 4096 tokens of width 1280. One ViT block: attention 4·1280² + 4·1280 = 6,558,720; MLP (hidden 5120) 2·1280·5120 + 5120 + 1280 = 13,112,320; two layer norms 5,120 → 19,676,160 per block; ×32 = 629.6 M. Add patch embedding 984,320 and a position table 4096·1280 = 5.2 M: the blueprint total is 635.9 M, within 1% of the published ≈ 632 M for the encoder (SAM uses a neck and relative positions instead of this simple table). Global attention over 4096 tokens costs 4096²·1280 ≈ 21 G multiply-adds per layer for the score matrix alone — which is why windowed attention is used in 28 of the 32 blocks. The archviz MAC count (3.96 T) therefore overstates SAM's real compute.

SAM was trained on SA-1B: 11 million images with 1.1 billion masks, created in a loop where the model itself helped annotators (assisted → semi-automatic → fully automatic), and the training loss is a mix of focal and Dice loss on masks plus an IoU-prediction regression.

  • SAM gives masks, not class names; it does not know "what" it segmented.

Where it shows up in AI
  • Annotation tools (click-to-label), photo editing cut-outs, video object tracking (SAM 2 adds memory), robotics, as the "mask generator" feeding open-vocabulary pipelines such as Grounded-SAM.

Draw it yourself

Diagram: image → ViT-H → 256×64×64 embedding (cached); prompt (points, box, mask, text) → prompt encoder → tokens; [tokens ⇄ embedding] ×2 → upsample ×4 → 3 masks (256×256) + 3 IoU scores. Counts: patch embedding 16·16·3·1280 + 1280 = 984,320; one 1280-wide block 19,676,160.

Check yourself

1. Why is SAM interactive although ViT-H is huge?
The image encoder runs once per image; the prompt encoder and mask decoder are tiny, so each new prompt costs milliseconds.
2. Why three output masks?
One point is ambiguous (part/whole); three masks avoid averaging them, and the loss uses only the best match.
3. Tokens for a 1024×1024 image with 16×16 patches?
64·64 = 4096.

Takeaways

  • Heavy encoder once, light decoder per prompt.
  • Prompts: points, boxes, masks, text; output: 3 masks + IoU scores for ambiguity.
  • Trained on 1.1 B masks; ViT-H ≈ 632 M parameters.
7.7

Depth, keypoints & pose

The questionA phone has one camera. How can it tell how far things are (for AR placement) or where a person's elbow is (for a fitness app)? Both are dense predictions — one number per pixel, or one location per joint — but the targets are numbers, not classes.

Intuition

Stereo depth uses two cameras: an object appears shifted between the images by the disparity d (pixels); near objects shift more. Geometry gives Z=fB/d. Monocular depth uses one image: the network learns the cues humans use (size, perspective, occlusion) and regresses a depth value for every pixel with an encoder-decoder, often a U-Net or a ViT with a dense head. The catch is scale ambiguity: a small house close up and a big house far away look alike, so many models predict depth only up to an unknown scale.

Worked example — stereo

Focal length f = 700 px, baseline B = 0.12 m, disparity d = 21 px: Z=700\cdot0.12/21=4.0 m. At d = 10.5 px the object is 8 m away: depth is inversely proportional to disparity, so far objects have tiny disparity and large depth errors.

Scale-invariant loss (Eigen et al.): with d_i=\log\hat y_i-\log y_i,

\mathcal L=\frac1n\sum_i d_i^2-\frac{\lambda}{n^2}\Big(\sum_i d_i\Big)^2,\quad\lambda\in[0,1]
\hat y_i, y_ipredicted and true depth at pixel i
d_ilog-depth error (a multiplicative error becomes additive)
λhow much of a global scale error is forgiven (λ = 1: fully)

Worked: errors d = (0.2, 0.2, 0.2) — the prediction is exactly 22% too large everywhere. With λ = 1: mean of squares 0.04 minus (0.6/3)² = 0.04 → loss 0. A pure global scale mistake costs nothing; only the relative structure is penalised.

Build it up: heatmap keypoints

To find the elbow, one might regress its (x, y) directly — but a single fully connected output is fragile and discards spatial structure. The dense way: the network outputs one heatmap per joint, a map that is high where the joint probably is. Training targets are Gaussian blobs centred on the true joint (σ about 2 pixels in heatmap units); the loss is the mean squared error between predicted and target heatmaps. At inference, find the arg-max of each heatmap, multiply by the stride to return to image coordinates, and refine by shifting a quarter pixel towards the larger neighbour.

Worked example

Image 256×192, stride 4, heatmap 64×48 for each of 17 joints (COCO). Joint peak at cell (x=20, y=30). Image coordinates: ((20+½)·4, (30+½)·4) = (82, 122). Quantisation error is at most stride/2 = 2 px; the quarter-pixel shift (±1 px) reduces it. Multi-person pose adds either top-down (detect people, then run this per crop) or bottom-up grouping.

SimpleBaseline shows how small the head is: ResNet-50 without its classifier (23.51 M parameters) → three deconvolution layers (4×4 kernels, stride 2, 256 channels: 2048·256·16 = 8,388,608 for the first, 256·256·16 = 1,048,576 for each of the other two) → a 1×1 conv to 17 channels. Feature map 2048×8×6 → 256×16×12 → 256×32×24 → 256×64×48 → 17×64×48. Total ≈ 34.0 M parameters. (The blueprint below uses 2×2 up-convs, so it counts 26.1 M — the 4×4 kernels cost 4× more per layer.)

Common traps

3. Why is the scale-invariant loss useful?

Takeaways

  • Depth: per-pixel regression (log, scale-invariant loss) or stereo geometry Z = fB/d.
  • Pose: one heatmap per joint, arg-max decode, scale by stride, sub-pixel refinement.
  • All dense tasks = backbone + decoder + a small per-pixel head.
