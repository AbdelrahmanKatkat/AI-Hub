7.1

Convolutional networks

The questionA 28×28 photo has 784 pixels. If every neuron looked at every pixel, one layer producing a 26×26×8 stack of feature maps would need over four million weights — and would have to relearn "an edge" separately at every position. Can we build a layer that learns one small detector and slides it everywhere?

Intuition

Imagine reading a page with a magnifying glass that only shows a 3×3 patch. You slide it along; at each stop you ask the same question ("is there a vertical edge here?") and write the answer in a grid. The glass is the filter (kernel), the grid of answers is a feature map. Two ideas make this powerful: locality (nearby pixels matter together) and weight sharing (the same nine numbers are reused at every position, so a cat's ear is detected wherever it appears). Pooling then shrinks the map by keeping the strongest response in each small window, giving some tolerance to small shifts.

This lesson is an overview. The full treatment — stride, padding, receptive fields, famous networks — lives in the Computer Vision topic: the convolution layer, pooling and ResNet.

Build it up: one conv layer by hand

Take a 5×5 patch of a grayscale image and a 3×3 vertical-edge kernel (left column +1, right column −1). With no padding and stride 1 the kernel has 3×3 = 9 positions, so the output is 3×3 (output size = 5 − 3 + 1).

\text{patch}=\begin{pmatrix}1&2&0&1&3\\0&1&3&1&2\\2&1&0&0&1\\1&0&2&1&0\\3&1&1&2&1\end{pmatrix},\quad K=\begin{pmatrix}1&0&-1\\1&0&-1\\1&0&-1\end{pmatrix}
Worked example — the top-left output

Overlay K on rows 1–3, columns 1–3 (values 1,2,0 / 0,1,3 / 2,1,0). Multiply element-wise and add: 1\cdot1+2\cdot0+0\cdot(-1) + 0\cdot1+1\cdot0+3\cdot(-1) + 2\cdot1+1\cdot0+0\cdot(-1) = 1 − 3 + 2 = 0.

Slide one column right: window 2,0,1 / 1,3,1 / 1,0,0 → (2−1)+(1−1)+(1−0) = 2. One more: window 0,1,3 / 3,1,2 / 0,0,1 → (0−3)+(3−2)+(0−1) = −3. Completing all nine positions gives

\begin{pmatrix}0&2&-3\\-2&0&2\\3&-1&1\end{pmatrix}\xrightarrow{\ \text{ReLU}\ }\begin{pmatrix}0&2&0\\0&0&2\\3&0&1\end{pmatrix}

ReLU zeroes negatives; a 2×2 max-pool of the top-left block of this map would keep 2. Large |values| mark places where left and right differ — an edge.

Parameter sharing versus dense

Blueprint for a 28×28×1 input, k=3, 8 filters, no padding:

A dense layer producing the same 8×26×26 = 5,408 outputs from 784 inputs needs 784·5,408 + 5,408 = 4,245,280 parameters — about 53,000 times more than the conv layer's 80. The saving is pure weight sharing plus locality.

The formal definition

y_{o,i,j}=b_o+\sum_{c=1}^{C_{in}}\sum_{u=0}^{k-1}\sum_{v=0}^{k-1}W_{o,c,u,v}\;x_{c,\,i+u,\,j+v},\qquad \text{params}=C_{out}(C_{in}k^2+1)
xc,i,jinput value in channel c at row i, column j
Wo,c,u,vshared weight of filter o, input channel c, kernel offset (u,v)
boone bias per filter
kkernel size (3 = 3×3)
Cin, Coutinput channels, number of filters (= output channels)

Output spatial size with padding p and stride s: \lfloor (n+2p-k)/s\rfloor+1. Inductive bias: translation equivariance — shift the input and the feature map shifts with it.

Common traps
  • Deep-learning "convolution" is really cross-correlation (the kernel is not flipped) — harmless because the kernel is learned.
  • Parameters ≠ compute. The conv layer above has 80 parameters yet does 26·26·8·9 = 48,672 multiplications; weight sharing saves memory, not arithmetic.
  • CNNs are equivariant to shifts, not rotations or scale; they must learn those from data (augmentation).
Where it shows up in AI
  • Image classification and detection (ResNet, EfficientNet), medical imaging, satellite imagery.
  • Audio: 1-D convolutions or 2-D convolutions over spectrograms for speech and sound classification.
  • Text and time series: 1-D convs as fast local pattern detectors; TCN, WaveNet.

Check yourself

1. How many parameters has a conv layer with 3 input channels, 16 filters of size 5×5?
16·(3·25 + 1) = 16·76 = 1,216.
2. What is the output size for a 32×32 input, k=5, p=0, s=1?
32 − 5 + 1 = 28, so 28×28 per filter.
3. Why is the vertical-edge output 0 where the patch is flat?
Left and right columns are equal, so (+1)·a + (−1)·a cancel in every row and the sum is 0.

Takeaways

  • A conv layer slides one small shared filter bank over the input: params = Cout(Cink²+1), independent of image size.
  • Locality + sharing give translation equivariance and a huge parameter saving versus dense layers.
  • Pooling shrinks maps and adds small-shift tolerance. Details: Computer Vision topic.
7.2

Recurrent networks, LSTM & GRU

The question"The movie was not good" — the word not flips the meaning of good three tokens later. A model must read words one at a time, remember what mattered, and cope with sentences of any length using a fixed number of weights. How do we give a network a memory?

Intuition

Read a sentence with a notepad. At every word you look at the word and your current notes, then rewrite the notes. The notepad is the hidden state h_t; the rewriting rule is the same at every step (shared weights, just like a conv filter shared across space — here shared across time). Drawing the loop unrolled gives a long chain of identical cells, one per time step.

The notepad has a flaw: after 50 rewrites the early words are barely visible, and during training the error signal fading back through those rewrites is even weaker. The LSTM fixes this with a second, protected notepad (the cell state) that only changes through gates — doors that open or close between 0 and 1.

Build it up: a vanilla RNN by hand

Use scalars to see every number: h_t=\tanh(w_h h_{t-1}+w_x x_t+b) with w_h=0.5,\ w_x=1,\ b=0,\ h_0=0 and inputs x=(1,\,0.5,\,-1).

The vanishing-gradient product

Training sends an error signal backwards through time. By the chain rule the sensitivity of h_t to an early state is a product of per-step factors, each w_h(1-h_k^2):

\frac{\partial h_t}{\partial h_0}=\prod_{k=1}^{t} w_h\,(1-h_k^{2})

From the table, the three factors are 0.5·0.4200 = 0.2100, 0.5·0.5004 = 0.2502 and 0.5·0.6758 = 0.3379. Their product over 3 steps is already 0.0178. Computed numerically for a long run (h starting at 0.5, bias 0.3):

Even with no tanh slope at all, a factor of 0.9 per step gives 0.910 = 0.35, 0.950 = 0.0052; a factor of 1.1 explodes: 1.150 ≈ 117. Gradients vanish or explode exponentially with sequence length; gradient clipping tames explosions, gating tames vanishing.

LSTM and GRU

The LSTM keeps cell state c_t and three gates computed from the current input and previous hidden state. Its key line is additive: c_t=f_t c_{t-1}+i_t g_t. If f_t\approx1 the old memory passes through untouched, so the gradient along c is multiplied by f_t instead of a squashing tanh slope — no exponential decay.

Worked example — one LSTM step with real numbers

Scalar cell (h = 1, d = 1). Input x=1, previous h_{t-1}=0.5, previous c_{t-1}=2. Each gate has weights (wx, wh, b): forget (0.5, 0.4, 0.1), input (0.8, −0.3, 0), output (0.3, 0.9, −0.2), candidate (1.0, 0.5, 0).

The GRU merges cell and hidden state and uses two gates (update z, reset r): h_t=(1-z_t)h_{t-1}+z_t\tilde h_t — 3 weight blocks instead of 4, about 25% fewer parameters.

\begin{aligned}f_t&=\sigma(W_f[h_{t-1},x_t]+b_f)\\ i_t&=\sigma(W_i[h_{t-1},x_t]+b_i)\\ o_t&=\sigma(W_o[h_{t-1},x_t]+b_o)\\ g_t&=\tanh(W_g[h_{t-1},x_t]+b_g)\\ c_t&=f_t\odot c_{t-1}+i_t\odot g_t\\ h_t&=o_t\odot\tanh(c_t)\end{aligned}

Parameters: each of the 4 blocks has an h×(h+d) matrix and h biases, so

\begin{aligned}\text{params}_{LSTM}&=4\,\bigl(h(h+d)+h\bigr)\ \text{params}_{GRU}&=3\,\bigl(h(h+d)+h\bigr)\ \text{params}_{RNN}&=h(h+d)+h\end{aligned}

Blueprint with d = 64, h = 128: LSTM 4·(128·192+128) = 98,816; GRU 74,112; vanilla RNN 24,704. The scalar cell above has 4·(1·2+1) = 12. Parameter count does not depend on sequence length; compute does (T sequential steps, which cannot run in parallel).

Common traps
  • The LSTM does not remove vanishing gradients everywhere — only along the cell path; very long dependencies (thousands of steps) still fail.
  • Bidirectional RNNs cannot be used for real-time generation: they need the future.
  • Sequence length costs time, not parameters: training time is O(T) sequential steps, which is why transformers displaced RNNs on GPUs.
Where it shows up in AI
  • Speech recognition, early machine translation (seq2seq with LSTM encoder/decoder, 2014–2016).
  • Sensor, finance and demand forecasting where streaming and small models matter (GRU on edge devices).
  • Modern revival: state-space models such as Mamba are recurrent networks with a hardware-friendly parallel scan.

Check yourself

1. How many parameters has a GRU with d = 10, h = 20?
3·(20·30 + 20) = 3·620 = 1,860.
2. If f = 1 and i = 0 at every step, what is ct?
ct = ct−1: the cell is a perfect memory and the gradient along it is exactly 1.
3. A per-step gradient factor of 0.9 acts over 100 steps. Roughly what is the total?
0.9100 ≈ 2.7×10−5: the early inputs receive almost no learning signal.

Takeaways

  • An RNN reuses one cell across time; hidden state is a running summary.
  • Backprop through time multiplies per-step factors, so gradients vanish or explode exponentially.
  • LSTM: params 4(h(h+d)+h); the additive cell update c = f·c + i·g protects memory. GRU is the leaner 3-block cousin.
7.3

Attention & transformers

The questionIn "The animal didn't cross the street because it was too tired", what does it refer to? A recurrent net must carry the answer through every intermediate word. Could each word instead look directly at any other word, in one step, and decide how much to listen?

Intuition

Attention is a soft dictionary lookup. Each token writes a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what I will hand over if chosen"). A token compares its query with every key; high similarity means high weight; the output is the weighted average of values. Everything is differentiable, so the network learns what to ask and what to advertise. The maths is derived in the attention lesson; here we build the blueprint.

Build it up: self-attention on 3 tokens, by hand

Three tokens with 2-dimensional embeddings x_1=(1,0),\ x_2=(0,1),\ x_3=(1,1) (rows of X). Take W_Q=I, W_K=\begin{pmatrix}1&1\\0&1\end{pmatrix}, W_V=\begin{pmatrix}1&0\\1&1\end{pmatrix}, and d_k=2.

Worked example

① Q, K, V (row-vector times matrix): Q = (1,0), (0,1), (1,1). K = (1,1), (0,1), (1,2). V = (1,0), (1,1), (2,1).

② Scores QK^\top/\sqrt{d_k}. Raw dot products row by row: token 1: (1, 0, 1); token 2: (1, 1, 2); token 3: (2, 1, 3). Divide by √2 = 1.414:

S=\begin{pmatrix}0.707&0&0.707\\0.707&0.707&1.414\\1.414&0.707&2.121\end{pmatrix}

③ Softmax each row. Row 1: e0.707 = 2.028, e0 = 1, e0.707 = 2.028, sum 5.056 → (0.401, 0.198, 0.401). Row 2 → (0.248, 0.248, 0.503). Row 3 → (0.284, 0.140, 0.576). Every row sums to 1.

④ Weighted sum of values. Token 1: 0.401·(1,0) + 0.198·(1,1) + 0.401·(2,1) = (1.401, 0.599). Token 2 → (1.503, 0.752). Token 3 → (1.576, 0.716).

Each output is a mixture of all three values, in one step, whatever the distance between tokens.

The transformer block

One block = multi-head self-attention (h heads of size d/h, outputs concatenated and mixed by W_O) → add & layer-norm → MLP (expand to 4d, nonlinearity, project back to d) → add & layer-norm. Residual connections keep a clear gradient path. Stack L blocks.

Cost. The score matrix QK^\top is n×n: computing it takes n²d multiply-adds, applying it to V another n²d, and storing it n² numbers per head. Attention is O(n²d) time and O(n²) memory; the MLP is O(n d²). Doubling the context quadruples attention cost: for n = 1,024 and d = 768, QKᵀ alone is 1,024²·768 = 805 M MACs.

Attention is order-blind (permuting tokens permutes outputs), so positional encodings are added to X. A causal mask sets future scores to −∞ for generation (GPT-style); no mask gives bidirectional encoders (BERT). Vision version: Vision Transformers.

Common traps
  • Attention weights are not a perfect explanation of the model's reasoning; they are one intermediate quantity.
  • Softmax is over keys (each row sums to 1), not over queries.
  • Parameters grow with d², not n; compute grows with n². Long context is expensive even though no extra weights are added.
Where it shows up in AI
  • Large language models (GPT, Llama, Claude): stacks of causal transformer blocks, 32–120+ layers.
  • Vision transformers, CLIP, speech models like Whisper, protein folding (AlphaFold's Evoformer).
  • Efficiency work: FlashAttention (same maths, less memory traffic), sparse and linear attention, KV caching at inference.

Check yourself

1. Block parameters for d = 512 (weights only)?
12·512² = 3,145,728.
2. Context grows from 4k to 16k tokens. How much more does the n² attention-score computation cost?
4× the tokens means 16× the score entries and score computation.
3. Why divide by √dk?

Takeaways

  • Attention = softmax(QKᵀ/√d)V: every token reads from every other in one step.
  • A block has 12d² weights (4d² attention + 8d² MLP); attention costs O(n²d) time and O(n²) memory.
  • Order comes from positional encodings; masking decides what a token may see.
7.4

Embeddings & autoencoders

The questionA shop has 100,000 products. One-hot vectors make "sneakers" and "running shoes" exactly as different as "sneakers" and "garden hose". How do we hand a model a short list of numbers in which similar things sit close together — and learn those numbers from data?

Intuition

An embedding places every item at a point in a low-dimensional space (a few hundred dimensions rather than 100,000), arranged so that distance means similarity. Mechanically it is nothing but a lookup table: row i of a matrix E holds the vector of item i; the rows are ordinary parameters learned by backpropagation. Because positions are learned from how items are used together, directions can acquire meaning — the classic king − man + woman ≈ queen.

An autoencoder learns such a representation without labels: squeeze the input through a narrow bottleneck and ask the network to rebuild it. If reconstruction is good, the few bottleneck numbers must have kept what matters.

Build it up: lookup and similarity search by hand

Worked example — a 5-word table, d = 3
wordvector
king(0.9, 0.8, 0.1)
queen(0.9, 0.1, 0.8)
man(0.1, 0.9, 0.1)
woman(0.1, 0.2, 0.8)
apple(−0.5, 0.1, 0.1)

Lookup: token id 0 (king) returns row 0 — equivalent to multiplying a one-hot vector by E, but without the wasted zeros. Similarity by cosine: \cos(a,b)=\frac{a\cdot b}{\|a\|\|b\|}. For king and man: dot = 0.09 + 0.72 + 0.01 = 0.82; norms 1.2124 and 0.9110; cosine = 0.745. king–woman: 0.329. king–apple: −0.573. Nearest neighbour of king among the others is therefore man (0.745), then queen (0.664).

Analogy: king − man + woman = (0.9−0.1+0.1, 0.8−0.9+0.2, 0.1−0.1+0.8) = (0.9, 0.1, 0.8), which is exactly queen in this toy table. Real embeddings are only approximately that clean.

Search at scale: store all vectors, embed the query, return the top-k by cosine (or dot product). Exact search costs N·d multiplications per query; approximate indexes (HNSW, IVF) trade a little recall for orders-of-magnitude speed. Table size is V·d parameters: 100,000 items at d = 128 is 12.8 M numbers.

Variants: denoising (corrupt the input, rebuild the clean one), sparse, and variational (code is a distribution, so you can sample new data).

Common traps
  • Embedding axes are not individually interpretable, and the space can be rotated without changing any similarity.
  • Cosine ignores vector length; dot product does not. Use whichever the model was trained with.
  • An autoencoder with a bottleneck as wide as the input can learn the identity and nothing useful; capacity must be limited (or noise/sparsity added).
  • Embeddings inherit biases from their training data.
Where it shows up in AI
  • Recommenders: user and item embeddings, score = dot product (two-tower models, matrix factorisation).
  • Retrieval and RAG: text/image embeddings in a vector database, nearest-neighbour search.
  • Every language model begins with a token-embedding table; autoencoders power anomaly detection, denoising and the latent space of image generators.

Takeaways

  • An embedding is a trainable lookup table E ∈ ℝV×d; closeness (cosine) encodes similarity.
  • Similarity search = embed the query, take the top-k nearest vectors.
  • An autoencoder compresses through a bottleneck (784→32 = 24.5×) and learns features without labels.
7.5

Graph neural networks

The questionA molecule is atoms joined by bonds; a social network is people joined by friendships. There is no grid and no sequence, the number of neighbours varies, and relabelling the nodes must not change the answer. What network can read that?

Intuition

Each node starts with a feature vector. In every round of message passing a node (1) collects its neighbours' vectors, (2) aggregates them (sum, mean or weighted mean — an order-independent operation), (3) transforms the result with a learned weight matrix and non-linearity. After k rounds a node knows about everything within k hops, much like a conv filter's receptive field growing with depth. In fact an image is just a graph where pixels connect to their 8 neighbours.

Build it up: one GCN layer on 4 nodes

Graph: edges 1–2, 2–3, 2–4, 3–4. Node features (2-dimensional): h_1=(1,0),\ h_2=(0,1),\ h_3=(1,1),\ h_4=(2,0). The GCN layer adds self-loops (\hat A=A+I) and normalises by degree: H'=\mathrm{ReLU}(\hat D^{-1/2}\hat A\hat D^{-1/2}HW). Degrees including self-loop: (2, 4, 3, 3). Weights W=\begin{pmatrix}1&-1\\0.5&1\end{pmatrix}.

Worked example

① Normalised adjacency entries 1/\sqrt{d_id_j} for connected pairs: (1,1) = 0.5, (1,2) = 0.354, (2,2) = 0.25, (2,3) = (2,4) = 0.289, (3,3) = (3,4) = (4,4) = 0.333.

② Aggregate \hat A_{norm}H. Node 1: 0.5·(1,0) + 0.354·(0,1) = (0.5, 0.354). Node 2: 0.354·(1,0) + 0.25·(0,1) + 0.289·(1,1) + 0.289·(2,0) = (1.220, 0.539). Node 3: 0.289·(0,1) + 0.333·(1,1) + 0.333·(2,0) = (1.000, 0.622). Node 4 has the same neighbourhood as node 3: (1.000, 0.622).

③ Transform by W (row-vector × W): node 1: (0.5·1 + 0.354·0.5, −0.5 + 0.354) = (0.677, −0.146); node 2: (1.489, −0.681); nodes 3 and 4: (1.311, −0.378).

④ ReLU: H′ = (0.677, 0), (1.489, 0), (1.311, 0), (1.311, 0). Nodes 3 and 4 are now identical — they are structurally interchangeable (same features after aggregation), a known limit of plain message passing.

Parameters do not depend on the number of nodes or edges: the same W is applied at every node, so one trained GNN runs on graphs of any size. A realistic layer F = 64 → F′ = 64 has 64·64 + 64 = 4,160 weights. Tasks: node classification (use hv), edge/link prediction (combine hu, hv), graph classification/regression (pool all nodes). Cost per layer ≈ O(|E|·F + N·F·F′) — linear in edges, unlike attention's n².

The formal definition

h_v^{(l+1)}=\sigma\Bigl(W^{(l)}\sum_{u\in\mathcal N(v)\cup\{v\}}\frac{1}{\sqrt{\hat d_u\hat d_v}}\,h_u^{(l)}\Bigr)
hv(l)feature vector of node v after l layers (h(0) = input features)
𝒩(v)neighbours of v; the node itself is added (self-loop)
d̂vdegree of v counting the self-loop
W(l)learned weights, shared by all nodes of layer l
σnon-linearity (ReLU)

Variants: GraphSAGE (sample neighbours), GAT (attention weights over neighbours — a transformer restricted to edges), GIN (sum aggregation, more expressive).

Common traps
  • Over-smoothing: too many layers make all node vectors similar.
  • Aggregation must be permutation-invariant (sum/mean/max), never a concatenation in arbitrary neighbour order.
  • Hub nodes with thousands of neighbours make full-batch training memory-hungry; sample neighbours.
Where it shows up in AI
  • Molecules and drug discovery (property prediction), materials science, weather models on mesh graphs.
  • Social, citation and fraud networks; recommendation on user–item graphs (PinSage).
  • Road and traffic forecasting, knowledge graphs, and transformers themselves (full attention = a GNN on the complete graph).

Check yourself

1. Why do nodes 3 and 4 get identical outputs in the example?
After adding self-loops both have the same neighbourhood {2, 3, 4} and same degree 3, and aggregation only sees the multiset of neighbour features (1,1), (2,0), and node 2's (0,1) — identical for both.
2. How many parameters has a GCN layer 16→8 with bias?
16·8 + 8 = 136, regardless of graph size.
3. After 2 layers, how far away can information come from?
Two hops: a node's output depends on all nodes within graph distance 2.

Takeaways

  • Message passing = aggregate neighbours, transform with shared W, update; k layers see k hops.
  • Parameters are independent of graph size; cost is linear in edges.
  • Use a GNN when relationships between items are data in themselves.
7.6

Choosing an architecture

The questionYou have 20,000 labelled X-rays and one GPU, or 8 million customer-event sequences, or a tabular spreadsheet of 50,000 rows. Which blueprint do you start with — and why is the answer often "not the newest one"?

Intuition

An architecture is a bet about the structure of your data, called its inductive bias. A CNN bets that nearby pixels belong together and patterns repeat across space. An RNN bets that order matters and the past can be summarised. A transformer makes few assumptions and lets data decide who attends to whom — flexible, but it needs more data to discover structure that a CNN is given for free. A GNN bets that connections carry information. The right bet saves data and compute; a wrong one wastes both.

Worked example — sizing against data

A rule of thumb: a model with P parameters wants on the order of 10 or more training examples per parameter-equivalent of signal when trained from scratch; far fewer if you fine-tune a pre-trained one. A from-scratch 86.6 M-parameter ViT-B on 20,000 images is badly over-parameterised (4,330 parameters per image) and will memorise; the 80-parameter conv layer of lesson 7.1 plus a small head has the right bias for the job. Compute check: attention over n = 4,096 tokens costs 4,096²·d = 16.8 M·d MACs per layer, 16× that of n = 1,024.

Start with the simplest model that respects the data's structure and beat it before escalating.

Common traps
  • Picking by headline (the latest architecture) instead of by data structure and budget.
  • Ignoring baselines: gradient boosting often beats deep nets on tabular data.
  • Comparing parameter counts across families — a CNN and a transformer with the same parameters can differ 100× in compute.
Where it shows up in AI
  • Hybrids are common: CNN stem + transformer body (ConvNeXt/ViT hybrids), GNN + transformer (molecules), CNN encoder + LSTM decoder (captioning), embeddings feeding gradient boosting.
  • Foundation models make "fine-tune a pre-trained transformer" the default for text and increasingly for images and audio.

Check yourself

1. 5,000 labelled leaf photos, one laptop GPU. First choice?
A pre-trained CNN with a new head fine-tuned (small data, image bias, modest compute).
2. Why prefer a GRU to a transformer for a 10 ms on-device sensor stream?
Constant memory per step, tiny parameter count and streaming inference without n² attention.
3. Which data type suggests a GNN?
Data whose relationships (bonds, friendships, roads) matter as much as node attributes, with variable neighbourhood size.

Takeaways

  • Architecture = inductive bias: match it to the data's structure (grid, sequence, set, graph).
  • Small data needs strong bias or transfer learning; large data can afford flexible models.
  • Always weigh latency, memory and compute, not only accuracy and parameter count.
