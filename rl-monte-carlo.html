Module 3 · Monte Carlo methods

A Monte Carlo method learns from whole episodes. The agent plays a game or a task from start to finish, the total reward it collected is recorded, and that total is averaged over many episodes. No model of the world is needed, only the experience itself. This module covers how those averages estimate values, how they drive control, how to reuse data from a different policy with importance sampling, and where the method is strong and where it is weak.

The running example. Every lesson uses the same tiny world, a corridor with five cells numbered 0 to 4. Cells 1, 2 and 3 are the inside of the corridor, and cells 0 and 4 are the two ends, where the episode stops. The agent moves L (one cell left) or R (one cell right). Entering cell 0 gives reward 0. Entering cell 4 gives reward 1. Every other step gives reward 0. The discount factor is γ = 0.9 unless a lesson says otherwise, and the start is cell 2 unless stated.

How the labs work. Every lab is animated in slow, real-time steps. The walker moves one cell at a time, the returns are then carried back along the path, and only then do the estimates change. The random numbers are seeded, so each run is reproducible. Labs marked illustrative are toy simulations of a larger idea.

3.1

Monte Carlo prediction

The questionA robot has run 200 times through an aisle of a warehouse. Each run was logged from start to finish, together with whether it succeeded. We do not know the motor noise, the floor friction or the exact probability of each move. Using only these logged runs, how good is the policy that produced them, at each position in the aisle?

Intuition

Suppose you want to know how long your commute takes from a particular junction to the office. You do not need a map of the traffic. You drive the route many times, and each time you pass the junction you note how long the rest of the trip took. Averaged over the trips, those remaining times are your estimate of the junction's value. The estimate is only ready when a trip ends, because until then you do not know the total.

That is the whole idea of Monte Carlo prediction. The value of a situation is the average of the total reward that followed it, measured over real episodes. The word "Monte Carlo" means exactly this: estimate an expectation by sampling.

Build it up, one piece at a time

Step 1: the return. Suppose at time t the agent is in state S_t. The rewards that follow are R_{t+1}, R_{t+2}, \dots, where R_{t+1} is the reward for the step taken at time t. The return is the discounted sum of everything that follows:

G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = R_{t+1} + \gamma\, G_{t+1}

The discount γ makes near rewards count more than distant ones. The second form is the one we use in code: work backwards from the end of the episode, and each return is the next reward plus γ times the return that follows it.

Step 2: the value. The value of a state under a policy π is the expected return from that state, V_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]. The expectation is over the randomness of the policy and the environment. We cannot compute it directly without a model, but we can sample it: every time an episode visits s, the return from that visit is one sample.

Step 3: first visit or every visit. An episode can pass through the same state more than once. The first-visit method uses only the return from the first time s appears in the episode. The every-visit method averages the returns from all of the visits. Both converge to V_\pi(s) as the number of episodes grows.

Worked example: three episodes in the corridor

Start in cell 2. The policy being evaluated chooses L or R at random with probability 0.5 each. Three episodes are recorded. Episode 1 goes 2 → 3 → 4. Episode 2 goes 2 → 1 → 2 → 3 → 4. Episode 3 goes 2 → 1 → 0.

The rewards are: episode 1 gives R_1 = 0,\; R_2 = 1. Episode 2 gives R_1 = R_2 = R_3 = 0,\; R_4 = 1. Episode 3 gives R_1 = R_2 = 0. Working backwards with γ = 0.9:

\begin{aligned} &\text{Ep 1: } G_1 = 1,\; G_0 = 0 + 0.9(1) = 0.90 \\ &\text{Ep 2: } G_3 = 1,\; G_2 = 0.9,\; G_1 = 0.81,\; G_0 = 0.729 \\ &\text{Ep 3: } G_1 = 0,\; G_0 = 0 \end{aligned}

Now collect the returns by state (time index in brackets):

State 2 is the only state visited twice in one episode (episode 2), which is why the two methods disagree there. The first-visit average uses 0.729 from that episode, and the every-visit average uses both 0.729 and 0.900. For comparison, the true value under the uniform random policy, found by solving the Bellman equations exactly, is V(1) = 0.170,\; V(2) = 0.378,\; V(3) = 0.670. Three episodes give a noisy answer, and the estimate for state 2 (0.543) is above the truth purely because of sampling noise.

The formal definition

For each state s let N(s) be the number of returns collected for it so far, and let \text{Returns}(s) be the list of those returns. The Monte Carlo estimate is the average:

V(s) \approx \frac{1}{N(s)}\sum_{G \in \text{Returns}(s)} G \qquad\text{equivalently}\qquad V(s) \leftarrow V(s) + \frac{1}{N(s)}\big(G_t - V(s)\big)

The incremental form is the one labs use. The update moves the estimate toward the new return by a fraction 1/N(s). Because the first visit's return is an independent sample per episode, first-visit MC has the simplest theory. Under the usual conditions (the expected return exists and the policy is evaluated in a finite episodic task), both versions converge to V_\pi(s) as N(s) \to \infty.

Common traps
  • No episode end, no return. A return is defined only when the episode finishes (or is cut off, which introduces bias). A continuing task that never ends gives no sample to average.
  • Index slips. G_t starts from R_{t+1}, not R_t. Off-by-one errors in the reward index change every number in a hand calculation.
  • Forgetting the discount on the first term. The first reward after time t is multiplied by γ⁰ = 1, so G_0 = R_1 + \gamma R_2 + \cdots, not \gamma R_1 + \cdots.
  • Counting visits as episodes. Every-visit MC averages visits, not episodes. Two visits in one episode are correlated, which is why the every-visit estimate needs care in its analysis.
Where it shows up in AI
  • Evaluating a fixed policy from recorded experience, for example scoring a game-playing policy from the full games it has played.
  • Monte Carlo return targets are the basis of REINFORCE and other policy-gradient methods in Module 6, where the return of each episode weights the gradient.
  • Rollout-based search, such as the random playouts used to evaluate positions in Monte Carlo tree search, uses the same averaging of complete outcomes.
Pipeline placement. Estimate stage (the average is updated after each episode ends); the interact stage produces the episode, and the store stage keeps the returns or running sums per state. Cost per update: one pass over the episode, O(T) work for an episode of length T, and O(1) memory per state.

Check yourself

1. Change episode 3 in the worked example to 2 → 3 → 4 (rewards 0, then 1). What is the first-visit estimate of V(2) after the three episodes?
In the new episode 3, state 2 is visited at time 0 with return G_0 = 0 + 0.9(1) = 0.900. The first-visit average is (0.900 + 0.729 + 0.900)/3 = 2.529/3 = 0.843.
2. Why does the every-visit estimate for state 2 differ from the first-visit one in the worked example?
Episode 2 visits state 2 twice, at time 0 (return 0.729) and at time 2 (return 0.900). First-visit uses only the time-0 return, while every-visit uses both, so the every-visit average has four samples instead of three.
3. The exact value of state 2 under the uniform random policy is about 0.378, but the three-episode estimate is 0.543. Is the estimate biased?
No, the difference is sampling noise. Each return is an unbiased sample of V(2), so the average is unbiased for every number of episodes. With only three samples, the random variation is large (the standard deviation of one return from state 2 is about 0.40), so the average can sit well away from the truth.

Takeaways

  • Monte Carlo prediction estimates the value of a state by averaging the returns observed after visits to it.
  • It needs no model of the environment, but it must wait until each episode ends before any estimate changes.
  • First-visit and every-visit both converge; the choice changes how the samples are correlated, not where the average goes.
3.2

Monte Carlo control with exploring starts

The questionKnowing that cell 2 is worth 0.378 is not enough to act. To choose between L and R in cell 2, we need to know how good each action is there. Can we estimate the value of taking a particular action in a particular state, using only episodes, and then improve the policy by picking the best action?

Intuition

Imagine a chess player who knows how good each position is, but cannot see the consequences of each possible move. To choose, the player must know how good each move is from the current position. The quantity that answers this is the action value, written Q(s,a): the expected return after taking action a in state s and then continuing with the policy.

Monte Carlo control alternates two steps. First, play episodes and average the returns to update Q. Second, make the policy greedy: in each state, choose the action with the highest Q. Then play again. This alternation of evaluation and improvement is called generalised policy iteration, and it is the pattern behind almost every method in this course.

Build it up, one piece at a time

Step 1: action values. Q_\pi(s,a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]. The returns are the same as before, but the first action is fixed to a. The action value is what lets us compare actions without a model.

Step 2: greedy improvement. Given estimates Q, the greedy policy is \pi'(s) = \arg\max_a Q(s,a). The policy improvement theorem says this new policy is at least as good as the old one in every state.

Step 3: the problem of unvisited pairs. If the policy is greedy, it may never take an action it has not already valued. The value of an action that is never tried stays at its starting value, so the agent cannot discover that it is better. The fix in this lesson is exploring starts: every episode begins from a random state and a random first action, so every pair has a chance of being visited.

Worked example: two episodes with exploring starts

The initial policy is always R. Each episode starts from a random pair (s, a), takes that action, then follows the current greedy policy. Episode 1 starts at (2, L): the agent goes to cell 1, then R to 2, R to 3, R to 4. Episode 2 starts at (3, L): the agent goes to cell 2, then R to 3, R to 4. The returns, with γ = 0.9, are:

\begin{aligned} &\text{Ep 1: } G(2,L)=0.729,\; G(1,R)=0.810,\; G(2,R)=0.900,\; G(3,R)=1.000 \\ &\text{Ep 2: } G(3,L)=0.810,\; G(2,R)=0.900,\; G(3,R)=1.000 \end{aligned}

Averaging by first visit gives Q(2,L)=0.729,\; Q(1,R)=0.810,\; Q(2,R)=(0.900+0.900)/2=0.900,\; Q(3,L)=0.810,\; Q(3,R)=1.000. The greedy action is R in every cell: in cell 2, Q(2,R) = 0.900 is larger than Q(2,L) = 0.729. The policy does not change, and it is already optimal. Compare these estimates with the true optimal action values: 0.729, 0.810, 0.900, 0.810 and 1.000. Every estimate matches, because each pair was sampled exactly once or twice in a deterministic world.

The formal definition

For each episode, after computing the return G_t for the first visit to the pair (s,a), update the running average of Q, and then set the policy to be greedy:

Q(s,a) \leftarrow \text{average of } \text{Returns}(s,a), \qquad \pi(s) \leftarrow \arg\max_{a} Q(s,a)

Under exploring starts, with every pair sampled infinitely often, the policy converges to an optimal policy (Sutton and Barto, Section 5.4, for the tabular case). The proof relies on the policy improvement theorem. The condition is strong, which is why the next lessons relax it.

Q(s,a)the action value: expected return after taking a in s and then following the policy
\text{Returns}(s,a)the list of returns collected after first visits to the pair (s, a)
\pi(s)the deterministic greedy action in state s
\arg\max_athe action with the largest value; ties broken toward R in the lab

Common traps
  • Exploring starts are not a real-world option. A robot cannot be placed in an arbitrary state with an arbitrary first action. Exploring starts work in simulators that can reset to any state, and they are a stepping stone to the later methods.
  • A zero estimate is not a value. An action never tried has no samples, so its Q is just the initial value. Greedy choice then compares a real number with an unknown, and the unknown can hide a better action.
  • Ties are a policy decision. With Q(s,L)=Q(s,R)=0 at the start, the choice of tie-breaking decides the early behaviour.
Where it shows up in AI
  • Model-free control from complete episodes, where the agent learns action values without a model of the environment.
  • Generalised policy iteration, the pattern of alternating evaluation and improvement, returns in Module 4 (SARSA and Q-learning) and Module 5 (deep Q-learning).
  • Simulators with resettable states are the main setting where exploring starts are used, for example in training controllers before deployment.
Pipeline placement. Improve stage (the greedy policy is recomputed after each episode); interact stage produces the episode; the store stage keeps a table of Q and counts. Cost per update: O(T) for the backward pass over the episode, plus a per-state argmax over the actions.

Check yourself

1. After the two-episode example, what action does the greedy policy take in cell 2, and why?
R. Q(2,R) = 0.900 is larger than Q(2,L) = 0.729, so the greedy choice is R.
2. Why do exploring starts guarantee that every state-action pair is eventually updated?
Each episode begins from a randomly chosen pair with positive probability. Over many episodes, every pair is chosen as a start, so every Q(s,a) receives returns. Without this, pairs that the greedy policy never takes would keep their initial values forever.
3. An agent always starts at (2,R) and then follows its greedy policy. What is Q(2,L) after 1000 episodes, and why is this a problem?
It stays at its initial value 0, because no episode takes L in cell 2. The true value is 0.729. The greedy choice is still R, so the policy looks right, but the agent has no evidence about L, and a change in the environment that made L better would never be noticed.

Takeaways

  • Control needs action values, not just state values, so that the agent can compare actions without a model.
  • Monte Carlo control alternates averaging returns and acting greedily; this is generalised policy iteration.
  • Exploring starts make the method converge in theory but are unrealistic; the next lessons keep exploration inside the policy.
3.3

On-policy Monte Carlo with ε-soft policies

The questionExploring starts need a simulator that can reset to any state. A real agent starts where it is. How can an agent keep trying all actions during learning, without needing to be placed in arbitrary states, and still end up with a useful policy?

Intuition

A restaurant reviewer who only ever orders the dish they like best will never learn whether another dish is better. A good reviewer orders their favourite most of the time, but occasionally tries something else. The reviewer's policy is still mostly "order the favourite", but no dish is ever ruled out completely. This is the idea of an ε-soft policy: every action keeps some probability, so exploration never stops.

On-policy means the same policy generates the data and is being improved. The agent learns about the behaviour it actually uses, including its exploratory moves.

Build it up, one piece at a time

Step 1: the ε-greedy policy. Let |\mathcal A| be the number of actions, here 2. With probability 1-\varepsilon take the greedy action; with probability \varepsilon take an action uniformly at random. The chance of the greedy action is then 1-\varepsilon+\varepsilon/|\mathcal A|, and each other action gets \varepsilon/|\mathcal A|.

Step 2: why the policy must stay ε-soft. A policy is ε-soft if every action in every state has probability at least \varepsilon/|\mathcal A|. Because every pair keeps a chance to be sampled, Monte Carlo evaluation still reaches every Q(s,a), and no exploring start is needed.

Step 3: improvement stays inside the class. When we make the policy greedy with respect to Q, we must keep the ε-soft constraint. The new policy is therefore the ε-greedy policy for the current Q. The policy improvement theorem still applies inside this class, so the improved policy is never worse than the old one.

Worked example: the ε-greedy policy in cell 2

Take ε = 0.2 and two actions. Suppose the current estimates in cell 2 are Q(2,R) = 0.900 and Q(2,L) = 0.729. The greedy action is R, so

\pi(R\mid 2)=1-0.2+\frac{0.2}{2}=0.9,\qquad \pi(L\mid 2)=\frac{0.2}{2}=0.1,\qquad 0.9+0.1=1

The expected action value in cell 2 under this policy is

0.9(0.900)+0.1(0.729)=0.8829

This is less than the greedy value 0.900, which is the price of exploration. The learner pays a small cost for keeping its options open. In this corridor, the best ε-soft policy puts probability 0.9 on R in every cell, because each action must keep at least 0.1 and R is always the better choice.

The formal definition

For a state s, the ε-greedy policy with respect to the action values Q is

\pi(a\mid s)=\begin{cases}1-\varepsilon+\dfrac{\varepsilon}{|\mathcal A|} & \text{if } a=\arg\max_{a'}Q(s,a') \\[6pt] \dfrac{\varepsilon}{|\mathcal A|} & \text{otherwise}\end{cases}

On-policy first-visit Monte Carlo control generates episodes with the current ε-soft policy, updates Q by averaging returns, and then sets π to the ε-greedy policy for the new Q. Among all ε-soft policies, the limit of this process is the best one, not the optimal deterministic policy. With ε > 0 the limit cannot place probability 0 on any action.

\varepsilonthe exploration rate, 0 ≤ ε ≤ 1; here 0.2 in the worked example
|\mathcal A|the number of actions in the state (2 in the corridor)
\pi(a\mid s)the probability of choosing action a in state s
\arg\max_{a'}Q(s,a')the action with the highest current action value

Common traps
  • The ε-soft optimum is not the optimal policy. The algorithm is optimal only among policies that keep exploring. If you need the best deterministic policy, you must reduce ε over time or act greedily after learning.
  • Wrong ε-soft probabilities. The greedy action gets 1 − ε + ε/|A|, not 1 − ε. With two actions and ε = 0.2 the greedy probability is 0.9, not 0.8.
  • Mixing on-policy and off-policy data. Episodes from an old policy should not update the current one unless you use the importance weights of lesson 3.4.
Where it shows up in AI
  • ε-greedy exploration is the default exploration rule in deep Q-learning (Module 5) and in many tabular agents.
  • On-policy methods with stochastic policies appear in policy-gradient methods such as PPO (Module 6), which keep an explicit probability over actions so that exploration is built into the policy.
  • Deployed systems that must keep learning from their own actions, such as recommendation or ad ranking, face the same trade-off between exploiting the best known action and sampling alternatives.
Pipeline placement. Interact stage (episodes are generated by the ε-soft policy); the improve stage recomputes the ε-greedy policy after each batch; the store stage keeps Q, counts and ε. Cost per update: O(T) per episode, plus an argmax per state.

Check yourself

1. With ε = 0.2 and two actions, what are π(R|s) and π(L|s) when R is greedy?
π(R|s) = 1 − 0.2 + 0.2/2 = 0.9, and π(L|s) = 0.2/2 = 0.1. They sum to 1.

0.9(0.900) + 0.1(0.729) = 0.810 + 0.0729 = 0.8829.
3. In this corridor R is always the better action. What probability on R does the best ε-soft policy converge to, and why can it not be 1?

Takeaways

  • An ε-soft policy keeps every action possible, so Monte Carlo can learn all action values without exploring starts.
  • On-policy control learns the best policy within the ε-soft class, which is slightly worse than the optimal one.
  • The greedy probability is 1 − ε + ε/|A|; check it with the worked example before trusting a lab.
3.4

Importance sampling

The questionA recommendation system logged a month of decisions made by an old policy, which showed items at random. We now want to know how well a new policy, which mostly shows the best item, would have done. We cannot run the new policy on the users again. Can the logged episodes still tell us its value?

Intuition

Suppose you want to know the average height of people in a city, but your sample was taken mostly from the basketball court. You can still correct the sample. Tall people were over-sampled, so give each measured person a weight that says how much more or less likely they were to be chosen under the city's real mix. This reweighting is importance sampling.

In reinforcement learning, the logged policy is the behaviour policy b, and the policy we want to evaluate is the target policy \pi. An episode that the target policy would have produced often, but the behaviour policy rarely produced, gets a large weight. An episode the target policy would never produce gets weight zero.

Build it up, one piece at a time

Step 1: the ratio for one step. At a single step in state s with action a, the ratio is \pi(a\mid s)/b(a\mid s). It is bigger than 1 when the target policy likes the action more than the behaviour policy does.

Step 2: the ratio for a whole episode. Multiply the step ratios from time t to the end of the episode. The product \rho_{t:T-1} is the weight of that trajectory. The environment's own transition probabilities cancel from the ratio, so no model is needed.

Step 3: two estimators. With n sampled returns, the ordinary importance-sampling estimate is the sum of weighted returns divided by n. The weighted estimate divides by the sum of the weights instead. Ordinary is unbiased but can have huge variance; weighted is biased for small n but usually much steadier.

Worked example: the corridor with a deterministic target

The target policy always goes right: π(R|s) = 1 everywhere. The behaviour policy chooses L or R with probability 0.5 each. The value we want is the value of state 2 under π, which is 0.900: from cell 2 the target goes 2 → 3 → 4, with reward 1 on the second step, so 0.9 × 1 = 0.900.

Each step taken by the target contributes a ratio of 1/0.5 = 2. Each step taken as L contributes 0/0.5 = 0. Three episodes from cell 2 are recorded:

episodeactionsweight ρreturn G
AR, R2 × 2 = 40.900
BL, R, R, R0 (first action is L)0.729
CR, L, R, R0 (second action is L)0.729
\text{ordinary}=\frac{4(0.900)+0+0}{3}=1.200,\qquad \text{weighted}=\frac{4(0.900)+0+0}{4+0+0}=0.900

With only three episodes, the ordinary estimate says 1.2, which overshoots the true 0.9 by a third. The weighted estimate gives exactly 0.9, here because the only trajectories with weight have the same return. Add a fourth episode that repeats A (R, R): the ordinary estimate becomes 7.2/4 = 1.800, while the weighted one stays at 7.2/8 = 0.900. The ordinary estimator is unbiased in expectation, but a single large weight can dominate a short sample.

The formal definition

\rho_{t:T-1}=\prod_{k=t}^{T-1}\frac{\pi(A_k\mid S_k)}{b(A_k\mid S_k)},\qquad V^{\text{ord}}(s)=\frac{\sum_{i=1}^{n}\rho^{(i)}G^{(i)}}{n},\qquad V^{\text{wt}}(s)=\frac{\sum_{i=1}^{n}\rho^{(i)}G^{(i)}}{\sum_{i=1}^{n}\rho^{(i)}}

Importance sampling requires b(a\mid s)>0 wherever \pi(a\mid s)>0 (coverage). Otherwise some target trajectories could never be observed and no reweighting could recover them. Under coverage, the ordinary estimate is unbiased for V_\pi(s), and the weighted one is consistent: it converges to V_\pi(s) as n grows.

bthe behaviour policy: the policy that generated the data
\pithe target policy: the policy whose value we want
\rho_{t:T-1}the importance ratio of the trajectory from time t to the end
nthe number of sampled returns
G^{(i)}the return of the i-th sampled episode from the state of interest

Common traps
  • Zero weight is not zero information. A trajectory with weight 0 is still a sample. Ignoring zero-weight trajectories in the denominator of the weighted estimator changes the answer.
  • Weights explode. A ratio of 2 per step gives 2^k after k steps. Long episodes with a mismatched behaviour policy produce enormous, rare weights.
  • Ordinary versus weighted is a bias–variance choice. Ordinary is unbiased but volatile; weighted is biased for small samples but usually more stable. Neither is "the right one" for all data sizes.
Where it shows up in AI
  • Off-policy evaluation of recommendation and advertising policies from logs uses inverse propensity scoring (IPS) and its self-normalised version, which are the importance-sampling estimators of this lesson.
  • Off-policy corrections in distributed RL, such as Retrace and V-trace, truncate the importance ratios so that the weights cannot explode.
  • Learning from logged data in healthcare or education, where the logging policy is known but the new policy cannot be tested on people directly, follows the same reweighting logic.
Pipeline placement. Evaluate stage (the new policy is scored from logs before deployment); the store stage keeps the logged episodes with their behaviour probabilities, which the ratio needs. Cost per update: O(T) per episode to form the product, plus one running sum for the numerator and denominator.

Check yourself

1. Under π = always R and b = 0.5 for each action, what is the importance ratio of the trajectory 2 → 1 → 2 → 3 → 4?
0. Its first action is L, and the target policy takes L with probability 0, so the ratio is 0/0.5 times the others, which is 0.
2. Suppose π(R|s) = 0.8 in every state and b = 0.5. What weight does a trajectory with actions R, R receive?
(0.8/0.5) × (0.8/0.5) = 1.6 × 1.6 = 2.56.
3. In the worked example, why does the weighted estimate equal exactly 0.900 with three episodes?
Only episode A has nonzero weight, and every trajectory with nonzero weight has the same return, 0.900. The weighted average is therefore 0.900 whatever the number of such episodes. The ordinary estimate, 1.2, depends on how many zero-weight episodes were included in the divisor.

Takeaways

  • Importance sampling reweights returns from a behaviour policy so they estimate the value of a target policy.
  • The weight is a product of per-step probability ratios, so it can be zero or very large.
  • The ordinary estimator is unbiased but volatile; the weighted estimator is biased for small samples but usually steadier.
3.5

Off-policy Monte Carlo control

The questionWe want the agent to end up with the best deterministic (greedy) policy, but the agent must keep exploring while it learns, and exploring makes it deviate from that policy. Can we learn the greedy policy's action values from exploratory episodes, using the importance weights of lesson 3.4?

Intuition

A student studies from a messy set of practice exams, some of which take unusual routes through the material. The final exam will use the clean method the teacher recommends. The student can still learn the recommended method from the practice exams, provided they count only the parts of each exam that follow the recommended method, and give extra weight to the parts that a careful student would have done the same way. Learning about one policy while behaving with another is off-policy learning.

Build it up, one piece at a time

Step 1: the target is greedy. The target policy is \pi(s)=\arg\max_a Q(s,a), a deterministic policy. The behaviour policy b is any exploratory policy with coverage, here uniform random.

Step 2: walk the episode backwards. Start at the end of the episode with weight W=1. At each step from the end toward the start, first add the return and the weight to the statistics, update Q, and recompute the greedy action. If the action that the behaviour policy took is not the greedy action, stop: the earlier steps have a target probability of zero for the rest of the trajectory, so they carry no information about the greedy policy's return.

Step 3: multiply the weight. If the action was greedy, multiply W by 1/b(A_t\mid S_t) before moving to the previous step. With uniform behaviour, each greedy step doubles the weight.

Worked example: two episodes, backwards

Start with Q = 0 everywhere, the greedy policy taking R on ties, and b = 0.5 for each action. Episode 1 is 2 → 1 → 2 → 3 → 4 with actions L, R, R, R and rewards 0, 0, 0, 1. Working backwards with γ = 0.9, and using the weighted update with the running count C(s,a):

t(s, a)GW (before)C(s,a)Q(s,a)greedy at scontinue?
3(3, R)1.000111.000Ryes, W → 2
2(2, R)0.900220.900Ryes, W → 4
1(1, R)0.810440.810Ryes, W → 8
0(2, L)0.729880.729Rno: L ≠ R, stop

The update at time 0 for (2, L) is still applied; the stop comes after it. Episode 2 is 3 → 2 → 1 → 0 with actions L, L, L and rewards 0, 0, 0. The backward pass starts at (1, L) with G = 0 and W = 1; C(1,L) = 1, Q(1,L) = 0. The greedy action at cell 1 is R, which differs from L, so the pass stops immediately. The final greedy policy is R in cells 1, 2 and 3, and Q(2,L) = 0.729 equals the true optimal value 0.9 × 0.81 = 0.729.

The weight doubles at each greedy step, so the last update in episode 1 used W = 8. A long run of greedy steps before a deviation would give even larger weights, which is why the weighted average matters.

The formal definition

\begin{aligned} &C(s,a)\leftarrow C(s,a)+W,\qquad Q(s,a)\leftarrow Q(s,a)+\frac{W}{C(s,a)}\big(G-Q(s,a)\big) \\ &\pi(s)\leftarrow\arg\max_{a}Q(s,a) \\ &\text{if } A_t\neq\pi(S_t)\text{ then exit}; \qquad W\leftarrow W\,/\,b(A_t\mid S_t) \end{aligned}

This is the incremental weighted importance-sampling control of Sutton and Barto (Algorithm 5.7). Under coverage and with the target greedy, it converges to the optimal policy in the tabular case. The weights are recomputed per episode, so the algorithm never needs the transition model.

Wthe importance weight accumulated so far in the backward pass
Gthe return from the current step, computed backwards
b(A_t\mid S_t)the probability that the behaviour policy took the action taken
\pithe greedy target policy with respect to the current Q

Common traps
  • Stopping early is the rule, not a bug. Once the behaviour action differs from the greedy action, earlier steps get no credit under this algorithm. The updates are correct but few.
  • Coverage must hold. If the behaviour policy never takes an action that the target policy would take, that action's value can never be learned from data.
  • Slow when behaviour and target disagree. A very exploratory behaviour makes the pass stop early, so each episode produces little learning. This is the main practical cost of the method.
Where it shows up in AI
  • Off-policy control from logged data, where a conservative behaviour policy generated the logs and a greedy policy is to be deployed.
  • Learning from demonstrations or from a previous controller, where the old controller's actions are the behaviour policy.
  • Off-policy corrections for value-based RL, such as Retrace (Module 4 and 5), which keep the spirit of stopping or truncating the trace when the behaviour and target policies disagree.
Pipeline placement. Interact stage (the exploratory behaviour policy generates the data); improve stage (the greedy policy is recomputed during the backward pass); store stage (Q, the count C and the logged behaviour probabilities). Cost per update: O(T) per episode, with an early stop that often reduces the work.

Check yourself

1. In episode 2 of the worked example, why is only the (1, L) update made?
The backward pass starts at the last step, (1, L). The greedy action at cell 1 is R, and the agent took L, so the pass stops after that one update. Nothing earlier in the episode is updated.
2. What is the weight W just before the update at time 0 in episode 1, and why?
8. The three greedy steps at times 3, 2 and 1 each multiply W by 1/0.5 = 2, giving 2 × 2 × 2 = 8 before the time-0 update.
3. Why is off-policy MC control limited to episodes where the behaviour and greedy actions often agree?
Once a behaviour action differs from the greedy one, the backward pass stops, so the steps before that point do not contribute. When behaviour and greedy actions disagree often, few steps per episode are used, and the method learns slowly.

Takeaways

  • Off-policy control learns the greedy policy's values from exploratory episodes, using importance weights.
  • The backward pass stops at the first action that the greedy policy would not take, because the later weights would be zero.
  • Coverage and the behaviour's exploration rate decide how fast the method learns in practice.
3.6

Monte Carlo strengths and limits

The questionWe now have a complete family of Monte Carlo methods. Before moving on to methods that learn from every step, how good is Monte Carlo as an estimator? When is it the right choice, and when does its need for complete episodes become a serious limit?

Intuition

A Monte Carlo estimate is like a poll. Each respondent gives one honest answer, and the poll average is unbiased: it is aimed at the truth. But the spread of the answers sets how precise the average is, and the more uncertain each answer, the more respondents you need. Monte Carlo returns are honest answers that are sometimes very noisy: a return adds up every random reward until the episode ends.

Build it up, one piece at a time

Step 1: unbiased. The return G_t is a sample of a quantity whose expectation is V_\pi(S_t). Averaging unbiased samples gives an unbiased estimate, for any number of episodes. Monte Carlo never has to guess what the value of a later state is.

Step 2: high variance. The return sums many random rewards. The more steps in the episode and the more random the transitions, the larger the spread of G_t. From state 2 under the uniform random policy with γ = 0.9, the exact mean return is 0.378 and the standard deviation of one return is about 0.398.

Step 3: the rate. The standard error of the average of n independent returns is \sigma/\sqrt{n}. Quadrupling the data only halves the error. From the numbers above: with n = 25 episodes the standard error is about 0.080, with n = 100 it is about 0.040, and with n = 400 it is about 0.020.

Step 4: the need for complete episodes. Monte Carlo must wait until the episode ends before it can make any update. In a task that lasts thousands of steps, or never ends, that wait is the central practical limit.

Worked example: the error budget

Suppose a practitioner needs the value of a state estimated to within ±0.05 with about 95% confidence. Using the standard error for the corridor from state 2, σ ≈ 0.398, the approximate half-width is 1.96 × σ/√n. Setting this equal to 0.05:

1.96\cdot\frac{0.398}{\sqrt n}=0.05\quad\Rightarrow\quad \sqrt n=\frac{1.96\cdot 0.398}{0.05}=15.6\quad\Rightarrow\quad n\approx 244 \text{ episodes}

In the corridor, 244 episodes is cheap. In a task where each episode takes an hour of robot time, the same precision costs 244 hours. This is why the lab shows the error curve: the cost of precision grows with the square of the accuracy you want.

The formal definition

\mathbb E[\hat V_n(s)]=V_\pi(s),\qquad \operatorname{Var}[\hat V_n(s)]=\frac{\operatorname{Var}[G\mid S_t=s]}{n},\qquad \text{standard error}=\frac{\sigma}{\sqrt n}

Here \hat V_n(s) is the sample average of n returns from s. The first equation says the method is unbiased, the second that its variance falls as 1/n, and the third is the standard error. These hold when the returns are independent samples, which first-visit MC with independent episodes satisfies.

\hat V_n(s)the Monte Carlo estimate of the value of s after n episodes
\sigmathe standard deviation of a single return from s
nthe number of independent episodes

Common traps
  • Unbiased does not mean accurate. An unbiased estimator with large variance can be far from the truth for a long time. Check the spread, not only the mean.
  • Doubling precision costs four times the data. The 1/√n rate is a fundamental feature of averaging independent samples.
  • Episodes are not free. Counting episodes ignores the cost of each one. Compare methods by cost per unit of accuracy.
Where it shows up in AI
  • Monte Carlo returns are the baseline target that later methods, such as TD learning in Module 4, trade against bootstrapped targets with lower variance but some bias.
  • Episodic tasks such as games, simulated navigation and episodic robot trials are the natural home of Monte Carlo methods.
  • Policy-gradient methods (Module 6) use Monte Carlo returns in REINFORCE, and their high variance is the reason baselines and advantage estimates were introduced.
Pipeline placement. Evaluate stage (the error bars and sample counts are tracked as episodes arrive); the store stage keeps running sums and counts. Cost per update: one episode per unit of data, so the cost of accuracy is paid in episodes, not in per-step computation.

Check yourself

1. The error at 100 episodes is 0.10. Roughly what is the error at 400 episodes?
About 0.05. Quadrupling n halves the standard error, since the error falls as 1/√n.
2. Why is a Monte Carlo return an unbiased target for the value of the current state?
The value is the expected return from that state under the policy, and the return from a visit is one random draw of that expectation. Its average over episodes therefore has the right expectation.
3. A task never ends and has no reset. Why can pure Monte Carlo not learn from it?
A return is the sum of rewards up to the end of the episode, and there is no end. Pure Monte Carlo needs finished returns; truncating the sum at a horizon makes the estimate biased by an amount that depends on the discount.

Takeaways

  • Monte Carlo estimates are unbiased, but their variance grows with episode length and randomness, and the error falls only as 1/√n.
  • The method needs complete episodes, so it fits episodic tasks well and continuing tasks poorly.
  • Monte Carlo is the honest baseline: the next module keeps the unbiased idea but learns from every step, trading bias for much lower variance.
