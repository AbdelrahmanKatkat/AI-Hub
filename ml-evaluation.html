Module 5 · Evaluation & model selection

Training a model is easy; knowing whether it is good is the hard part. This module teaches you to measure a model honestly: the right metric for the job, a trustworthy estimate of future performance, a disciplined way to tune, a way to diagnose what is wrong, probabilities you can believe, and a check that the model treats groups fairly.

5.1

Classification metrics

The questionA screening model flags patients for a rare disease that affects 1 in 100 people. A colleague proudly reports "99% accuracy". Should you be impressed? And if not, which number should you look at — and where exactly do you cut the model's score to turn it into a yes/no decision?

Intuition

A classifier can be wrong in two different ways, and they rarely cost the same. Telling a healthy person "you might be ill" (a false alarm) costs a worry and a follow-up test. Telling a sick person "you are fine" (a miss) can cost a life. A single number like accuracy mixes both errors together and hides which one you are making. So we first count each kind of outcome separately — that table of counts is the confusion matrix — and then summarise it in different ways, each answering a different question:

  • Precision: "when the model raises an alarm, how often is it right?" (trust in alarms)
  • Recall (sensitivity): "of all the real cases, how many did it catch?" (coverage)
  • F1: one number balancing the two.
  • MCC: one number that uses all four cells and stays honest on imbalanced data.

Most models do not output yes/no; they output a score (a probability or a margin). You turn it into a decision with a threshold: "alarm if score ≥ t". Moving t trades false alarms for misses. ROC and precision–recall curves show all thresholds at once.

Build it up: 20 predictions by hand

Call "disease" the positive class. For each of 20 patients we have the truth and the model's yes/no answer. Counting gives four cells:

predicted positivepredicted negativetotal
actually positiveTP = 6FN = 410
actually negativeFP = 2TN = 810
total81220
Worked example

Accuracy = (TP+TN)/N = (6+8)/20 = 0.70.

Precision = TP/(TP+FP) = 6/8 = 0.75 — three alarms in four are real.

Recall = TP/(TP+FN) = 6/10 = 0.60 — it caught 6 of the 10 sick patients. Specificity = TN/(TN+FP) = 8/10 = 0.80.

F1 = 2PR/(P+R) = 2·0.75·0.60/1.35 = 0.90/1.35 = 0.667 (the harmonic mean, always closer to the smaller of the two).

MCC = (TP·TN − FP·FN)/√((TP+FP)(TP+FN)(TN+FP)(TN+FN)) = (48 − 8)/√(8·10·10·12) = 40/√9600 = 40/97.98 = 0.408.

The accuracy paradox

Now return to the rare disease: 1000 patients, 10 sick, 990 healthy. A model that always says "healthy" gets TN = 990, FN = 10, TP = FP = 0: accuracy = 990/1000 = 99%, recall = 0/10 = 0. It never finds a single sick patient. A genuinely useful model with TP = 8, FN = 2, FP = 30, TN = 960 has accuracy 968/1000 = 96.8% — lower — yet recall 0.80 and precision 8/38 = 0.21. The accuracy number rewarded the useless model. When classes are imbalanced, look at recall, precision, PR curves or MCC. (MCC of the always-healthy model is 0 — it correctly says "no better than chance".)

Worked example — AUC

The area under the staircase is the sum, over each negative, of the TPR height when that step moves right (width ⅓): 0.7 → ⅔, 0.4 → 1, 0.3 → 1. Area = ⅓(⅔ + 1 + 1) = ⅓·(8/3) = 8/9 = 0.889.

Equivalent meaning: AUC is the probability that a random positive is scored above a random negative. There are 3×3 = 9 pairs; the positive 0.9 wins 3, 0.8 wins 3, 0.6 wins 2 (it loses to the negative 0.7): 8 of 9 = 0.889 ✓.

Precision–recall on the same list: after rank 1 precision 1/1 at recall ⅓; after rank 2 precision 2/2 at recall ⅔; after rank 4 precision 3/4 at recall 1. Average precision AP = ⅓(1 + 1 + 0.75) = 0.917.

Choosing t by cost. If a miss costs c_{FN} and a false alarm costs c_{FP}, pick the threshold that minimises total expected cost c_{FP}\,FP+c_{FN}\,FN. With a calibrated probability p the rule is "alarm when p\ge c_{FP}/(c_{FP}+c_{FN})": if a miss is 9× worse than a false alarm, alarm whenever p ≥ 0.1, not 0.5.

Pipeline view — post-processing. The threshold is not part of the trained model; it is stored configuration applied after inference: score = model(x) (inference), then decision = score ≥ t[segment] (post-processing). Keep it in a config store so business can change the cost trade-off without retraining. Log for every request: model version, raw score, threshold used, decision, timestamp and (later) the true label — otherwise you can never recompute precision/recall in production or re-tune t.

The formal definition

P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad F_1=\frac{2PR}{P+R},\quad F_\beta=\frac{(1+\beta^2)PR}{\beta^2P+R}
MCC=\frac{TP\cdot TN-FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}},\quad AUC=\Pr\big(s(x^+)>s(x^-)\big)
TP, FP, FN, TNcounts of true/false positives and negatives; "positive" is the class you want to find
P, Rprecision and recall; recall equals the true-positive rate TPR = TP/(TP+FN)
FPRfalse-positive rate FP/(FP+TN) = 1 − specificity
βFβ weights recall β times as much as precision (β=2 favours recall)
MCCMatthews correlation, from −1 to +1; 0 = no better than chance
s(x)the model's score; x⁺ a random positive, x⁻ a random negative

Common traps
  • Accuracy on imbalanced data — see above. Always compare with the "predict the majority" baseline.
  • Threshold 0.5 is a default, not a law. It is only optimal when both errors cost the same and probabilities are calibrated.
  • ROC-AUC flatters rare-positive problems: the huge number of negatives keeps FPR tiny even when most alarms are false. Use PR-AUC/AP there.
  • Averaging metrics across classes (macro vs micro vs weighted) gives different answers; state which one you report.
  • Tuning t on the test set leaks. Choose it on validation data.
Where it shows up in AI
  • Fraud, spam and medical screening report precision/recall at an operating point; search and retrieval report precision@k.
  • Object detectors report AP (area under a PR curve) per class; the mean is mAP.
  • Logistic regression, gradient boosting and neural nets all output scores; the threshold is the product decision layered on top.
  • LLM safety classifiers are tuned to a recall target (e.g. catch 99% of unsafe content) and then judged by the precision they leave.

2. A miss costs 5 and a false alarm costs 1. With calibrated probabilities, at what probability should you raise an alarm?

Takeaways

  • Start from the confusion matrix; every other metric is a ratio of its cells.
  • Accuracy lies on imbalanced data; use precision, recall, F1, MCC and PR curves.
  • The threshold is a stored post-processing config chosen by cost, separate from training; log scores and thresholds.
  • ROC-AUC = probability a positive outranks a negative; PR-AUC is more honest when positives are rare.
5.2

Regression & ranking metrics

The questionA model predicts delivery times in minutes. It is off by 1, 0, 2, 2 and 10 minutes on five orders. Is it "about 3 minutes off" or "about 4.7 minutes off"? Both are correct answers to different questions — which one should you report, and how do you say it is better than just guessing the average?

Intuition

For numbers there is no "right or wrong", only how far off. The residual e_i=y_i-\hat y_i is the signed miss. Different metrics summarise the five misses differently:

  • MAE averages the sizes of the misses. Easy to read: "typically 3 minutes off". Every minute counts equally.
  • RMSE squares first, then averages, then takes the root. Squaring makes big misses count much more: a 10-minute miss weighs 100 while a 2-minute miss weighs only 4, so RMSE says "watch out for big errors".
  • R² asks: "how much of the variation did I explain compared to always predicting the mean?" 1 is perfect, 0 is no better than the mean, negative is worse.
  • MAPE reports errors as a percentage of the true value — scale-free, but explodes when y is near 0.

Worked example

MAE = 15/5 = 3. MSE = 109/5 = 21.8, RMSE = √21.8 = 4.669. MAPE = 0.583/5 = 11.7%.

Mean of y = 97/5 = 19.4. Total variation SStot = 9.4²+7.4²+4.4²+0.6²+20.6² = 88.36+54.76+19.36+0.36+424.36 = 587.2. Residual SSres = 109. R² = 1 − 109/587.2 = 0.814.

Outlier sensitivity. Drop the point with the 10-minute miss: MAE of the other four = 5/4 = 1.25, RMSE = √(9/4) = 1.5. With the outlier MAE went 1.25 → 3 (×2.4) while RMSE went 1.5 → 4.67 (×3.1). RMSE reacts harder, as designed.

Residual analysis matters more than any single number: plot residuals against the prediction. They should look like shapeless noise around zero. A curve means the model missed a pattern; a funnel (spread growing with ŷ) means errors are proportional — consider predicting log y; a few huge points mean outliers or data errors. The mean of the residuals above is 9/5 = 1.8 > 0: the model under-predicts on average (bias).

Ranking metrics judge ordered lists (search results, recommendations) where only the top matters. Precision@k = fraction of the top k that are relevant. NDCG uses graded relevance rel and discounts lower positions: DCG=\sum_i \frac{2^{rel_i}-1}{\log_2(i+1)}, divided by the DCG of the perfect ordering.

Worked example — NDCG@5

The system returns documents with relevance (3, 2, 3, 0, 1). DCG = 7/1 + 3/1.585 + 7/2 + 0 + 1/2.585 = 7 + 1.893 + 3.5 + 0 + 0.387 = 12.780. The ideal order (3,3,2,1,0) has DCG = 7 + 7/1.585 + 3/2 + 1/2.322 + 0 = 7 + 4.416 + 1.5 + 0.431 = 13.347. NDCG = 12.780/13.347 = 0.957. MAP averages precision at each relevant hit, then averages over queries — it is the ranking cousin of AP from 5.1.

The formal definition

MAE=\frac1N\sum_i|y_i-\hat y_i|,\quad RMSE=\sqrt{\frac1N\sum_i(y_i-\hat y_i)^2},\quad R^2=1-\frac{\sum_i(y_i-\hat y_i)^2}{\sum_i(y_i-\bar y)^2}
MAPE=\frac{100\%}{N}\sum_i\frac{|y_i-\hat y_i|}{|y_i|}
yi, ŷitrue value and prediction for example i
ȳmean of the true values (the "predict the average" baseline)
Nnumber of examples
R²fraction of variance explained, measured on held-out data (can be negative there)
religraded relevance of the document at rank i

MAE is the optimal-score metric for the median and RMSE for the mean of the conditional distribution — so training with squared loss targets the mean and absolute loss targets the median (see maximum likelihood).

Common traps
  • R² on training data always looks good and never decreases when you add features; report it on held-out data.
  • MAPE blows up when y≈0 and penalises over-prediction less than under-prediction; consider sMAPE or MAE.
  • Comparing RMSE across datasets with different scales is meaningless; compare with a baseline on the same data.
  • One average hides subgroups: the model can be fine on typical orders and terrible on rush hour.
Where it shows up in AI
  • Demand and price forecasting (RMSE, MAPE, quantile loss); regression heads inside detectors use L1/Huber losses.
  • Search, recommendation and RAG retrieval are scored with NDCG, MAP and recall@k.
  • Huber loss blends the two: quadratic for small errors, linear for large ones — a trained-in compromise between RMSE and MAE.

Check yourself

1. y = (2, 4, 6), ŷ = (3, 4, 4). Compute MAE and RMSE.
Errors −1, 0, 2. MAE = 1. RMSE = √((1+0+4)/3) = √1.667 = 1.291.
2. A model has R² = −0.2 on the test set. What does it tell you?
It predicts worse than always outputting the training mean — it has overfit or is broken.
3. Why prefer MAE over RMSE for data with a few corrupt outliers?
Squaring lets a few huge errors dominate RMSE; MAE grows only linearly with them and reflects the typical error.

Takeaways

  • MAE = typical miss; RMSE punishes big misses; R² compares with the mean baseline; MAPE is relative.
  • Residual plots reveal what a single number hides.
  • Ranking tasks use precision@k, MAP and NDCG, which reward putting relevant items first.
5.3

Cross-validation

The questionYou have only 20 labelled examples. One random 16/4 split gives 100% accuracy; another gives 50%. Which number do you believe? How can you use all the data for both training and honest testing?

Intuition

A single validation split is one roll of a die: with few examples, luck decides. k-fold cross-validation rolls it k times in a way that every example is used for validation exactly once. Cut the data into k equal folds. Round 1: train on folds 2..k, test on fold 1. Round 2: train on all but fold 2, test on fold 2. And so on. You get k scores; their mean is your estimate of performance, and their spread tells you how much to trust it.

Build it up: exact folds by hand

20 examples numbered 1–20, shuffled once with a fixed seed, then dealt into k = 5 folds of 4:

foldvalidation examplescorrect / 4accuracy
17, 14, 3, 1930.75

Worked example

Mean accuracy = (0.75+1+0.75+0.5+1)/5 = 4/5 = 0.80. Deviations: −0.05, +0.20, −0.05, −0.30, +0.20; squares sum to 0.0025+0.04+0.0025+0.09+0.04 = 0.175. Sample variance = 0.175/(5−1) = 0.04375, std = 0.209.

Standard error of the mean = std/√k = 0.209/√5 = 0.094. So "0.80 ± 0.09". A competitor scoring 0.83 is not clearly better. Caveat: the folds share training data and are not independent, so this standard error is somewhat optimistic — treat it as a lower bound on the uncertainty.

Cost: k models trained instead of one. Each trains on (k−1)/k of the data = 16 examples here.

Choosing k. Larger k (e.g. 10, or leave-one-out k = N) trains on nearly all data, so each score is less pessimistic, but costs more and the estimates are more correlated. k = 5 or 10 is the usual compromise.

Variants — match the split to how the model will be used:

  • Stratified k-fold: keep the class ratio in every fold. With 5 positives and 15 negatives and k = 5, each fold gets exactly 1 positive and 3 negatives; unstratified folds could contain none.
  • Group k-fold: all rows of one patient/user/site stay in the same fold, otherwise the model "recognises" the person and the score is inflated.
  • Time-series (rolling-origin) CV: only train on the past: train [1..4]→test 5, train [1..5]→test 6, … Never shuffle time.
  • Nested CV: an inner CV picks hyper-parameters, an outer CV measures the whole procedure — the honest way to report a tuned model's performance (lesson 5.4).
Pipeline view. Everything learned from data — imputation means, scalers, encoders, feature selection — must be fitted inside each training fold and only applied to the validation fold. Fitting a scaler on all data first leaks validation statistics. In code: put preprocessing and model in one pipeline object and cross-validate that.

The formal definition

\widehat{CV}=\frac1k\sum_{j=1}^{k}\ell\big(\mathcal D_j;\,f^{(-j)}\big),\qquad SE=\frac{s}{\sqrt k},\quad s^2=\frac1{k-1}\sum_j\big(\ell_j-\widehat{CV}\big)^2
𝒟jthe j-th fold, used only for validation in round j
f(−j)the model trained on all folds except j
ℓjthe metric (loss or accuracy) of that model on fold j
s, SEspread across folds and the standard error of the mean

  3. Lower the class separation: the fold scores spread out and the ± grows.
Common traps
  • Leakage through preprocessing fitted before the split; or duplicates of the same item in train and validation folds.
  • Shuffling time-series lets the model peek at the future.
  • Reporting the best fold or the CV score of a model you tuned on the same folds — optimistic; use nested CV.
  • Treating ±SE as exact: folds are correlated; for model comparison use the paired differences on the same folds.
Where it shows up in AI
  • Every tabular benchmark and Kaggle workflow (out-of-fold predictions also feed stacking ensembles).
  • Medical and geospatial ML use group/spatial CV so neighbouring samples do not leak.
  • Forecasting uses rolling-origin evaluation; deep learning with huge data usually uses one fixed validation set because k trainings are too expensive.

2. Why group k-fold for 50 patients with 20 scans each?
Scans of one patient are highly similar; if some are in train and others in validation the model is rewarded for recognising the patient, inflating the score. Keeping each patient in one fold measures generalisation to new patients.

Takeaways

  • k-fold uses every example for validation once; report mean ± standard error.
  • Choose stratified, group or time-series splits to mimic deployment.
  • Fit preprocessing inside each fold; use nested CV when tuning.
5.4

Hyper-parameter tuning

The questionYour gradient-boosting model has a learning rate, a tree depth and a regularisation strength. Each run takes minutes. You can afford about 60 runs. Where do you put them — and how do you avoid fooling yourself with a validation score you have optimised against?

Intuition

Parameters (weights, split points) are learned by training; hyper-parameters (depth, learning rate, k in k-NN, C in an SVM) are set before training and control how learning happens. Tuning is itself a search problem: the unknown function validation score = g(hyper-parameters) is expensive to evaluate and noisy. Think of hunting for the highest hilltop in fog with a limited number of altitude readings.

  • Grid search: lay a regular lattice of values and try them all. Simple and reproducible, but the cost multiplies with every added hyper-parameter.
  • Random search: draw each setting at random from a range (often log-uniform for rates). Every trial tests a new value of every hyper-parameter.
  • Bayesian optimisation: build a cheap model of g from the trials so far (a Gaussian process or TPE), then pick the next trial where improvement looks most promising (explore uncertain regions, exploit good ones).

Build it up: counting trials

Worked example — grid vs random

Three hyper-parameters with 5 values each: the grid needs 5³ = 125 runs. Add a 4th and it is 625; with d = 6 it is 5⁶ = 15,625.

Suppose only one of the three really matters (common in practice). The 125 grid runs test just 5 distinct values of it, each repeated 25 times. 125 random runs test 125 distinct values of it.

Budget 60 runs. If the "good region" is the best 5% of the search space, one random trial misses it with probability 0.95, so all 60 miss it with 0.95⁶⁰ = 0.046: a 95.4% chance of at least one hit, regardless of dimension d. (59 trials give 95.1%; the break-even is n ≥ ln 0.05/ln 0.95 = 58.4, so 59.) A grid with the same budget in d = 6 could afford only 2 values per axis (2⁶ = 64) — it would barely sample the space.

Worked example — one Bayesian step (expected improvement)

The best score so far is f* = 0.82. The surrogate says a candidate has predicted mean μ = 0.80, uncertainty σ = 0.05. Its mean is below f*, but uncertainty gives a chance. With z = (μ − f*)/σ = −0.4, Φ(−0.4) = 0.3446, φ(−0.4) = 0.3683:

EI = (μ − f*)Φ(z) + σφ(z) = (−0.02)(0.3446) + 0.05(0.3683) = −0.0069 + 0.0184 = 0.0115. The next trial goes where EI is highest.

Budgets and early stopping. Most configurations are clearly bad after a little training. Successive halving: start 27 configurations at 1 epoch, keep the best third and give them 3 epochs, keep the best third → 9 epochs, then the last survivor gets 27. Total cost 27·1+9·3+3·9+1·27 = 108 epochs, versus 27·27 = 729 for training all fully — about 7× cheaper. (Hyperband runs several such brackets.) Early stopping during one run is the same idea: stop when validation loss stops improving.

Over-tuning the validation set. Every trial peeks at the validation score. Suppose 100 configurations all have a true accuracy of 0.80 and the validation set has 400 examples, so each measured score has noise σ = √(0.8·0.2/400) = 0.02. The maximum of 100 such scores is about 2.5σ above the mean: ≈ 0.85. You "found" 0.85 when the truth is 0.80. Remedies: a final untouched test set, nested CV, fewer trials, and being suspicious of tiny gains.

Pipeline view. The chosen hyper-parameters are stored with the model artifact (model card + config) so training is reproducible; log every trial (params, seed, score, time) in an experiment tracker. The search lives in the training pipeline, never in inference.

The formal definition

\lambda^\*=\arg\min_{\lambda\in\Lambda}\;\widehat{CV}\big(A_\lambda,\mathcal D\big),\qquad EI(\lambda)=\mathbb E\big[\max(0,\,f^\*-g(\lambda))\big]\;\text{(for a loss; mirrored for a score)}
λa hyper-parameter setting; Λ the search space
Aλthe learning algorithm configured by λ
CVcross-validated loss (lesson 5.3)
f*best value seen so far
EIexpected improvement: the acquisition function used to choose the next λ

Lab — three searches on one landscape

Try this
  1. Run grid and random with the same budget on a landscape where only one axis matters: compare the best score each found and how many distinct values of the important axis each tested.
  2. Run Bayesian search: early points are spread out, later points cluster near the peak.
  3. Switch to the narrow-ridge landscape and add noise: all methods struggle; the best-so-far curve flattens.
Common traps
  • Linear grids for rates: learning rates and regularisation span orders of magnitude; search on a log scale.
  • Tuning on the test set or reporting the validation score of the winner as the expected performance.
  • Ignoring noise: a 0.3-point difference between two trials may be seed luck; average over seeds or folds.
  • Search ranges too narrow: if the best value sits on the boundary, extend the range.
Where it shows up in AI
  • AutoML (Optuna, Hyperopt, Ray Tune, Vizier) = random/TPE/Bayesian search plus Hyperband pruning.
  • Neural architecture search and learning-rate schedules are tuned the same way, at scale, with early stopping.
  • Large-model training cannot afford many full runs: hyper-parameters are tuned on small models and transferred.

Check yourself

1. A grid with 4 values for each of 5 hyper-parameters: how many runs? With 5-fold CV?
4⁵ = 1024 configurations; × 5 folds = 5120 trainings.
2. Why does random search beat grid when only a few hyper-parameters matter?
Each random trial uses a new value of the important parameter; a grid wastes most runs repeating the same few values of it while varying unimportant ones.
3. Successive halving, 16 configs, keep the best half, epochs 1, 2, 4, 8 per round. Total epochs?
16·1 + 8·2 + 4·4 + 2·8 = 16+16+16+16 = 64 (versus 16·8 = 128 for full training of all).

Takeaways

  • Random search beats grid in high dimensions; Bayesian search spends trials wisely when runs are expensive.
  • Early stopping and successive halving cut cost by abandoning bad configurations early.
  • The more you tune, the more optimistic the validation score: keep a final test set or use nested CV.
5.5

Diagnosing models

The questionYour model scores 85% on validation and you need 95%. Should you collect more data, build a bigger model, add features, regularise more, or clean labels? Guessing wastes weeks. Is there a measurement that tells you which lever to pull?

Intuition

Compare two numbers: the error on the data the model trained on and the error on unseen validation data.

  • Both high and close together: the model is too simple to capture the pattern even on its own training data — high bias (underfitting). It is like a student who only read the chapter titles: poor on homework and on the exam.
  • Training error low, validation error much higher: the model memorised the training set — high variance (overfitting). The student who memorised last year's answers: perfect homework, fails the exam.

A learning curve plots both errors against the amount of training data. A validation curve plots them against a complexity knob (tree depth, polynomial degree). The shape of the curves tells you which problem you have and whether more data would help.

Build it up: reading numbers

casetrain errorval errorgapdiagnosis
A18%20%2 ptshigh bias — both high, tiny gap
B2%15%13 ptshigh variance — big gap
C3%5%2 ptshealthy (compare with target / human level)
Worked example — decomposing 15% error

Suppose the best achievable error (humans / label noise floor) is 1%. In case B: avoidable bias = train error − floor = 2 − 1 = 1 pt; variance = val − train = 13 pts. The gap is the problem: attack variance. In case A: avoidable bias = 18 − 1 = 17 pts, variance = 2 pts: attack bias.

Learning-curve reading: if, as data grows from 100 to 1000 to 10000 examples, validation error falls 25% → 18% → 15% while training error rises 0% → 1% → 2%, the curves are converging slowly with a 13-pt gap: more data helps. If instead both curves have already flattened at 20% and sit together, more data is useless — you need a more expressive model or better features.

Error analysis. Take 100 validation mistakes and tag each by cause. Example tally: 40 blurry photos, 30 mislabelled, 20 rare class, 10 other. Fixing the 30 mislabelled cases can remove at most 30% of all errors (30 of 100), an upper bound on the gain of each fix. Work on the biggest bucket first; this beats guessing. Also check slices (by region, device, class) for hidden weak spots.

Data fix or model fix? If a human can solve the example from the same input, the model can learn it: look at data quantity/quality. If even humans cannot (information is missing from the features), no model change will help; add a feature or accept the floor.

The formal definition

\mathbb E\big[(y-\hat f(x))^2\big]=\underbrace{\big(\mathbb E\hat f(x)-f(x)\big)^2}_{\text{bias}^2}+\underbrace{\operatorname{Var}\big(\hat f(x)\big)}_{\text{variance}}+\underbrace{\sigma^2}_{\text{noise}}
f(x)the true underlying relationship
f̂(x)the learned model; its expectation 𝔼 is over different random training sets
bias²systematic error: how far the average model is from the truth (too-simple models)
variancehow much the model changes with the training sample (too-flexible models)
σ²irreducible noise in y; no model can beat it

Lab — curves, complexity and a diagnosis

Try this
  1. Complexity at 1 (a straight line on curved data): both curves flatten high and close — the lab says "high bias" and suggests a richer model.
  2. Complexity at 9: training error is near zero, validation error stays high — "high variance"; raise the data size to watch the gap shrink.
  3. Move to the middle: the validation error is lowest. This is the sweet spot of the bias–variance trade-off. Press play to watch the curves being drawn as data grows.
Common traps
  • "More data always helps" — not when bias dominates.
  • "Bigger model always helps" — not when variance dominates, and it costs inference time.
  • Comparing with the wrong yardstick: 15% error may be excellent if humans reach 14%.
  • Diagnosing from one noisy run: repeat with different seeds/folds before concluding.
Where it shows up in AI
  • Deep-learning practice (the "train/dev gap" recipe): reduce avoidable bias with bigger nets and longer training, then reduce variance with data and regularisation.
  • Scaling-law studies are learning curves on a log-log scale: error versus data and parameters.
  • Model debugging dashboards track train vs validation loss every epoch — the same diagnosis in time.

Check yourself

1. Train error 1%, validation error 12%. Name the problem and two remedies.
High variance (gap of 11 pts). More data/augmentation, stronger regularisation, simpler model, early stopping.
2. Train 22%, validation 24%, human level 2%. Will 10× more data fix it?
Unlikely: avoidable bias is 20 pts and the gap only 2. Use a more flexible model, better features or longer training.
3. Of 200 validation errors, 60 are label mistakes. What is the maximum gain from fixing the labels, if overall error is 10%?
60/200 = 30% of errors, i.e. at most 3 points (10% → 7%).

Takeaways

  • Small gap, high error = bias; large gap = variance.
  • Learning curves say whether more data helps; validation curves find the right complexity.
  • Error analysis by category ranks the fixes by their upper-bound payoff.
5.6

Calibration & uncertainty

The questionA model says "90% chance of rain" on 100 days. On how many of those days should it actually rain for you to trust the number? If it rained on only 67, your decisions (umbrellas, loans, treatments) built on "90%" are wrong even if the model ranks days well. How do we measure and repair this?

Intuition

A model is calibrated if its stated probabilities match reality: among all cases where it says 0.8, about 80% are positive. Ranking quality (AUC) and calibration are separate properties: a model can order cases perfectly yet be wildly over-confident — typical for boosted trees, SVMs and big neural networks. Calibration matters whenever the number itself feeds a decision: expected-cost thresholds (5.1), risk scores, or combining models.

A reliability diagram puts predicted probability on the x-axis and the observed frequency on the y-axis, one dot per bin. A perfect model lies on the diagonal. Points below the diagonal = over-confident; above = under-confident.

Build it up: Brier score and bins by hand

Ten predictions: probabilities p = (0.9, 0.9, 0.8, 0.8, 0.7, 0.7, 0.3, 0.3, 0.2, 0.1) with outcomes y = (1, 1, 1, 0, 1, 0, 0, 1, 0, 0).

Worked example

Brier score = mean of (p − y)²: 0.01, 0.01, 0.04, 0.64, 0.09, 0.49, 0.09, 0.49, 0.04, 0.01 → sum 1.91 → 0.191. Reference: always saying the base rate 0.5 gives 0.25, so 0.191 is better than that baseline (0 is perfect).

Reliability bins. High bin (p ≥ 0.5): six predictions, mean p = (0.9+0.9+0.8+0.8+0.7+0.7)/6 = 0.80, observed positives 4 of 6 = 0.667. Low bin (p < 0.5): four predictions, mean p = 0.225, observed 1 of 4 = 0.25.

Expected calibration error ECE = Σ (nb/N)·|mean pb − freqb| = 0.6·|0.80−0.667| + 0.4·|0.225−0.25| = 0.08 + 0.01 = 0.09. The high bin sits below the diagonal: over-confident.

Repairing it (post-hoc, on held-out data). Keep the trained model, learn a small map from raw score to calibrated probability on a calibration set that was not used for training:

  • Platt scaling: fit p'=\sigma(a\,s+b) — two numbers; smooth, works with little data; good when the distortion is sigmoid-shaped.
  • Isotonic regression: fit a monotonically increasing staircase to (score, outcome) — flexible, needs more data (hundreds+) and can overfit. In the example the high bin would be mapped from 0.80 down to ≈0.67.
  • Temperature scaling for neural nets: divide logits by T > 1 before the softmax to soften over-confidence; one parameter, ranking unchanged.

Uncertainty beyond one probability. For regression we want a prediction interval. Conformal prediction gives one with a guarantee using only a calibration set: compute the absolute residuals on held-out data, take a high quantile q, and report ŷ ± q.

Worked example — split conformal

Nine calibration residuals: 0.4, 1.1, 0.2, 0.7, 1.5, 0.3, 0.9, 0.6, 2.0. Want 80% coverage (α = 0.2). Sort: 0.2, 0.3, 0.4, 0.6, 0.7, 0.9, 1.1, 1.5, 2.0. Take the ⌈(n+1)(1−α)⌉ = ⌈10·0.8⌉ = 8-th smallest: q = 1.5. A new prediction of 20.0 becomes the interval [18.5, 21.5]. Under exchangeability, it covers the truth at least 80% of the time — whatever the model.

Pipeline view — post-processing again. The calibrator (Platt a, b, isotonic table, temperature T, conformal q) is a few stored numbers applied after inference: raw → calibrated probability → threshold → decision. Version it together with the model; re-fit it when the data drifts. Log raw and calibrated scores, bin-wise observed rates (once labels arrive) and ECE over time — a rising ECE is an early drift alarm.

The formal definition

\Pr(y=1\mid \hat p=p)=p\;\;\forall p,\qquad Brier=\frac1N\sum_i(\hat p_i-y_i)^2,\qquad ECE=\sum_{b=1}^{B}\frac{n_b}{N}\,\big|\overline{p}_b-\overline{y}_b\big|
C(x)=\big[\hat y(x)-q,\;\hat y(x)+q\big],\quad q=\text{the }\lceil (n+1)(1-\alpha)\rceil\text{-th smallest of }|y_j-\hat y_j|
p̂the model's predicted probability of the positive class
b, nba probability bin and the number of predictions in it
p̄b, ȳbmean predicted probability and observed positive fraction in bin b
αmiscoverage level (α = 0.2 → 80% intervals)
qthe conformal half-width from calibration residuals

Lab — slide a miscalibrated model onto the diagonal

Try this
  1. Make the model over-confident with the slider: the reliability curve bends below the diagonal and ECE and Brier rise.
  2. Choose Platt, then slide the correction strength from 0 to 1: the curve glides onto the diagonal. Isotonic gives a staircase that fits the bins more tightly.
  3. Notice AUC does not change — calibration is monotone, so ranking is untouched.
Common traps
  • Calibrating on the training or test data: use a separate calibration split (or CV).
  • Too few points per bin gives a noisy reliability diagram; check bin counts, use quantile bins.
  • Good calibration ≠ good model: always predicting the base rate is perfectly calibrated and useless.
  • Calibration drifts when prevalence or data changes; re-check periodically.
Where it shows up in AI
  • Modern deep nets are typically over-confident; temperature scaling is the standard fix.
  • Medical risk scores, credit default and weather forecasts are judged by Brier score and reliability diagrams.
  • Active learning, abstention ("I don't know") and LLM-as-classifier confidence all rely on probabilities meaning something.
  • Conformal prediction wraps any model (including LLM-based) with coverage-guaranteed sets or intervals.

Check yourself

1. p = (0.8, 0.4), y = (1, 1). Brier score?
((0.8−1)² + (0.4−1)²)/2 = (0.04+0.36)/2 = 0.20.
2. Of 50 cases scored 0.9, 40 were positive. Over- or under-confident, and what is the gap?
Observed 0.80 < 0.90: over-confident by 0.10 (point below the diagonal).
3. Can calibration change AUC?
No. Platt, isotonic (strictly monotone parts) and temperature scaling preserve the order of scores, so ROC-AUC is unchanged (isotonic ties can slightly flatten it).

Takeaways

  • Calibrated means "says 80% → right 80% of the time"; reliability diagram, ECE and Brier measure it.
  • Fix with Platt, isotonic or temperature scaling on a held-out calibration set; it is a stored post-processing step.
  • Conformal prediction turns any model into one with intervals/sets of guaranteed coverage.
5.7

Interpretability & fairness

The questionA loan model has 94% accuracy. A regulator asks two things: "Why did it reject this applicant?" and "Does it treat the two demographic groups equally?" A single accuracy number answers neither. What can we compute?

Intuition

Interpretability asks which inputs drive the model. Global methods describe the whole model ("income matters most"); local ones explain one prediction ("this applicant was rejected mostly because of debt ratio"). Fairness asks whether error rates and decisions are distributed acceptably across groups. Both start from simple counting.

Build it up: permutation importance by hand

Idea: if a feature matters, shuffling it (breaking its link to the target) should hurt the score. Take a fitted model \hat y=2x_1+0.5x_2 and five validation rows:

rowx₁x₂yŷerror
1154.54.50
2235.55.50
3347.58.0−0.5
4418.08.5−0.5
55211.511.00.5
Worked example

Baseline MSE = (0+0+0.25+0.25+0.25)/5 = 0.15.

Permute x₁ by rotating it up one row → (2,3,4,5,1), keep x₂: predictions become 2·2+2.5 = 6.5, 7.5, 10, 10.5, 3 → errors y−ŷ = −2, −2, −2.5, −2.5, 8.5 → squares 4+4+6.25+6.25+72.25 = 92.75 → MSE = 18.55. Importance of x₁ = 18.55 − 0.15 = 18.40.

Permute x₂ → (3,4,1,2,5): errors 1, −0.5, 1, −1, −1 → squares 1+0.25+1+1+1 = 4.25 → MSE = 0.85. Importance of x₂ = 0.85 − 0.15 = 0.70.

So x₁ matters about 26× more than x₂ (coefficient 2 vs 0.5, and bigger spread). In practice repeat with several random shuffles and average. Caveat: correlated features share importance and shuffling creates unrealistic rows.

Partial dependence (PDP): set one feature to a value v for every row, predict, average; sweep v to get the curve "average prediction vs feature". SHAP idea: split a prediction fairly among features using Shapley values from game theory — each feature's share is its average marginal contribution over all orderings. For our linear model it is exact and simple: φj = wj(xj − mean xj). With means x̄₁ = 3, x̄₂ = 3, the average prediction is 7.5; for the point (5, 2): φ₁ = 2(5−3) = +4, φ₂ = 0.5(2−3) = −0.5, and 7.5 + 4 − 0.5 = 11 = ŷ ✓. The contributions add up to the prediction — that is why SHAP is popular.

Fairness metrics from a small table

100 applicants per group. Group A has 60 truly creditworthy, group B has 30. The model's outcomes:

TPFNFPTNselected
group A481283256
group B181276325
Worked example

Demographic (statistical) parity: selection rates A = 56/100 = 0.56, B = 25/100 = 0.25; difference = 0.31, ratio 0.25/0.56 = 0.446 (below the "four-fifths" rule-of-thumb 0.8).

Equal opportunity: true-positive rates A = 48/60 = 0.80, B = 18/30 = 0.60; difference = 0.20 — qualified people in B are missed more often. Equalised odds also compares FPR: A 8/40 = 0.20, B 7/70 = 0.10.

Predictive parity: precision A = 48/56 = 0.857, B = 18/25 = 0.72.

The groups have different base rates (0.60 vs 0.30), and that has a consequence: with unequal base rates and an imperfect model, you cannot satisfy parity of selection rates, equal error rates and equal precision at the same time (the impossibility results of Kleinberg et al. and Chouldechova). Choosing which fairness notion applies is a policy and ethics decision, not a statistical one.

Pipeline view and documentation. Group-specific thresholds, if used, are stored post-processing config just like 5.1's threshold — and are legally sensitive in some jurisdictions. Log decisions with group membership (where lawful) to monitor these gaps over time. Document limits in a model card: intended use, training data, metrics per slice and group, known failure modes, and what the model must not be used for.

The formal definition

DPD=\Pr(\hat y=1\mid A)-\Pr(\hat y=1\mid B),\qquad EOD=\Pr(\hat y=1\mid y=1,A)-\Pr(\hat y=1\mid y=1,B)
PI_j=\mathrm{score}(\text{shuffled }x_j)-\mathrm{score}(\text{original}),\qquad \phi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(|F|-|S|-1)!}{|F|!}\big[v(S\cup\{j\})-v(S)\big]
A, Bthe two groups (a protected attribute such as gender or age band)
ŷ=1the favourable decision (approve, hire, flag)
DPDdemographic parity difference (0 = equal selection rates)
EODequal-opportunity difference (0 = equal true-positive rates)
PIjpermutation importance of feature j: the loss increase when its link to y is broken
φj, F, S, vShapley value of feature j; F all features; S a subset; v(S) the model output using only the features in S

Lab — two groups, one threshold, a trade-off

Try this
  1. With one shared threshold, find the accuracy-maximising value and read the parity and equal-opportunity gaps.
  2. Unlock separate group thresholds: slide group B's threshold left until the true-positive rates match (equal opportunity) and note what happens to accuracy and to selection rates.
  3. Try to make selection rate, TPR and precision all equal at once — you cannot when base rates differ.
Common traps
  • "Remove the protected attribute and the model is fair." Proxies (postcode, school) carry it back in; check outcomes, not inputs.
  • Importance is not causation: a feature can be important because it is a proxy for something else.
  • Correlated features split or hide importance; permute them as a group.
  • One fairness metric is never "the" answer; they conflict, and groups are not the only slices that matter.
Where it shows up in AI
  • Tree ensembles ship with feature importance; TreeSHAP and permutation importance are standard audit tools for credit, insurance and clinical models.
  • Regulation (EU AI Act, equal-credit and anti-discrimination law, GDPR "meaningful information about the logic") pushes explanations and bias audits.
  • Toolkits (Fairlearn, AIF360) compute these gaps and provide post-processing threshold optimisers; image/LLM systems are audited per demographic slice.

Check yourself

1. Group A selected 30 of 60 applicants, group B 10 of 40. Demographic parity difference?
0.50 − 0.25 = 0.25 (ratio 0.5).
2. Shuffling feature f leaves the validation error unchanged. What does that suggest?
The model does not rely on f (it may still be informative but redundant with a correlated feature that carries the signal).
3. Why can't we equalise selection rate, TPR and precision when base rates differ?
Precision depends on base rate through Bayes' rule; with different base rates, equal TPR/FPR forces unequal precision, and equal selection rates forces unequal TPR or FPR (unless the model is perfect).

Takeaways

  • Permutation importance, PDP and SHAP explain what the model uses; shuffling a feature and measuring the loss is the simplest honest test.
  • Fairness metrics compare selection rates, TPR, FPR or precision across groups; they cannot all be satisfied together.
  • Thresholds per group and calibration are stored post-processing config; document limits in a model card and monitor gaps in production.
