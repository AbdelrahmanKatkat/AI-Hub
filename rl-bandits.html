Module 1 · Bandits & exploration

The simplest reinforcement learning problem has no states at all: you face a row of slot machines, pull one lever at a time, and see a noisy reward. Even this stripped-down problem contains the central tension of all RL: you must explore to learn which option is good and exploit what you already know to earn reward now. Everything later in the course builds on these ideas.

Where this sits in the loop. A bandit learner runs the whole learning loop with one state: interact (pull an arm), store (a running estimate per arm), estimate (update that estimate from the reward), improve (choose the next arm from the estimates). Nothing depends on where the agent is, so every choice affects only the immediate reward and the information it reveals.

How the labs work. Each lab is an illustrative simulation with a fixed random seed, so every run is reproducible. Press Play, Step or change a slider and the learner responds at a slow, readable pace. Every number is labelled.

1.1

The k-armed bandit

The questionA casino has three slot machines. Each pull costs the same and pays a random amount whose average differs from machine to machine. You have 100 pulls and no information. Which machine do you play, and how do you decide when to keep playing one and when to try another?

Intuition

Picture yourself in front of the three machines. The first pull tells you a little: machine 2 paid 1.7 units, machine 1 paid 0.4. Is machine 2 better? One pull cannot tell, because every machine pays noisily: even the best machine sometimes pays less than the worst one. Yet you cannot wait forever, since each pull is also money you are spending. This is the bandit problem, named after the one-armed slot machine, which is also called a "one-armed bandit".

Three things make it hard. First, the rewards are noisy: a single reward is a weak clue about a machine's average. Second, you learn only about the machine you pulled. Pulling machine 1 tells you nothing about machine 3. Third, every pull has a cost of learning: if you spend all your pulls on a bad machine to find out it is bad, you have paid for that knowledge with reward you did not collect.

The bandit problem is the reinforcement learning problem with the states removed. There is an agent, an action, a reward, and a learning goal, but the world never changes, so no action leads to a different situation. That makes it the cleanest place to see exploration and exploitation without anything else getting in the way.

Build it up: one machine, then three

Step 1: a reward is a random draw around a mean. Suppose machine 1 pays a random amount with average q^*(1)=1.0. Each pull returns a value that sometimes is above 1.0 and sometimes below. The average, q^*(1), is the number that matters for choosing; the single rewards are noise around it.

Step 2: the value of an action is its average reward. Write A_t for the arm chosen at step t and R_t for the reward it returns. The action value of arm a is the expected reward when we choose it:

q^*(a) = \mathbb{E}\,[\,R_t \mid A_t = a\,]

With three arms, the best possible average is q^*_{\max}=\max_a q^*(a). If we knew q^* we would pull the best arm every time and never waste a pull.

Step 3: measure a strategy by its regret. Regret is the reward we gave up compared with always pulling the best arm. Each pull of arm a costs the gap q^*_{\max}-q^*(a). Over T pulls:

\mathrm{Regret}_T = \sum_{t=1}^{T}\big(q^*_{\max} - q^*(A_t)\big)

Regret is the right yardstick because it is zero for a perfect player and it grows whenever we pull bad arms. A good learner keeps its regret growing slowly, ideally more slowly than T itself, so that its average reward per pull approaches the best value.

Worked example: scoring a sequence of pulls

Three arms with true values q^*=(1.0,\;2.0,\;1.5). The best value is q^*_{\max}=2.0 (arm 2). Suppose we pull arms 1, 3, 2, 1. The gaps are:

\begin{array}{c|c|c}\text{pull}&\text{arm}&\text{gap } 2.0-q^*(A_t)\\\hline 1&1&2.0-1.0=1.0\\2&3&2.0-1.5=0.5\\3&2&2.0-2.0=0.0\\4&1&2.0-1.0=1.0\end{array}

So \mathrm{Regret}_4 = 1.0+0.5+0+1.0 = 2.5. The expected reward of this sequence is (1.0+1.5+2.0+1.0)/4 = 1.375 per pull, against 2.0 for an oracle: the gap is 0.625 per pull, and 4 × 0.625 = 2.5, which matches.

Now a realised reward. Pull 3 chose arm 2 and returned 1.7, not 2.0. That single number is not q^*(2); it is q^*(2) plus noise of -0.3. The regret above uses the true values, which the learner never sees.

The formal definition

We have a set of actions \mathcal A=\{1,\dots,k\}. At each step the agent picks A_t\in\mathcal A and receives R_t drawn from a distribution that depends only on the chosen arm. The policy, written \pi_t(a), is the probability of picking arm a at step t.

q^*(a)=\mathbb E[R_t\mid A_t=a],\qquad \mathrm{Regret}_T=T\,q^*_{\max}-\mathbb E\Big[\sum_{t=1}^{T}R_t\Big]

The two forms are equal in expectation: the first writes the regret as a sum of gaps, the second as the best possible total minus what the agent actually collected.

kthe number of arms (actions)
t, Tthe step counter, and the horizon (total number of pulls)
A_tthe arm pulled at step t
R_tthe reward returned at step t; it is random
q*(a)the true action value of arm a: the mean reward if a is pulled
q*_maxthe best true action value, max over a
E[·]expectation: the average over the randomness

Common traps
  • A single reward is not a value. An arm that paid 3.0 once is not necessarily better than one that averages 2.0. Values are averages over many pulls.
  • Regret needs the true values. The learner cannot compute regret; it is a yardstick the designer uses to compare strategies on problems where the truth is known.
  • Exploring is not wasted. Pulls on worse arms cost reward, but they buy information. The question is how much to spend, which is the rest of this module.
Where it shows up in AI
  • A/B testing and online experiments. Show two versions of a page and measure a conversion rate. A bandit version shifts traffic towards the better version as evidence accumulates, instead of splitting it 50/50 until the end.
  • Recommendation and ad selection. Each impression chooses one item from a set and observes a click or no click. Systems such as news recommenders treat the choice as a bandit with many arms.
  • Choosing among model outputs. Picking which of several candidate answers to show, given a noisy quality score, is a bandit problem whenever the score can be observed only after a choice.

Check yourself

1. With q* = (1.0, 2.0, 1.5), what is the regret after pulling arm 1 five times?
Each pull of arm 1 costs 2.0 − 1.0 = 1.0, so five pulls give regret 5.0.
2. Why can a learner not simply compute its regret while it learns?
Regret compares rewards with q*_max and q*(a), which are the true means. The learner only observes noisy rewards, so it can estimate those means but cannot know them exactly.
3. If all three arms had the same true value, what would the regret of any policy be?
Zero. Every gap q*_max − q*(a) is zero, so no pull costs anything. Exploration is free when the options are equally good.

Takeaways

  • A bandit is repeated choice among k actions, each with an unknown mean reward q*(a) and noisy observations.
  • Regret is the reward lost compared with always pulling the best arm; it is the standard measure of a strategy.
  • Each pull both earns reward and reveals information, which is why exploration has a cost and a purpose.
1.2

Sample averages & incremental updates

The questionAn arm has paid 1, 3, 2 and then 6. What is its value? And if the arm is pulled a million times, should we store a million rewards to compute its average, or can we update a single number after each pull?

Intuition

The obvious estimate of an arm's value is the average of the rewards it has paid. If it paid 1, 3, 2 and 6, its average is 3. The average is the best guess that uses the data without favouring any one reward, and it is what the word "expected" means in the definition of q^*.

There is a catch for a learner. Storing every reward is wasteful, and recomputing the average from scratch after each pull repeats work. Instead, keep the current estimate Q and nudge it towards each new reward. The nudge is the error (new reward minus current estimate), scaled by a step size. This pattern, new estimate = old estimate + step × error, will return in every lesson of this course, so it is worth understanding it here in its simplest form.

Build it up: the average as a nudge

Step 1: the average of n rewards. Let R_1,\dots,R_n be the rewards an arm returned in its first n pulls. The sample average is

Q_n = \frac{1}{n}\sum_{i=1}^{n} R_i

Step 2: the same average, one reward at a time. Suppose we already have Q_{n-1}, the average of the first n−1 rewards. The sum of the first n is the old sum plus R_n, and the old sum is (n-1)Q_{n-1}. So

Q_n = \frac{(n-1)\,Q_{n-1} + R_n}{n} = Q_{n-1} + \frac{1}{n}\big(R_n - Q_{n-1}\big)

The last form is the important one. The new estimate is the old one plus 1/n times the error R_n - Q_{n-1}. A surprising reward (large error) moves the estimate a lot when n is small, and a nearly-expected reward barely moves it. As n grows, each new reward has less weight, because the average already holds many rewards.

Worked example: the arm that paid 1, 3, 2, 6

Start with Q_0=0 and use the update with step 1/n.

\begin{aligned}Q_1&=0+\tfrac11(1-0)=1.000\\Q_2&=1+\tfrac12(3-1)=2.000\\Q_3&=2+\tfrac13(2-2)=2.000\\Q_4&=2+\tfrac14(6-2)=3.000\end{aligned}

Check against the definition: the averages are (1)/1=1, (1+3)/2=2, (1+3+2)/3=2 and (1+3+2+6)/4=3. They agree.

Notice step 3. The reward 2 was exactly what the arm had already been estimated at, so the error was zero and the estimate did not move. The update never needs the old rewards, only Q_{n-1} and n.

How reliable is Q_4=3? If the noise has standard deviation \sigma=1, the standard error of an average of four rewards is \sigma/\sqrt4 = 0.5. The estimate is good to about half a unit, and it becomes twice as precise only after four times as many pulls.

The formal definition

Q_n = Q_{n-1} + \alpha_n\big(R_n - Q_{n-1}\big),\qquad \alpha_n = \frac{1}{n}

With \alpha_n=1/n this rule reproduces the sample average exactly. If the rewards are independent draws with the same finite mean q^*, then Q_n \to q^* as n\to\infty (the law of large numbers). The standard error of Q_n is \sigma/\sqrt n, where \sigma is the noise standard deviation.

Q_nthe estimate of the arm's value after its n-th pull
R_nthe reward from the n-th pull of this arm
α_nthe step size; here 1/n, which shrinks as data accumulates
R_n − Q_{n−1}the error: what happened minus what we expected
σthe standard deviation of the reward noise

  2. Let it run to about 40 rewards. The orange line wanders at first and then settles near the dashed line μ. The blue band (Q_n ± 2σ/√n) narrows as n grows.

Common traps
  • Off-by-one in the step size. The first reward should set the estimate exactly, so the first step size is 1/1 = 1. A step of 1/(n−1) or a fixed 1/2 gives a different number.
  • The average assumes a fixed target. If the arm's true mean drifts, an average over all history lags behind it. Lesson 1.6 replaces 1/n with a constant step size for this reason.
  • Small samples mislead. Four rewards give an estimate with a standard error of half the noise level. Acting greedily on such estimates is a problem we return to in the next lessons.
Where it shows up in AI
  • Monte Carlo value estimation. Module 3 estimates a state's value as the average of observed returns, using exactly this incremental rule with step 1/n.
  • Constant-step updates everywhere in RL. The temporal-difference update of Module 4 has the form new = old + α × error, the same pattern with a target that depends on the next estimate.
  • Streaming statistics. Systems that track click-through or latency without storing every event use the same running update, so they use constant memory.

Check yourself

1. An arm pays 4, 4, 10. Using Q_0 = 0 and step 1/n, what is Q_3?
Q_1 = 4. Q_2 = 4 + (4 − 4)/2 = 4. Q_3 = 4 + (10 − 4)/3 = 6. This equals the plain average (4 + 4 + 10)/3 = 6.
2. If the noise standard deviation is σ = 2, how many pulls are needed before the standard error is 0.2?
σ/√n = 0.2 gives √n = 2/0.2 = 10, so n = 100.
3. Why does the update Q_n = Q_(n−1) + (R_n − Q_(n−1))/n not need to store past rewards?
The sum of past rewards is hidden in Q_(n−1): it equals (n−1)·Q_(n−1). The new average needs only the old average, the count n and the new reward.

Takeaways

  • A sample average can be updated one reward at a time: Q_n = Q_(n−1) + (1/n)(R_n − Q_(n−1)).
  • The update has the form new = old + step × error; this pattern runs through all of reinforcement learning.
  • The standard error σ/√n shows how precise an estimate is, and why many pulls are needed to separate close arms.
1.3

Epsilon-greedy exploration

The questionSuppose you have estimated the three arms as Q = (1.2, 0.4, 0.9) after some pulls. Always pulling the arm with the highest estimate looks sensible. But what if the estimate for arm 2 is wrong, and it is in fact the best arm? How do we keep learning about arms we currently think are worse, without giving up too much reward?

Intuition

The simplest answer is a coin with a small chance of landing on "explore". Most of the time, pick the arm that currently looks best (greedy). Occasionally, with probability \varepsilon (epsilon), pick an arm uniformly at random. The random picks are the exploration; the greedy picks are the exploitation. A pure greedy learner can lock onto an early winner and never find a better arm. A small amount of randomness is enough to break the lock.

The trade-off is simple to state. A larger \varepsilon finds the best arm more reliably, but it wastes more pulls on the others, so the average reward per pull is lower. A smaller \varepsilon earns more per pull, but it may take longer to discover the best arm or, with a bad start, never find it.

Build it up: how often do we pull each arm?

Step 1: the greedy choice. If the greedy arm is the one with the largest Q(a), the greedy choice is \arg\max_a Q(a), read "the arm whose index gives the largest Q".

Step 2: the random choice. With probability \varepsilon we ignore Q and pick each of the k arms with probability 1/k. Random picks include the greedy arm too, so the greedy arm gets extra pulls from exploration as well.

Step 3: the probability of choosing the greedy arm. Add the two routes: greedy with probability 1-\varepsilon, plus random with probability \varepsilon landing on it, which is \varepsilon/k. Each other arm is chosen with probability \varepsilon/k only.

Worked example: four arms, two values of ε

Four arms with true values q^*=(1.0,\;2.0,\;1.5,\;0.5); the best is arm 2 and the estimates have found it. With k=4:

\varepsilon=0.1:\quad P(\text{greedy arm}) = 1-0.1+\tfrac{0.1}{4} = 0.925,\qquad P(\text{each other arm}) = \tfrac{0.1}{4} = 0.025
\varepsilon=0.3:\quad P(\text{greedy arm}) = 1-0.3+\tfrac{0.3}{4} = 0.775,\qquad P(\text{each other arm}) = 0.075

The expected reward per pull is the probability-weighted average of the true values. For \varepsilon=0.1, the other arms have a total value of 1.0+1.5+0.5=3.0:

\mathbb E[R]=0.925\cdot 2.0 + 0.025\cdot(1.0+1.5+0.5) = 1.850+0.075 = 1.925

For \varepsilon=0.3: 0.775\cdot 2.0 + 0.075\cdot 3.0 = 1.550+0.225 = 1.775. The oracle, which always pulls arm 2, earns 2.0. So the 0.1 learner loses 0.075 per pull and the 0.3 learner loses 0.225 per pull, even though both find the best arm.

Over T=1000 pulls, the 0.1 learner makes about 100 random picks. About a quarter of them land on the best arm, so roughly 900 + 25 = 925 pulls go to arm 2, which is 92.5% of pulls, as the formula predicts.

A learner that never explores gets stuck. Take two arms, q^*=(1.0,\;2.0), with all estimates starting at 0. Greedy breaks the tie by picking arm 1. Its reward is 1.2 (a lucky draw), so Q(1)=1.2. Now Q(1)=1.2 > Q(2)=0, so the greedy learner pulls arm 1 forever. Its estimate for arm 1 converges to 1.0, and arm 2, the best arm, is never tried. Its reward is 1.0 per pull against 2.0 for the oracle. An ε of 0.1 would eventually pull arm 2 about 5% of the time, and the estimate for it would correct itself.

The formal definition

A_t=\begin{cases}\text{a uniformly random arm} & \text{with probability }\varepsilon\\ \arg\max_a Q_t(a) & \text{with probability }1-\varepsilon\end{cases}

Here Q_t(a) is updated by the sample-average rule of lesson 1.2. In the testbed used by the lab, ties are broken by the lowest arm index, and the same random numbers are reused for every ε, so the curves are directly comparable.

εthe exploration rate, between 0 and 1: the probability of a random pick
kthe number of arms
argmax_a Q_t(a)the arm whose current estimate is largest
1 − ε + ε/kthe probability of choosing the greedy arm

  2. Watch the tally chips at the bottom. Blue chips are greedy picks; orange chips are random picks. About one chip in ten should be orange.

Common traps
  • Exploring is not the same as choosing the worst arm. A random pick is uniform over all arms, so it is usually a worse arm but sometimes the best one.
  • A fixed ε never stops exploring. With ε = 0.1, the learner keeps paying about 0.075 per pull even after it knows the answer. Decaying ε over time reduces this cost, at the price of needing a schedule.
  • Comparing at one step can mislead. A high ε can look better early and worse late. Always read the curves over the full horizon.
Where it shows up in AI
  • The default exploration baseline. ε-greedy is the simplest exploration method and is often the first thing tried before more sophisticated ones.
  • Deep Q-learning. DQN (Module 5) chooses actions ε-greedily while it learns a value network, and the ε schedule is one of its tuned hyperparameters.
  • Recommendation with a safety margin. Showing a random item a small fraction of the time keeps estimates for new items from freezing at their first impressions.

Check yourself

1. With k = 5 arms and ε = 0.2, what is the probability that the greedy arm is chosen?
1 − 0.2 + 0.2/5 = 0.8 + 0.04 = 0.84.
2. Using the four-arm worked example with ε = 0.1, what is the expected reward per pull if the greedy arm were arm 3 (value 1.5) instead of arm 2?
Probability 0.925 on arm 3 and 0.025 on each other arm. The other arms total 2.0 + 1.0 + 0.5 = 3.5, so E[R] = 0.925·1.5 + 0.025·3.5 = 1.3875 + 0.0875 = 1.475. This is lower because the greedy arm is worse than the oracle, which is why the estimates must find arm 2 first.
3. Why does the two-arm example with ε = 0 never discover arm 2, even though its estimate is 0 and not negative?
The greedy rule compares estimates only. Arm 1's estimate (1.2) is above arm 2's (0), so arm 2 is never chosen. Since arm 2 is never pulled, its estimate never changes from 0, and the comparison never changes.

Takeaways

  • ε-greedy picks the greedy arm with probability 1 − ε + ε/k and each other arm with probability ε/k.
  • A pure greedy learner can lock onto a poor arm forever; a small ε is enough to keep it learning.
  • Larger ε buys faster discovery at the cost of a steady loss per pull; the right value depends on the horizon.
1.4

Upper confidence bound

The questionEpsilon-greedy explores blindly: a random pick is as likely to go to an arm pulled 100 times as to one pulled once. Could the learner instead explore where it is most uncertain? An arm with few pulls has an unreliable estimate and might be much better than it looks.

Intuition

Imagine two restaurants. One you have visited ten times and rated 3 stars on average. The other you have tried once and rated 4 stars. Which should you visit next? The one you tried once might be better than 4 stars, or worse than 3. Your uncertainty about it is large. A sensible strategy is optimism under uncertainty: act as if each option could be as good as its plausible upper limit. The arm with the highest plausible limit is either good, or it is a clear candidate to learn about.

The upper confidence bound (UCB) formalises this. For each arm it adds to the estimate a bonus that is large when the arm has few pulls and shrinks as the arm is pulled. The learner then picks the arm with the largest estimate-plus-bonus. Exploration is not random; it is aimed at the arms whose true value is still unknown.

Build it up: the bonus

Step 1: the estimate with an uncertainty allowance. Let N_t(a) be the number of times arm a has been pulled before step t, and t the total number of pulls so far. The UCB score of arm a is

\text{score}_t(a) = Q_t(a) + c\sqrt{\frac{\ln t}{N_t(a)}}

Step 2: read the bonus. The term \sqrt{\ln t / N_t(a)} grows with \ln t, which means the bonus of every arm slowly rises while the arm waits, and falls with N_t(a). An arm pulled often gets a small bonus; a neglected arm's bonus keeps rising until it is pulled. The constant c sets how strongly we trust the bonus: c=0 is pure greedy, and larger c means more exploration.

Step 3: untried arms come first. An arm with N=0 has an unbounded score, so each arm is pulled once before the formula takes over.

Worked example: which arm is pulled after 10 pulls?

After t=10 pulls, arms 1, 2 and 3 have been pulled N=(5,\,3,\,2) times, with estimates Q=(1.0,\,1.2,\,0.8). Use c=2, so \ln 10 = 2.3026.

\begin{aligned}\text{arm 1: }&\; 2\sqrt{2.3026/5}=2\cdot0.6786=1.3572,&\;\text{score}=1.0+1.3572=2.3572\\\text{arm 2: }&\; 2\sqrt{2.3026/3}=2\cdot0.8760=1.7522,&\;\text{score}=1.2+1.7522=2.9522\\\text{arm 3: }&\; 2\sqrt{2.3026/2}=2\cdot1.0730=2.1460,&\;\text{score}=0.8+2.1460=2.9460\end{aligned}

Arm 2 has the highest score, 2.9522, narrowly ahead of arm 3 at 2.9460. Arm 3 has the largest bonus, because it has been pulled only twice, but its estimate is low. The margin is small, and that is what makes UCB interesting: the choice depends on the bonus and the estimate together.

Arm 1 has the most pulls (five), so its bonus is the smallest, and its score, 2.3572, is the lowest of the three.

The formal definition

A_t = \arg\max_a\Big[\,Q_t(a) + c\sqrt{\frac{\ln t}{N_t(a)}}\,\Big]

Under the standard analysis (Auer, Cesa-Bianchi and Fischer, 2002), the expected regret of UCB grows only logarithmically in T, which is a strong guarantee compared with ε-greedy, whose regret is linear in T for a fixed ε.

score_t(a)the UCB score: estimate plus uncertainty bonus
Q_t(a)the sample-average estimate of arm a
N_t(a)the number of pulls of arm a so far
tthe total number of pulls so far
cthe exploration constant; c = 2 is a common choice in examples

  2. Watch the faded bonus bar on top of each arm. Each time an arm is pulled, its bonus shrinks, and the others' bonuses keep growing slowly.

Common traps
  • The bonus is not a probability. It is a term that makes the score optimistic in a controlled way. Its scale depends on c and on the time t.
  • UCB assumes rewards in a known range. The standard guarantees need rewards bounded in a known interval, and a tuned c. A large c explores too much; c = 0 is greedy.
  • Stationarity is assumed. The bonus shrinks with N, so it stops exploring an arm whose value has changed. Lesson 1.6 returns to this.
Where it shows up in AI
  • Principled exploration in bandits and monte-carlo tree search. The UCT rule used in MCTS (Module 7) is UCB applied at every node of a search tree.
  • Online experiments. Adaptive experiment platforms use upper confidence bounds to move traffic towards promising variants while keeping a record of uncertainty.
  • Bonus-based exploration in deep RL. Count-based and prediction-error bonuses (Module 8) follow the same principle: add an uncertainty term to the reward.

Check yourself

1. Using the worked example, what would arm 2's bonus be if it had been pulled 12 times instead of 3, with t = 10 and c = 2?
2·√(2.3026/12) = 2·√0.19188 = 2·0.4380 = 0.8760. So the bonus drops from 1.7522 to 0.8760 and the score falls to 1.2 + 0.8760 = 2.0760.
2. Why does the formula pull each arm once before using the score?
An arm with N = 0 has no estimate and an infinite bonus, so its score is infinite. The rule treats each untried arm as maximally uncertain, and tries it first.
3. With c = 0, what does UCB reduce to, and what is the risk?
It becomes pure greedy: the arm with the largest estimate (after the initial untried pulls). The risk is locking onto an early lucky arm, as in the ε-greedy example with ε = 0.

Takeaways

  • UCB adds an uncertainty bonus c√(ln t / N(a)) to each estimate and picks the largest score.
  • Exploration is aimed at arms with few pulls, not spread at random, and each arm's bonus shrinks as it is tried.
  • The guarantee is logarithmic regret under stated assumptions (bounded rewards, stationarity), a strong property compared with fixed-ε exploration.
1.5

Gradient bandits & softmax preferences

The questionBoth ε-greedy and UCB pick arms from value estimates. What if the learner instead keeps a preference for each arm, a number that says how much it likes that arm, and turns the preferences into probabilities? Then the learner can improve its policy directly, by nudging preferences up for arms that paid better than expected.

Intuition

Think of a student choosing a seat in a lecture. Each seat has a preference score, a number the student raises when the seat turned out well and lowers when it did not. The student does not pick the highest score deterministically; the scores become probabilities, and seats with higher scores are chosen more often. Over time the scores reflect experience and the choices concentrate on the good seats.

This is a different style of learning. Instead of estimating values and acting greedily, the learner adjusts a policy, here a probability distribution over arms, to make rewarded actions more likely. The policy is always stochastic, so exploration is built into it. Later modules (policy gradients, Module 6) use the same idea on much larger problems.

Build it up: preferences to probabilities

Step 1: preferences. Keep a number H_t(a) for every arm. Preferences start at 0 for all arms, so every arm begins equally likely.

Step 2: softmax. Turn preferences into probabilities with the softmax, which makes every probability positive and the total equal to 1:

\pi_t(a)=\frac{e^{H_t(a)}}{\sum_{b} e^{H_t(b)}}

A preference that is higher by 1 makes an arm about e\approx2.72 times as likely, relative to the others. With all preferences at 0 each arm has probability 1/k.

Step 3: the update. After pulling arm A_t and seeing reward R_t, every preference moves by

H_{t+1}(a)=H_t(a)+\alpha\,(R_t-\bar R_t)\,\big(\mathbf 1[a=A_t]-\pi_t(a)\big)

Read it piece by piece. The factor (R_t-\bar R_t) is the surprise: a reward above the average raises the chosen arm's preference, and a reward below it lowers it. The factor \mathbf 1[a=A_t]-\pi_t(a) says the chosen arm moves up by 1-\pi_t(A_t), and every other arm moves down by \pi_t(a). Both pieces together push probability towards arms that earned more than average.

Step 4: the baseline. The reference \bar R_t is the average reward so far. It does not change which way the expected update points, but it reduces the size of the random jumps. Without it, a positive reward always raises the chosen arm, even when the arm was only average.

Worked example: three arms, α = 0.5, baseline on

Start with H_0=(0,0,0), so \pi_0=(1/3,1/3,1/3). The baseline starts at \bar R_0=0.

Step 1. Arm 1 is pulled and returns R_1=2.0. The surprise is 2.0-0=2.0. Arm 1 rises by 0.5\cdot2.0\cdot(1-1/3)=0.6667. Arms 2 and 3 each fall by 0.5\cdot2.0\cdot(1/3)=0.3333.

H_1=(0.6667,\,-0.3333,\,-0.3333),\qquad \pi_1=(0.5761,\,0.2119,\,0.2119)

The baseline becomes \bar R_1=2.0. Arm 1 now has more than half the probability, and that came from one reward.

Step 2. Arm 2 is pulled and returns R_2=1.0. The surprise is 1.0-2.0=-1.0, which is below average. Arm 2 falls by 0.5\cdot(-1.0)\cdot(1-0.2119)=-0.3941, so H(2)=-0.3333-0.3941=-0.7274. Arm 1 rises by 0.5\cdot(-1.0)\cdot(0-0.5761)=+0.2881, so H(1)=0.9547. Arm 3 rises by 0.5\cdot(-1.0)\cdot(0-0.2119)=+0.1060, so H(3)=-0.2274.

H_2=(0.9547,\,-0.7274,\,-0.2274),\qquad \pi_2=(0.6700,\,0.1246,\,0.2054),\qquad \bar R_2=1.5

A pull of arm 2 that gave a below-average reward lowered its probability. Arm 1, the arm that paid 2.0, is now chosen 67% of the time. Note that arm 1's preference went up on step 2 even though arm 1 was not pulled. The update for an unpulled arm is −α·(surprise)·π(a), and the surprise was negative, so the sign flips and the preference rises.

The formal definition

\pi_t(a)=\frac{e^{H_t(a)}}{\sum_b e^{H_t(b)}},\qquad H_{t+1}(a)=H_t(a)+\alpha\,(R_t-\bar R_t)\big(\mathbf 1[a=A_t]-\pi_t(a)\big),\qquad \bar R_{t}=\bar R_{t-1}+\tfrac1t(R_t-\bar R_{t-1})

The update is stochastic gradient ascent on the expected reward with respect to the preferences. The expected step equals the gradient, so the baseline does not change the expected direction, only the noise.

H_t(a)the preference for arm a at step t; any real number
π_t(a)the probability of choosing arm a at step t (the policy)
αthe step size for preferences; here 0.5 in the worked example
R̄_tthe baseline: the average reward so far
𝟙[a = A_t]1 if arm a was the one pulled, 0 otherwise (an indicator)

Common traps
  • The preferences are not values. A preference of 0.9 for arm 2 does not mean its reward is 0.9. Only the probabilities have a direct meaning.
  • The baseline must not depend on the current action. Using the reward of the action being updated as its own baseline biases the update. The running average over past rewards is a safe choice.
  • The probabilities never reach zero exactly. Softmax keeps every arm possible, so the learner always explores a little. This is a feature, but it means the policy is never fully deterministic.
Where it shows up in AI
  • Policy gradients. REINFORCE and the actor in actor–critic methods (Module 6) use softmax preferences and a baseline in exactly this way, over states as well as bandit arms.
  • Language-model decoding and RLHF. A language model's next-token distribution is a softmax over logits, and reinforcement learning from human feedback nudges those logits with a reward and a baseline.
  • Stochastic policies for games and robots. Keeping a probability over actions gives natural exploration, which is why softmax policies appear in many deep RL agents.

Check yourself

1. With all preferences equal at 0 and three arms, what is π? Then if H(1) rises by 1 and the others stay at 0, what is π(1)?
π = (1/3, 1/3, 1/3). With H = (1, 0, 0), π(1) = e / (e + 1 + 1) = 2.718/4.718 = 0.576.
2. In the worked example, why did arm 1's preference rise on step 2 even though arm 1 was not pulled?
The indicator for arm 1 is 0 and its probability is π(1) = 0.5761, so the term 𝟙 − π is −0.5761. Multiplied by the negative surprise (−1.0) and α = 0.5, the preference increases by 0.2881. Every arm that was not pulled moves in the direction of the surprise times its probability.
3. Why does subtracting a baseline keep the expected update the same but reduce its size?
The baseline is subtracted from every update, and the expected value of the term (𝟙[a = A] − π(a)) over the random choice of A is zero, so the subtraction adds zero in expectation. The random size of the update drops when the reward is close to the average.

Takeaways

  • A gradient bandit keeps preferences, turns them into probabilities with softmax, and moves them according to the surprise in each reward.
  • A baseline, usually the average reward so far, reduces the size of the updates without changing their expected direction.
  • Learning the policy directly keeps exploration inside the probabilities; this is the seed of policy gradient methods.
1.6

Non-stationary problems & constant step size

The questionA streaming service recommends a video to a viewer. The viewer's taste changes week by week, so a video that earned clicks last year may earn none now. A sample average over all history will be slow to notice. How should the estimate weigh recent rewards against old ones?

Intuition

An average over all history treats a reward from a year ago exactly like one from this morning. That is correct when the arm's true value is fixed. When it drifts, the old rewards describe a world that no longer exists. We want the estimate to forget gradually: recent rewards count for more, and old ones fade.

The fix is a small change to the sample-average rule. Replace the step size 1/n with a fixed number \alpha between 0 and 1. The update is the same as before, but the step no longer shrinks, so each reward keeps a constant weight and older rewards are discounted by a constant factor each time a new one arrives.

Build it up: what the constant step does

Step 1: the update. Use Q_n = Q_{n-1} + \alpha\,(R_n - Q_{n-1}) with a fixed \alpha.

Step 2: unroll it. Substitute repeatedly to see how each past reward is weighted. The result, starting from Q_0, is

Q_n = (1-\alpha)^n Q_0 + \sum_{i=1}^{n}\alpha(1-\alpha)^{n-i}R_i

The newest reward has weight \alpha, the one before it \alpha(1-\alpha), and so on. Each step back multiplies the weight by 1-\alpha, so the weights decay geometrically, like a memory that halves every few pulls.

Step 3: the memory length. The weight of a reward halves after h pulls when (1-\alpha)^h = 1/2, which gives h = \ln(0.5)/\ln(1-\alpha). For \alpha = 0.1 this is about 6.6 pulls. A rough rule is that the effective window is about 1/\alpha pulls.

Worked example: a reward jump with α = 0.5

Rewards are 1,\;1,\;4, and Q_0=0, with a constant step \alpha = 0.5.

\begin{aligned}Q_1&=0+0.5(1-0)=0.500\\Q_2&=0.5+0.5(1-0.5)=0.750\\Q_3&=0.75+0.5(4-0.75)=2.375\end{aligned}

Check with the unrolled form: Q_3 = 0.125\cdot0 + 0.125\cdot1 + 0.25\cdot1 + 0.5\cdot4 = 0.125+0.25+2.0 = 2.375. The weights are 0.5 on the newest reward, 0.25 on the one before, 0.125 on the first, and 0.125 on the initial value; they sum to 1.

The sample average after the same three rewards would be (1+1+4)/3 = 2.0, which weighs the 4 at 1/3. The constant-step estimate weighs it at 0.5, so it reacts faster to the jump, and forgets the early 1s sooner.

The formal definition

Q_n = Q_{n-1} + \alpha\,(R_n - Q_{n-1}),\qquad 0 < \alpha \le 1

For a fixed \alpha the estimate never converges to a single value if the arm's mean keeps moving; it keeps tracking. Its variance is larger than the sample average's, because it uses fewer effective rewards. The choice of \alpha is a trade-off between tracking speed and noise. The sample average is the right choice when the mean is fixed; a constant step is the right choice when it moves.

αthe constant step size, between 0 and 1; a larger α forgets faster
(1 − α)^(n−i)the weight given to reward i after n pulls (for constant α)
hthe half-life: pulls until a reward's weight halves

Common traps
  • A constant step is not free. It forgets old rewards, so it is noisier than the sample average when the world is stable.
  • α = 1 is pure memory of one reward. The estimate becomes the last reward, which is very noisy. Values close to 0 remember too long.
  • Initial values matter. With a constant step, Q_0 keeps a weight of (1 − α)^n. It fades, but slowly for small α.
Where it shows up in AI
  • Tracking drifting users and content. Recommenders and ad systems use recency-weighted estimates so that yesterday's trends count more than last year's.
  • Temporal-difference learning. The TD update of Module 4 uses a constant step size α in its tabular form; choosing α is a central tuning decision.
  • Exponential moving averages in training. Momentum and running statistics in optimisers use the same exponentially decaying weights as the constant step.

Check yourself

1. With α = 0.1, what is the weight of a reward that arrived 3 pulls ago relative to the newest reward?
The newest reward has weight α = 0.1, one pull back has 0.1·0.9, two back 0.1·0.81, three back 0.1·0.729 = 0.0729. The reward three pulls ago has weight 0.0729.
2. Using the worked example, what would Q_3 be if the update used step 1/n instead of α = 0.5?
The sample average after 1, 1, 4 is (1 + 1 + 4)/3 = 2.0. With step 1/n, Q_1 = 1, Q_2 = 1, Q_3 = 1 + (4 − 1)/3 = 2.0.
3. If the true mean of an arm is fixed, which estimator is better, and why?
The sample average. It uses every reward with equal weight, which reduces the variance to σ²/n. A constant step keeps a weight on recent rewards and so has a larger variance; the extra responsiveness is wasted when nothing changes.

Takeaways

  • A constant step size α gives exponentially decaying weights on past rewards, a memory of about 1/α pulls.
  • Use the sample average when the mean is fixed and a constant step when it drifts; the choice is a trade-off between lag and noise.
  • The same constant-step update reappears in temporal-difference learning and in optimiser statistics.
