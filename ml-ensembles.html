4.1

Why ensembles work & bagging

The questionA fully grown decision tree fits the training set perfectly, yet change three training rows and its boundary reshuffles completely. Can we keep the tree's flexibility but remove this instability, using nothing but more computing power and no new maths model?

Intuition

Ask one friend to guess the weight of an ox and they may be far off; ask a hundred and average, and the errors — some too high, some too low — largely cancel. That is the wisdom of crowds. It only works if the guesses are not all wrong in the same way. If all hundred friends copied the same neighbour, averaging gives you nothing.

An unpruned tree has low bias (it can fit anything) but high variance (its answer depends strongly on exactly which rows it saw). Variance is exactly what averaging removes. So: train many trees, each on a slightly different version of the data, and average. The trick for getting "different versions of the data" from one dataset is the bootstrap.

Build it up

Step 1: the variance of an average. Suppose we have n predictors T_1,\dots,T_n, each with variance \sigma^2, and any two of them have correlation \rho (so covariance \rho\sigma^2). The ensemble is their average \bar T=\frac1n\sum_iT_i. Variance of a sum is the sum of all variances and covariances:

\operatorname{Var}(\bar T)=\frac1{n^2}\Big[\underbrace{n\sigma^2}_{\text{n variances}}+\underbrace{n(n-1)\rho\sigma^2}_{\text{n(n-1) ordered pairs}}\Big]=\frac{\sigma^2}{n}+\frac{n-1}{n}\rho\sigma^2=\rho\sigma^2+\frac{1-\rho}{n}\sigma^2

Read it: the second term shrinks as 1/n — more trees always helps there. The first term, \rho\sigma^2, never shrinks: it is the part of the error the trees share. Adding trees cannot beat the correlation floor. The only ways to go lower are making each tree better, or making trees less correlated — which is the whole idea of random forests (next lesson).

Worked example — variance of the average

Let \sigma^2=1.

Independent trees, \rho=0,\ n=10: 0+\frac{1}{10}=0.10. Ten times less variance.

\rho=0.3,\ n=10: 0.3+\frac{0.7}{10}=0.37. With 100 trees: 0.3+0.007=0.307. With infinitely many: 0.30. Going from 10 to 100 trees bought only 0.063.

\rho=0.9,\ n=10: 0.9+0.01=0.91 — highly correlated trees are almost useless to average.

(Here the horizontal axis of the plot is a dummy variable x; read the readout, and drag rho and n.)

Step 2: the bootstrap. We only have one dataset of N rows, but we want many different ones. A bootstrap sample draws N rows with replacement: each draw picks any of the N rows with probability 1/N, so some rows appear twice or three times and others not at all. Each tree gets its own bootstrap sample — they all look like the data, but differ in which rows are over- and under-represented.

The 63.2% fact. The chance that a particular row is not chosen in one draw is 1-\frac1N; not chosen in all N independent draws: (1-\frac1N)^N\to e^{-1}\approx0.368. So each bootstrap sample contains about 63.2% of the distinct rows, and about 36.8% are left out. For small N: N = 6 gives 1-(5/6)^6=66.5\% in-bag; N = 10 gives 65.1%; N = 100 gives 63.4%.

Bagging = bootstrap aggregating: train one deep tree per bootstrap sample; predict by averaging (regression) or by majority vote / averaging class probabilities (classification).

Step 3: out-of-bag (OOB) error — a free validation set. The ~36.8% of rows a tree never saw are its personal test set. To score the whole ensemble, predict each row using only the trees that did not train on it, then compare with the truth. No separate hold-out needed.

Worked example — bagging and OOB on six points

Data (x → y): 1→3, 2→5, 3→4, 4→10, 5→12, 6→11. Three bootstrap samples (row numbers drawn with replacement) and a depth-1 tree (a stump: one split, leaf = mean) per sample:

treebootstrap rowsin-bag distinctbest splitleaf meansOOB rows
11,1,2,4,4,61,2,4,6x < 33.667 | 10.3333, 5
22,3,3,5,6,62,3,5,6x < 44.333 | 11.3331, 4
31,3,4,5,5,61,3,4,5,6x < 3.53.5 | 11.252

OOB predictions: row 3 (y=4) → 10.333, error² = 40.11; row 5 (y=12) → 10.333, 2.78; row 1 (y=3) → 4.333, 1.78; row 4 (y=10) → 11.333, 1.78; row 2 (y=5) → 3.5, 2.25. Row 6 was in-bag for all three trees, so it has no OOB prediction. OOB MSE = (40.11+2.78+1.78+1.78+2.25)/5 = 9.74 (RMSE 3.12). With hundreds of trees every row has dozens of OOB trees and the estimate is stable. (Three stumps is a toy; real bagging uses deep trees.)

The formal definition

\hat f_{\text{bag}}(x)=\frac1B\sum_{b=1}^{B}\hat f^{*b}(x),\qquad \text{OOB error}=\frac1N\sum_{i}L\Big(y_i,\ \frac1{|B_i|}\sum_{b\in B_i}\hat f^{*b}(x_i)\Big)
Bnumber of trees (bootstrap samples)
\hat f^{*b}the tree trained on the b-th bootstrap sample
B_iset of trees whose bootstrap sample did not contain row i
\rho,\sigma^2correlation between trees' predictions, variance of one tree's prediction
Lper-row loss (squared error, or 0/1 error for votes)

Pipeline view. Stored: B full trees (each up to ~N nodes if grown deep: memory ≈ B × nodes × 16–32 bytes). Training: B × the cost of one tree, O(B\cdot dN\log N), but trees are independent, so it parallelises perfectly across cores. Inference: B × depth comparisons per row — latency scales with trees × depth (100 trees × depth 20 = 2000 comparisons, microseconds in C, milliseconds in naive Python). Preprocessing: none — no scaling, tolerates monotone transforms and outliers. Use when: you have a high-variance learner. Do not use when: the base learner is already stable (bagging linear regression barely changes anything — averaging identical models gives \rho\approx1) or biased (it fixes variance, not bias).

Common traps
  • "More trees overfit." Not for bagging: B only affects the 1/n term, which just converges. (Boosting is different — see 4.3.)
  • Bagging cannot reduce bias. Averaging many depth-1 stumps of an XOR pattern is still wrong.
  • OOB error is a good validation estimate only if rows are independent; with grouped or time-ordered data the leakage makes it too optimistic (Module 5).
  • Bootstrap rows are duplicated, so do not use min_samples_leaf reasoning based on distinct rows.
Where it shows up in AI
  • Random forests (next lesson) are bagging plus one extra trick; extra-trees push decorrelation further.
  • Model averaging in deep learning: ensembles of networks with different seeds, snapshot ensembles, and dropout (an implicit exponential ensemble) rely on the same variance formula.
  • Test-time augmentation averages predictions over perturbed copies of one input — bagging over inputs instead of training sets.

Check yourself

1. 25 trees, σ² = 4, ρ = 0.5. What is the variance of their average?
0.5·4 + (0.5/25)·4 = 2 + 0.08 = 2.08. Half the variance is the shared floor.
2. In a dataset of 1000 rows, about how many distinct rows does one bootstrap sample contain?
1 − (0.999)^1000 ≈ 0.632, so about 632 distinct rows; ~368 are out-of-bag.
3. Why can you not reduce error below ρσ² by adding trees?
The ρσ² term of the variance formula does not depend on n. It is the error the trees make together; only less-correlated or more accurate trees can lower it.

Takeaways

  • Var(average) = ρσ² + (1−ρ)σ²/n: more trees kills the second term only.
  • Bootstrap = N draws with replacement → 63.2% distinct rows, 36.8% out-of-bag.
  • OOB error is a free validation score; bagging cuts variance, not bias.
  • Cost: B× training (parallel), B×depth inference, no preprocessing.
4.2

Random forests

The questionSuppose one feature is very strong. Every bagged tree will split on it at the root, so all B trees look alike (ρ close to 1) and averaging helps little. How can we force trees to disagree without making each one worse?

Intuition

Imagine a committee in which every member is handed the same star witness's report first: they all reach the same conclusion. A random forest blindfolds part of the evidence: at every split, a tree may look at only a random handful of the features. Sometimes the star feature is hidden, so the tree must find the next-best structure. Individual trees become slightly worse (higher bias) but far less alike (lower ρ), and by the formula of lesson 4.1 the net effect on the average is a big win.

Build it up

The algorithm, per tree b = 1…B:

  1. Draw a bootstrap sample of the N rows.
  2. Grow a deep tree. At each node, choose m of the d features at random, and search for the best split (Gini or entropy gain, as in the decision-trees lesson) among those m only.
  3. No pruning. Stop at a minimum leaf size.

Defaults: m=\lfloor\sqrt d\rfloor for classification, m=d/3 for regression. With m=d you recover plain bagging. With m=1 you get nearly random trees: very decorrelated, but weak.

Worked example — how much does subsampling decorrelate?

Say d = 10 features and one strong feature S. With m = 10 every tree splits on S at the root: probability 1. With m = 3, the root sees S with probability 3/10 = 0.3, so 70% of trees must pick a different root feature. Suppose this lowers the correlation from ρ = 0.8 to ρ = 0.4 while a single tree's variance rises from σ² = 1 to 1.2. Ensemble variance with n = 100: before 0.8+0.2/100=0.802; after 0.4\cdot1.2+0.6\cdot1.2/100=0.487. A noticeably better ensemble from individually worse trees. (Numbers are illustrative to show the mechanics, not measured.)

Feature importance. Two common measures: (1) impurity importance — sum, over every split on feature j in every tree, of the impurity decrease weighted by the fraction of rows reaching it, normalised to sum to 1 (cheap, but biased toward high-cardinality or continuous features); (2) permutation importance — shuffle feature j in the OOB rows and measure how much OOB accuracy drops (slower, more honest; Module 5).

OOB error as you add trees. The OOB curve falls as B grows and then flattens — you can pick B as "the point where OOB stops improving"; more trees cost only compute, never accuracy.

The formal definition

\hat f_{\text{RF}}(x)=\frac1B\sum_{b=1}^{B}T_b(x;\Theta_b),\qquad \mathrm{Imp}(j)=\sum_{t:\,\text{split on }j}\frac{n_t}{N}\,\Delta\mathrm{imp}_t
\Theta_bthe randomness of tree b: its bootstrap sample and its feature subsets at every node
m, dfeatures tried per split, total features (max_features)
n_t/Nfraction of training rows reaching node t
\Delta\mathrm{imp}_timpurity decrease from the split at node t

Pipeline view. Stored: B trees, typically 100–1000 trees, each with up to ~N leaves (a forest on 1M rows can be gigabytes: this is its main weakness). Training: O(B\cdot m N\log N) — smaller m also makes it faster; embarrassingly parallel. Inference: B × depth per row, no sequential dependency. Preprocessing: none for scaling or outliers; needs numeric encoding of categories and imputation (most libraries). Strengths: hard to ruin, few hyper-parameters, OOB score, importance. Weaknesses: large and slower to predict than boosting of small trees, cannot extrapolate beyond the training range, usually a little less accurate than tuned gradient boosting.

Try this
  1. Set features-per-split to 2 (all). Notice every tree uses the same strong feature; the correlation reading is high and the OOB error flattens early.
  2. Set it to 1: trees become more different (correlation drops) but each is weaker. Find the setting that gives the lowest OOB error.

Common traps
  • Impurity importance ranks a random ID column surprisingly high when it has many unique values. Cross-check with permutation importance.
  • Correlated features share importance between them, so each looks less important than it is.
  • A forest predicts averages of training targets: it can never predict outside the observed y-range, and it is flat beyond the data in x.
  • Tuning B on the test set — use OOB or CV instead.
Where it shows up in AI
  • Strong tabular baseline: the first model to try after a linear baseline; used for credit risk, churn, fraud triage.
  • Isolation forests (anomaly detection) and quantile regression forests reuse the random-tree machinery.
  • Feature selection and data exploration via importance; proximity (rows ending in the same leaves) as a similarity measure.

Check yourself

1. A dataset has 16 features. What is the default m for a classification forest?
⌊√16⌋ = 4 features per split.
2. Why can individually worse trees give a better forest?
Lower correlation ρ reduces the shared-error floor ρσ²; if that gain exceeds the increase in each tree's own variance/bias, the average improves.
3. Name two reasons not to read impurity importance literally.
It is biased toward high-cardinality/continuous features, and correlated features split the credit. It is also computed on training data, so it can credit features that only help overfitting.

Takeaways

  • Random forest = bagging + random feature subset at every split → lower ρ.
  • OOB score, importance and almost no tuning: the safe default.
  • Costly in memory (B full trees) and cannot extrapolate.
  • m is the key knob; B just needs to be big enough.
4.3

Gradient boosting

The questionBagging averages many strong, independent trees to cut variance. What if instead we used many weak, tiny trees — each of which is badly biased — but built them one after another, each fixing what the previous ones got wrong? Can a chain of stumps become a state-of-the-art model?

Intuition

Think of a golfer. The first shot goes roughly toward the hole; you do not start over, you take the next shot from where the ball landed, aiming at the remaining gap. Each shot is crude, but each one reduces the distance. Boosting is exactly this: the current prediction is where the ball is; the residual (truth minus prediction) is the remaining distance; each new small tree is a crude shot at the residual, and we add a fraction of it (the learning rate) so we never overshoot.

Build it up

Start with the simplest model, a constant F_0 (the mean of y for squared loss). Then repeat: compute residuals, fit a small tree to them, add a shrunken version of it to the model.

Worked example — two full boosting rounds, squared loss

Data: x = 1…6, y = 3, 5, 4, 10, 12, 11. Learning rate \eta=0.5, base learner = stump.

Round 0. F_0=\text{mean}(y)=7.5 for every row. MSE = (20.25+6.25+12.25+6.25+20.25+12.25)/6 = 12.917.

Round 1. Residuals r=y-F_0 = −4.5, −2.5, −3.5, +2.5, +4.5, +3.5. Try every split of the residuals by the sum of squared errors (SSE) left after predicting each side's mean: split x<1.5 → 53.2; x<2.5 → 40.75; x<3.5 → 4.0; x<4.5 → 29.5; x<5.5 → 62.8. Best: x<3.5, with leaf values mean(−4.5,−2.5,−3.5) = −3.5 and mean(2.5,4.5,3.5) = +3.5. Update F_1=F_0+\eta\cdot\text{leaf}: left rows 7.5 + 0.5(−3.5) = 5.75, right rows 7.5 + 0.5(3.5) = 9.25. MSE falls 12.917 → 3.729.

Round 2. New residuals y-F_1 = −2.75, −0.75, −1.75, +0.75, +2.75, +1.75. The best split is again x<3.5 (SSE 4.0) with leaves −1.75 and +1.75. F_2 = 5.75 + 0.5(−1.75) = 4.875 (left), 9.25 + 0.875 = 10.125 (right). MSE = 1.432.

Each round with the same split shrinks the remaining gap by a factor (1-\eta)=0.5. The stump cannot go below the noise inside each group: two groups with SSE 2 each → MSE floor 4/6 = 0.667. In round 3 the best split changes to x<4.5 (SSE 2.92) — the trees start chasing individual points, and MSE falls to 0.723. This is the start of overfitting: more rounds can hurt.

Why "gradient"? For squared loss L=\tfrac12(y-F)^2, the derivative with respect to the prediction is \partial L/\partial F=-(y-F): the residual is the negative gradient. So boosting is gradient descent in function space: instead of nudging parameters \theta (gradient descent), we nudge the function itself, in the direction of steepest loss decrease, but because a function can only be moved at the training points we fit a tree to the negative gradient values to generalise the step to new x. For any differentiable loss the recipe is the same: compute r_i=-\partial L(y_i,F)/\partial F\big|_{F=F_{m-1}(x_i)} (the "pseudo-residual") and fit a tree to it.

Worked example — log-loss boosting (classification)

Labels on x = 1…6: y = 0, 1, 0, 0, 1, 1. The model outputs a log-odds score F; probability p=\sigma(F). Log-loss L=-[y\ln p+(1-y)\ln(1-p)] has gradient \partial L/\partial F=p-y, so the pseudo-residual is y − p.

F_0=\ln\frac{p_0}{1-p_0} with p_0=\text{mean}(y)=0.5 gives F₀ = 0, p = 0.5 everywhere, log-loss ln 2 = 0.6931. Residuals y−p = −0.5, +0.5, −0.5, −0.5, +0.5, +0.5. Best stump of these (SSE): x<4.5 (0.75), leaves mean(−.5,.5,−.5,−.5) = −0.25 and mean(.5,.5) = +0.5. With η = 0.5: F₁ = −0.125 for x = 1…4 and +0.25 for x = 5, 6, i.e. p = 0.469 and 0.562. Log-loss = 0.6345 (down from 0.6931). Next residuals: −0.469, +0.531, −0.469, −0.469, +0.438, +0.438.

(Real libraries refine the leaf value with a Newton step: \sum r/\sum p(1-p), here −1/1 = −1 and 1/0.5 = 2, as developed in lesson 4.4.)

AdaBoost: the same idea, older view. AdaBoost boosts classifiers with exponential loss e^{-y F} (y = ±1) by reweighting rows instead of fitting residuals: after a stump with weighted error \varepsilon, its vote is \alpha=\tfrac12\ln\frac{1-\varepsilon}{\varepsilon}, wrong rows are multiplied by e^{\alpha}, right rows by e^{-\alpha}, then weights are renormalised.

Worked example — one AdaBoost reweighting

Five rows, weights 0.2 each. A stump gets one row wrong: \varepsilon=0.2. \alpha=\tfrac12\ln(0.8/0.2)=\tfrac12\ln4=0.693, so e^{\alpha}=2 and e^{-\alpha}=0.5. New weights: four right rows 0.2·0.5 = 0.1; the wrong row 0.2·2 = 0.4. Sum = 0.8, so normalise: 0.125 each and 0.5 for the wrong row. The next stump now faces a problem in which the previously missed row carries half of all weight.

The formal definition

F_m(x)=F_{m-1}(x)+\eta\,h_m(x),\qquad h_m=\arg\min_h\sum_i\big(r_{im}-h(x_i)\big)^2,\qquad r_{im}=-\frac{\partial L(y_i,F)}{\partial F}\Big|_{F=F_{m-1}(x_i)}
F_mthe ensemble after m rounds (a sum of trees, not an average)
\etalearning rate / shrinkage, 0 < η ≤ 1; smaller needs more rounds but generalises better
h_mthe m-th small tree (depth 3–8 typically), fitted to pseudo-residuals
r_{im}pseudo-residual of row i: negative gradient of the loss at the current prediction
Lloss: squared (r = y−F), absolute (r = sign), Huber, log-loss (r = y−p), softmax (one tree per class per round)

Pipeline view. Stored: M trees (typically 100–5000, small: ≤ 2depth leaves each) plus F₀ — often a few MB. Training: inherently sequential across trees (each needs the previous residuals), cost ≈ O(M\cdot dN\log N), parallel only inside a tree. Inference: M × depth comparisons, summed; latency scales with trees × depth, e.g. 500 trees × depth 6 = 3000 comparisons. Preprocessing: none for scaling; categories need encoding (unless CatBoost/LightGBM native). Regularisation: small η, shallow trees, row/column subsampling ("stochastic" gradient boosting), early stopping on a validation set. Use when: tabular data and you want the best accuracy. Avoid when: images/text/audio raw inputs, extremely noisy labels (it will chase them), or when you need strict extrapolation.

Lab: trees added one at a time

Try this
  1. In regression mode press Step. Follow the caption: current prediction (line) → residuals (vertical segments) → the new stump fitted to those segments → the line moves by η × stump. Repeat. The loss plot falls.
  2. Halve the learning rate: each step moves less, you need twice the rounds, but the curve is smoother.
  3. Run many rounds with the noisy data: the training loss keeps dropping, the validation loss turns up — overfitting. Early stopping would stop at the minimum.
  4. Switch to classification: the boundary refines as stumps accumulate.
Common traps
  • Boosting does overfit with many rounds, unlike bagging. Always use a validation set and early stopping.
  • Learning rate and number of trees trade off — tune them together (lower η, more trees).
  • Fitting residuals only equals gradient boosting for squared loss. For other losses, the thing being fit is the negative gradient.
  • Boosting is sequential: you cannot parallelise over trees, so training can be slower than a forest for the same M.
Where it shows up in AI
  • Tabular state of the art: GBDTs (XGBoost, LightGBM, CatBoost) win most structured-data competitions and power fraud, ranking, ads CTR and credit models.
  • Learning to rank: LambdaMART is gradient boosting with a ranking gradient — used in web search.
  • Functional gradient idea reappears in residual networks (each block adds a correction, ResNet) and in diffusion denoising steps.

Check yourself

1. After round 1 of the worked example the prediction for x = 1 is 5.75 while y = 3. What is the residual that round 2 fits for that row?
3 − 5.75 = −2.75.
2. Squared loss ½(y−F)². Show that the negative gradient equals the residual.
d/dF ½(y−F)² = −(y−F), so −d/dF = y−F, the residual.
3. AdaBoost: weighted error ε = 0.1. Compute α.
½ ln(0.9/0.1) = ½ ln 9 = 1.099.

Takeaways

  • Boosting adds small trees sequentially, each fitted to the negative gradient (residuals for squared loss, y−p for log-loss).
  • η shrinks every step; small η + many trees generalises best; early stopping is essential.
  • It reduces bias; bagging reduces variance.
  • Cost: sequential training, inference = trees × depth.
4.4

XGBoost, LightGBM & CatBoost

The questionPlain gradient boosting uses only the slope of the loss and has no built-in brake against complex trees. Can we also use the curvature to take better steps, price every split by its true benefit, penalise complexity inside the objective — and make training fast enough for millions of rows?

Intuition

Gradient descent looks at the slope; Newton's method also looks at how fast the slope changes, and jumps closer to the minimum. XGBoost does a Newton step on the loss for the new tree and, because everything is a sum over leaves, can compute in closed form how good each leaf is and how much a candidate split gains. The same formulas then double as a regulariser: a split must earn more than γ, and leaf values are shrunk by λ.

Build it up

At round m, approximate the loss around the current prediction with a second-order Taylor expansion. For each row define the gradient g_i=\partial L/\partial F and the hessian h_i=\partial^2L/\partial F^2, both at F_{m-1}(x_i). For squared loss \tfrac12(F-y)^2: g_i=F-y_i, h_i=1. For log-loss: g_i=p_i-y_i, h_i=p_i(1-p_i).

The objective of a new tree with leaves j (each with weight w_j and the set I_j of rows in it), including a penalty \gamma per leaf and \tfrac12\lambda w_j^2:

\mathcal L\approx\sum_{j}\Big[G_jw_j+\tfrac12(H_j+\lambda)w_j^2\Big]+\gamma T,\qquad G_j=\sum_{i\in I_j}g_i,\ H_j=\sum_{i\in I_j}h_i

For one leaf this is a parabola in w_j; its minimum is at

w_j^\star=-\frac{G_j}{H_j+\lambda},\qquad \mathcal L^\star_j=-\frac12\frac{G_j^2}{H_j+\lambda}

(Check: derivative G+(H+\lambda)w=0.) A node's "score" is thus \tfrac12G^2/(H+\lambda). Splitting a node into left and right replaces one score with two, and costs one extra leaf (γ):

\text{Gain}=\tfrac12\Big[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\Big]-\gamma

Grow the split with the largest gain; if the best gain is negative, do not split (pruning built into the objective).

Worked example — splitting with gradients

Use the boosting data of 4.3 at F_0=7.5, squared loss: g=F-y = 4.5, 2.5, 3.5, −2.5, −4.5, −3.5 and all h = 1. Totals: G = 0, H = 6. Candidate split x<3.5: G_L=4.5+2.5+3.5=10.5,\ H_L=3,\ G_R=-10.5,\ H_R=3.

λ = 1, γ = 0: \frac{10.5^2}{3+1}=27.5625 for each side, parent term 0^2/(6+1)=0. Gain = ½(27.5625+27.5625−0) = 27.5625. Leaf weights -10.5/4=-2.625 and +2.625 (compare plain boosting: −3.5/+3.5 — λ shrinks them).

λ = 0: gain = ½(36.75+36.75) = 36.75, weights ∓3.5 (exactly the residual means, so XGBoost with λ = 0 and squared loss is the 4.3 algorithm). λ = 5: ½(13.78+13.78) = 13.78.

All five candidates at λ = 1: x<1.5 → 6.75; x<2.5 → 13.07; x<3.5 → 27.56; x<4.5 → 17.07; x<5.5 → 4.08. With γ = 30 even the best split has gain 27.56 − 30 < 0, so the tree stays a single leaf; with γ = 5 the best split survives.

Engineering that makes it fast.

  • Histogram splits (LightGBM, XGBoost hist): bucket each feature into ≤ 256 bins once; for each node, accumulate (G, H) per bin and scan bins. Cost per feature drops from sorting N values to O(N + bins), and a child's histogram = parent's minus sibling's ("subtraction trick").
  • Leaf-wise growth (LightGBM): always split the leaf with the largest gain, anywhere in the tree, rather than level by level. Reaches lower loss with the same number of leaves but can build deep lopsided trees and overfit small data — control with num_leaves and min_data_in_leaf. XGBoost default is level-wise; CatBoost uses oblivious trees (the same split at every node of a level), which are slow to overfit and extremely fast at inference.
  • GOSS / EFB (LightGBM): keep rows with large gradients, subsample small ones; bundle mutually exclusive sparse features.
  • Native categoricals: LightGBM finds the best partition of category values; CatBoost uses ordered target statistics (each row's category encoding computed only from earlier rows, avoiding target leakage) and ordered boosting.
  • Missing values: each split learns a default direction for NaN, so no imputation is required.

The formal definition

w_j^\star=-\frac{G_j}{H_j+\lambda},\qquad \text{Gain}=\tfrac12\Big[\tfrac{G_L^2}{H_L+\lambda}+\tfrac{G_R^2}{H_R+\lambda}-\tfrac{(G_L+G_R)^2}{H_L+H_R+\lambda}\Big]-\gamma

Pipeline view. Stored: M trees with split feature, threshold, default direction and leaf weight per node (a 1000-tree depth-6 model ≈ 64k leaves × a few bytes ≈ a few MB). Training: histogram GBDT ≈ O(M\cdot(N\cdot d+\text{bins}\cdot d\cdot\text{leaves})) — minutes on millions of rows, GPU support. Inference: trees × depth lookups, trivially batched; microseconds per row on CPU with compiled predictors (treelite, ONNX). Preprocessing: none for scale/outliers/NaN; keep categories as such for LightGBM/CatBoost.

Common traps
  • Leaf-wise trees with default num_leaves on a few thousand rows overfit; lower num_leaves and raise min_data_in_leaf.
  • Early stopping on the same validation set you report is optimistic; keep a separate final test set.
  • One-hot encoding a high-cardinality column for a boosted model explodes the feature count; use native categoricals or target encoding with out-of-fold statistics.
  • Feature "gain" importance has the same biases as impurity importance; check with permutation importance or SHAP.
Where it shows up in AI
  • Kaggle tabular winners and production scoring: credit risk, insurance pricing, click-through prediction, demand forecasting with lag features.
  • Ranking (LightGBM/XGBoost lambdarank) in search and recommendation.
  • The second-order objective is the same Newton idea used in second-order optimisers; leaf regularisation parallels weight decay.

Takeaways

  • XGBoost uses g and h: leaf weight −G/(H+λ), split gain ½[…]−γ.
  • λ shrinks leaves, γ prunes splits; λ=0 squared loss recovers plain boosting.
  • LightGBM = histograms + leaf-wise; CatBoost = ordered statistics + oblivious trees.
  • Tune η with early stopping first, then depth, min-child-weight, subsampling, λ/γ.
4.5

Stacking & blending

The questionYou have a random forest, a boosted model and a linear model, each good at something different. Averaging them equally ignores that one is better. Can we learn how much to trust each — without cheating by judging them on data they were trained on?

Intuition

Imagine three doctors who each give an opinion, and a senior physician (the meta-model) who has learned over many past cases which doctor to believe for which kind of patient. The senior physician must learn from cases in which the doctors had not seen the answer: if the doctors had memorised the cases, they would all look perfect and the physician would learn to trust the biggest memoriser — the most overfit model.

Build it up

Stacking trains level-0 (base) models, then trains a level-1 (meta) model whose input features are the base models' predictions. The central rule: meta-features must be out-of-fold (OOF) predictions. Split the training data into K folds; for each fold, train every base model on the other K−1 folds and predict the held-out fold. Concatenating the K held-out predictions gives one honest prediction per training row. Then, for the test set, refit the base models on all training data (or average the K fold models) and feed their predictions to the meta-model.

Worked example — OOF predictions and a meta-weight

Data x = 1…6, y = 3, 5, 4, 10, 12, 11. Folds: {1,2}, {3,4}, {5,6}. Base model A = least-squares line; base model B = 1-nearest-neighbour. For each fold, train on the other four rows.

Fold {1,2}: the line fitted to rows 3–6 is ŷ = −1.1 + 2.3x → A(1) = 1.2, A(2) = 3.5; 1-NN: nearest training row to x=1 and x=2 is x=3 (y=4) → B = 4, 4. Fold {3,4}: line fitted to rows 1,2,5,6: slope 1.794, intercept 1.471 → A(3) = 6.853, A(4) = 8.647; 1-NN: x=3→x=2 (y=5), x=4→x=5 (y=12) → B = 5, 12. Fold {5,6}: line on rows 1–4: ŷ = 0.5+2x → A = 10.5, 12.5; 1-NN: x=5,6→x=4 (y=10) → B = 10, 10.

OOF MSE: A = 3.327, B = 2.000. The simplest meta-model: a blend w A+(1-w)B. Minimising squared error gives w^\star=\frac{\sum(A-B)(y-B)}{\sum(A-B)^2}=0.364, MSE 1.354 — better than either alone (3.33, 2.00) and better than a plain 50/50 average (1.444). Had we trained A and B on all six rows and predicted those same rows, 1-NN would be perfect (error 0) and the meta-model would learn "trust B completely": the leak this protocol prevents.

Blending is the cheaper cousin: hold out one fixed validation split (say 10–20%), train base models on the rest, and fit the meta-model on the base models' predictions for the hold-out. Simpler and leak-safe, but the meta-model sees less data and the estimate is noisier.

Diversity is what pays. By the formula of 4.1, the gain comes from low correlation between errors. Averaging a forest with a slightly different forest buys almost nothing; averaging a tree model with a linear model and a k-NN buys a lot. Check the correlation of OOF residuals before adding a model. Keep the meta-model simple (ridge/logistic regression with non-negative weights, or a small GBM with strong regularisation): it has few rows of low-dimensional features and overfits easily.

When ensembling stops helping. When base models make the same mistakes (error correlation near 1); when the remaining error is label noise; or when the extra 0.1% costs 10× the inference time and maintenance. Production teams often stop at a single tuned GBDT, or distil the ensemble into one model.

The formal definition

\hat y(x)=g\big(\hat f_1(x),\dots,\hat f_M(x)\big),\qquad z_{im}=\hat f_m^{(-k(i))}(x_i)
\hat f_mbase model m (level 0)
gthe meta-model (level 1), trained on (z_{i1},\dots,z_{iM})\to y_i
k(i)the fold containing row i
\hat f_m^{(-k)}model m trained with fold k left out: the OOF prediction

Pipeline view. Stored: M base models + 1 meta-model (and K fold models if you average them for test). Training: M × K base fits (K = 5 → 5× the cost of one set of base models) plus a cheap meta fit. Inference: the sum of all base-model latencies plus the meta-model: three ensembles of 500 trees each is 1500 trees × depth — a real cost in a low-latency service. Preprocessing: whatever each base model needs; the meta-model needs only predictions (scale-free for trees, probabilities or logits for linear). Use when: competitions or accuracy is worth the latency. Avoid when: latency/memory budgets are tight, models are similar, or interpretability matters.

Common traps
  • Leakage: fitting the meta-model on in-sample base predictions. Always OOF.
  • Using a complex meta-model on a few hundred rows.
  • Validating the stack on rows that were used anywhere in training (including hyper-parameter selection); nest your CV.
  • Time-series: folds must respect time order (Module 5).
Where it shows up in AI
  • Competition-winning pipelines (Kaggle, KDD, Netflix Prize) are multi-layer stacks of GBDTs, neural networks and linear models.
  • Mixture of experts in large language models is a learned, gated version of "meta-model chooses among experts".
  • Knowledge distillation compresses an ensemble into one cheaper student for deployment.

Check yourself

1. Why must the meta-model be trained on out-of-fold predictions?
In-sample predictions of flexible models are too good; the meta-model would over-trust the most overfit model. OOF predictions mimic how base models will behave on unseen data.
2. Two models have OOF residual correlation 0.98. Should you stack them?
Probably not: errors are nearly identical, so by the 4.1 formula averaging cannot reduce much variance, and you double the inference cost.
3. 5-fold stacking of 3 base models: how many base-model training runs (excluding the final refit)?
3 × 5 = 15, plus one meta-model fit.

Takeaways

  • Stacking = base models → OOF predictions → meta-model; blending = same with one hold-out.
  • Diversity beats count; keep the meta-model simple.
  • Cost adds up: K× training, sum of latencies at inference.
  • For most tabular production work a tuned GBDT is the sweet spot.
