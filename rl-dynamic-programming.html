Module 2 · Dynamic programming

Suppose you know the rules of the world exactly: from every state, what each action does and what it pays. Then you do not need to try anything. You can compute how good each state is, and then compute a better way to act. This module shows how to do that with the Bellman equations, iterative policy evaluation, policy improvement, policy iteration and value iteration, and why all of them are one pattern.

What "known model" means. Dynamic programming assumes the transition probabilities p(s',r\mid s,a) and the rewards are available to the algorithm. The agent does not learn them from experience; it reads them from a table or a simulator it fully trusts. That is a strong assumption, and it is why this module is the first place to build intuition: every update here is an exact calculation, so you can check each number by hand. Later modules remove the assumption.

The running example. Most labs use a 4×4 gridworld. The two corner cells in the top-left and bottom-right are terminal: an episode ends there. Every move costs -1. A move that would leave the grid leaves you where you are. The question is always the same: what is the value of each cell, and how should the agent move?

How the labs work. Each lab computes its numbers in the browser with the same rules as the hand examples, so change a slider and the table responds. A lab marked illustrative would stand in for something larger; the labs in this module are exact on their small worlds.

2.1

Bellman expectation & optimality equations

The questionAn agent stands in state A. It can stay: reward 1, and it remains in A. Or it can go: reward 3 on the way to a state B, where the only move pays 0 and returns to A. Which choice is worth more over a long horizon? The answer depends on the value of A, but A's value depends on the states it leads to, and those depend on A again. How can we assign a number to a state when its value is defined in terms of other values?

Intuition

Think of value as a running ledger. The value of being in a state is what you collect right now, plus what the position you land in will be worth, discounted a little because later money is worth less than money now. Write one such ledger line for every state and you get a system of equations. These are the Bellman equations, named after Richard Bellman, who saw in the 1950s that a problem over a long horizon can be split into "this step, plus the rest" at every step.

The important point is that the Bellman equations are not a formula that gives the value directly. They are a consistency condition: the true values are the numbers that satisfy every ledger line at once. Finding those numbers is the job of the algorithms in the rest of this module.

Build it up, one piece at a time

Step 1: the return splits into "now" and "later". The return from time t is G_t = R_{t+1} + \gamma G_{t+1}, where \gamma \in [0,1) is the discount factor. Taking the expectation of this identity, given that the agent is in state s and follows a policy \pi, gives the value of that state as a one-step average of "reward now plus discounted value next":

V^\pi(s)=\mathbb E_\pi\!\left[R_{t+1}+\gamma V^\pi(S_{t+1})\mid S_t=s\right]

Step 2: a worked example with no choices. First remove the decisions, so that the only randomness is in the world. Take two states. From A, with probability one half the agent stays in A and earns 1, and with probability one half it moves to B and earns 0. From B the agent always returns to A and earns 2. Use \gamma = 0.9. Writing one ledger line per state:

Worked example: two states, no choices
V(A)=\tfrac12\big(1+0.9\,V(A)\big)+\tfrac12\big(0+0.9\,V(B)\big),\qquad V(B)=2+0.9\,V(A)

Substitute the second line into the first: V(A)=0.5+0.45V(A)+0.45(2+0.9V(A))=1.4+0.855\,V(A). Therefore 0.145\,V(A)=1.4, so V(A)=9.655 and V(B)=2+0.9(9.655)=10.690.

Check the first line: \tfrac12(1+8.690)+\tfrac12(9.621)=4.845+4.810=9.655. Both ledger lines balance, so these are the values.

Step 3: add a choice, and the average becomes a maximum. Now let the agent choose. Give A two actions: stay (reward 1, back to A) and go (reward 3, to B). Give B one action (reward 0, back to A). The value of the best behaviour is no longer an average over the policy's choices; the agent picks the action whose ledger line is largest:

Worked example: the choice in state A

With \gamma=0.9, the optimality equations are V^*(A)=\max\{1+0.9\,V^*(A),\;3+0.9\,V^*(B)\} and V^*(B)=0.9\,V^*(A).

If the agent always chooses go, then V(A)=3+0.9\cdot 0.9\,V(A)=3+0.81\,V(A), so V(A)=3/0.19=15.789 and V(B)=14.211. Now check the alternative: Q(A,\text{stay})=1+0.9(15.789)=15.211, which is less than Q(A,\text{go})=3+0.9(14.211)=15.789. Going is better, so the solution is consistent. Always staying would give only 1/(1-0.9)=10.

So V^*(A)=15.79, V^*(B)=14.21. The reward of 3 is worth taking a longer route, but only because the discounted value of the route is large enough to compensate.

The formal definition

For a policy \pi (a rule that gives probabilities of actions in each state), the two value functions and the three equations are:

V^\pi(s)=\sum_a \pi(a\mid s)\sum_{s',r}p(s',r\mid s,a)\big[r+\gamma V^\pi(s')\big]
Q^\pi(s,a)=\sum_{s',r}p(s',r\mid s,a)\Big[r+\gamma\sum_{a'}\pi(a'\mid s')\,Q^\pi(s',a')\Big]
V^*(s)=\max_a\sum_{s',r}p(s',r\mid s,a)\big[r+\gamma V^*(s')\big]
s,\ s'the current state and the state reached next
aan action
rthe reward received on the transition
p(s',r\mid s,a)the probability of landing in s' with reward r, after action a in state s
\pi(a\mid s)the probability that the policy picks action a in state s
\gammathe discount factor, with 0\le\gamma<1 here; it sets an effective horizon of about 1/(1-\gamma) steps
V^\pi(s),\ Q^\pi(s,a)the expected discounted return from s (or from s after taking a) when following \pi
V^*,\ Q^*the best values achievable by any policy

The first equation averages over the policy's choices (\sum_a\pi). The third takes a maximum over choices instead. That single change, average versus maximum, separates evaluating a behaviour from finding the best one.

Lab: a fixed point you can watch

The lab below solves the two-state choice problem by repeatedly applying the right-hand side of a Bellman equation to the current guesses. Start with zero everywhere. Each backup replaces the guess by the ledger line, and the guesses settle on the exact values. This is the "fixed point" view: the Bellman equation is a map, and its solution is the place where the map returns its input unchanged.

Try this
  1. Leave the mode on Optimal. Press Play and watch V(A) climb towards 15.79 and V(B) towards 14.21. Note that each backup uses the previous numbers, not the ones it is computing.
  2. Switch to Always stay. V(A) now converges to r_s/(1-\gamma)=10. Switch to Always go and watch it converge to 15.79 instead.
  3. Set γ to 0.5. The values shrink and settle in fewer backups. Set γ to 0.99 and the process takes hundreds of backups: a long horizon makes the ledger slow to balance.
  4. Set the stay reward to 2. Staying is now worth 2/(1 − 0.9) = 20, more than going (15.79), so the optimal mode switches to stay, and the dashed exact line changes to match.

Common traps

Common traps
  • Average versus maximum. V^\pi averages over \pi; V^* takes the best action. Using a max where the policy is fixed evaluates the wrong thing.
  • The equation is a constraint, not a recipe. Plugging in guessed numbers and checking that they balance is a test; a set of values that balances every line is the answer only when the solution is unique, which holds for \gamma<1 on finite problems.
  • Rewards belong to transitions. The reward r is paid when the agent moves, not when it arrives. Writing R(s') is only correct if the reward really depends on the destination alone.
  • Terminal states have value zero. Once an episode ends there is nothing more to collect, so V(\text{terminal})=0 in every equation.
Where it shows up in AI
  • Every value-based RL method is a sampled Bellman equation. TD(0) moves V(S) towards R+\gamma V(S') using one observed successor. Q-learning and DQN move Q(S,A) towards R+\gamma\max_{a'}Q(S',a'), which is the optimality equation with one sampled next state in place of the expectation.
  • Planning with a known model. Inventory control, routing and game-tree search all write a Bellman recursion over states and solve it exactly when the state space is small.
Pipeline placement. Estimate stage (value estimation) with the model supplied rather than learned. Stores one number per state for V, or one per state–action pair for Q. Cost per backup is the number of successor outcomes for one state and action.

Check yourself

1. In the choice example, what is V*(B), and why?
V*(B) = 0.9 · V*(A) = 0.9 · 15.789 = 14.21. B has one action, pays 0, and returns to A, so its value is the discounted value of A.
2. In state A, which action is optimal and what is Q*(A, stay) compared with Q*(A, go)?
Go. Q*(A, stay) = 1 + 0.9 · 15.789 = 15.21, while Q*(A, go) = 3 + 0.9 · 14.211 = 15.79. The larger immediate reward of go outweighs its longer route.
3. A policy picks each of two actions with probability 1/2 in state s. Write its Bellman expectation equation for V^π(s).
V^π(s) = ½ Σs′,r p(s′,r | s,a₁)[r + γV^π(s′)] + ½ Σs′,r p(s′,r | s,a₂)[r + γV^π(s′)]. The policy's probabilities multiply the one-step backup of each action, and the two are averaged.

Takeaways

  • The value of a state is one step's reward plus the discounted value of the next state, averaged over what the policy does.
  • Bellman equations are consistency conditions. They are solved by iteration, not by plugging values in.
  • Replacing the policy's average with a maximum gives the optimality equation, whose solution is the best value.
2.2

Iterative policy evaluation

The questionA robot starts somewhere on the 4×4 grid and moves at random: up, down, left or right, each with probability one quarter. Every move costs 1, and the episode ends when it reaches either corner marked as terminal. From each cell, how many moves does it take on average before the episode ends? We could simulate thousands of walks, but the Bellman equations promise an exact answer without any sampling.

Intuition

Start with a guess for every cell, say zero. Then go through the grid, cell by cell, and replace each cell's guess by its one-step ledger line: the cost of the move plus the current guess for the cell it lands in, averaged over the directions. Repeat. Each pass is called a sweep. Information travels one cell per sweep: the cells next to a goal learn their correct value first, then their neighbours learn from them, and so on, like ripples spreading from a stone.

Nothing about the answer changes if you stop early or change the order of the cells; only the speed does. That is why the method is called iterative: it converges, and you decide how close is close enough.

Build it up, one piece at a time

Step 1: the rules. Label the cells 0 to 15, row by row. Cells 0 and 15 are terminal, so V(0)=V(15)=0. Cells 1 to 14 are non-terminal. For cell 1, moving left reaches the terminal cell 0, moving right reaches cell 2, moving down reaches cell 5, and moving up stays in cell 1 because the grid edge blocks it.

Step 2: sweep one. Start with all values zero. Every move from a non-terminal cell costs 1 and lands on a cell whose value is 0, so every non-terminal cell becomes -1.

Step 3: sweep two, carefully, for cell 1. The values after sweep one are −1 for every non-terminal cell. Now:

Worked example: cell 1 under the uniform random policy, γ = 1
V_2(1)=\tfrac14\big[(-1+0)+(-1+V_1(1))+(-1+V_1(2))+(-1+V_1(5))\big]=\tfrac14\big[-1-2-2-2\big]=-1.75

The four terms are: left reaches the goal (value 0); up stays in cell 1 (value −1); right reaches cell 2 (−1); down reaches cell 5 (−1). Each costs 1 and adds the neighbour's value. Cell 5 gets V_2(5)=-2 by the same reasoning, because none of its neighbours is a goal.

Sweep three for cell 1. The values after sweep two are V_2(1)=-1.75, V_2(2)=-2, V_2(5)=-2. Then V_3(1)=\tfrac14[(-1)+(-1-1.75)+(-1-2)+(-1-2)]=\tfrac14(-9.75)=-2.4375.

Step 4: the answer. If we keep sweeping, the values settle. For this policy with \gamma=1, after 426 sweeps every change is smaller than 10^{-10}, and the table is:

0 (goal)−14−20−22
−14−18−20−20
−20−20−18−14
−22−20−140 (goal)

Cells next to a corner have the highest values because a random walk reaches the corner sooner from there. Cell 1 is −14: on average a random walk needs 14 moves from it.

The formal definition

Start from any V_0 (zero is the usual choice; terminal states are fixed at zero). For k=0,1,2,\dots, sweep every non-terminal state:

V_{k+1}(s)=\sum_a\pi(a\mid s)\sum_{s',r}p(s',r\mid s,a)\big[r+\gamma V_k(s')\big]

Stop when \max_s |V_{k+1}(s)-V_k(s)|<\theta, for a small tolerance \theta. The update is called a backup: a Bellman expectation equation turned into an assignment.

V_kthe estimate after k sweeps (not the true value)
\pi(a\mid s)the policy being evaluated; uniform random in the worked example
p(s',r\mid s,a)the model: here a move is deterministic, so the probability is 1 for one successor
\thetathe stopping tolerance on the size of one sweep's change

Two facts make the method correct. For \gamma<1 the backup is a contraction: the largest error shrinks by a factor of at least \gamma each sweep, so \max_s|V_k(s)-V^\pi(s)|\le\gamma^k\max_s|V_0(s)-V^\pi(s)|. When the policy ends every episode with probability one, the same convergence holds with \gamma=1.

Lab: sweeping the table

The lab runs exactly the sweeps above on the 4×4 grid. Each sweep replaces every cell at once, using the previous sweep's numbers (the "two-array" form). Watch the goal's influence spread out.

Try this
  1. Keep γ = 1 and the uniform policy. Step once at a time and check that the first sweep gives −1 everywhere, and the second gives −1.75 for cell 1.
  2. Change the stopping tolerance from 0.01 to 0.000001. Count how many sweeps are needed. Notice that the change per sweep drops quickly at first and then slowly.
  3. Set γ to 0.9. Each value is now smaller in size, because far-away outcomes count for less.
  4. Choose Always down with γ = 1. The values fall without limit. Explain why, using the trap below.

Common traps

Common traps
  • A small change is not a small error. A sweep with a tiny change can still be far from the answer when γ is close to 1. The error is bounded by about \gamma\,\Delta/(1-\gamma), where Δ is the change in the last sweep.
  • Undiscounted improper policies diverge. Under always down, cells 1, 5 and 9 walk to the bottom row and then stay there forever, never reaching a goal. With γ = 1 each sweep subtracts another 1, so the values run off to −∞. The same policy with γ = 0.9 converges, to −10 for those cells.
  • Two arrays or one. Updating in place (using values already changed in this sweep) also converges, usually faster, but the numbers in a sweep then depend on the order of cells. The two-array form used here gives reproducible sweeps.
  • Forgetting that terminal cells stay at zero. If the goal is updated like any other cell, the whole table drifts.
Where it shows up in AI
  • Critics in actor–critic methods. A critic network is trained to predict the value of the current policy, which is policy evaluation with a function approximator in place of the table.
  • Advantage estimation in PPO. The advantage that drives each policy-gradient step is computed from values of the current policy, the same quantity this method computes exactly on a small grid.
  • Offline policy evaluation. When a company tests a new policy using logged data, it estimates the policy's value by an extension of the same backup.
Pipeline placement. Evaluate stage. Stores one value per state (a table with 16 numbers here, a network in large problems). One sweep costs one backup per non-terminal state and action: 14 × 4 = 56 backups, each reading a single successor because the moves here are deterministic.

Check yourself

1. Under the uniform policy with γ = 1, why is V₂(5) = −2?
Each of the four moves from cell 5 costs −1 and lands on a non-goal cell whose sweep-one value is −1 (or stays put, which also has value −1). Each term is therefore −1 + (−1) = −2, and the average is −2.
2. Cell 1 ends at −14 under the uniform policy. Roughly how many moves does a random walk need from it, on average?
About 14. With γ = 1 the value is the negative of the expected number of moves until the episode ends, so −14 means 14 moves on average.
3. Why does "always down" with γ = 1 never converge?
From cell 1 the moves are 1 → 5 → 9 → 13, and from 13 the down move stays in 13 forever. The episode never ends, so the sum of −1 rewards is infinite and each sweep makes the values more negative.

Takeaways

  • Policy evaluation is repeated Bellman expectation backups: each sweep replaces each value by its one-step look-ahead under the policy.
  • Information spreads one step per sweep, so convergence is fast on small grids and slow for long horizons.
  • The tolerance controls how much you trust the answer; with γ near 1, a small change can still hide a large error.
2.3

Policy improvement & the greedy policy

The questionWe now know that a random walker in cell 1 of the 4×4 grid needs about 14 moves to finish. Suppose the walker is allowed to pick its move on purpose. Is a random move the best choice in cell 1? If not, what should it do, and does changing the move in cell 1 alone matter, or do we have to change the policy everywhere?

Intuition

Imagine you have a map with a good estimate of how far each town is from the destination. Standing in a junction, you look at each road, add up the cost of driving it and the estimated distance from where it leads, and take the road with the smallest total. You did not have to know the whole route in advance; a one-step look-ahead with the current estimates is enough to improve on a random choice.

This look-ahead is the action value Q^\pi(s,a): the value of taking action a once in state s, then following \pi. If one action has a larger action value than the policy's own average, switching to it is an improvement.

Build it up, one piece at a time

Step 1: the policy's average is its value. In cell 1, the uniform policy takes each action with probability one quarter. Its value is the average of the four action values: V^\pi(1)=\sum_a\pi(a\mid 1)Q^\pi(1,a).

Step 2: compute the action values from the converged table. Using the values from lesson 2.2 (cell 2 is −20, cell 5 is −18, and the goal is 0), the four action values in cell 1 are:

Worked example: action values in cell 1, uniform policy, γ = 1
Q^\pi(1,\text{left})=-1+0=-1,\qquad Q^\pi(1,\text{up})=-1+V^\pi(1)=-1-14=-15
Q^\pi(1,\text{down})=-1+V^\pi(5)=-1-18=-19,\qquad Q^\pi(1,\text{right})=-1+V^\pi(2)=-1-20=-21

Check that the average of these four equals the policy's value: \tfrac14(-1-15-19-21)=\tfrac14(-56)=-14=V^\pi(1). The bookkeeping is consistent.

The best action is left, with value −1: go straight to the goal. Acting greedily in cell 1 improves its value from −14 to −1. Note that the choice in cell 1 only needed the values of the neighbours, not a new evaluation.

Step 3: why one state's improvement is worth making in every state. Take the new greedy action in every cell at once. The policy improvement theorem says the resulting policy is at least as good as the old one in every state, and strictly better in some state unless the old policy was already optimal. The argument is that replacing the first action of a policy by a better one, then following the old policy, never decreases value; repeating that step for every decision in sequence then pushes the whole value up.

The formal definition

Given a policy \pi and its action values Q^\pi, the greedy policy \pi' is defined by

\pi'(s)=\arg\max_a Q^\pi(s,a)\qquad\text{for every state }s

and the theorem states that V^{\pi'}(s)\ge V^\pi(s) for every state s, when \pi' is greedy with respect to Q^\pi and both are evaluated under the same conditions (a finite problem with \gamma<1, or proper policies when \gamma=1).

Q^\pi(s,a)the value of taking a in s once, then following \pi
\arg\max_athe action that gives the largest value; if several tie, any of them is greedy
\pi'the improved policy, which is deterministic when there are no ties

Lab: one look-ahead at a time

The lab starts from the uniform policy and its converged values. Click any cell to see its four action values as bars, with the arithmetic written out in the readout. Then apply the greedy improvement to every cell and see how many decisions change.

  2. Press Improve. Count how many cells changed their arrow. Then press Evaluate and check that the value of cell 1 rises above −14.
  3. Repeat Improve and Evaluate a few times. Note that the arrows stop changing after the improved policy is evaluated: the policy is now greedy with respect to its own values.

Common traps

Common traps
  • Greedy is with respect to Q, not V. Choosing the action with the largest V(s') of the next state ignores the reward on the move. Use r+\gamma V(s') for each action, which is exactly Q.
  • Improvement needs an evaluation to be trusted. The new values are only known after you evaluate the new policy. Improvement by itself uses the old values.
  • Ties are not an error. If two actions have equal values, either is greedy; a policy that splits probability among them is still optimal.
  • The theorem assumes exact values. With approximate or sampled Q, an apparent improvement can be noise. Sampling-based methods need care here.
Where it shows up in AI
  • The control step of every value-based method. Q-learning, SARSA and DQN act greedily with respect to their current action values, which is this step applied to samples.
  • Greedy decoding in search. Choosing the next move with the best look-ahead is the same operation as the greedy policy, applied in board games and planners.
Pipeline placement. Improve stage. Reads the value table and writes a new policy (a table of arrows here, a softmax or network in larger problems). Cost is one look-ahead per state and action, which is cheap compared with the evaluation that precedes it.

Check yourself

1. Under the uniform policy, what is Q(1, right), and why is it not the best action in cell 1?
Q(1, right) = −1 + V(2) = −1 − 20 = −21. It is the worst action because cell 2 is far from a goal, so the walk to the right takes many more moves.
2. Check that the uniform policy's value at cell 1 is the average of its action values.
(−1 − 15 − 19 − 21) / 4 = −56 / 4 = −14 = V(1). Every action value is consistent with the value of the policy that chooses among them.
3. Does greedy improvement in one cell help the policy elsewhere?
Not by itself. The theorem applies to the whole policy: when every cell is made greedy at once, the values are no worse anywhere, and strictly better somewhere unless the policy was already optimal.

Takeaways

  • An action's value is its one-step reward plus the discounted value of where it leads: Q=r+\gamma V(s').
  • Acting greedily with respect to the action values of a policy never makes the policy worse.
  • Improvement and evaluation are separate steps; the new values are known only after evaluating the new policy.
2.4

Policy iteration

The questionStart the robot on the 4×4 grid with a bad habit: it always moves down. With a discount of γ = 0.9, the values under that habit are poor, and many cells have values of −10 because they never reach a goal. Can we find the best policy from this starting point without guessing, and how do we know when we are done?

Intuition

Use the two tools from the last lessons in turn. First, evaluate the current policy honestly: find its values. Second, improve it by acting greedily on those values. Then evaluate the new policy, improve again, and so on. Think of a coach who first grades the team's current play, then changes the tactics that the grades show to be weakest. Each round either changes the tactics or confirms that nothing more can be gained.

Each improvement is a strict gain until the policy is optimal, and there are only finitely many policies, so the process must stop. It stops exactly when the greedy policy equals the policy that was just evaluated.

Build it up, one piece at a time

Step 1: the bad starting policy. Let \pi_0 be "always move down", with the usual rule that a move off the grid leaves you in place. With \gamma=0.9, evaluate it. Cells that never reach a goal under this habit are worth -1/(1-0.9)=-10: cell 1 goes down to cell 5, to cell 9, to cell 13, and then stays in 13 forever.

Step 2: the values that reach a goal. Cell 3 goes down to 7, to 11, to 15: three moves. Its value is -1-0.9-0.81=-2.71. Cell 7 has value -1-0.9=-1.9, and cell 11 has value −1.

Step 3: improve. In cell 2, the choices are:

Worked example: improving cell 2 under "always down", γ = 0.9
Q(2,\text{right})=-1+0.9\,V(3)=-1+0.9(-2.71)=-3.44,\qquad Q(2,\text{left})=-1+0.9\,V(1)=-1+0.9(-10)=-10

Down and up give −10 as well, because they lead to cells with value −10. So the greedy action in cell 2 is right. The same comparison, done for every cell, gives the first improved policy. Cell 1's greedy action is left, which goes straight to the goal.

Step 4: repeat. Evaluating the first improved policy takes 78 sweeps; the next improvement changes a few more cells, and so on. The run of the algorithm from "always down" is:

RoundEvaluation sweepsWhat the improvement changed
1220cell 2 now right; cell 1 now left; many others
278cells 2, 5, 6, 9 and 10 now point towards a goal
34cell 3 and cell 6 change to their final choices
44nothing: the greedy policy equals the evaluated one, so it stops

The final values, which are the optimal values V^* at γ = 0.9, are:

0 (goal)−1.0−1.9−2.7
−1.0−1.9−2.7−1.9
−1.9−2.7−1.9−1.0
−2.7−1.9−1.00 (goal)

Notice that the fourth round needed only four sweeps. This table restarts each round's evaluation from zero, as the lab does, so the drop comes from this policy's values settling quickly, not from a warm start. Starting evaluation from the previous round's values (a warm start) is a common practical speed-up.

The formal definition

\pi_0\ \rightarrow\ V^{\pi_0}\ \xrightarrow{\text{improve}}\ \pi_1\ \rightarrow\ V^{\pi_1}\ \rightarrow\ \cdots\ \rightarrow\ \pi^*

Evaluation is the iterative method of lesson 2.2 run until its sweeps change less than \theta. Improvement is the greedy step of lesson 2.3, \pi_{k+1}(s)=\arg\max_a Q^{\pi_k}(s,a). The algorithm stops when \pi_{k+1}=\pi_k in every state, at which point the Bellman optimality equation holds and \pi_k is optimal.

\pi_kthe policy after round k
V^{\pi_k}its evaluated values
\pi^*an optimal policy: one whose values equal V^* in every state

Why it converges. In a finite MDP there are finitely many deterministic policies, and each round produces a policy at least as good as the last, strictly better unless it is already optimal. A sequence of strictly improving policies cannot repeat, so it must reach an optimal one. With γ = 1 the same argument needs every policy considered to terminate.

Common traps

Common traps
  • Stopping on equal values instead of equal policies. Two policies can have different arrows and the same values in some cells. The stopping rule is that the greedy policy is unchanged.
  • Evaluating too loosely. A loose tolerance can make the improvement step choose from noisy values and oscillate. Evaluate to a tolerance well below the size of the value differences you care about.
  • Confusing the evaluation with the answer. A policy can be evaluated exactly and still be bad. Evaluation tells you its value; only the improvement step looks for a better policy.
  • Expecting this to scale. Each round needs a full evaluation. Large state spaces need approximate evaluation, which is the subject of the next modules.
Where it shows up in AI
  • Model-based planning. Planners for games and logistics with a known model use policy iteration, or its variants, to compute the best plan.
  • The template for approximate control. Methods that alternate between fitting a critic and improving the actor follow this loop, with the evaluation step done approximately by a network.
Pipeline placement. Evaluate and improve stages in alternation, both run offline on a model. Stores the policy and the value table; each round costs one full evaluation, which dominates the total cost.

Check yourself

1. Under "always down" with γ = 0.9, why is V(1) = −10?
From cell 1 the walk is 1 → 5 → 9 → 13, then it stays in 13 forever with reward −1 each step. The discounted sum is −1/(1 − 0.9) = −10.
2. Why did the fourth evaluation take only four sweeps?
Round four's policy is already close to optimal, and this table restarts evaluation from zero, so the four sweeps reflect how fast this policy's values settle. A warm start from round three's values is a further speed-up that practical implementations use.
3. Why must policy iteration terminate on a finite MDP?
Each round produces a policy at least as good as the previous one, and strictly better unless the previous one is optimal. There are finitely many deterministic policies (4 actions in each of 14 cells here, so 4^14), so the sequence cannot go on forever without stopping at an optimal policy.

Takeaways

  • Policy iteration alternates full evaluation and greedy improvement until the policy stops changing.
  • Each round is an exact improvement, so the algorithm converges in a finite number of rounds on a finite MDP.
  • The cost is dominated by evaluation; a good starting policy makes later evaluations much faster.
2.5

Value iteration

The questionPolicy iteration evaluates a full policy before every improvement, and each evaluation can take hundreds of sweeps. The floor of the gridworld is now slippery: when the robot tries to move, with probability 0.2 it instead moves in one of the other three directions, chosen at random. Do we really need to evaluate a whole policy before improving it, or can we improve the values directly, sweep by sweep?

Intuition

Value iteration removes the separate evaluation. In each sweep, every cell takes the best one-step look-ahead, rather than the average under a policy. The values are then the best achievable values after one more step of planning. The policy is never written down during the process; it is read off the final values at the end, by acting greedily.

You can think of it as policy iteration with exactly one evaluation sweep before each improvement. There is no need to finish evaluating a policy that is about to change anyway.

Build it up, one piece at a time

Step 1: start with the deterministic grid. Every move succeeds, \gamma=0.9, and the values start at zero. In sweep one, every cell's best move costs −1 and lands on a cell of value 0, so every non-terminal cell becomes −1.

Step 2: sweep two. Cell 5 can move up to cell 1, which now has value −1, so it gets -1+0.9(-1)=-1.9. Cell 1 is still −1, because moving left reaches the goal directly. On this grid every cell is at most three moves from a goal, so the values are already optimal after sweep three; a fourth sweep changes nothing.

Step 3: add the slip, and the problem becomes a real convergence question. Take \text{slip}=0.2: the intended move happens with probability 0.8, and each of the three other moves with probability 0.2/3. The best action in cell 1 during sweep two is again left:

Worked example: cell 1 with slip 0.2, γ = 0.9, sweep two

After sweep one, V_1=-1 for every non-terminal cell. The action "left" has four possible outcomes, and the cost of each move is −1:

Q(1,\text{left})=0.8\,(-1+0)+\tfrac{0.2}{3}\big[(-1+0.9V_1(1))+(-1+0.9V_1(2))+(-1+0.9V_1(5))\big]
=0.8(-1)+\tfrac{0.2}{3}\big[-1.9-1.9-1.9\big]=-0.8-0.38=-1.18

So V_2(1)=-1.18. Each later sweep changes the values by at least a factor of γ less than the sweep before, so the sequence settles.

Step 4: the formal update. Each sweep replaces V_k by the best backup of V_k. With tolerance 0.001 the values settle near −1.38 at cell 1 after about 13 sweeps (the lab shows the count).

The formal definition

V_{k+1}(s)=\max_a\sum_{s',r}p(s',r\mid s,a)\big[r+\gamma V_k(s')\big]

Stop when \max_s|V_{k+1}(s)-V_k(s)|<\theta, then act greedily with respect to V_{k+1}. Two results matter. First, the backup contracts: \max_s|V_k(s)-V^*(s)|\le\gamma^k\max_s|V_0(s)-V^*(s)|. Second, if the last sweep changed the values by less than θ, then \max_s|V_{k+1}(s)-V^*(s)|\le\frac{\gamma}{1-\gamma}\theta. The second bound is the one to use when deciding when to stop.

\max_athe best action in each state, instead of the policy's average
p(s',r\mid s,a)the model; with slip, the intended action has probability 0.8 and each other action 0.2/3
\thetathe stopping tolerance on one sweep's largest change
\gamma/(1-\gamma)the factor that turns a small change into an error bound: 9 for γ = 0.9

Cost. One sweep looks at every state, every action and every possible successor. The 4×4 grid has 14 non-terminal cells (the two goals are fixed), 4 actions and 4 outcomes each, so a sweep is 14 × 4 × 4 = 224 outcome terms. Small grids make this trivial; the cost grows with the number of states times the number of actions times the branching of each action.

  2. Set slip to 0.2 and step once at a time. Check the sweep-two value for cell 1 against the worked example: −1.18.
  3. Set the tolerance to 0.01 and read the number of sweeps and the error bound at the stop. Then set it to 0.0001 and compare.

Common traps

Common traps
  • Stopping on a small change without the bound. A tolerance of 0.01 on the change means an error of up to 0.09 at γ = 0.9, and up to 0.99 at γ = 0.99. Choose the tolerance with γ in mind.
  • Mixing up max and average. Value iteration uses the max over actions; if you average over a fixed policy, you have written policy evaluation, not value iteration.
  • The greedy policy of an early sweep can be wrong. Only the final values determine the optimal policy. Arrows drawn from early sweeps may still change.
  • Mistaking exact convergence for a general fact. The deterministic grid converges in three sweeps because of its small size. With slip or larger grids, convergence takes many more sweeps.
Where it shows up in AI
  • Planning in known models. Operations research and robotics planners solve Markov decision processes with value iteration over a discretised state space.
  • Q-learning in disguise. Q-learning replaces the expectation over successors in the max-backup by one sampled successor. Value iteration is its exact, model-based counterpart.
Pipeline placement. Estimate and improve stages, fused into one update, run offline on a known model. Stores one value per state; the policy is computed from the values when needed.

Check yourself

1. With slip 0.2 and γ = 0.9, what is Q(1, left) after sweep two, if every value after sweep one is −1?
0.8(−1) + (0.2/3)(−1.9 − 1.9 − 1.9) = −0.8 − 0.38 = −1.18.
2. The sweep changed the values by at most 0.01, and γ = 0.9. What is the largest possible error of the current values?
γθ/(1 − γ) = 0.9 × 0.01 / 0.1 = 0.09. The values are within 0.09 of V* in the worst state.
3. How many outcome terms does one sweep need on the 4×4 grid with four outcomes per action?
14 non-terminal states × 4 actions × 4 outcomes = 224 terms. The two goal cells are skipped because their values are fixed.

Takeaways

  • Value iteration applies the best one-step backup in every sweep and does not evaluate a policy in between.
  • The values contract by γ per sweep, so the error after k sweeps is bounded by γk times the starting error.
  • Stop on a small change, but convert it to an error bound with γ/(1 − γ) before trusting the answer.
2.6

Generalised policy iteration

The questionPolicy iteration does a complete evaluation before each improvement; value iteration does a single sweep. Between these extremes lie many choices: three sweeps of evaluation, then an improvement; ten sweeps; or a very long evaluation. Which is best? And is there a single principle that explains all of them, including the learning methods that come later?

Intuition

Every method in this module keeps two things: a value table and a policy. The evaluation process pushes the values towards the values of the current policy. The improvement process pushes the policy towards the greedy policy for the current values. Each process moves the other: a new policy makes the old values wrong, and new values make the old policy suboptimal.

Picture two people walking toward each other on a path, one holding the values and one holding the policy. They do not need to finish their steps before the other begins. Whatever the amount of evaluation per round, the pair ends at the same place: the point where the values match the policy and the policy is greedy for the values. That point is the solution of the Bellman optimality equation.

Build it up, one piece at a time

Step 1: a tiny example where the two processes meet. Return to the two-state choice problem of lesson 2.1, with γ = 0.9. Start from the policy "always stay" in A. Its value is V(A)=1/(1-0.9)=10 and V(B)=0.9\cdot10=9.

Worked example: evaluation and improvement in turn

Improve. The action values under the current values are Q(A,\text{stay})=1+0.9(10)=10 and Q(A,\text{go})=3+0.9(9)=11.1. "Go" is larger, so the greedy policy is "go".

Evaluate. Under "always go", the values are V(A)=3+0.81V(A), so V(A)=15.789 and V(B)=14.211. Both values rose, as the improvement theorem promised.

Improve again. Q(A,\text{stay})=1+0.9(15.789)=15.21 and Q(A,\text{go})=3+0.9(14.211)=15.79. The greedy action is still "go", so nothing changes and the pair has met: these values are the optimal ones.

Step 2: how much evaluation per round? Let k be the number of evaluation sweeps before each improvement. With k=1 the evaluation sweep is followed by a greedy step over the same values, which is exactly the value iteration of lesson 2.5. With k=\infty, evaluation runs to convergence before each improvement, which is policy iteration. Values of k in between trade work per round against the number of rounds.

Step 3: what is shared. Both extremes converge to the same optimal values, and so does every value of k in between, under the same conditions. Only the path changes: small k makes many cheap rounds, large k makes few expensive rounds with a good policy to evaluate.

The formal definition

Generalised policy iteration (GPI) is any scheme that alternates an evaluation process and an improvement process, each applied with any schedule:

\text{evaluation: } V \leftarrow T^{\pi}V \quad (\text{repeated } k \text{ times}),\qquad \text{improvement: } \pi(s)\leftarrow\arg\max_a Q_V(s,a)

Here T^\pi is the Bellman expectation backup for the policy \pi, and Q_V(s,a)=\sum_{s',r}p(s',r\mid s,a)[r+\gamma V(s')] is the action value computed from the table V. The process has reached its goal when the values are unchanged by evaluation and the policy is unchanged by improvement, which is the optimality equation.

T^\pithe expectation backup for policy \pi: one sweep of policy evaluation
kthe number of evaluation sweeps per improvement; k=1 is value iteration, k=\infty is policy iteration
Q_Vthe action values computed from a value table V

The value of a policy and the policy that is greedy for those values are two descriptions of the same fixed point. GPI is a description of the pattern, not a single algorithm.

Common traps

Common traps
  • More evaluation is not always cheaper. A large k can waste sweeps evaluating a policy that is about to change. The best k depends on how quickly the policy settles.
  • GPI does not mean "evaluate until perfect, then improve". That is policy iteration, one special case. Evaluation can be stopped early and the process still converges.
  • The optimum is a fixed point of both processes. If the values stop changing but the policy would change, you are not done; if the policy is stable but its values are still moving, you are not done either.
  • Convergence assumes the usual conditions. The results above need a finite MDP and γ < 1, or a terminating problem. With function approximation the two processes can interfere with each other, which is the subject of Module 5.
Where it shows up in AI
  • Actor–critic methods. A2C and PPO alternate a few critic updates (evaluation) with actor updates (improvement). They are GPI with a truncated, approximate evaluation.
  • Q-learning and SARSA. Each step evaluates the current policy with one sampled backup and improves it greedily (or ε-greedily). The pattern is GPI with k of one, on samples.
Pipeline placement. Estimate and improve stages interleaved on a schedule chosen by the designer; a model is needed for exact backups. Stores the value table and the policy; the cost of a round is k sweeps plus one improvement.

Check yourself

1. Which special case of GPI is value iteration?
k = 1: one evaluation sweep, then a greedy improvement on the same values. After a greedy improvement, one evaluation sweep of the new policy is exactly the max-backup of the old values, so the pair is value iteration.
2. In the two-state example, why is the greedy action "go" after evaluating "always stay"?
Q(A, go) = 3 + 0.9 · V(B) = 3 + 0.9 · 9 = 11.1, which is larger than Q(A, stay) = 1 + 0.9 · 10 = 10. Going is worth more given the current values.
3. Does a different k change the optimal values that GPI converges to?
No. Under the same conditions every schedule converges to the same optimal values and policy. The schedule changes how many sweeps and rounds it takes to get there.

Takeaways

  • Evaluation and improvement are two pressures that push a value table and a policy towards each other.
  • Policy iteration and value iteration are the two extremes of how much evaluation to do before each improvement.
  • Almost every RL control method is GPI with samples, approximate evaluation or a learned critic.
