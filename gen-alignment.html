Module 4 · Alignment & post-training

A pretrained model continues text: it imitates whatever text it saw, including rude, wrong and useless text. Post-training reshapes it into an assistant that follows instructions, prefers helpful answers and declines some requests. This module sits in the align stage of the pipeline (collect and tokenise, pretrain, align, adapt and compress, generate, evaluate and guard). Every lesson is taught on a toy with three answers to one prompt, so each probability, reward and loss can be computed by hand.

4.1

Instruction tuning

The questionA pretrained model, shown the text "What is 2 + 2 ?", may continue with "What is 3 + 3 ? What is 4 + 4 ?", because lists of questions are common in its training text. How do we turn a text continuer into something that answers? And when we train on question-and-answer examples, which tokens should the loss count: all of them, or only the answer?

Intuition: show it what a good reply looks like

The pretraining objective (Module 3) is next-token prediction on raw text. The model has the knowledge but no habit of using it as a reply. Supervised fine-tuning (SFT), also called instruction tuning, continues training on a much smaller set of examples that each look like a conversation: an instruction, then the reply we would like. It is the same next-token loss as before. Only the data changed, so the model learns "after a user turn, I produce an assistant turn".

Two practical details matter. First, the examples are written in a fixed chat template: special marker tokens that say who is speaking. Second, the model only needs to learn to write the reply, not to write the user's question, so the loss is computed on the reply tokens alone. That is loss masking.

Build it up

The template. The conversation is flattened into one token sequence. We use three toy markers: <usr> opens the user's turn, <bot> opens the assistant's turn, and <end> ends it. (Real systems use their own marker tokens; the idea is identical.) The end marker matters: it is how the model learns to stop.

Worked example: one training example, token by token

The example is the sequence <usr> What is 2 + 2 ? <bot> It is 4 . <end>. That is 8 prompt tokens (<usr> What is 2 + 2 ? <bot>) and 5 response tokens (It is 4 . <end>), 13 in all. Suppose, at the start of training, the toy model gives each response token these probabilities when it is shown the tokens before it:

response tokenItis4.<end>
probability p0.500.400.250.800.90
loss -\ln p0.69310.91631.38630.22310.1054

The losses add to 3.3242, and the masked loss is their mean, 3.3242/5=0.6648. Now suppose the model also gave each of the 8 prompt tokens probability 0.2, so each costs -\ln 0.2=1.6094, 12.8755 in total. If we did not mask, the loss would be (12.8755+3.3242)/13=1.2461, almost twice as large, and most of it would come from tokens we never want the model to produce: the user's own words.

Why does the unmasked version hurt? The gradient would spend effort making the model better at writing questions in this template. At best that is wasted capacity; at worst the model learns to hallucinate user turns. With the mask, the prompt is context the model reads (it still influences every response prediction through attention), but it receives no gradient as a target.

Data diversity. SFT sets are small compared with pretraining sets, so what they contain is decisive. A set with only one style of instruction (all short factual questions) teaches a narrow habit; a set that mixes tasks, lengths, formats and tones teaches a general habit of following instructions. Quality beats quantity here: a small number of careful, varied examples often moves the model more than a larger set of repetitive or sloppy ones, and errors in the replies are copied faithfully, because the model is trained to imitate them.

The formal picture

Write the flattened example as tokens t_1,\dots,t_T and let m_i\in\{0,1\} mark the response tokens. The SFT loss is the masked average of the usual next-token cross-entropy:

\mathcal{L}_{\text{SFT}}(\theta)\;=\;-\frac{1}{\sum_i m_i}\sum_{i=1}^{T} m_i\,\ln p_\theta\!\left(t_i\mid t_{<i}\right)
Symbols. \theta: the model's parameters. t_i: the i-th token of the flattened conversation. t_{<i}: all tokens before it (the model always sees the whole prefix, including the prompt). p_\theta(t_i\mid t_{<i}): the probability the model assigns to the true next token. m_i: the mask, 1 on response tokens and 0 on prompt tokens. The sum in the denominator counts the response tokens, so the result is a mean. Setting every m_i=1 recovers plain next-token training (cross-entropy).

Across a batch there are two common averaging choices: mean per example, then over examples (every example counts equally) or mean over all response tokens in the batch (long replies count more). Neither is wrong, but they weight long and short answers differently, which is a design decision worth knowing about.

Try this

  2. Switch to "all tokens" and reset. The orange prompt tokens now also climb: the model is being trained to write the question. Compare the "loss being minimised" number with the first run at the same step.
  3. Edit the response (for example to It is four . <end>), press Enter, and watch the number of trained tokens change with it.
Common traps
  • "SFT teaches the model new knowledge." It mainly teaches a format and a habit on top of what pretraining stored. Facts absent from pretraining are not reliably added by a small SFT set, and training on replies that state facts the model does not know can push it toward confident invention.
  • Forgetting the end marker. If the stop token is left out of the loss, the model never learns to stop and keeps generating.
  • Wrong template at inference. A model tuned with one template behaves worse if prompted with a different one, because the marker tokens are part of what it learned.
  • Imitation copies mistakes. SFT can only be as good as its demonstrations; it cannot tell a better reply from a worse one. The next lessons add a signal for that.
Where it shows up in AI
  • Assistant models commonly begin post-training with an SFT stage on instruction-and-reply pairs, then apply preference methods (lessons 4.2 to 4.4) on top.
  • Cheap adaptation: SFT is the standard way to specialise a model to a format or domain, often combined with low-rank adapters so that only a few parameters are updated.
  • Synthetic data: replies written by another model can serve as SFT data; the quality caveat above applies, and so do the licensing terms of whatever produced them.

Check yourself

1. In the worked example, what are the masked loss and the unmasked loss, and what does the difference tell you?
Masked: (0.6931 + 0.9163 + 1.3863 + 0.2231 + 0.1054)/5 = 3.3242/5 = 0.6648. Unmasked: (12.8755 + 3.3242)/13 = 16.1997/13 = 1.2461. The unmasked loss is dominated by the 8 prompt tokens, which the model is not meant to generate, so it is a misleading target.
2. If the model's probability for the response token "4" rose from 0.25 to 0.50, by how much does that one token's loss fall?
From -ln 0.25 = 1.3863 to -ln 0.50 = 0.6931, a fall of 0.6931 (that is, ln 2: doubling a probability always removes ln 2 from that token's loss).
3. Why do the prompt tokens still matter if they carry no loss?
They are in the prefix t_{<i} of every response token, so the model's prediction of each reply token depends on them through attention. Masking only removes them as targets; they remain context.

Takeaways

  • SFT is ordinary next-token training on conversation-formatted data; only the loss mask and the data differ.
  • Loss on the response only: -\frac{1}{\sum m_i}\sum m_i\ln p_\theta. For the example, 0.6648 masked versus 1.2461 unmasked.
  • It teaches format and habit by imitation, cannot rank good against bad replies, and depends on the diversity and quality of its examples.
4.2

Preference data and reward models

The questionIt is hard to write the single best answer to a question, but easy to say which of two answers you prefer. How do we turn a pile of "answer X beats answer Y" judgements into a number that scores any answer, and what happens when the people judging disagree with each other?

Intuition: chess ratings for answers

Imagine rating chess players. You never see a player's "true strength"; you only see who beat whom. A model that gives each player a number, and says the player with the bigger number usually wins, can be fitted to the results. The same trick scores answers: each answer gets a number called a reward, and an answer with a larger reward should usually win a comparison. A reward model is a neural network (typically the language model with a small scoring head) that reads a prompt and an answer and outputs that number.

Comparisons are cheaper and more consistent than asking people to give absolute scores: two people disagree about whether an answer is a 6 or a 7 out of 10, but they often agree which of two answers is better.

Build it up

A preference record is a prompt x, two answers, and a label saying which was preferred, written y_w\succ y_l ("winner" and "loser"). The Bradley-Terry model says that the probability that y_w wins depends only on the difference of the two rewards, squashed into 0 to 1 by the logistic function \sigma(z)=1/(1+e^{-z}).

Worked example: three answers, three rewards

For the prompt "What is the capital of France?", let the answers be A = "Paris.", B = "The capital of France is Paris.", C = "Lyon." and let a reward model currently score them r(A)=1,\ r(B)=2,\ r(C)=0.

pairgap r_w-r_lP(y_w\succ y_l)=\sigma(\text{gap})
B over A10.7311
A over C10.7311
B over C20.8808

Loss for one labelled pair. If the label says B beat A, the model's probability of that label is 0.7311 and the loss is -\ln 0.7311=0.3133. If the label had said A beat B, the gap would be -1, the probability \sigma(-1)=0.2689 and the loss 1.3133. If both rewards were equal the gap is 0, the probability is 0.5 and the loss is \ln 2=0.6931: no opinion costs ln 2.

One update. Take the pair B over A with learning rate 0.5. The gradient of the loss with respect to the gap is -(1-\sigma(\text{gap}))=-0.2689, so the update raises r(B) and lowers r(A) by 0.5\times0.2689=0.1345 each: new rewards 2.1345 and 0.8655, new gap 1.2689, new probability 0.7806, new loss 0.2477. The loss fell from 0.3133 to 0.2477 after one step.

Notice that the update shrinks as the model gets the pair right: the weight 1-\sigma(\text{gap}) is 0.5 when the gap is 0 and approaches 0 when the gap is large. A pair the model already ranks correctly with confidence barely changes anything; a pair it ranks wrongly pushes hard.

Annotator noise. Real labels are noisy. If annotators pick B over A only with probability 0.7311, then even a perfect reward model cannot make its average loss lower than the entropy of that label, -[0.7311\ln0.7311+0.2689\ln0.2689]=0.5822, not zero. That floor is a feature of the data, not a failure of training. It also explains why a reward model should not be trained to drive its loss to zero: a loss far below the noise floor means it is memorising particular labels.

The formal picture

P(y_w\succ y_l\mid x)=\sigma\!\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big),\qquad \mathcal{L}_{\text{RM}}(\phi)=-\,\mathbb{E}_{(x,y_w,y_l)}\Big[\ln\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\Big]
Symbols. x: the prompt. y_w,y_l: the preferred and rejected answers. r_\phi(x,y): the reward model's scalar score, with parameters \phi. \sigma: the logistic function. \mathbb{E}: average over the preference dataset. The loss is the negative log-likelihood of the observed winners under Bradley-Terry, so minimising it is maximum-likelihood fitting. The gradient with respect to the gap is -(1-\sigma(\text{gap})), as used above.

Two properties are worth stating. The model sees only differences: adding the same constant to every reward changes no probability, so the absolute value of a reward has no meaning on its own (it will matter again in lesson 4.4, where the constant cancels). And the model assumes a transitive, single-scale preference: if B beats A and A beats C, it expects B to beat C. Real groups of annotators can violate this.

Try this
  1. In the first lab set r_w = 2 and r_l = 1 and read gap 1, probability 0.7311, loss 0.3133. Then make r_l larger than r_w and watch the loss grow roughly in a straight line.
  2. In the second lab press play at noise 0.6: the bars drift toward the dashed hidden qualities and the loss falls below the grey ln 2 line. Each update names the pair that was used.
  3. Set the noise to 3 and reset. The ranking is still recoverable but slowly, and the loss stays higher: noisy labels limit what any reward model can reach.
Common traps
  • Reading a reward as a score out of ten. Only differences are meaningful. A reward of 2 does not mean "good".
  • Treating the labels as truth. The data records what these annotators, under this guideline, preferred. Length, confident tone and formatting are frequently over-rewarded by people reading quickly, and the reward model learns exactly that.
  • Distribution shift. A reward model is accurate on answers like those it was trained on. If a policy later produces answers unlike any in the data, the scores there are extrapolation (lesson 4.3 shows why that is dangerous).
  • Ties and disagreement. Dropping pairs where annotators split loses information; keeping them with a hard label adds noise. How to handle them is a data-design choice.
Where it shows up in AI
  • RLHF (lesson 4.3) uses the trained reward model as the signal to optimise a policy against.
  • Evaluation and ranking: reward models are also used to rank or filter candidate answers (for instance, picking the best of several samples), and to filter training data.
  • Pairwise comparison is also how many public leaderboards compute ratings from human votes, using the same Bradley-Terry family of models.

Check yourself

1. A reward model gives the winner a reward 3 higher than the loser. What probability does it assign to the observed label, and what is the loss?
σ(3) = 0.9526, so the loss is -ln 0.9526 = 0.0486. The model is confident and right, so there is almost nothing to learn from this pair (the update weight is 1 - 0.9526 = 0.0474).
2. Adding 100 to every reward: does any preference probability or the loss change?
No. Every probability depends only on a difference r_w-r_l, and the constant cancels. Rewards are defined only up to an additive constant.
3. Annotators prefer B over A 73.11% of the time. Why can no reward model reach a loss of 0 on that pair of answers?
The label is itself random: 26.89% of the time the opposite label appears. The best any model can do is predict the probabilities 0.7311 and 0.2689, which gives an expected loss equal to the label entropy, 0.5822. A lower training loss would mean the model had memorised noise.

Takeaways

  • Bradley-Terry: P(y_w\succ y_l)=\sigma(r_w-r_l); the reward-model loss is -\ln\sigma(r_w-r_l), which is ln 2 = 0.6931 at a gap of 0 and 0.3133 at a gap of 1.
  • The update is weighted by 1-\sigma(\text{gap}): wrong and confident pairs teach most.
  • Rewards are only defined up to a constant; labels are noisy, so the loss has a floor above zero; and the model reproduces the annotators' habits, good and bad.
4.3

Reinforcement learning from human feedback

The questionWe now have a reward model that scores answers. Why not simply change the language model until its average reward is as high as possible? What goes wrong if we do, and what does a "leash" to the original model do about it?

Intuition: climbing a hill you can only see through a foggy window

The reward model is a proxy for what people want, learned from limited comparisons. Near the kind of answers it was trained on it is a decent guide. Far from them it is a guess, and an optimiser is very good at finding the places where the guess is too high. If you let a policy chase the proxy with no limit, it tends to find answers the proxy loves and people do not. That is reward hacking (also called reward over-optimisation): the proxy reward keeps rising while the true quality falls.

The standard remedy is a penalty for moving away from a trusted reference policy \pi_{\text{ref}}, usually the SFT model of lesson 4.1. The policy may improve its reward, but every step away from the reference costs something. How much it costs is set by a strength \beta.

Build it up

The objective. Sample an answer y from the policy \pi, score it with the reward model r, and subtract \beta times the log-ratio of the policy to the reference probability of that answer. Averaged over the policy's own samples, the penalty is exactly the KL divergence from the policy to the reference.

Worked example: a hackable reward on three answers

Same prompt, new answers: A = a concise correct reply, B = a longer correct reply, C = a padded, flattering reply that is actually wrong. The reference policy gives them probabilities 0.5,\,0.3,\,0.2. A reward model trained on fast-reading annotators over-scores length and flattery, so its proxy rewards are 1.0,\,1.8,\,3.0, while the true usefulness is 1,\,1,\,0.

Before any training the average proxy reward is 0.5\cdot1+0.3\cdot1.8+0.2\cdot3=1.64 and the average true reward is 0.8.

After optimising with a leash (the exact optimum, derived in lesson 4.4, is \pi^*\propto\pi_{\text{ref}}\,e^{r/\beta}):

\betapolicy (A, B, C)KL to referenceaverage proxyaverage true
20.3353, 0.3001, 0.36460.08501.96930.6354
10.1890, 0.2524, 0.55860.34632.31910.4414
0.50.0387, 0.1151, 0.84611.01102.78430.1539

Read the last two columns. The proxy reward rises from 1.64 each time, while the true reward falls from 0.80 to 0.44 (and 0.15 for a weaker leash). Mass has moved to the wrong, flattering answer C because the reward model scored it highest. That is reward hacking on a three-answer toy. A larger \beta (shorter leash) keeps the policy nearer the reference and limits the damage, at the price of a smaller gain. If the proxy were accurate, the same procedure would help.

Check the objective at \beta=1: average proxy 2.3191 minus 1\times0.3463 gives 1.9729, the largest value any policy can reach. Any other distribution, such as all mass on C, scores lower: 3-\ln(1/0.2)=1.3906.

How it is optimised in practice. The policy is a language model, and its answers are long token sequences, so the expectation cannot be computed exactly as in the toy. The usual outline is: (1) sample answers from the current policy for a batch of prompts; (2) score each with the reward model; (3) subtract the KL penalty, often implemented per token, to give a total reward; (4) update the policy with a policy-gradient method, very commonly PPO with its clipped probability ratio and an advantage estimate from a learned value network; (5) repeat, with the reference and the reward model held fixed. The lab below replaces steps (1) to (4) by the exact gradient, so you can watch only the effect of the objective.

The formal picture

\max_{\pi}\ \ \mathbb{E}_{x}\,\mathbb{E}_{y\sim\pi(\cdot\mid x)}\Big[\,r(x,y)\;-\;\beta\,\ln\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)}\Big]\;=\;\max_\pi\ \mathbb{E}\big[r\big]-\beta\,\mathrm{KL}\big(\pi\,\Vert\,\pi_{\text{ref}}\big)
Symbols. \pi(y\mid x): the policy, the language model being trained, giving the probability of answer y to prompt x. \pi_{\text{ref}}: the frozen reference policy. r(x,y): the reward model's score. \beta>0: the KL strength. \mathrm{KL}(\pi\Vert\pi_{\text{ref}})=\sum_y\pi\ln(\pi/\pi_{\text{ref}}): zero when the policy equals the reference and growing as it moves away. As \beta\to\infty the policy stays at the reference; as \beta\to0 it chases the reward alone.
Try this
  1. Leave the defaults (beta 1) and press play. The blue bars slide toward the orange ticks. Read the readout: it should settle at 0.1890, 0.2524, 0.5586, with true reward 0.4414. The red line (proxy) rises and the green line (true) falls: reward hacking.
  2. Raise beta to 2, then 4: the policy moves less, the KL stays small, and the true reward falls less. Lower beta to 0.5 and the damage grows.
  3. Edit the proxy reward of C down to 0.5 (so the proxy is no longer fooled): optimising the proxy now also raises the true reward.
Common traps
  • Reward hacking is not a bug in the optimiser. The optimiser does exactly what it is told. The reward model is a learned approximation, so any gap between it and the real goal is an opportunity for the optimiser. More optimisation pressure finds more such gaps.
  • The KL term is not a safety guarantee. It limits how far the policy moves, not in which direction. A policy can stay close in KL and still exploit a flaw, as the beta 2 row shows.
  • Choosing beta by the proxy reward. The proxy always prefers a smaller beta. It must be tuned against held-out human judgements or other independent checks.
  • Many moving parts. RLHF with PPO needs the policy, a reference copy, a reward model and a value network at once, and is sensitive to its settings. That cost motivates the next lesson.
Where it shows up in AI
  • Aligned chat models: many assistant models have been tuned with some form of reward optimisation against human preferences, with a penalty to a reference model. The precise recipes differ and are not given here.
  • Length and style drift: over-optimisation commonly shows up as answers becoming longer, more flattering or more hedged, which is why evaluations check length-controlled and independent measures.
  • Best-of-n sampling (generate n answers, return the highest-scoring) is a gentler way to use a reward model; it also over-optimises as n grows.

Check yourself

1. In the toy, what is the average proxy reward of the reference policy, and what is it at beta = 1 after optimisation?
Reference: 0.5·1 + 0.3·1.8 + 0.2·3 = 1.64. After optimisation at beta = 1 the policy is (0.1890, 0.2524, 0.5586) and the average proxy is 0.1890·1 + 0.2524·1.8 + 0.5586·3 = 2.3191.
2. Compute the objective for the policy that puts probability 1 on C (beta = 1).
Proxy reward 3. KL to the reference = ln(1/0.2) = 1.6094. Objective = 3 - 1.6094 = 1.3906, lower than the optimum 1.9729. Going all the way to the highest-scored answer is worse once the leash is counted.
3. Why does lowering beta raise the proxy reward and lower the true reward in this toy?
A weaker leash lets the policy move further toward the answer with the highest proxy score (C). C is the answer the proxy over-scores relative to the truth, so more of the policy's mass sits on an answer that is actually wrong. Both numbers change together because they are two averages over the same moving distribution.

Takeaways

  • RLHF maximises \mathbb{E}[r]-\beta\,\mathrm{KL}(\pi\Vert\pi_{\text{ref}}): reward, minus a leash to a reference policy.
  • Because the reward is a learned proxy, optimising it hard produces reward hacking: on the toy the proxy went from 1.64 to 2.3191 while the true reward went from 0.80 to 0.4414.
  • In practice the optimisation is sampled, with PPO or a similar policy-gradient method; the toy uses the exact gradient to show the objective itself.
4.4

Direct preference optimisation

The questionRLHF needs a reward model, sampling from the policy, a value network and a delicate optimiser. The objective, though, has a closed-form answer. Could we use that answer to skip the reward model and the reinforcement learning, and train on the preference pairs directly?

Intuition: solve the objective, then run it backwards

The KL-regularised objective of lesson 4.3 is a clean optimisation problem, and its best policy can be written down. That best policy depends on the reward in a simple way, so the relationship can be flipped: given any policy, we can say which reward it would be the best policy for. Call that its implicit reward. The Bradley-Terry model of lesson 4.2 only needs reward differences, and in the difference a troublesome constant cancels. We can therefore fit the preference pairs by treating the policy's own log-ratio to the reference as the reward. The result is direct preference optimisation (DPO): a single supervised loss on pairs, no reward model, no sampling.

Build it up: the derivation, step by step

Step 1: rewrite the objective. For one prompt, the objective is J(\pi)=\sum_y\pi(y)\,r(y)-\beta\sum_y\pi(y)\ln\frac{\pi(y)}{\pi_{\text{ref}}(y)}. Define a distribution proportional to the reference weighted by the exponential of the reward:

\pi^*(y)=\frac{\pi_{\text{ref}}(y)\,e^{r(y)/\beta}}{Z},\qquad Z=\sum_{y}\pi_{\text{ref}}(y)\,e^{r(y)/\beta}

so that \pi_{\text{ref}}(y)e^{r(y)/\beta}=Z\,\pi^*(y), that is r(y)=\beta\ln\frac{Z\pi^*(y)}{\pi_{\text{ref}}(y)}. Substitute this for r inside the objective:

J(\pi)=\beta\sum_y\pi(y)\Big[\ln\frac{\pi^*(y)}{\pi_{\text{ref}}(y)}+\ln Z-\ln\frac{\pi(y)}{\pi_{\text{ref}}(y)}\Big]=\beta\ln Z-\beta\,\mathrm{KL}\big(\pi\,\Vert\,\pi^*\big)

Step 2: read off the optimum. A KL divergence is never negative and is zero only when the two distributions are equal. So J is largest exactly when \pi=\pi^*, and the best achievable value is \beta\ln Z. That is the statement: the optimal policy is proportional to \pi_{\text{ref}}\,e^{r/\beta}.

Worked example: the optimum on the three-answer toy

Take the reference (0.5,0.3,0.2) and rewards r=(1,2,0), \beta=1. The unnormalised weights \pi_{\text{ref}}e^{r/\beta} are 0.5e^{1}=1.3591, 0.3e^{2}=2.2167 and 0.2e^{0}=0.2000. Their sum is Z=3.7759, so \pi^*=(0.3600,\ 0.5871,\ 0.0530). The maximum of the objective is \beta\ln Z=\ln 3.7759=1.3286. With \beta=2 the leash is shorter: Z=1.8398 and \pi^*=(0.4481,\ 0.4432,\ 0.1087), closer to the reference.

The implicit reward. Solving for the reward: r(y)=\beta\ln\frac{\pi^*(y)}{\pi_{\text{ref}}(y)}+\beta\ln Z. On the toy at \beta=1: \ln(0.3600/0.5)=-0.3286, \ln(0.5871/0.3)=0.6714, \ln(0.0530/0.2)=-1.3286. Adding \beta\ln Z=1.3286 gives 1,\ 2,\ 0, exactly the rewards we started from.

Step 3: put it into Bradley-Terry. From lesson 4.2, P(y_w\succ y_l)=\sigma(r(y_w)-r(y_l)). Insert the implicit reward for both answers. The term \beta\ln Z depends only on the prompt, so it appears in both and cancels in the difference. That cancellation is the whole trick, because Z is a sum over every possible answer and cannot be computed for a language model. What is left is a probability expressed only with policy and reference probabilities. Now let a trainable model \pi_\theta play the role of \pi^* and maximise the likelihood of the observed pairs. That gives the DPO loss below.

Worked example: one DPO loss and its gradient weight

Reference (0.5,0.3,0.2); the current policy is \pi_\theta=(0.40,\,0.45,\,0.15); the pair is B preferred over A; \beta=0.5.

Log-ratios: for the winner B, \ln(0.45/0.3)=0.4055; for the loser A, \ln(0.40/0.5)=-0.2231. The margin is m=0.5\,(0.4055-(-0.2231))=0.3143. Then \sigma(m)=0.5779 and the loss is -\ln0.5779=0.5483. The gradient weight is \sigma(-m)=0.4221. With \beta=1 instead, m=0.6286 and the loss is 0.4274. If the policy equals the reference, both log-ratios are 0, the margin is 0, the loss is \ln2=0.6931 and the weight is 0.5.

The formal picture

\mathcal{L}_{\text{DPO}}(\theta)=-\,\mathbb{E}_{(x,y_w,y_l)}\Big[\ln\sigma\Big(\beta\ln\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}-\beta\ln\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\Big)\Big]
\nabla_\theta\mathcal{L}=-\beta\,\sigma(-m)\,\big[\nabla_\theta\ln\pi_\theta(y_w\mid x)-\nabla_\theta\ln\pi_\theta(y_l\mid x)\big],\qquad m=\beta\Big[\ln\tfrac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)}-\ln\tfrac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}\Big]
Symbols. \pi_\theta: the model being trained (starts equal to \pi_{\text{ref}}). y_w,y_l: preferred and rejected answers. \beta: the same leash strength as in RLHF. m: the margin, the gap between the implicit rewards \hat r(y)=\beta\ln(\pi_\theta/\pi_{\text{ref}}). \sigma(-m): the weight on the update, large when the implicit rewards rank the pair wrongly and small when they already rank it right. The gradient raises the probability of the winner and lowers that of the loser, weighted by how wrong the model currently is. For a sequence, \pi_\theta(y\mid x) is the product of the token probabilities, so the log is a sum of token log-probabilities.

Comparison with RLHF. Same objective, same optimum in the idealised case (the lab shows the policy converging to \pi^* from noisy pairs alone). DPO needs only the dataset of pairs and the reference model: no reward model, no sampling loop, no value network, and training is as simple as supervised learning. The price: it learns only from the fixed pairs, which were usually written by other policies, so it cannot explore new answers or correct a reward model's flaws by seeing fresh samples; and it is sensitive to \beta and to the quality of the pairs. RLHF can keep sampling from the current policy and keep scoring, which is more expensive and more flexible. Which works better in practice depends on the task and data, and I make no general claim here.

  2. Change beta to 2: the orange ticks move closer to the grey outline. Change a hidden reward (for example r(C) = 3) and watch the target move with the labels.
  3. Switch the labels to "always the same winner". The loss now falls without limit, C and A are pushed toward zero probability, and the policy runs far from the reference. That is DPO over-fitting a dataset with no disagreement.
Common traps
  • "DPO has no reward." It has one, implicitly: \beta\ln(\pi_\theta/\pi_{\text{ref}}) up to a prompt-dependent constant. It simply never trains or uses a separate reward network.
  • Probabilities of both answers can fall. The loss depends on a difference, so training may lower the likelihood of the winner as well, as long as the loser drops more. Watching the margin alone can hide this.
  • Equivalence is idealised. The match to RLHF assumes the data follow Bradley-Terry, the model class can represent \pi^*, and the pairs cover the answers that matter. None is guaranteed for real data.
  • Reference mismatch. If \pi_{\text{ref}} is not the model the pairs were drawn from, the implicit reward is measured against the wrong baseline.
Where it shows up in AI
  • Open-model tuning: because it needs only a pair dataset, a reference and ordinary training code, DPO and its many variants are widely used for tuning openly available models.
  • Variants change the loss (for example, adding a length term or a margin) to fix specific failure modes; they all keep the idea of a log-ratio to a reference.
  • Iterative use: pairs can be re-sampled from the updated policy and re-labelled, which gives back some of RLHF's exploration.

Check yourself

1. With reference (0.5, 0.3, 0.2) and rewards (1, 2, 0), beta = 1, what is the optimal policy?
Weights 1.3591, 2.2167, 0.2000, Z = 3.7759, so π* = (0.3600, 0.5871, 0.0530).
2. Why does Z not appear in the DPO loss?
Z depends only on the prompt, not on the answer, so it adds the same constant β ln Z to the implicit reward of both answers in a pair. The Bradley-Terry probability uses the difference, and the constant cancels. That is essential, because Z sums over every possible answer and cannot be computed for a language model.
3. Policy (0.40, 0.45, 0.15), reference (0.5, 0.3, 0.2), pair B over A, beta = 0.5: give the DPO loss.
Margin = 0.5·(ln 1.5 - ln 0.8) = 0.5·(0.4055 + 0.2231) = 0.3143; σ(0.3143) = 0.5779; loss = 0.5483.

Takeaways

  • The KL-regularised objective equals \beta\ln Z-\beta\,\mathrm{KL}(\pi\Vert\pi^*), so the optimum is \pi^*\propto\pi_{\text{ref}}\,e^{r/\beta} and the implicit reward is r=\beta\ln(\pi^*/\pi_{\text{ref}})+\beta\ln Z.
  • Bradley-Terry cancels Z, giving the DPO loss -\ln\sigma\big(\beta[\ln\tfrac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)}-\ln\tfrac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}]\big): a supervised loss on pairs.
  • Simpler and cheaper than RLHF, but limited to the fixed pairs and exposed to over-fitting when labels never disagree.
4.5

Verifiable rewards and reasoning

The questionFor a maths problem or a coding task, we do not need a learned reward model: a checker can say whether the final answer is right. How can a model be trained directly from such pass-or-fail signals, and how do we turn a plain 1 or 0 into a learning signal without a value network?

Intuition: practise problems with an answer key

A student who has an answer key can practise alone: attempt a problem, check, adjust. For tasks with a mechanical check (a numeric answer compared with the key, code run against unit tests, a formal proof checked by a verifier) the same loop works for a model. The reward is a verifiable reward: computed by a program, hard to flatter, and free of the annotator-taste problems of lesson 4.2. This removes one source of reward hacking (the proxy is the truth), but not all of them, as the traps show.

There is one practical problem. A reward of 1 or 0 on its own is a poor learning signal: if a problem is usually solved, almost every sample gets 1 and nothing seems to separate the good from the bad. The fix is to compare answers with each other. Sample a group of answers to the same question, and ask how each compares with the group's typical result.

Build it up

Group-relative advantage. For one question, draw G answers from the policy and score each with the checker. Subtract the group mean (so an average answer gets 0) and divide by the group standard deviation (so the scale is the same whatever the rewards are). This is the idea behind group-relative policy-gradient methods: the group itself acts as the baseline in place of a learned value network (compare baselines and advantages). Published methods differ in their details (clipping, KL terms, how long sequences are normalised); this lesson states only the central idea and makes no claim about any particular system.

Worked example: eight sampled answers to "17 × 3 = ?"

A checker gives reward 1 to the answer 51 and 0 to anything else. Eight samples came back with these rewards:

reward r_i10010100
advantage A_i1.2910-0.7746-0.77461.2910-0.77461.2910-0.7746-0.7746

Mean: 3/8=0.375. Variance (dividing by G=8): [3(0.625)^2+5(0.375)^2]/8=1.875/8=0.234375, so the standard deviation is 0.4841. Correct samples: (1-0.375)/0.4841=1.2910. Wrong samples: (0-0.375)/0.4841=-0.7746. They sum to zero: 3(1.2910)+5(-0.7746)=0.

Partial credit. With four answers scored by a checker that gives partial marks, rewards 0,2,1,3: mean 1.5, standard deviation 1.1180, advantages -1.3416,\ 0.4472,\ -0.4472,\ 1.3416.

When nothing can be learned. If all eight got 1 (or all 0) the standard deviation is 0, every advantage is 0, and the group provides no signal: the question was too easy or too hard for the current policy. Implementations typically add a tiny constant to the denominator to avoid dividing by zero, and often favour questions of intermediate difficulty.

The update. Each sampled answer's log-probability is pushed up in proportion to its advantage: the correct samples become more likely, the wrong ones less likely. In the toy, with the policy a softmax over four candidate answers, a step is \Delta\theta_k=\eta\,\frac1G\sum_i A_i\,(\mathbb 1[y_i=k]-\pi_k), which is the policy-gradient rule with the group-relative advantage in place of the return. The lab runs this loop.

Long reasoning traces. For harder problems the answer comes after a long chain of intermediate steps written by the model. The reward is checked only at the end (an outcome reward); a policy that is rewarded for correct final answers is free to develop longer or more careful intermediate text if that raises the pass rate. Spending more tokens at inference to reason before answering is one way to trade compute for accuracy, and it makes sampling cost grow with trace length. Rewarding the correctness of each step (a process reward) is an alternative that needs step labels, which are costly and can themselves be wrong.

The formal picture

A_i=\frac{r_i-\bar r}{s_r},\qquad \bar r=\frac1G\sum_{j=1}^{G}r_j,\qquad s_r=\sqrt{\frac1G\sum_{j=1}^{G}(r_j-\bar r)^2}
\nabla_\theta J\approx\mathbb{E}_{x}\Big[\frac1G\sum_{i=1}^{G}A_i\,\nabla_\theta\ln\pi_\theta(y_i\mid x)\Big]
Symbols. G: group size, the number of answers sampled for one question x. y_i: the i-th sampled answer (a whole trace). r_i: its reward from the checker. \bar r and s_r: the group mean and standard deviation. A_i: the advantage, positive when the answer beat its group. \pi_\theta: the policy. Because the advantages sum to zero, subtracting the group mean acts as a baseline and does not bias the gradient direction in expectation, though the finite group makes it noisy (see the baseline lesson). Real systems commonly add a KL term to a reference and a clipped ratio as in PPO, omitted here.
Try this
  1. Let a round play out slowly: answers appear one at a time, then the mean, standard deviation and advantages, then the bars move. Check the readout against the worked example when the group has 3 correct out of 8.
  2. Set the start probability to 0.05 with G = 4. Most groups contain no correct answer, so the advantages are all zero and the policy does not move: a hard problem teaches nothing until luck produces a success. Then raise G to 16 and watch learning start sooner.
  3. Raise the start probability to 0.9: now most groups are all correct and again there is no signal. Learning is fastest at intermediate success rates.
Common traps
  • "Verifiable" does not mean "correct in every sense". A checker tests what it tests. Weak unit tests can be passed by special-casing the examples; a numeric match can be reached with an invalid chain of reasoning. The model optimises the checker, not the intention behind it.
  • Reasoning text is not a faithful transcript. A longer trace can raise accuracy, but the visible steps need not be the real cause of the answer, so they should not be treated as an audit trail.
  • Coverage. The method applies where a reliable checker exists. Open-ended writing, advice or judgement has none, and gains on checkable tasks do not automatically transfer.
  • Standardising by the standard deviation magnifies tiny differences in a group where almost everything has the same reward, and different normalisations weight easy and hard questions differently. That is a design choice with consequences.
Where it shows up in AI
  • Reasoning models: training with checkable rewards on maths, programming and logic puzzles is a widely discussed route to models that produce long step-by-step solutions.
  • Code: unit tests and compilers are ready-made verifiers; the quality of the tests bounds what the model can learn.
  • Test-time compute: sampling several solutions and choosing by a checker or by majority vote uses the same machinery at inference.

Check yourself

1. In the worked group (3 correct out of 8), recompute the advantage of a wrong answer.
Mean 0.375, standard deviation 0.4841, so (0 - 0.375)/0.4841 = -0.7746.
2. Rewards in a group of four are 0, 2, 1, 3. What advantage does the answer scoring 3 get, and do the advantages sum to zero?
Mean 1.5; deviations -1.5, 0.5, -0.5, 1.5; variance (2.25 + 0.25 + 0.25 + 2.25)/4 = 1.25; standard deviation 1.1180. The answer with 3 gets 1.5/1.1180 = 1.3416. The four advantages (-1.3416, 0.4472, -0.4472, 1.3416) sum to zero.
3. A question is so easy that all 16 samples are correct. What happens to the update from that question, and why might that be sensible?
The standard deviation is 0, every advantage is 0 (with a small constant in the denominator in practice), and the gradient from that group is zero. It is sensible because no sample did better than the others, so there is nothing to learn from comparing them.

Takeaways

  • A program that checks answers gives a reward that is hard to flatter; it cannot reward anything the checker does not test.
  • Group-relative advantage: sample G answers, subtract the group mean, divide by the group standard deviation. For rewards 1,0,0,1,0,1,0,0 the advantages are +1.2910 and -0.7746.
  • Groups with identical rewards carry no signal; learning is fastest at intermediate success rates; verifiable does not mean complete.
4.6

AI feedback and red teaming

The questionHuman preference labels are slow and costly. Can a model write some of the feedback, guided by a written set of principles? And once a model is trained to decline some requests, how do we find where it fails, and how do we balance wrongly answering a request it should have declined against wrongly refusing one it should have answered?

Intuition: written rules, a second reader, and a tester who tries to break things

AI feedback. Instead of asking a person "which of these two replies is better?", we ask a model, giving it a short written list of principles (a constitution): for example "prefer the reply that is honest about uncertainty" or "prefer the reply that does not help with harming others". The model judges pairs, and the judgements become preference data for the methods of lessons 4.2 to 4.4. Sometimes the model also critiques and rewrites its own replies against the principles, and the revised replies become SFT data (lesson 4.1). This is sometimes called reinforcement learning from AI feedback.

Red teaming. A red team deliberately probes a system to find where it fails: wrong answers, unsafe behaviour, leaks, inconsistent refusals. The term comes from security practice. Red teamers can be people or other models; the point is to discover failures before real users do, so they can be fixed, and to measure how often they occur.

Build it up

Why AI feedback can work, and where it stops. A judge model can be cheap, fast and consistent, and it makes the principles explicit and editable: change the text, and the labels change. But the judge has its own biases (for example a preference for longer or more confident replies), inherits the blind spots of the model that produced it, and can only apply principles it understands. If a judge is wrong in the same way as the policy it trains, agreement between them proves nothing. Careful setups check the judge against human labels on a sample, and keep people in the loop for the principles themselves, because deciding what a model should and should not do is a value judgement, not a technical fact.

Worked example: how reliable must a judge be?

Suppose the judge agrees with a careful human on 80% of pairs and picks the opposite on 20%. Used as a labeller, it behaves like noise on the labels: it adds the entropy floor of lesson 4.2 for that fraction of pairs. If the judge's errors are random, a large number of pairs can still teach the correct ranking, just as in the noisy reward-model lab. If its errors are systematic (say it always favours the longer reply), more pairs do not help: the reward model learns the bias, and the policy optimises it (lesson 4.3).

Refusals and the two kinds of error. Training a model to decline some requests creates a classification problem: for each incoming request, answer or refuse. There are two ways to be wrong. Missed refusal: the model answers something it should have declined. Over-refusal: it declines something harmless and useful, which frustrates legitimate users and withholds help (for example from someone asking a safety question in order to stay safe). No setting removes both: if the model's internal "risk score" for harmless and harmful requests overlaps, moving the threshold trades one error for the other. Only better separation, from better training, better context handling and better data, reduces both. How to weigh the two mistakes is a judgement about costs and values that differs by setting (a medical-information service and a children's learning app would reasonably choose differently), and it is the responsibility of the people and organisations deploying the system. The lab uses abstract scores and prints no request content.

Measuring safety behaviour. A single number hides this trade-off, so it is common to report both rates: the share of requests that should be declined that were declined, and the share of harmless requests that were wrongly declined. Evaluation sets should be fixed in advance, cover different categories and contexts, and be kept partly secret from training so they remain a fair test. Red-team measurement also has a statistical side. If each attempt finds a failure with probability p, independent attempts find at least one with probability 1-(1-p)^k.

Worked example: what k attempts can and cannot tell you

If p=0.02, then 100 independent attempts find at least one failure with probability 1-0.98^{100}=0.8674: about one run in seven finds nothing even though the failure is real. If a red team makes 100 attempts and finds no failure, the 95% upper bound on p is 1-0.05^{1/100}=0.0295, close to the common "rule of three" estimate 3/k=0.03. So "nothing found in 100 tries" supports "p is probably below about 3%", not "p=0". Rare failures need many varied attempts.

The formal picture

P(\text{at least one failure in }k\text{ independent attempts})=1-(1-p)^k,\qquad p_{95\%}^{\max}=1-0.05^{1/k}\approx\frac{3}{k}\ \ \text{(zero failures seen)}
\text{missed-refusal rate}=P(\text{answer}\mid\text{should refuse}),\qquad \text{over-refusal rate}=P(\text{refuse}\mid\text{should answer})
Symbols. p: the chance that a single attempt finds a failure. k: the number of attempts, assumed independent (many near-copies of one trick are not independent). p^{\max}_{95\%}: the largest p still consistent, at the 95% level, with seeing zero failures in k attempts. The two rates are conditional probabilities and depend on the evaluation set: change the mix of requests and they change.
Try this
  1. In the refusal lab, drag the threshold right: wrong refusals (over-refusal) fall while wrongly answered requests rise. Move the "cheapest threshold" marker by changing the two costs, and note how it depends on them.
  2. Raise "how well the scores separate" from 1 to 4: both error rates fall at once. That is what better training buys; moving the threshold cannot.
  3. In the red-team lab set p = 2%, press play, and see when the first failure turns up; reset to a different run by changing p. At p = 0.5% watch how many attempts can pass with nothing found, and read the upper bound.
Common traps
  • One number for safety. A model that refuses everything has no missed refusals and is useless. Report both error rates, and for several kinds of request separately.
  • "Found nothing" as proof. It bounds the failure rate; it does not show there is none, and it only covers the kinds of attempts that were tried.
  • Training on the test. If red-team prompts that are used to measure safety also appear in training, the measurement is no longer a fair test, and the system may handle those exact prompts while failing on a rephrasing.
  • Judge circularity. Evaluating a model with a judge built from the same family, using the same principles it was trained on, can understate its failures.
  • Principles are not neutral. Any written constitution encodes choices about what to prefer; publishing and revisiting them, and checking them against affected users, is part of doing this responsibly.
Where it shows up in AI
  • Safety training: AI-generated critiques and preference labels, guided by written principles, are one published route to scaling preference data; human oversight of the principles and spot-checks of the labels are the usual safeguards.
  • Evaluation before release: structured red teaming, internal and external, is widely used to find failures across categories; results are better reported as rates with uncertainty than as anecdotes.
  • Deployment guardrails: input and output filters add a second layer with their own missed-refusal and over-refusal rates, which compound with the model's own (production lesson).

Check yourself

1. Each attempt finds a failure with probability 2%. What is the probability that 100 independent attempts find none?
0.98^100 = 0.1326, so at least one is found with probability 1 - 0.1326 = 0.8674. Even a real, 2%-frequency failure is missed by a 100-attempt red team about 13% of the time.
2. A model refuses 100% of requests. What are its missed-refusal and over-refusal rates, and why is this not "safe"?
Missed refusal 0%, over-refusal 100%. It never answers a harmless request, so it provides no value and withholds legitimate help. Safety behaviour has to be judged on both rates together.
3. An AI judge agrees with careful human labels 80% of the time, with errors that are random. Another judge agrees 80% of the time but always errs by favouring longer replies. Which is more harmful as a labeller, and why?
The second. Random errors average out over many pairs, so a reward model still learns the right ranking. A systematic error is a consistent signal: the reward model learns "longer is better" and the policy optimises that, a form of reward hacking (lesson 4.3), however many pairs there are.

Takeaways

  • AI feedback uses a model and a written set of principles to produce preference labels or revisions; it scales cheaply, but systematic judge bias is learned, not averaged away, and the principles are human value judgements.
  • Refusal behaviour has two errors, missed refusals and over-refusals; a threshold trades them off, better separation lowers both, and the weighting is a policy choice.
  • Red teaming measures failure rates: 1-(1-p)^k to find one, and "none in 100" only bounds p below about 3% (0.0295).
