Module 2 · Attention & the Transformer

Almost every modern language model is a stack of one repeated block. This module builds that block from the ground up: how one token can fetch information from every other token (attention), how the model knows the order of words, how the pieces are wired together with a residual stream, why a language model must not look ahead, and what all this costs in compute and memory. It sits in the pretrain stage of the pipeline (collect and tokenise, pretrain, align, adapt and compress, generate, evaluate and guard), and it explains the part of generate that makes long prompts expensive.

2.1

Attention as a soft lookup

The questionIn "The trophy did not fit in the suitcase because it was too big", what does "it" mean? To decide, the model at the word "it" must go back, find "trophy", and borrow information from it. An older kind of network read the text one word at a time and carried a single fixed-size vector forward as its memory. Whether the text has 10 words or 1 000, that vector has the same few hundred numbers. Is there a way for a position to look directly at any earlier word, and to decide by content which words matter?

Intuition: a dictionary that blends

An ordinary dictionary (a Python dict, a database table) works by exact lookup. You hand it a query, it compares the query with every stored key, finds the one that matches, and returns the value stored under it. Either you get one value or nothing.

Attention is the same machinery with one change: the match is not yes or no but a degree. The query is compared with every key and each key gets a score for how well it matches. The scores are turned into positive weights that add up to 1, and the answer is not one value but the weighted average of all the values. A key that matches strongly contributes a lot; a key that matches weakly contributes a little. Because nothing is a hard decision, the whole operation can be trained by gradient descent: nudging a query or a key changes the weights smoothly.

The reason this fixes the bottleneck is that the values of all earlier tokens stay available. Nothing is squeezed into one vector; each position decides, fresh, how much of each token to read.

Build it up

Every token has three roles, and each role is a vector of numbers. Its key says what the token offers ("I am a noun that is a thing you can carry"). Its value is the content it hands over if it is read. A query says what the token currently looks for. Where those vectors come from (learned projection matrices) is the subject of lessons 2.2 and 2.3. For now they are given.

Three tokens A, B, C, with 2-number keys and values:

tokenkey kvalue v
A(1, 0)(10, 0)
B(0, 1)(0, 10)
C(1, 1)(4, 4)
Worked example: query q = (2, 0)

Step 1, score each key with the dot product q\cdot k (large when the two vectors point the same way): A: 2·1 + 0·0 = 2. B: 2·0 + 0·1 = 0. C: 2·1 + 0·1 = 2. The query "looks like" A and C equally, and not like B.

Step 2, softmax turns scores into weights: e^2=7.389, e^0=1, e^2=7.389, which add to 15.778. Weights: A 7.389/15.778 = 0.4683, B 1/15.778 = 0.0634, C 0.4683. They are positive and add to 1.

Step 3, blend the values. Output = 0.4683·(10, 0) + 0.0634·(0, 10) + 0.4683·(4, 4) = (4.683 + 0 + 1.873, 0 + 0.634 + 1.873) = (6.556, 2.507).

A sharper query. Double it to q = (4, 0): scores 4, 0, 4, weights 0.4955, 0.0091, 0.4955, output (6.937, 2.073). B has almost vanished. A different query. q = (0.5, 2): scores 0.5, 2, 2.5, weights 0.0777, 0.3482, 0.5741, output (3.073, 5.779): now C and B dominate. A hard lookup would have returned one stored value exactly; the soft lookup gives a blend that moves smoothly as the query moves.

The formal definition

\alpha_i=\frac{\exp(q\cdot k_i)}{\sum_{j=1}^{n}\exp(q\cdot k_j)},\qquad \text{output}=\sum_{i=1}^{n}\alpha_i\,v_i
Symbols. q: the query vector. k_i: the key of item i, same length as q. v_i: the value of item i (any length). n: the number of items (tokens that can be read). q\cdot k_i: the score, a dot product (see the dot product). \alpha_i: the attention weight of item i, with \alpha_i>0 and \sum_i\alpha_i=1. The output has the same length as a value. The scaling factor that real systems add to the score is the subject of the next lesson.

Compared with a recurrent summary: after reading n tokens a recurrent network carries one vector of fixed size, whereas attention has n keys and n values to consult, so the information available grows with the text. The price, studied in lesson 2.7, is that every query is compared with every key.

  2. Drag the length to 0. All three weights become 1/3 and the output stops at the average of the three values. Now drag it to 3: the output hugs the ring (the hard lookup) but never quite reaches it.
  3. Set the direction to 90° and find which two tokens get the most weight. Predict it from the arrows before looking at the bars.
Common traps
  • "Attention picks one token." It averages all of them; weights are never exactly 0 or 1. Only the sharpness of the scores moves it toward a pick.
  • Keys, values and queries are not the raw word. They are learned linear views of the token's vector (lesson 2.2). The same token can be a good key for one purpose and carry a quite different value.
  • The weights are not an explanation by themselves. A large weight says where information was read from, not why the final answer was produced.
Where it shows up in AI
  • Every transformer (language, image, audio) is built from this operation. Encoder-decoder translation models were the first place attention beat a fixed-size summary, by letting the decoder look back over the source sentence.
  • Retrieval-style memory in later modules has the same shape: a query, a set of stored keys, a blend or selection of stored values.
  • Vision: attention maps in a Vision Transformer are exactly these weights over image patches.

Check yourself

1. With the table above, what are the weights and output for q = (0, 2)?
Scores: A 0, B 2, C 2. Weights 0.0634, 0.4683, 0.4683. Output = 0.0634·(10,0) + 0.4683·(0,10) + 0.4683·(4,4) = (2.507, 6.556): the mirror image of the worked example, because the table is symmetric between the two coordinates.
2. If all three keys were identical, what would the output be for any query?
All scores are equal, so all weights are 1/3 and the output is the plain average of the values: ((10+0+4)/3, (0+10+4)/3) = (4.667, 4.667). The query could not tell the tokens apart.
3. Why not replace the softmax by "take the key with the largest score"?
The arg-max is a hard choice: moving the query slightly changes nothing until the winner flips, so the gradient is zero almost everywhere and the model cannot learn which keys to match. The softmax gives every key a small, smoothly changing weight, which gradient descent can follow.

Takeaways

  • Attention compares a query with every key, turns the scores into weights with softmax, and returns the weighted average of the values.
  • It is a differentiable, soft version of a lookup, and every earlier token stays readable instead of being squeezed into one summary vector.
  • Longer query vectors give sharper weights; the weights are always positive and add to 1.
2.2

Scaled dot-product attention

The questionLesson 2.1 handled one query. A sentence has many tokens, and every one of them needs its own lookup, all at once. How is that written as a few matrix multiplications so that a GPU can do it in one go? And the standard formula divides the scores by \sqrt{d_k} before the softmax. What goes wrong if you leave that division out?

Intuition: every token asks, every token answers

In self-attention the queries, keys and values all come from the same sequence. Every token plays all three roles: it asks a question (its query), advertises what it holds (its key) and carries content (its value). If the sequence has T tokens, stack the T queries as the rows of a matrix Q, the keys as the rows of K, the values as the rows of V. Then all the dot products of lesson 2.1 are one matrix product QK^{\top}: a T\times T table whose entry in row i, column j says how much token i wants to read token j.

Where do Q,K,V come from? From the token vectors X (one row per token) by three learned matrices: Q=XW_Q, K=XW_K, V=XW_V. Different matrices mean one vector can ask one thing, advertise another and carry a third.

Build it up: three tokens, real numbers

Take the sentence "the cat sat" and suppose the projections have produced (key size d_k=4, value size d_v=2):

tokenquery qkey kvalue v
the(1, 2, 0, 1)(2, 1, 0, 1)(1, 0)
cat(2, 0, 1, 3)(0, 3, 1, 0)(0, 2)
sat(0, 1, 2, 1)(1, 0, 2, 2)(3, 1)
Worked example: the whole computation

① Scores S=QK^{\top}. Row "the": q·k_the = 1·2 + 2·1 + 0·0 + 1·1 = 5; q·k_cat = 0 + 6 + 0 + 0 = 6; q·k_sat = 1 + 0 + 0 + 2 = 3. Doing all nine entries:

③ Softmax along each row. Row "the": e^{2.5}=12.182, e^{3}=20.086, e^{1.5}=4.482, sum 36.750, so the weights are 0.3315, 0.5465, 0.1220. All three rows:

What the scale did. Skip step ②, so the softmax sees the raw scores. Row "the" becomes (0.2595, 0.7054, 0.0351), row "cat" becomes (0.0474, 0.0001, 0.9525) and row "sat" becomes (0.0132, 0.2654, 0.7214). The largest weight in each row rises from 0.547, 0.810, 0.574 (with the scale) to 0.705, 0.952, 0.721 (without). The entropy of each row, in bits (three equal weights would give 1.585), falls from 1.375, 0.753, 1.276 to 1.030, 0.277, 0.930. The output for "cat" shifts from (2.611, 0.828) to (2.905, 0.953). With only d_k=4 the effect is modest; the next paragraph shows why it grows.

Why divide by \sqrt{d_k}. Suppose the entries of a query and a key are independent with average 0 and variance 1. A score is a sum of d_k products, each with variance 1, so the score has variance d_k and spread \sqrt{d_k}. Bigger key vectors therefore produce bigger scores, and a softmax fed large scores puts almost all its weight on one key. A simulation (4 000 trials, 8 keys each) gives the following. Dividing by \sqrt{d_k} brings the spread back to about 1 for every d_k, so the softmax stays in a sensible range. There is a training reason too. A softmax with one weight near 1 has almost no gradient: for the row "cat" without scaling, the last weight is 0.9525 and its slope p(1-p) is 0.045, against 0.154 for the scaled weight 0.8102. A saturated softmax barely learns.

The formal definition

\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
Symbols. Q\in\mathbb{R}^{T\times d_k}: one query per row. K\in\mathbb{R}^{T\times d_k}: one key per row. V\in\mathbb{R}^{T\times d_v}: one value per row. QK^{\top}: the T\times T score table. \sqrt{d_k}: the scale, the square root of the key length. \operatorname{softmax}: applied to each row separately, so every row of weights is positive and sums to 1. The result is T\times d_v: one blended value per token. (This is a single head and has no mask yet; both are added in later lessons. The matrix derivation and gradient are in the attention mathematics lesson; softmax stability is in softmax and numerical stability.)

Common traps
  • Softmax over the wrong axis. Each row (one query over all keys) is normalised, not the columns. Row sums are 1; column sums are not.
  • The scale uses the key size d_k, not the number of tokens T and not the model width unless they coincide.
  • Q and K must have the same length; V may differ. The output length follows V, not K.
  • "The scale is a minor detail." For small d_k it is (our example), for large d_k it decides whether training works.
Where it shows up in AI
  • This formula is the core of every transformer layer, run once per head (next lesson). Efficient implementations compute it in blocks without ever storing the full T\times T table, but the mathematics is identical.
  • The T\times T table is why long inputs are costly: its size grows with the square of the length (lesson 2.7).

Check yourself

1. A key has length d_k = 16 and a raw score is 12. What goes into the softmax?
12 / √16 = 12 / 4 = 3.
2. In the scaled table, which token's value does "cat" copy most, and what is its output?
"sat", with weight 0.8102 (and 0.1808 on "the", 0.0090 on "cat" itself). The output is 0.1808·(1,0) + 0.0090·(0,2) + 0.8102·(3,1) = (2.611, 0.828).
3. Going from d_k = 64 to d_k = 256 with unit-variance entries, what happens to the spread of raw scores with and without the scale?
Without the scale the spread doubles, from √64 = 8 to √256 = 16 (simulation: 8.00 and 16.09). With the scale both are divided by √d_k and stay close to 1 (1.00 and 1.01).

Takeaways

  • All queries attend at once: \operatorname{softmax}(QK^{\top}/\sqrt{d_k})V, a T\times T weight table times the values.
  • A raw score is a sum of d_k products, so its spread grows like \sqrt{d_k}; dividing by \sqrt{d_k} keeps the softmax from saturating.
  • In the worked example the scale lowers the largest weights from (0.705, 0.952, 0.721) to (0.547, 0.810, 0.574).
2.3

Multi-head attention

The questionA single attention head gives each token one weighted average of the other tokens. But the word "sat" in "the cat sat on the mat" needs to know who sat (the cat), where (the mat) and in what tense, and those are different questions with different best answers. One set of weights cannot ask all of them. How do we let a layer ask several questions at once without making it much more expensive?

Intuition: a committee of readers

Imagine h readers going through the same sentence at the same time. Each has its own idea of what to look for and its own notebook of what to write down. One reader tracks grammatical subjects, another the nearest neighbour, another punctuation. Afterwards their notes are laid side by side and a final person merges them into one summary per word. Each reader has a narrow notebook: instead of giving every reader the full width d, we split the width, so h readers of width d/h cost about the same as one reader of full width.

Build it up

The token vectors have width d (called d_{\text{model}}). A single head would project them with three d\times d matrices. Multi-head attention instead gives each head its own three matrices that project down to the smaller head dimension d_{\text{head}}=d/h. Each head runs the scaled dot-product attention of lesson 2.2 on its own small queries, keys and values, producing a T\times d_{\text{head}} result. The h results are placed side by side (concatenated) to give T\times d again, and one last matrix W_O mixes the heads together.

Worked example: d = 8, h = 2, a six-token sentence

Width d=8, heads h=2, so d_{\text{head}}=8/2=4. The input X for "the cat sat on the mat" is 6\times 8.

Shapes. Head 1 has W_Q^{(1)},W_K^{(1)},W_V^{(1)}, each 8\times 4, so its Q,K,V are 6\times 4. Its score table is 6\times 6, its output 6\times 4. Head 2 does the same with its own matrices. Concatenating gives 6\times 8, and W_O (8\times 8) maps that to the layer output 6\times 8. There are two score tables, h\cdot T^2=2\cdot 36=72 score entries.

Parameters (no biases). Per head: 3\times(8\times 4)=96. Two heads: 192. Plus W_O: 64. Total 256, which equals 4d^2=4\cdot 64. Equivalent view: W_Q as one 8\times 8 matrix (64 numbers) whose 8 output columns are split into 2 groups of 4, one group per head; the same for W_K and W_V, so 3·64 = 192, plus 64 for W_O. With biases on all four projections, add 4d=32 for 288.

Does h change the parameter count? Try h=1: one head of width 8, three 8\times 8 matrices (192) plus W_O (64) = 256. Try h=4: four heads of width 2, three 8\times 2 matrices each (48 per head, 192 total) plus 64 = 256. The count is 4d^2 for every h that divides d. At a realistic width, d=512 and h=8 (d_{\text{head}}=64): 4\cdot 512^2=1{,}048{,}576 parameters in the attention part of one layer.

The formal definition

\operatorname{head}_i=\operatorname{Attention}\!\left(XW_Q^{(i)},\,XW_K^{(i)},\,XW_V^{(i)}\right),\qquad \operatorname{MHA}(X)=\operatorname{Concat}(\operatorname{head}_1,\dots,\operatorname{head}_h)\,W_O
Symbols. X\in\mathbb{R}^{T\times d}: the token vectors entering the layer. h: the number of heads, chosen so that d_{\text{head}}=d/h is a whole number. W_Q^{(i)},W_K^{(i)},W_V^{(i)}\in\mathbb{R}^{d\times d_{\text{head}}}: the projections of head i. \operatorname{Concat}: place the head outputs side by side, giving T\times h\,d_{\text{head}}=T\times d. W_O\in\mathbb{R}^{d\times d}: the output projection that lets information flow between heads. Parameters per layer: 4d^2 (plus 4d if the projections have biases).

Cost: the compute of attention over all heads is about that of one full-width head (each head's score table is T\times T with a d_{\text{head}}-sized dot product, and there are h of them), but the number of score entries is h\,T^2, which matters for memory.

  2. Increase to 2, 4 and 8 heads. Different heads pick out different columns for the same query token, and with h=8 each head is only one number wide, so its map is a simple function of two scalars.
  3. Read the parameter line under the maps: it stays at 256 for every h. The heads here are random, not trained, so they show the mechanism, not meaningful linguistic roles.
Common traps
  • "More heads means more parameters." At fixed width d, no: the heads split the width. What grows is the number of separate score tables, and with it memory.
  • Heads are not assigned jobs by hand. Each head's role emerges in training. Studies find some heads with interpretable behaviour and others that look redundant; do not assume every head is meaningful.
  • Too many heads make each one too thin. With d_{\text{head}}=1 a head's score is a product of two single numbers, which can express little.
  • W_O is not optional. Without it the heads would be concatenated but never mixed within the layer.
Where it shows up in AI
  • Every layer of a transformer language model, and of the Vision Transformer, uses multi-head attention.
  • Many serving systems share the keys and values across several query heads to shrink memory (the idea is called multi-query or grouped-query attention); lesson 2.7 shows exactly what that saves.

Check yourself

1. d = 512 and h = 8. What is d_head, and how many parameters do the four projection matrices hold (no biases)?
d_head = 512/8 = 64. Four matrices of 512 × 512 = 262,144 entries each: 4 × 262,144 = 1,048,576.
2. A layer with 8 heads reads a 10-token prompt. How many attention weights does it compute?
One 10 × 10 table per head: 8 × 100 = 800 weights (before any mask).
3. The model width is doubled from d = 8 to d = 16 with h = 2 fixed. By what factor does the attention parameter count change, and what is d_head?
4d² grows from 256 to 1,024, a factor of 4. d_head = 16/2 = 8, up from 4.

Takeaways

  • Heads run attention in parallel on narrower slices (d_{\text{head}}=d/h) and are merged by W_O.
  • The four matrices W_Q,W_K,W_V,W_O hold 4d^2 parameters whatever h is (256 for d=8).
  • What grows with h is the number of T\times T score tables, hT^2.
2.4

Position information

The question"Man bites dog" and "dog bites man" use the same three words and mean very different things. Self-attention scores each pair of tokens from their content alone. Can it tell the two sentences apart? If not, how do we give the model the order of the words, and can we do it in a way that depends on how far apart two words are rather than on where in the document they sit?

Intuition: attention sees a bag, not a line

Attention takes a weighted average over tokens; an average does not care about the order of what it averages. If you shuffle the input tokens, every token still gets the same weights over the same set, and the outputs are just shuffled the same way. This property is called permutation equivariance. It is useful (the same machinery handles any length) but it means the order information must be added by hand. Three families of ways to do that:

  • Absolute positions added to the input. Give each position number p its own vector and add it to the token's vector (fixed sinusoidal formula, or a table of learned vectors).
  • Relative positions. Let the score between two tokens depend on the distance between them.
  • Rotary embeddings (RoPE). Rotate the query and key by an angle that grows with position, so that the dot product depends only on the offset.

Build it up

Worked example 1: attention cannot see order

Use 2-number vectors: man = (1, 0), bites = (0, 1), dog = (1, 1), and (to keep it plain) no projections, one head, scale 1/sqrt 2. For the query "bites" = (0, 1) the scores against (man, bites, dog) are 0, 1, 1, which become 0, 0.7071, 0.7071 after dividing by 1.4142. Softmax: e^0=1, e^{0.7071}=2.0281 twice, sum 5.0562, so the weights are (0.1978, 0.4011, 0.4011). Output = 0.1978·(1,0) + 0.4011·(0,1) + 0.4011·(1,1) = (0.5989, 0.8022).

Now read the sentence in the other order, (dog, bites, man). The set of keys and values is the same, so the weights are the same numbers attached to the same words, and the output for "bites" is again (0.5989, 0.8022). Attention cannot see that the word order changed. The lab below lets you verify this with live numbers and then add positions.

Positions fix this by making the vectors of identical words in different places differ.

Worked example 2: sinusoidal encodings, d = 4

The classical fixed encoding writes, for position p and pair i, a sine and a cosine at the frequency \omega_i=10000^{-2i/d}. For d=4 there are two pairs, with \omega_0=1 and \omega_1=10000^{-1/2}=0.01:

The fast pair changes at every position (it is like the seconds hand); the slow pair barely moves (like the hour hand), so together they identify a position, much like the digits of a clock. A useful property: for any fixed offset \delta, the dot product PE(p)\cdot PE(p+\delta)=\sum_i\cos(\omega_i\delta) does not depend on p, as the first lab shows. Learned absolute positions are simply a table with one trainable vector per position up to a maximum length; nothing guarantees sensible vectors beyond the longest position seen in training.

Worked example 3: rotary embedding on one 2-D pair

RoPE does not add anything to the token vectors. It rotates the query and the key, in the 2-D plane, by an angle proportional to their positions. Write R(a) for rotation by angle a. A query at position m becomes R(m\theta)q and a key at position n becomes R(n\theta)k, where \theta is the angle per position. Take q=(2,1), k=(1,2) and \theta=0.5 rad. Without rotation, q\cdot k=4. The same offset gives the same dot product at every absolute position, and a different offset gives a different one. Why: rotation matrices satisfy R(a)^{\top}R(b)=R(b-a), so (R(m\theta)q)\cdot(R(n\theta)k)=q^{\top}R((n-m)\theta)\,k, which contains only n-m. In angle form, with \varphi_q,\varphi_k the angles of the original vectors, the value is \lVert q\rVert\lVert k\rVert\cos(\varphi_k-\varphi_q-(m-n)\theta). Check: \lVert q\rVert\lVert k\rVert=5, \varphi_k-\varphi_q=1.1071-0.4636=0.6435, offset 2 gives 5\cos(0.6435-1)=5\times 0.9371=4.686, as in the table.

In more dimensions. A vector of even length d is cut into d/2 pairs, and pair i is rotated by m\theta_i with \theta_i=\text{base}^{-2i/d} (commonly base 10 000). For d=64 the first pair turns 1 radian per position, the last pair 10000^{-62/64}=1.3335\times10^{-4} radians per position, a wavelength of about 47 117 positions. The attention score is the sum over pairs, so it still depends on m-n only. Only queries and keys are rotated; values are left alone.

The formal definition

\operatorname{PE}(p,2i)=\sin(p\,\omega_i),\quad \operatorname{PE}(p,2i+1)=\cos(p\,\omega_i),\quad \omega_i=10000^{-2i/d}
\tilde q_m=R_m\,q,\quad \tilde k_n=R_n\,k,\qquad \tilde q_m\cdot\tilde k_n=q^{\top}R_{n-m}\,k
Symbols. p: an absolute position (0, 1, 2, …). i: the index of a pair of dimensions, 0\le i<d/2. \omega_i: the frequency of pair i (radians per position), fast for small i and slow for large. R_m: the block-diagonal matrix that rotates pair i by the angle m\theta_i; R_m^{\top}R_n=R_{n-m}. q,k: the query and key before rotation. \tilde q_m,\tilde k_n: the rotated ones for positions m,n. Sinusoidal and learned encodings are added to the input once; RoPE is applied to q and k inside every attention layer.

Absolute versus relative. Adding an absolute encoding to the input mixes position and content before the projections, so the relative-offset structure is present but entangled with content. RoPE makes the offset dependence exact and leaves the content untouched. What happens for positions beyond the training length depends on the scheme; learned tables have nothing to say, and rotary schemes are often adjusted (for example by rescaling the angles) before being used on longer texts. Treat any claim that a method "extends the context" as something to verify by measurement.

Common traps
  • "The model knows order automatically." A stack of attention and per-token layers without any position signal treats the input as a set (the causal mask of lesson 2.6 leaks a little order information, but this is not a substitute).
  • Relative is not the same as "distance only". The score still depends on content; position only changes how the angle between q and k shifts.
  • Fixed formulas do not guarantee long-text quality. Having a defined value at position 50 000 does not mean the model learned to use it.
  • Rotation is applied to q and k, not v, and pairs must be of even length.
Where it shows up in AI
  • Rotary embeddings are widely used in open language models. The original transformer used the sinusoidal formula, and other models use learned tables or distance-dependent biases added to the scores.
  • Long-context work largely amounts to choosing a position scheme that still behaves sensibly beyond the training length, then testing it on long inputs.
  • Vision transformers add a position embedding to each patch for the same reason: patches are otherwise an unordered set.

  • Attention alone is blind to order: reversing the input only reverses the outputs.
  • Sinusoidal or learned vectors are added to the input; RoPE rotates pairs of dimensions of q and k by position-dependent angles.

2.5

The transformer block

The questionAttention only mixes information between tokens, and the mixing itself is a weighted average. Where does the model compute new features from each token's own vector, and how do we stack dozens of such layers so that training stays stable? And once stacked, where do the parameters actually sit: in the attention part, or somewhere else?

Intuition: a shared whiteboard

Think of each token's vector as a whiteboard that travels through the network. The board is never wiped. Every sublayer reads the board, computes something, and writes a small addition on it. This running whiteboard is called the residual stream. A transformer block has two sublayers: attention (read other tokens' boards, write what was learned from them) and an MLP (think about this one token's own board, write the result). Because each sublayer only adds, the information that was already on the board is still there at the end, and the gradient has a direct path from output to input.

One more tool keeps the numbers tame: layer normalisation rescales a vector to a standard size before a sublayer reads it, so a sublayer sees inputs of a predictable scale no matter how large the stream has grown.

Build it up

The pre-norm block (common in recent language models) is two lines, with x the stream at one token:

x'=x+\operatorname{Attn}(\operatorname{LN}(x)),\qquad x''=x'+\operatorname{MLP}(\operatorname{LN}(x'))
Worked example 1: layer normalisation

LayerNorm subtracts the mean of the vector's own entries and divides by their standard deviation (then multiplies by a learned scale \gamma and adds a learned shift \beta, taken as 1 and 0 here). Take x=(1,2,3,6). Mean = 12/4 = 3. Variance = ((−2)² + (−1)² + 0² + 3²)/4 = 14/4 = 3.5, standard deviation = \sqrt{3.5}=1.8708. Normalised: (−2, −1, 0, 3)/1.8708 = (−1.0690, −0.5345, 0, 1.6036). (A tiny constant \varepsilon, such as 10⁻⁵, is added to the variance to avoid dividing by zero.) Some recent models use a simpler variant, RMSNorm, which divides by the root-mean-square 3.5355 without subtracting the mean, giving (0.2828, 0.5657, 0.8485, 1.6971) for the same vector.

The MLP. After attention, each token's vector goes separately through a two-layer network: expand from width d to fd (usually f=4), apply a nonlinearity (ReLU, GELU or a gated variant), and project back to d. This is where a block does nonlinear per-token feature computation; attention supplies the context, the MLP processes it.

Worked example 2: counting the parameters of one block

Let the width be d, the expansion 4, with biases. Attention: four projections W_Q,W_K,W_V,W_O, each d\times d, plus four bias vectors: 4d^2+4d. MLP: W_1 is d\times 4d (4d^2) with bias 4d; W_2 is 4d\times d (4d^2) with bias d: 8d^2+5d. Two LayerNorms: each has \gamma and \beta of length d: 4d. Total:

P_{\text{block}}=(4d^2+4d)+(8d^2+5d)+4d=12d^2+13d

Check against an explicit small configuration, d = 8: W_Q 64, b_Q 8, W_K 64, b_K 8, W_V 64, b_V 8, W_O 64, b_O 8 (attention subtotal 288); W_1 8×32 = 256, b_1 32, W_2 32×8 = 256, b_2 8 (MLP subtotal 552); LayerNorm 1 γ and β 16, LayerNorm 2 γ and β 16 (32). Adding all sixteen tensors gives 288 + 552 + 32 = 872, and the formula gives 12·64 + 13·8 = 768 + 104 = 872. They agree. (The lab below recounts the tensors one by one for any configuration you choose.)

Where the parameters live. For large d the linear terms are negligible and the block holds about 12d^2: attention 4d^2 (one third) and the MLP 8d^2 (two thirds). At d=8 the MLP holds 552 of 872 (63%). Many recent models drop the biases and use RMSNorm, in which case the block is close to exactly 12d^2 (a gated MLP changes the split somewhat).

Why add instead of replace? Writing y=x+f(x) gives the derivative \partial y/\partial x=I+\partial f/\partial x. The identity part carries the gradient straight through, however deep the stack, the same trick that made very deep image networks trainable. Why norm before the sublayer (pre-norm)? The stream itself is never rescaled, so the identity path stays clean; the original transformer instead normalised after each addition (post-norm), which trains less stably at large depth in many reports. Treat that as common practice, not a law.

The formal definition

\operatorname{LN}(x)=\gamma\odot\frac{x-\mu}{\sqrt{\sigma^2+\varepsilon}}+\beta,\qquad \mu=\tfrac1d\sum_j x_j,\quad \sigma^2=\tfrac1d\sum_j (x_j-\mu)^2
\operatorname{MLP}(x)=W_2\,\phi(W_1x+b_1)+b_2,\qquad W_1\in\mathbb{R}^{4d\times d},\ W_2\in\mathbb{R}^{d\times 4d}
Symbols. x\in\mathbb{R}^d: one token's vector in the residual stream. \mu,\sigma^2: the mean and variance of its d entries (not across tokens). \gamma,\beta\in\mathbb{R}^d: learned per-entry scale and shift; \odot is entry-wise multiplication. \varepsilon: a small constant. \phi: the nonlinearity. W_1,b_1,W_2,b_2: the MLP's weights and biases (here written for a column vector x). Attention is the multi-head layer of lesson 2.3. A full model is an embedding, L such blocks, a final LayerNorm, and a linear layer to the vocabulary logits (see the neural language model). Normalisation and initialisation are discussed in initialisation and normalisation.

  2. Look at the "update/stream" ratio in the line under the bars. Each sublayer changes the stream by a modest fraction, and the stream after four blocks still resembles the input.

Common traps
  • LayerNorm is over the vector, not over the batch or the sequence: each token's d numbers are normalised independently of other tokens.
  • The MLP does not mix tokens. Only attention moves information between positions; the MLP acts on each position alone, with the same weights for every token.
  • "Attention holds the parameters." At the usual expansion of 4, the MLP has twice as many as attention.
  • Pre-norm versus post-norm are different networks; copying a formula from a paper without noting which one is used gives a different model.
Where it shows up in AI
  • GPT-style models are an embedding, a stack of these blocks, and an output layer. Scaling a model mostly means more blocks (L) and a wider stream (d); the parameter count grows like 12Ld^2 plus the embedding table.
  • Interpretability work reads the residual stream directly, because every sublayer writes into the same shared space.
  • The same pre-norm block, with patches instead of words, is the Vision Transformer layer.

Check yourself

2. How many parameters does one block with biases have for d = 16, and how are they split?
12·256 + 13·16 = 3072 + 208 = 3 280. Attention 4·256 + 64 = 1 088; MLP 8·256 + 80 = 2 128; two LayerNorms 4·16 = 64. Check: 1 088 + 2 128 + 64 = 3 280.
3. If W_O and W_2 were all zeros, what would a pre-norm block compute?
Both sublayers would output zero, so x' = x and x'' = x': the block is the identity. This is why residual networks can start close to "do nothing" and learn small corrections.

Takeaways

  • A block adds an attention update and an MLP update to the residual stream, each computed from a normalised copy.
  • One block has 12d^2+13d parameters with biases (872 at d=8); two thirds of the weights sit in the MLP.
  • Attention mixes across tokens; the MLP and LayerNorm act on each token separately.
2.6

The causal decoder

The questionA language model is trained to predict the next token. To train on a sentence of 1 000 tokens you could run the model 1 000 times, each time showing the first t tokens and asking for token t+1. That is slow. Could one pass over the whole sentence give all 1 000 predictions at once, without the model cheating by looking at the answer? And at generation time, when the text does not exist yet, what changes?

Intuition: cover the future with a card

When you read a sentence word by word and guess the next word, you cover the rest of the page with a card. Training a decoder does the same for all positions simultaneously: every row of the attention table is only allowed to look at itself and the tokens before it. Position 3 cannot read positions 4 and 5. The causal mask is that card, implemented by forbidding every entry above the diagonal of the score table.

With the card in place, token t's output depends only on tokens 1,\dots,t, exactly as if we had shown the model only the first t tokens. So reading the whole sequence once is equivalent to T separate next-token problems, computed in parallel.

Build it up

Replace each forbidden score by -\infty before the softmax; since e^{-\infty}=0, those weights are exactly 0 and the remaining weights in the row are renormalised.

Worked example: the three-token example with a mask

Take the scaled scores of lesson 2.2: rows (2.5, 3, 1.5), (3.5, 0.5, 5), (1, 2.5, 3), with values "the" (1, 0), "cat" (0, 2), "sat" (3, 1). The mask removes the entries above the diagonal:

query \ keythecatsat
the2.5−∞−∞
cat3.50.5−∞
sat12.53

Row "the" has one allowed entry, so its weight is 1: weights (1, 0, 0), output (1, 0). Row "cat": e^{3.5}=33.115 and e^{0.5}=1.649, sum 34.764, weights (0.9526, 0.0474, 0); output = 0.9526·(1,0) + 0.0474·(0,2) = (0.9526, 0.0949). Row "sat" may see everything, so it is unchanged: weights (0.0777, 0.3482, 0.5741), output (1.800, 1.271).

Compare with the unmasked outputs of lesson 2.2: "the" changed from (0.697, 1.215) to (1, 0), "cat" from (2.611, 0.828) to (0.953, 0.095), "sat" did not change. The leak test: change the value of the last token "sat" and the masked outputs of "the" and "cat" are exactly unchanged. Without the mask all three would change. The lab runs this test.

Teacher forcing. The decoder reads the true text shifted by one: the input at position t is token x_{t-1} (position 1 sees a start symbol) and the target at position t is x_t. Position t uses the true earlier tokens, whether or not the model would have produced them. The loss is the sum of the cross-entropies at all positions, the quantity defined in the pretraining objective.

Decoder-only architecture. Stack L transformer blocks whose attention is masked, add a final LayerNorm and a linear layer that maps each position's vector to a logit per vocabulary entry. The logits at position t define the distribution of token t+1 (see decoding and sampling for how a token is chosen). Other arrangements exist: an encoder uses no mask, so every token sees all others (suited to understanding a fixed input), and an encoder-decoder adds a second attention in which the decoder's queries read the encoder's keys and values (cross-attention). Many current chat and text-generation models are decoder-only.

Parallel training, sequential generation. Training knows the whole text, so one forward pass covers all positions: for 8 tokens, 1 pass and 8 loss terms. Generation does not know the future: to produce token k+1 the model must first sample token k, append it and run again, so 8 tokens need 8 passes one after another. That makes generation slow compared with training on the same number of tokens (lesson 2.7 shows how the cache avoids repeating work inside each pass). A mismatch also exists: during training the model always sees correct history, during generation it sees its own samples, which can drift; this is sometimes called exposure bias.

The formal definition

\operatorname{Attn}_{\text{causal}}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}+M\right)V,\qquad M_{ij}=\begin{cases}0 & j\le i\\ -\infty & j>i\end{cases}
\mathcal{L}=-\frac1T\sum_{t=1}^{T}\log p_\theta\!\left(x_t\mid x_1,\dots,x_{t-1}\right)
Symbols. M: the mask matrix, added to the scores; M_{ij} belongs to query i and key j. j\le i: key at or before the query's position (allowed). -\infty: forbids a pair, so its weight is 0. x_t: the token at position t of the training text. p_\theta(x_t\mid x_{<t}): the model's probability of the true token given the true tokens before it. \mathcal{L}: the average negative log-likelihood per position (the cross-entropy, in nats). The sum is computed for all t in one forward pass because of the mask.

  2. Tick "add +1 to the value of the last token". With the mask only row 5 changes; the other rows show exactly 0.

Common traps
  • Mask the scores, not the weights. Setting weights to 0 after the softmax leaves rows that no longer sum to 1; setting the scores to −∞ before it keeps them summing to 1.
  • The last row is not masked in a useful way: the final position sees everything, which is why unmasked and masked outputs agree there.
  • Parallel training does not mean parallel generation. Each new token is an input of the next pass.
  • An all-masked row would produce 0/0; the first token always sees at least itself, so this never occurs in a causal mask, but padding needs care.
Where it shows up in AI
  • GPT-style language models, code models and many multimodal generators train with exactly this masked next-token loss.
  • The sequential nature of generation is why serving systems batch many requests and why prefill and decode are treated as two different phases.
  • Bidirectional (unmasked) encoders are used where the entire input is known, for example to embed or classify text.

Check yourself

1. In a causal mask over 5 positions, how many score entries are set to −∞?
The entries strictly above the diagonal: 4 + 3 + 2 + 1 + 0 = 10 = 5·4/2. The other 15 (5 + 4 + 3 + 2 + 1) remain.
2. A 100-token text is used for training; the model then generates 100 new tokens. How many forward passes does each take?
Training: 1 pass over the 100 tokens (it yields 100 predictions and loss terms). Generation: 100 passes, because every token depends on the previous one. (With a KV cache each of those passes handles one new token instead of the whole prefix.)
3. What would happen if the mask were forgotten during training?
Position t could read token t+1, which is its own target, so the loss would collapse by copying and the model would learn nothing useful about prediction. At generation time the future tokens do not exist, and the model would fail.

Takeaways

  • The causal mask sets scores above the diagonal to -\infty, so token i reads only tokens 1 to i.
  • That lets one pass compute all next-token predictions (teacher forcing), while generation still needs one pass per new token.
  • Decoder-only models are masked self-attention blocks plus an output layer to vocabulary logits.
2.7

Cost and the KV cache

The questionYou are given a transformer's configuration: width, layers, heads, vocabulary. How many parameters does it have? How much compute does one layer need for a prompt of T tokens, and what happens when you double the prompt? And while generating, why is memory, not arithmetic, often the limit, and how many bytes does each generated token add?

Intuition: three bills

A transformer sends three different bills. The parameter bill (storing the weights) depends on the architecture only, not on the prompt. The compute bill for reading a prompt has two parts: the dense layers, linear in T, and attention, which compares every pair of tokens, so it grows as T^2. The cache bill appears during generation: to avoid recomputing the keys and values of all earlier tokens every time a token is added, the model stores them. That store is the KV cache, and it grows linearly with the text.

Build it up

A toy configuration used throughout this lesson (not any real product): width d=64, L=4 layers, h=4 heads of size d_{\text{head}}=16, MLP expansion f=4, vocabulary V=1000, rotary positions (so no position table), biases on, output layer sharing the embedding table.

Worked example 1: the parameter count

From lesson 2.5, one block has 12d^2+13d parameters: 12\cdot 4096+13\cdot 64=49{,}152+832=49{,}984. Four blocks: 199 936. The embedding table has V\cdot d=64{,}000 entries; sharing it with the output layer adds nothing. The final LayerNorm has 2d=128. Total:

N=Vd+L\,(12d^2+13d)+2d=64{,}000+199{,}936+128=264{,}064

Stored in 2 bytes each, that is 528 128 bytes, about 516 KiB. If the output layer were separate it would add another Vd = 64 000.

Worked example 2: the quadratic part

For one layer and a prompt of T tokens, count 2 floating-point operations per multiply-add. Attention scores QK^\top: for each of the T^2 pairs, a dot product of length d summed over all heads: 2T^2d. Weighted sum (weights times V): another 2T^2d. Together 4T^2d. Dense layers: the four attention projections cost 2\cdot 4d^2 per token and the MLP 2\cdot 2fd^2, so (8+4f)\,Td^2 in total, which is 24Td^2 for f=4.

Tscore entries per layer (h·T²)attention FLOPs 4T²ddense FLOPs 24Td²
12865 5364 194 30412 582 912
256262 14416 777 21625 165 824
5121 048 57667 108 86450 331 648

Doubling T quadruples the attention part and merely doubles the dense part. The two are equal when 4T^2d=24Td^2, i.e. at T=6d=384 here (in general T=(2+f)d). Short prompts are dominated by the dense layers; long prompts by attention. The score table itself has hT^2 entries per layer, which is why implementations avoid storing it in full.

Worked example 3: the KV cache

During generation, the keys and values of token t in layer l do not change when later tokens are added (the causal mask guarantees it). So compute them once and keep them. Each new token then needs one new query, key and value per layer, and its query reads the t cached keys. Per token and per layer the cache holds one key vector and one value vector for each head: 2\cdot h\cdot d_{\text{head}} numbers. Over L layers, with b bytes per number:

\text{bytes per token}=2\,L\,h\,d_{\text{head}}\,b,\qquad \text{cache}(T)=2\,L\,h\,d_{\text{head}}\,b\,T

Toy configuration, 16-bit numbers (b=2): 2\cdot 4\cdot 4\cdot 16\cdot 2=1024 bytes per token. At T=128: 131 072 bytes (128 KiB). At T=1024: 1 048 576 bytes (1 MiB). At T=2048: 2 097 152 bytes (2 MiB), which is four times the size of the 516 KiB of weights. With 8-bit numbers every figure halves (512 bytes per token).

What the cache saves. Without it, step t would recompute keys and values for all t tokens, so after T steps T(T+1)/2 of them: 36 for T=8, 528 for T=32. With it, T of them (8 and 32). Attention score entries per head, counting one full table per step without a cache (\sum t^2) against one row per step with it (\sum t): 204 against 36 for T=8.

The formal definition

N=Vd+L\,\big((4+2f)\,d^2+(f+7)\,d\big)+2d\qquad(\text{biases, tied output, no position table})
\text{FLOPs}_{\text{layer}}(T)\approx\underbrace{(8+4f)\,T\,d^2}_{\text{projections and MLP}}+\underbrace{4\,T^2\,d}_{\text{scores and weighted sum}}
Symbols. N: total parameters. V: vocabulary size; d: model width; L: layers; f: MLP expansion factor (4 above, giving 12d^2+13d per block; here (4+2f)d^2+(f+7)d is the general form). T: tokens in the sequence. h: heads; d_{\text{head}}: head size, with hd_{\text{head}}=d in standard multi-head attention. b: bytes per stored number (1, 2 or 4). The FLOP expression counts only matrix multiplications, 2 per multiply-add, and ignores norms, softmax and the output layer. The cache formula assumes every head has its own keys and values; when a model shares keys and values among several query heads (grouped-query attention), replace h by the smaller number of key-value heads, which shrinks the cache by the sharing factor.

Training also stores activations and optimiser state, which module 3 ( parallelism and memory ) counts; serving, where the cache competes with the weights for memory, is treated in prefill, decode and batching.

Common traps
  • The cache is not the attention matrix. The score table is T\times T per head and need not be stored; the cache stores K and V, which are T\times d_{\text{head}} per head and grow linearly.
  • The factor 2 in the cache formula is K plus V, not two copies of anything else.
  • Parameters do not depend on T. A longer prompt costs compute and cache, not weights.
  • Quadratic is the cost of dense attention. Many systems use sparse, windowed or low-memory exact kernels to reduce the memory (and sometimes the compute); they change the cost, and some change the result, so check which.
  • Real configurations differ in many details (gated MLPs, shared key-value heads, untied output layers), so the formulas here are a template to adapt, not a lookup for any given product.
Where it shows up in AI
  • Long-context serving: the cache grows with each request, so memory decides how many requests fit on one device at once; cutting the cache (shared key-value heads, 8-bit storage, dropping old tokens) is a standard trade of quality against cost.
  • Planning a model: the parameter formula is what you evaluate before training; with compute roughly 6 times parameters times tokens (module 3) you can estimate cost.
  • Latency: in generation each step moves the weights and the whole cache through memory to produce one token, which is why decoding is often limited by memory bandwidth rather than arithmetic.

Check yourself

Bytes per token 2·4·4·16·2 = 1 024, so 1 024 × 2 048 = 2 097 152 bytes = 2 MiB. With 8-bit numbers (b = 1): 512 × 2 048 = 1 048 576 bytes = 1 MiB.
2. The prompt is doubled from 256 to 512 tokens. By what factors do the attention FLOPs, the dense FLOPs and the cache change?
Attention FLOPs ×4 (16 777 216 to 67 108 864 per layer in the toy configuration), dense FLOPs ×2 (25 165 824 to 50 331 648), cache ×2. The parameter count does not change.
3. What is the parameter count of the toy configuration, and what share is the embedding table?
264 064 in total; the embedding table is 64 000 of them, 64 000 / 264 064 = 24.2%. The four blocks hold 199 936 (75.7%) and the final norm 128.

Takeaways

  • Parameters: N=Vd+L(12d^2+13d)+2d, which is 264 064 for the toy configuration.
  • Attention costs 4T^2d FLOPs per layer against 24Td^2 for the dense layers (equal at T=6d): quadratic in prompt length.
  • KV cache bytes per token = 2\,L\,h\,d_{\text{head}}\,b (1 024 for the toy configuration), linear in length, and it trades memory for recomputation.
