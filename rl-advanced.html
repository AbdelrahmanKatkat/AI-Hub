Five extensions that change the basic agent–environment loop. Exploration when reward is rare, hierarchy when a task has many steps, several learners sharing one world, learning from a fixed log with no new experiments, and recovering the reward from an expert who shows what they do.

8.1

Exploration with intrinsic rewards

The questionA robot must find a charging dock in a building. The only reward is +1 at the dock, and the building has 400 rooms. A robot that moves at random may need hundreds of steps to reach the dock once, and until then every estimated value is zero and every update is zero. Can we pay the robot for something else, such as visiting rooms it has never seen, so that it explores long enough to find the dock? And if we do, what stops it from being paid forever for something pointless?

Intuition

Think of a visitor in a new city with no map and no guidebook. Nothing is labelled as "worth seeing", yet the visitor still walks down streets they have not walked before. Most of the city is found that way, and the visitor finds the famous square as a side effect. This is curiosity: the agent is rewarded for novelty, and the reward from the environment is only one part of its total.

There are two common ways to measure novelty. The first counts visits: a state visited 10 times is less interesting than one visited once. The second measures surprise: if the agent has a model that predicts what happens next, a large prediction error means the outcome was new. Both give an intrinsic reward that the environment does not supply, and both fade as the agent learns.

Build it up, one piece at a time

Step 1: add a second reward. Let the environment reward be r^e_t (the +1 at the dock) and the intrinsic reward be r^i_t. The learner optimises r_t = r^e_t + \beta\, r^i_t, where \beta \ge 0 sets how much curiosity is worth relative to the task. With \beta = 0 we get back the original problem.

Step 2: count visits. Let N(s) be the number of times state s has been entered so far. A simple intrinsic reward is r^i = 1/\sqrt{N(s)}, so the first visit pays 1, the second about 0.71, the third about 0.58. Why the square root and not 1/N? The bonus must keep some pull for a while: with 1/\sqrt{N} the bonuses of the first n visits add up to roughly 2\sqrt{n}, so a barely visited state stays attractive, while a constant bonus would never stop paying.

Step 3: a worked trace. Let the agent walk along a chain of states 0, 1, 2, 3 and back, with \beta = 1. Each visit increases the count, and the bonus is paid on arrival:

Step 4: curiosity from prediction error. Count tables do not scale to images or continuous positions, because almost every state is new. Instead, learn a forward model \hat f that predicts the features of the next state, and pay for the error: r^i = \eta\,\lVert \phi(s') - \hat f(\phi(s),a)\rVert^2. Where the model has learned the dynamics, the error is small and the agent moves on. Where the outcome is new, the error is large and the agent is drawn there.

Worked example: one prediction error

The model predicts the next feature value 0.4 after an action; the true value is 0.7. With \eta = 1: r^i = (0.7 - 0.4)^2 = 0.09. After the model is trained on this transition, the prediction moves toward 0.7 and the bonus for the same transition drops. The bonus is a memory of what has not yet been learned.

Step 5: the noisy-TV trap. Suppose an action makes the next state a fair coin flip between feature values 0 and 1 (a television showing static). The best possible prediction is 0.5, and the expected error is \mathbb E[(X-0.5)^2] = 0.25 however long the agent watches. The error never falls, so a prediction-error bonus keeps paying for the static. The fix is to predict only the parts of the state the agent can influence, which is the idea behind learned feature spaces.

  2. Set β to 1 and reset. Compare the number of cells visited after 150 steps with the random walk. The bonus spreads the agent out.

Common traps
  • The bonus is not the task. A policy trained only on the intrinsic reward explores the whole grid and then has no reason to stay anywhere. Use the bonus to find rewards early, and reduce it (anneal β) so that the environment reward takes over.
  • The noisy TV. Prediction-error bonuses pay for randomness that cannot be learned, as Step 5 showed. Count bonuses are immune to this, but they fail in large state spaces.
  • Scale matters. If β is larger than the typical environment reward, the agent wanders for ever. If it is too small, the bonus is ignored. Check the ratio of bonus to reward in the logs.
Where it shows up in AI
  • Count-based exploration with bonuses of the form \beta/\sqrt{N} has a formal basis in the optimism principle (Strehl and Littman, 2008). Bellemare and colleagues (2016) extended counts to large spaces with pseudo-counts from a density model.
  • The Intrinsic Curiosity Module (Pathak and colleagues, 2017) uses prediction error in a learned feature space that ignores what the agent cannot control, which avoids the noisy TV.
  • Random Network Distillation (Burda and colleagues, 2018) pays for the error of a predictor that copies a fixed random network. It was among the first agents to make progress on the hardest Atari exploration games, where the reward is sparse.
Pipeline placement. Interact stage (the bonus is computed for each transition) and estimate stage (the agent learns from the sum of both rewards). Cost: a count table is a constant-time update per step; a forward model adds one network pass and one gradient step per update. Stores: the visit counts or the model weights, and the rewards used for training, kept separate from the environment reward for logging.

Check yourself

1. In the chain trace, what is the total intrinsic reward (β = 1) if the last step went to state 1 instead of state 3?
State 1 would then have count 4 on the last arrival, so the bonus is 1/√4 = 0.5 instead of 1.0. The total is 5.6987 − 1.0000 + 0.5000 = 5.1987.
2. Why does the noisy-TV agent keep receiving a bonus even after it has seen a million transitions?
The error comes from randomness that no model can predict. For a fair coin between 0 and 1 the best prediction is 0.5 and the expected squared error is 0.25 whatever the data count, so the bonus never shrinks.
3. Why is the bonus designed to shrink with the count, rather than being a constant?
A constant bonus would pay for every visit forever, so the agent would never settle on exploiting the reward it has found. Shrinking the bonus with the count means familiar states stop attracting the agent, and unfamiliar ones keep doing so.

Takeaways

  • An intrinsic reward pays for novelty, so the agent gathers data when the environment reward is rare.
  • Count bonuses of order \beta/\sqrt{N} shrink as states become familiar; prediction-error bonuses shrink only where the outcome is learnable.
  • The bonus is a means to finding reward. Anneal it, and watch for noise that never goes away.
8.2

Hierarchical RL and options

The questionA cooking robot must fetch eggs, crack them, whisk, and then plate the dish. Its motors take a decision every 20 milliseconds, so the whole meal is tens of thousands of decisions. The reward arrives only when the plate is served, so the credit must travel back through tens of thousands of updates. Could the robot decide at a coarser level, for example "go to the fridge" as a single decision, and leave the small motions to a lower layer?

Intuition

In a company, the manager says "get the quarterly report written", and a team member then makes many small decisions: open the spreadsheet, check the numbers, draft a paragraph. The manager does not choose each keystroke, but the manager does decide which job comes next once the report is finished. Two levels of decision, each working at its own time scale.

Sutton, Precup and Singh (1999) formalised this as options. An option is a temporally extended action. It has three parts: where it can start, a low-level policy that acts while it runs, and a rule for when it stops. The high-level policy then chooses among options, and the low-level policy chooses primitive actions.

Build it up, one piece at a time

Step 1: an option. An option \omega is a triple (I_\omega, \pi_\omega, \beta_\omega). It can start in states I_\omega. While it runs, it uses the low-level policy \pi_\omega to choose primitive actions. At each state s, it stops with probability \beta_\omega(s). (Here \beta_\omega is a termination function, not the bonus scale of lesson 8.1.)

Step 2: options last a random number of steps. An option that runs for k steps collects the discounted reward R = \sum_{j=0}^{k-1} \gamma^j r_{t+j} and lands in a new state s_{t+k}. The next state must be discounted by \gamma^k, not by \gamma, because the option took k steps to get there. Taking the wrong power is the most common error in this lesson.

Step 3: learn at the option level. Since options are chosen at decision points and finish after k steps, the high-level decision process is a semi-Markov decision process. Its Q-learning update is

Q(s,\omega) \leftarrow Q(s,\omega) + \alpha\Big[R + \gamma^{k}\max_{\omega'} Q(s',\omega') - Q(s,\omega)\Big]

Only the decision points are updated, so the value of the first state of a long option is learned in one update rather than in k separate ones.

A worked example with two options

Take a corridor of states 0 to 6. Entering state 6 pays +1 and ends the episode, and every other step pays 0. Use \gamma = 0.9 and \alpha = 0.5, with all Q values starting at 0. There are two options. toA starts in state 0, runs 3 primitive steps to state 3 and pays 0 on the way. toG starts in state 3, runs 3 steps to state 6 and pays 0, 0, +1.

Worked example: two episodes at the option level

Episode 1. The agent takes toA from 0. It runs 3 steps, collects R = 0, and arrives at 3. The update for toA uses the best option value at 3, which is still 0:

Q(0,\text{toA}) \leftarrow 0 + 0.5\,[\,0 + 0.9^{3}\cdot 0 - 0\,] = 0

Next the agent takes toG from 3. It runs 3 steps and collects R = 0 + 0.9\cdot 0 + 0.9^2\cdot 1 = 0.81. It lands in the terminal state 6, so there is no future value:

Q(3,\text{toG}) \leftarrow 0 + 0.5\,[\,0.81 - 0\,] = 0.405

Episode 2. The agent takes toA from 0 again. This time the value at 3 is 0.405, so the update for toA is

Q(0,\text{toA}) \leftarrow 0 + 0.5\,[\,0 + 0.9^{3}\cdot 0.405\,] = 0.5\cdot 0.295245 = 0.14762

Finally toG runs again and Q(3,\text{toG}) \leftarrow 0.405 + 0.5\,(0.81 - 0.405) = 0.6075. After two episodes, state 0 already knows that reaching the goal is worth something, even though it has never been past state 3. A flat learner that updates one primitive step at a time would need a separate update for each of the three steps between states 3 and 6, and a separate chain of updates to pass the value back to state 0.

  2. Raise door top to 0.90. The high level changes its choice at its next decision, but the low-level path code is unchanged. Note that the options are the same, only the choice moved.

Common traps
  • Discount by γ^k, not γ. An option that takes 3 steps must multiply the next value by 0.9³ = 0.729. Using 0.9 overstates the value of options that run for a long time.
  • Options need an initiation set. A door option that starts in room B is meaningless, and a learner that tries it will waste effort. Restrict the choice to options that can start in the current state.
  • Hand-made options encode the designer. The "doors" here came from knowing the layout. Learned options (the option-critic) are harder to train, and they can collapse into a single option that does everything.
Where it shows up in AI
  • The option-critic (Bacon, Harb and Precup, 2017) learns the internal policies and termination functions of options end to end with policy gradients.
  • HIRO (Nachum and colleagues, 2018) trains a high-level policy that sets goals for a low-level policy, and relabels past data with the goals that were actually reached.
  • SayCan (Ahn and colleagues, 2022) uses a language model to score which of a library of learned robot skills to run next, which is a high-level policy choosing among options.
Pipeline placement. Interact stage (the high level acts every k steps) and estimate stage (the SMDP update). The high-level table has one entry per state and option, which is small; each low-level policy is a separate network or table. Stores: the option-value table and the low-level policies. Cost: decisions are fewer, so there are fewer high-level updates per episode.

Check yourself

1. An option runs for k = 4 steps and the value of its end state is 0.405. What discount multiplies that value in the update, and what is it numerically?
γ⁴ = 0.9⁴ = 0.6561, so the discounted value is 0.6561 × 0.405 = 0.2657.
2. In the worked example, why is Q(0, toA) still 0 after episode 1?
The toA update happens when the option ends at state 3, before toG has run. At that moment the best value at state 3 is still 0, so the target is 0. The value of 3 reaches state 0 only in episode 2.
3. An option collects rewards 0, 2 and 1 in its three steps, with γ = 0.9. What is R?
R = 0 + 0.9 × 2 + 0.9² × 1 = 1.8 + 0.81 = 2.61.

Takeaways

  • An option is a temporally extended action with a start set, a low-level policy and a stop rule.
  • Learning at the option level is a semi-Markov problem: discount the next value by \gamma^k for the k steps the option took.
  • Options shorten credit assignment and make decisions cheaper, but they are only as good as the structure they encode.
8.3

Multi-agent reinforcement learning

The questionTwo delivery robots share a narrow corridor. Each has learned, over a week, to wait when the other is coming. Then one robot receives a software update that makes it faster, and the other starts colliding with it. Nothing about the second robot's own code changed. Why did a policy that worked yesterday stop working, and what does "best" mean when two learners are each part of the other's world?

Intuition

Imagine learning to drive on a road where every other driver is also learning. When you decide to merge, your reward depends on what the other drivers do, and they are changing their habits too. From your point of view the road keeps changing. A rule that was right last week can be wrong this week, because the other drivers changed, not because you did.

In single-agent RL the environment is fixed, and Q-learning converges under standard conditions because the target does not move. With several learners the environment includes the other learners, so each agent faces a non-stationary target. This single fact drives most of what follows.

Build it up, one piece at a time

Step 1: joint actions. With two agents, each step has a joint action (a_1, a_2). Each agent receives its own reward R_i(s, a_1, a_2), which can depend on what the other agent did. The model is a stochastic game (a Markov game): a generalisation of an MDP to several decision-makers.

Step 2: independent learners. The simplest method gives each agent its own learner and treats the other agents as part of the environment. This is easy to build and scales to many agents, but each learner's target depends on the other agents' current policies, which are moving. So the convergence guarantees of single-agent Q-learning do not carry over.

Step 3: what counts as a solution. In a game with two or more decision-makers, the natural target is an equilibrium. A Nash equilibrium is a joint policy in which no agent can do better by changing only its own policy. The team's total return is a separate question, and it is where cooperation and competition differ: in a cooperative game the agents share one reward, and in a competitive (zero-sum) game one agent's gain is the other's loss.

Worked examples in three games

Use two players, each with actions A and B. Payoffs are written as (player 1, player 2).

Worked example 1: the coordination game and a moving best reply

Both players get 1 if they both choose A, 2 if they both choose B, and 0 if they choose different actions. Let player 2 play A with probability q. Player 1's expected payoffs are

\mathbb E[\text{payoff of A}] = q\cdot 1 + (1-q)\cdot 0 = q
\mathbb E[\text{payoff of B}] = q\cdot 0 + (1-q)\cdot 2 = 2(1-q)

The two are equal at q = 2/3. Player 1 should play A when player 2's probability of A is above 2/3, and B when it is below. With the same payoffs:

player 2's P(A) = qpayoff of A = qpayoff of B = 2(1 − q)player 1's best reply
0.50.51.0B
0.80.80.4A

Player 1 has not changed at all, but its best reply has flipped because player 2 changed. Both pure equilibria, (A, A) with payoff 1 each and (B, B) with payoff 2 each, are stable, and independent learners can settle on either. Nothing in the update tells them which is better for both.

Worked example 2: the prisoner’s dilemma

Let A mean "cooperate" and B mean "defect". Payoffs (player 1, player 2): (A, A) gives (3, 3); (A, B) gives (0, 5); (B, A) gives (5, 0); (B, B) gives (1, 1). Compare player 1's payoffs for each action given player 2's choice: if player 2 plays A, B gives 5 and A gives 3; if player 2 plays B, B gives 1 and A gives 0. Defecting is better whatever the other player does, so B is a dominant action. The unique pure Nash equilibrium is (B, B), with total payoff 2. The joint outcome (A, A) has total payoff 6, but neither player can reach it alone.

Worked example 3: matching pennies has no pure equilibrium

Player 1 wins 1 if the two actions match and loses 1 if they differ; player 2 is the reverse. Let player 2 play A with probability q. Player 1's payoff of A is q - (1-q) = 2q - 1 and of B is -q + (1-q) = 1 - 2q. These are equal at q = 1/2. Each player's best reply flips around the other's probability of 1/2, so independent learners tend to chase each other in cycles rather than settle. The only equilibrium is the mixed one, where each player plays A with probability 1/2.

The formal definition

\text{Nash: for each } i:\quad V_i(\pi_i^*, \pi_{-i}^*) \;\ge\; V_i(\pi_i, \pi_{-i}^*)\quad\text{for every alternative } \pi_i

Here the stochastic game has states s, joint actions \mathbf a = (a_1,\dots,a_n) and transitions P(s' \mid s, \mathbf a). Each agent's value depends on all the policies, which is why the definition compares one agent at a time.

Common traps
  • Treating other agents as noise. Independent learners are not guaranteed to converge when others are learning too. A test that looks stable for 10 000 rounds can fail after a policy update somewhere else.
  • An equilibrium is not an optimum. The prisoner’s dilemma equilibrium is stable, and it is worse for both players than cooperation. Stability and efficiency are different properties.
  • Many equilibria. The coordination game has two. Which one learners reach depends on their early experience, so results can differ from run to run. Report the spread over seeds.
Where it shows up in AI
  • AlphaStar (Vinyals and colleagues, 2019) trained a league of agents that played against past versions of each other, so that no single opponent could be exploited for long.
  • Hide-and-seek experiments (Baker and colleagues, 2019) showed agents inventing tool use in a competitive game, driven by the other team’s changing strategy.
  • QMIX (Rashid and colleagues, 2018) learns a team value that decomposes into per-agent values for cooperative control, such as the StarCraft micromanagement tasks.
Pipeline placement. Interact stage (all agents act together each step) and estimate stage (each agent updates its own value). The joint action space has |A|^n entries, so tabular methods fail quickly as agents are added. Stores: one table or network per agent, and, for training with a centralised critic, the joint experience. Evaluation must test against a population of opponents, not one.

Check yourself

1. In the coordination game, what is player 1’s best reply if player 2 plays A with probability 0.6?
A pays q = 0.6 and B pays 2(1 − 0.6) = 0.8. B is better, so the best reply is B.
2. In the prisoner’s dilemma, why is (B, B) the only pure Nash equilibrium, and what is the total payoff there compared with (A, A)?
B is better for each player whatever the other does (5 against 3, and 1 against 0), so each player's best reply is B in every case. Total payoff at (B, B) is 1 + 1 = 2, and at (A, A) it is 3 + 3 = 6.
3. Why can a single agent’s learning rule be stable against a fixed opponent but oscillate against a learning one in matching pennies?
Against a fixed opponent, the best reply is a fixed target and Q-learning can settle on it. Against a learning opponent, the best reply switches whenever the opponent's probability crosses 1/2, so each agent keeps overshooting the other's new policy and the pair cycles.

Takeaways

  • Other learners make the environment non-stationary, which breaks the single-agent convergence arguments.
  • The right target is an equilibrium, and an equilibrium can be stable yet inefficient.
  • Test against populations of opponents, report results over seeds, and use team methods when the reward is shared.
8.4

Offline reinforcement learning

The questionA hospital holds five years of treatment records: what each patient received, and what happened next. It may not run new trials on patients to find a better treatment. Can an agent learn a better policy from those records alone? And what goes wrong when the policy it learns would prescribe a treatment that the records never contain?

Intuition

Suppose you are learning to drive by watching hours of dash-camera footage, with no car of your own. You can learn a great deal: how drivers slow for junctions, what they do in rain. But you cannot learn what happens if you swerve into a ditch, because no one filmed it. If you then try to decide for yourself by imagining the ditch as a fine option, you will believe something false and nothing in the footage will correct you.

That is the core of offline RL (also called batch RL). The agent receives a fixed dataset of transitions, collected by some unknown behaviour policy \mu, and it may not interact with the environment while learning. The danger is not the lack of data for common actions, but the use of actions that the data never contains.

Build it up, one piece at a time

Step 1: the dataset. The data are tuples (s, a, r, s') recorded while the behaviour policy acted. Some actions are common in the data; others never appear in a given state.

Step 2: the Bellman target uses a maximum. Q-learning computes r + \gamma \max_{a'} Q(s', a'). The maximum ranges over all actions, including the ones the data never tried. If the estimate for an untried action is too high, the target is too high, and the error spreads backwards through every state that leads to it. Nothing in the data can correct the error, because there is no sample of that action to compare with.

Step 3: stay close to the data or be pessimistic. There are two broad remedies. One is to restrict the learned policy to actions similar to the behaviour policy (behaviour-constrained methods). The other is to penalise values of actions the data do not support, so that the learner only prefers an unseen action when the evidence is strong. Pessimism is the idea behind conservative methods.

A worked example: an unseen action with a high estimate

Worked example: naive versus pessimistic choice

One state, two actions. Action a1 appears n = 50 times in the data, and its estimate is \hat Q(s,a_1) = 1.0. Action a2 never appears (n = 0), but a neural network extrapolates to \hat Q(s,a_2) = 3.0.

Naive rule. Pick the largest estimate: a2, with value 3.0. The data cannot check this number at all.

Pessimistic rule. Subtract an uncertainty penalty \kappa/\sqrt{n+1} with \kappa = 3:

\text{a1: } 1.0 - \frac{3}{\sqrt{51}} = 1.0 - 0.4201 = 0.5799,\qquad \text{a2: } 3.0 - \frac{3}{\sqrt{1}} = 0.0

The pessimistic rule picks a1. The unseen action has lost its advantage, because its estimate is not supported by any data. (The same penalty is smaller for a1 because it is well sampled.)

The conservative penalty in CQL. Conservative Q-learning adds, for each state, a term \log \sum_a e^{Q(s,a)} - Q(s, a_{\text{data}}). Here \log(e^{1} + e^{3}) - 1 = 3.1269 - 1 = 2.1269. Minimising this lowers the values of all actions in proportion to how large they are, and raises the value of the action the data actually used. An unseen action with an inflated value is pushed down.

The formal definition

\min_Q\;\; \alpha\,\mathbb E_{s\sim\mathcal D}\Big[\log\sum_a e^{Q(s,a)} - \mathbb E_{a\sim\hat\mu(\cdot\mid s)}\,Q(s,a)\Big]
\qquad + \tfrac12\,\mathbb E_{\mathcal D}\big[(Q(s,a) - r - \gamma \bar Q(s'))^2\big]

The first term is the conservative penalty, and the second is the usual Bellman error on the logged transitions. The learned policy is then greedy with respect to the conservative Q. The version above is a simplified form of the objective in Kumar and colleagues (2020).

\mu, \hat\muthe behaviour policy that generated the data, and its estimate from the data
\alphathe strength of the conservative penalty
\bar Qa target network, a slowly updated copy of Q used for stability

  1. Set κ to 0 (the naive rule). Note the chosen action in state 0 (a3, never in the data) and in state 2 (a2, never in the data).
  2. Set κ to 3. The chosen action in state 0 changes to a1, and the penalty bar for a3 drops to zero.
  3. Increase κ slowly from 2 to 3. Find the value at which state 0 switches to a1. It is about κ = 2.33. Check it by hand: a2 has penalised score 3 − κ, a1 has 1 − κ/√51, and they are equal at κ = 2/(1 − 1/√51).
  4. In state 2, the two candidates a1 and a3 are close after penalty (0.5955 and 0.5753 at κ = 3). Notice how little it takes to change the choice.
Common traps
  • More data does not fix missing actions. A larger log of the same behaviour leaves untried actions untried. Coverage, not size, decides what the learner can justify.
  • Pessimism can become copying. If the penalty is too strong, the learner only picks the most-logged actions, which is behaviour cloning under another name, with no gain over the logs.
  • Offline evaluation is itself biased. Scoring a new policy with the same Q values that chose it reuses the optimistic errors. Use held-out logs, importance-weighted estimates (which need the behaviour probabilities), or a simulator, and report uncertainty.
Where it shows up in AI
  • Batch-constrained Q-learning (Fujimoto and colleagues, 2019) restricts the learned policy to actions that the data make plausible, and it was among the first offline methods to show the extrapolation failure clearly.
  • Conservative Q-learning (Kumar and colleagues, 2020) and implicit Q-learning (Kostrikov and colleagues, 2021) are the standard baselines on the D4RL benchmark of logged datasets.
  • Logged data from recommendation and advertising systems is the everyday setting: the system only ever showed the items its old policy chose, so any new policy must be judged against that coverage.
Pipeline placement. Learn stage only: training uses the fixed log and does not touch the act loop. The trained policy is evaluated offline, then rolled out carefully (a small share of traffic, or a simulator first), and monitored. Stores: the immutable dataset with the behaviour probabilities if you have them, and the model versions. Cost: one pass over the log per epoch, with no new interaction.

Check yourself

1. With κ = 3, what does the pessimistic rule choose in state 1, where a2 has n = 60 and Q̂ = 1.6, and why?
a2. Its penalised score is 1.6 − 3/√61 = 1.216, against about −0.94 for a1 and −0.53 for a3. a2 is also the naive choice, because it is well covered by the data.
2. Using the worked example, what is the conservative penalty term if the data action were a2 instead of a1?
log(e¹ + e³) − 3 = 3.1269 − 3 = 0.1269. The penalty is smaller, because the logged action is the high-value one: the term pushes down the unseen values and leaves the logged high value alone.
3. Why does a larger dataset from the same behaviour policy not remove the need for pessimism?
The new samples come from the same behaviour policy, so they cover the same actions. The untried actions still have no data, and their estimates are still unchecked by any observation.

Takeaways

  • Offline RL learns from a log, and the danger is in the actions the log never contains.
  • The Bellman maximum can pick an unsupported action; pessimism or policy constraints stop it doing so.
  • Judge an offline policy by its coverage of the data, and evaluate it without trusting the same optimistic numbers.
8.5

Imitation and inverse reinforcement learning

The questionAn experienced surgeon shows a trainee how to close a wound. Behaviour cloning (lesson 7.1 of the robotics module) would copy the surgeon's movements in the situations shown. But the trainee will face new tissue and new angles. What the surgeon was really optimising (speed, safety, tissue damage, a neat seam) would transfer to those situations, while the copied movements would not. Can we recover the reward that explains the surgeon's choices, and then plan with it?

Intuition

When you watch someone choose, you learn about what they value. A friend who always orders the spicy dish, even when a mild one is on offer, probably likes heat. You can predict what they will order at a restaurant you have never visited, because you learned their taste, not a list of their past orders. Inverse reinforcement learning (IRL), introduced by Ng and Russell (2000), does this for an agent: the demonstrations are treated as optimal behaviour, and the task is to find the reward that makes them optimal.

This is different from behaviour cloning. Cloning learns a map from situations to actions. IRL learns the goal, and then a planner (ordinary RL) produces actions for any situation, including new ones.

Build it up, one piece at a time

Step 1: a parametrised reward. Assume the reward is linear in features: r(s,a) = w^\top \phi(s,a). The features are chosen by the designer, for example distance to the curb, a collision indicator and a jerk penalty. The unknown is the weight vector w.

Step 2: expected feature counts. For a policy \pi, let \mu(\pi) = \mathbb E_\pi[\sum_t \gamma^t \phi(s_t,a_t)] be its discounted feature count. Its value under reward w is V_w(\pi) = w^\top \mu(\pi). So a learner whose feature counts match the expert's does as well as the expert under every linear reward (Abbeel and Ng, 2004). This is the matching idea that most IRL methods use.

Step 3: the ambiguity. Many different w explain the same demonstrations. Scaling w by 2 changes no choice, because the best action is unchanged. And if the expert's choices are indifferent between options, any reward that makes them tie also explains them. The worked example below makes this exact.

Step 4: maximum-entropy IRL. To pick one answer, Ziebart and colleagues (2008) assume the expert is noisy: the probability of a choice grows exponentially with its reward. For a single choice from a set of actions, P(a) \propto \exp(w^\top\phi(a)). The gradient of the log-likelihood of a demonstration is then

\nabla_w \log P_w(a_{\text{demo}}) = \phi(a_{\text{demo}}) - \mathbb E_{P_w}[\phi(a)]

The gradient is the demonstrated features minus the features the learner currently expects. Gradient ascent moves w until the two agree.

Worked example 1: many rewards explain one choice

Three actions with features \phi(a_1) = (1,0), \phi(a_2) = (0,1) and \phi(a_3) = (0.5, 0.5). The expert chooses a1 when all three are on offer. Chosen a1 must beat a2 and a3:

w_1 \ge w_2 \qquad\text{(a1 against a2)}
w_1 \ge \tfrac12(w_1 + w_2) \iff w_1 \ge w_2 \qquad\text{(a1 against a3)}

Both constraints reduce to the same half-plane w_1 \ge w_2. The reward (1,0), the reward (2,1), and the reward (10, 0) all explain the choice, and so does (1,1), where all three actions tie. A learner cannot tell them apart from this one demonstration.

Worked example 2: one maximum-entropy step

Start at w = (0,0). All three actions are equally likely, P = 1/3 each, so the expected features are \mathbb E[\phi] = \tfrac13(1+0+0.5,\; 0+1+0.5) = (0.5, 0.5). The gradient from one demonstration of a1 is

\phi(a_1) - \mathbb E[\phi] = (1,0) - (0.5,0.5) = (0.5,\,-0.5)

A step of size 0.5 gives w = (0.25, -0.25). The learner now assigns P(a_1) = 0.4192, P(a_2) = 0.2543 and P(a_3) = 0.3265. The probability of the demonstrated action has risen from one third to 0.42, and the gradient at this point is smaller, so repeated steps settle.

Worked example 3: a second demonstration narrows the set

Suppose a later demonstration offers the same three actions and the expert picks a3. Then a3 must beat a1 and a2:

\tfrac12(w_1 + w_2) \ge w_1 \iff w_2 \ge w_1 \qquad\text{(against a1)}
\tfrac12(w_1 + w_2) \ge w_2 \iff w_1 \ge w_2 \qquad\text{(against a2)}

Together with the first demonstration (which needs w_1 \ge w_2), the feasible set is w_1 = w_2: a line through the origin on which all three actions tie. Two demonstrations that pick different actions leave only the directions in which the expert is indifferent.

The formal definition

Maximum-entropy IRL chooses the weights that make the demonstrations most likely under a noisy expert. Its gradient has the familiar form: demonstrated features minus expected features.

\max_w \sum_{i=1}^{m}\log P_w(\tau_i),\qquad P_w(\tau)\propto \exp\big(w^\top \phi(\tau)\big)
\nabla_w = \hat\mu_{\text{demo}} - \mathbb E_{P_w}[\phi(\tau)]
\phi(s,a)the feature vector of a state–action pair, chosen by the designer
wthe unknown reward weights to be recovered
\mu(\pi)the discounted feature count of policy π, the expected sum of features along its trajectories
\tau_ithe i-th demonstrated trajectory, and \phi(\tau) its total feature count
P_wthe probability of a trajectory when the expert is noisy with reward w

Lab: the set of rewards that explain the expert

Try this
  1. Keep θ* at 30° and press Play. Each demonstration offers 3 of the 5 points. The green arc, the directions still consistent with every choice, narrows as demonstrations accumulate.
  2. Pause after about 10 demonstrations. Find the orange arrow (the expert’s true direction) inside the green arc. It is always there, because the expert’s choices are consistent with its own reward.
  3. Let the run continue to its end. The arc stops shrinking before it becomes a point: the directions that remain are those in which the expert's chosen point is best, and no finite set of choices can separate them further.
  4. Change θ* to 200°. The demonstrations restart and the arc moves to a different part of the circle. The learner recovers direction, not magnitude: the scale of w is never shown.
Common traps
  • Recovered rewards are ambiguous. Worked example 1 shows that many rewards fit the same data. A recovered reward can plan well in the demonstrated setting and poorly elsewhere, so check it on held-out situations.
  • The features limit the reward. If the true objective is not a linear function of your features, the recovered reward explains the demonstrations badly and the learned plans will show it. Add features, or move to a nonlinear reward model.
  • Each step needs a planner. Standard IRL solves a forward RL problem inside every gradient step, so it is expensive. Demonstrations that are not optimal also need a noisy-expert model such as maximum entropy.
Where it shows up in AI
  • Apprenticeship learning (Abbeel and Ng, 2004) matched feature counts to fly a helicopter through aerobatic manoeuvres from expert pilot demonstrations.
  • Maximum-entropy IRL (Ziebart and colleagues, 2008) was used to predict driver route choices from GPS traces of taxi drivers.
  • Generative adversarial imitation learning (Ho and Ermon, 2016) learns a discriminator that acts like a reward, and the same idea appears in reward modelling from human preferences, which is the subject of Module 9.
Pipeline placement. Learn stage: the demonstrations are stored offline, and the inner loop solves a forward RL problem for each reward estimate. The output, the reward weights, is then used by a planner in the act loop. Stores: the demonstration trajectories with their features, and the recovered weights with the version of the feature code that produced them.

Check yourself

1. In worked example 1, what constraints does a demonstration of a2 (offered with a1 and a3) impose?
a2 must beat a1, so w2 ≥ w1; and a2 must beat a3, so w2 ≥ 0.5(w1 + w2), which is also w2 ≥ w1. The feasible set is the half-plane w2 ≥ w1.
2. After the first maximum-entropy step in worked example 2, what is the probability of a1, and what does it say about the learning?
P(a1) = 0.4192. It rose from 1/3, because the demonstrated features (1, 0) were above the expected features (0.5, 0.5) in the direction of a1, so the update pushed the reward toward a1.
3. Why can the reward not be recovered in magnitude from choices alone, and how does this affect planning?
Multiplying w by a positive number does not change which action is best, so the choices are unchanged. Planning needs only the ordering of rewards, so the recovered reward is defined up to a positive scale (and, for policies, up to shaping terms that do not change the optimal policy).

Takeaways

  • Inverse RL recovers the reward that explains demonstrations; it transfers to new situations where copying does not.
  • Choices reveal reward only up to ambiguity: many weights fit, and scale is never identified.
  • Matching feature counts, with a maximum-entropy model for noisy experts, is the standard route, at the cost of an inner planning loop.
